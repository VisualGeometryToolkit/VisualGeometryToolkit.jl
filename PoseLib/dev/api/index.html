API reference

Every docstring of the package: the module, the exported refiners and the LeZachTruncation loss, the public Rigid3 pose type and is_available, the unexported bundle_adjust alias, and the PoseLibSolver methods this package adds to VisualGeometryToolkitCore's minimal-solver kernels.

PoseLib.PoseLib — Module
PoseLib

Julia bindings to PoseLib, the C++ library of minimal solvers and robust refiners for camera pose estimation.

Loading this package extends VisualGeometryToolkitCore:

  • Its minimal solvers gain a PoseLib backend, PoseLibSolver(): the four-point homography, the seven-point fundamental matrix, the perspective-three-point (P3P) absolute pose and the five-point essential matrix. The eight-point essential matrix, essential_dlt, has no native variant, so its default routes here.
  • PoseLib's robust Levenberg–Marquardt refiners are exported: refine_homography, refine_fundamental, refine_relpose and refine_absolute_pose. Each takes a seed model and its correspondences, and returns the refined model in the caller's frame.

The C++ library and its flat C wrapper ship prebuilt as this package's PoseLib artifact, on Linux only for now. The manual's "Platforms and binaries" page says how to run against a library built from source.

PoseLib.LeZachTruncation — Type
LeZachTruncation()

The truncated loss ρ = min(r², w²), optimized by the iteratively reweighted least-squares scheme of Le and Zach (International Conference on 3D Vision, 2021). This is PoseLib's TRUNCATED_LE_ZACH loss.

The loss itself is VisualGeometryToolkitCore's TLSShape() at loss_width = w. LeZachTruncation() is a marker, not a loss shape: it selects how the same loss is optimized. Any refiner takes it as its loss keyword.

PoseLib.Rigid3 — Type
Rigid3

The rigid motion x ↦ R·x + t that the pose refiners take as their seed and return: a VisualGeometryToolkitCore EuclideanMap in 3D with a RotMatrix rotation, a Vec3 translation and unlabeled frames. EuclideanMap(RotMatrix{3}(R), Vec3(t)) builds one.

For refine_relpose it maps the first camera's frame to the second's. For refine_absolute_pose it maps the world frame to the camera's. A labeled pose, such as the Extrinsics3 that P3P returns, is converted with VisualGeometryToolkitCore's unlabel.

PoseLib.bundle_adjust — Function
PoseLib.bundle_adjust(pose, K, cs; max_iter, loss, loss_width)

An alias of refine_absolute_pose under PoseLib's own name for absolute-pose refinement. It is not exported. It takes refine_absolute_pose's arguments (the pose first, then the X => u correspondences), not upstream's (x, X, pose) order.

PoseLib.refine_absolute_pose — Method
refine_absolute_pose(pose::Rigid3, K, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Robust Levenberg–Marquardt refinement of an absolute pose from 3D-to-2D correspondences, through PoseLib's bundle_adjust. The residual is the reprojection error project(camera, R X + t) − u.

pose is the seed Rigid3, mapping the world frame to the camera's. K is the intrinsic matrix of the frame the image points are in. cs holds the correspondences X => u of 3D points to 2D image points. Returns the refined Rigid3.

loss_width is the width of the loss on the reprojection residual, in the unit of u and K (pixels for a pixel-frame K). loss and loss_width are as in refine_homography. Only the six degrees of freedom of the pose are refined; K stays fixed.

K reaches PoseLib as its SIMPLE_PINHOLE camera model, with focal length (K₁₁ + K₂₂)/2 and principal point (K₁₃, K₂₃). Skew and any difference between K₁₁ and K₂₂ are dropped, so the model is exact only for square pixels and zero skew.

PoseLib.refine_absolute_pose — Method
refine_absolute_pose(pose::Rigid3, cs::…StaticVector{2}…; max_iter, loss, loss_width)

This form is refused with an ArgumentError. Its targets would be calibrated points on the z = 1 plane (GnomonicFrame), with a loss width divided by the focal length. That plane has no point for a ray at or beyond 90° from the optical axis.

Use refine_absolute_pose(pose, K, cs) instead: the same correspondences in pixels, the intrinsic matrix K, and loss_width in pixels.

PoseLib has no absolute-pose refiner on bearings. Its residual is a reprojection error in the image, so the pixel form is the only one, and it reaches PoseLib as a SIMPLE_PINHOLE camera. That model cannot project a ray at or beyond 90° either, so this package offers no correct absolute-pose refinement for a fisheye camera.

PoseLib.refine_absolute_pose — Method
refine_absolute_pose(pose::UnitfulEuclideanMap{3}, K, cs; max_iter, loss = TLSShape(), loss_width)

The physical form of refine_absolute_pose: pose a world→camera pose whose translation is a length (FlexUnits quantities) and cs the correspondences X => u with the world points X lengths. Both are stripped in metres once, the plain refinement runs, and the refined pose comes back with its translation in metres: equal, after ustrip(m, ·), to the plain refinement's on the inputs' ustrip(m, ·). u, K and loss_width stay in pixels. A labeled seed (an estimate's CameraExtrinsics, world → camera) is read unlabeled; the refined pose comes back unlabeled. A physical seed with plain points, or the reverse, is an ArgumentError.

PoseLib.refine_fundamental — Method
refine_fundamental(F, cs; max_iter, loss = TLSShape(), loss_width) -> FundMat

Robust Levenberg–Marquardt refinement of a fundamental matrix through PoseLib's refine_fundamental. It minimizes the Sampson error over the Bartoli–Sturm parametrization of F, which keeps the matrix at rank 2.

F is the seed 3×3 fundamental matrix. cs holds the correspondences x1 => x2 of 2D image points, in the frame F is expressed in (pixels for a pixel-frame F). loss_width is the width of the loss on the Sampson residual, in the same unit. loss and loss_width are as in refine_homography. Returns the refined FundMat.

PoseLib.refine_homography — Method
refine_homography(H, cs; max_iter, loss = TLSShape(), loss_width) -> HomographyMat

Robust Levenberg–Marquardt refinement of a homography through PoseLib's refine_homography. It minimizes the symmetric transfer error: the forward residual x2 − π(H x1) and the backward residual x1 − π(H⁻¹ x2), each robustified per point, where π divides by the third coordinate.

H is the seed 3×3 homography. cs holds the correspondences x1 => x2 of 2D image points, in the frame H is expressed in (pixels for a pixel-frame H). loss_width is the width of the loss on a one-sided transfer residual, in the same unit. Returns the refined HomographyMat.

loss is one of VisualGeometryToolkitCore's loss shapes, or LeZachTruncation():

lossρ(r)note
TLSShape() (default)min(r², w²)truncated quadratic: inliers have r < w, outliers get zero weight
HuberShape()r² up to w, linear beyond
CauchyShape()w² log(1 + r²/w²)
GaussianShape()r²plain least squares; takes no loss_width
LeZachTruncation()min(r², w²)the truncated loss under Le and Zach's scheme

loss_width is the width w of VisualGeometryToolkitCore's closed form for that shape. PoseLib's own loss_scale equals it for every loss bound here, so it reaches PoseLib unchanged. max_iter, the iteration budget, has no default.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, K1, K2, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Robust Levenberg–Marquardt refinement of a relative pose from pixel correspondences and the two cameras' intrinsics.

pose is the seed Rigid3, mapping the first camera's frame to the second's. cs holds the correspondences x1 => x2, each point in its own image's frame. K1 and K2 are the intrinsic matrices of those frames: pixel matrices for pixel points, or matrices in whatever frame the points are in. Returns the refined Rigid3.

loss_width is in the unit of the points. PoseLib back-projects through each camera, so one width serves both images even when their focal lengths differ. loss and loss_width are as in refine_homography. max_iter, the iteration budget, has no default.

Each K reaches PoseLib as its SIMPLE_PINHOLE camera model, with focal length (K₁₁ + K₂₂)/2 and principal point (K₁₃, K₂₃). Skew and any difference between K₁₁ and K₂₂ are dropped, so the model is exact only for square pixels and zero skew.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, cs::…StaticVector{2}…; max_iter, loss, loss_width)

This form is refused with an ArgumentError. Calibrated 2-vectors are coordinates on the z = 1 plane (GnomonicFrame). That plane has no point for a ray at or beyond 90° from the optical axis, which excludes fisheye and omnidirectional cameras. Relative pose is calibrated geometry, so in this stack it takes unit bearings (unit rays).

Use one of the two supported forms:

  • refine_relpose(pose, cs), with cs of unit bearings f₁ => f₂ that carry their back-projection Jacobians M₁ and M₂. This is PoseLib's tangent-Sampson refiner.
  • refine_relpose(pose, K1, K2, cs), with pixel points and the two intrinsic matrices. PoseLib back-projects through the cameras and runs the same refiner.

backproject_with_jacobian(camera, u) returns a bearing and its Jacobian together.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Robust Levenberg–Marquardt refinement of a relative pose from unit bearings, through PoseLib's tangent-Sampson refiner.

pose is the seed Rigid3, mapping the first camera's frame to the second's. cs holds the correspondences f₁ => f₂ of unit bearings (StaticVector{3}). They carry their 3×2 back-projection Jacobians as the attribute columns M₁ and M₂, attached with withattrs(cs; M₁, M₂). VisualGeometryToolkitCore's backproject_with_jacobian(camera, u) returns each bearing together with its Jacobian. Returns the refined Rigid3.

No image plane is involved, so a ray at or beyond 90° from the optical axis is an ordinary input. A 3-vector that is not of unit length is refused with an ArgumentError: a point on the z = 1 plane lifted to (x, y, 1) has the right type but is not a bearing.

The unit of loss_width

loss_width is the width w of the loss on the tangent-Sampson residual

r = (f₂ᵀ E f₁) / √(‖M₂ᵀ E f₁‖² + ‖M₁ᵀ Eᵀ f₂‖²)

The denominator is the gradient norm of the epipolar constraint with respect to the coordinates that M differentiates against. The residual r is in the unit of those coordinates, and loss_width must be given in the same unit. The Jacobians set the unit; the call cannot.

M isr and loss_width are in
∂f/∂u from backproject_with_jacobianpixels of u
an orthonormal basis of the tangent plane of the sphere at fradians

A width in the wrong unit is off by a factor of the focal length. Nothing reports this: a truncated loss simply keeps the wrong inliers.

All arguments are in the caller's frame, and the refined pose comes back in it.

PoseLib.refine_relpose — Method
refine_relpose(pose::UnitfulEuclideanMap{3}, args...; kw...)

This form is refused with an ArgumentError. A calibrated relative pose is determined only up to scale, so its translation is a direction, not a length: there is no unit to strip at entry or to reattach at exit. Hand over the plain seed, ustrip(m, pose) converted to a Rigid3.

VisualGeometryToolkitCore.homography_4pt — Method
homography_4pt(::PoseLibSolver, s₁, s₂, s₃, s₄, d₁, d₂, d₃, d₄) -> Union{HomographyMat, Nothing}

PoseLib's four-point homography solver, the PoseLibSolver backend of VisualGeometryToolkitCore's homography_4pt kernel. The points are 2-vectors: sources sᵢ and targets dᵢ with dᵢ ≃ H sᵢ. Returns the homography, sign normalized, or nothing for a degenerate sample. The public entry point is solve(Homography4pt(PoseLibSolver()), cs, idx).
