PoseLib.PoseLib — Module
PoseLib

Julia bindings to the PoseLib C++ minimal-solver library.

Extends VisualGeometryToolkitCore with PoseLib-backed methods. Loading this package adds:

  • Backend overloads (::PoseLibSolver) for shared solvers: homography_4pt, fundamental_7pt, p3p, essential_5pt.
  • A PoseLib-only solver (no native variant): essential_dlt, whose convenience default routes to the PoseLib backend when no AbstractSolverBackend is supplied.
  • Robust-loss LM refinement, model first and correspondences as one Cspond vector: refine_relpose, refine_fundamental, refine_homography, refine_absolute_pose. The loss is a VisualGeometryToolkitCore loss shape (TLSShape(), HuberShape(), CauchyShape(), GaussianShape()) or LeZachTruncation(), at the loss_width the shape's own closed forms use. The calibrated pair each take the caller's own units, and REFUSE the z = 1 chart: refine_relpose(pose, cs) on unit BEARINGS carrying their M₁/M₂ backprojection Jacobians (PoseLib's tangent Sampson — no chart, so a ray at or beyond 90° is ordinary), and refine_absolute_pose(pose, K, cs) on pixel points with a pixel loss width. Handing either a calibrated 2-vector raises an ArgumentError naming the form to use. Each docstring names the unit its loss_width is in, and what sets it.

Binary

The C++ library and its flat C wrapper (wrapper/julia_wrapper.cpp) ship prebuilt as this package's own PoseLib artifact (Artifacts.toml; Linux only until the PoseLib_jll release), built from the recipe yggdrasil/P/PoseLib/build_tarballs.jl by scripts/build_binaries.jl. To run against a library built from source, override the artifact in the depot's Overrides.toml (see the README, "Building the wrapper from source").

PoseLib.LeZachTruncation — Type
LeZachTruncation()

The truncated loss ρ = min(r², w²) (VisualGeometryToolkitCore's TLSShape at loss_width = w) optimized by the TR-IRLS scheme of Le & Zach (3DV 2021), PoseLib's TRUNCATED_LE_ZACH. A marker, not a loss shape: the LOSS is TLSShape's, the marker selects the optimization scheme.

PoseLib.refine_absolute_pose — Method
refine_absolute_pose(pose::Rigid3, K, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Camera-aware absolute-pose bundle adjustment — PoseLib's bundle_adjust(x, X, &image, opt) (bundle.cc:105, the Image overload), whose AbsolutePoseRefiner forms the residual as project(camera, R X + t) − x through the camera's OWN projection. pose is the seed world→camera pose, K the intrinsics of the frame cs's image points are in, and cs the correspondences X => u of 3D points to 2D image points in that same frame. Returns the refined Rigid3.

loss_width is the loss's width on that reprojection residual, in the units of u and K — pixels for a pixel-frame K; loss and loss_width are as in refine_homography. Nothing is pre-divided on the caller's behalf; this is the only absolute-pose form, the calibrated z = 1 one having been withdrawn.

K is NOT refined: BundleOptions leaves refine_focal_length, refine_principal_point and refine_extra_params false, so only the 6-DOF pose moves.

K reaches C++ as a SIMPLEPINHOLE camera: focal (K₁₁ + K₂₂)/2 and principal point (K₁₃, K₂₃); the skew and any K₁₁ ≠ K₂₂ are dropped, so the model is exact only for a square-pixel, zero-skew K — the same lossy crossing [`refinerelpose`](@ref) documents.

Binding layer: pose, cs, K and loss_width are all in the caller's frame and the result comes back in it; nothing here normalizes.

PoseLib.refine_absolute_pose — Method
refine_absolute_pose(pose::Rigid3, cs::…StaticVector{2}…; max_iter, loss, loss_width)

Refused. The 2-vectors were coordinates on the z = 1 chart (GnomonicFrame) — "calibrated image points" — with the loss width pre-divided by the focal length. PnP is calibrated geometry, and the chart has no point for a ray at or beyond 90°, so this shape is the one the stack is removing.

Use refine_absolute_pose(pose, K, cs): the same correspondences as pixels with their intrinsics, and loss_width in pixels. Nothing is pre-divided, and the frame the caller hands over is the frame the result comes back in.

The gap this leaves, stated rather than papered over

PoseLib has no absolute-pose refiner on bearings — every bundle_adjust overload in bundle.h takes Point2D, because the residual is a reprojection into an image, not an angle on the sphere. So the pixel form above is the only absolute-pose path here, and it crosses as SIMPLE_PINHOLE, which cannot project a ray at or beyond 90° either. A fisheye caller therefore has no correct absolute-pose refinement in this package — which was equally true before, and is now visible instead of hidden behind a chart that silently mis-measured it.

PoseLib.refine_fundamental — Method
refine_fundamental(F, cs; max_iter, loss = TLSShape(), loss_width) -> FundMat

Robust-loss (truncated by default: MSAC) Levenberg–Marquardt refinement of a fundamental matrix via PoseLib's refine_fundamental (Sampson error, optimized over the Bartoli–Sturm SVD factorization of F). F is the seed 3×3 fundamental matrix, cs the correspondences x1 => x2 of 2D image points (same coordinate frame as F — pixels for a pixel-frame F), and loss_width the loss's width on the Sampson residual. loss and loss_width are as in refine_homography. Returns the refined FundMat.

PoseLib.refine_homography — Method
refine_homography(H, cs; max_iter, loss = TLSShape(), loss_width) -> HomographyMat

Robust-loss (truncated by default: MSAC) Levenberg–Marquardt refinement of a homography via PoseLib's refine_homography (symmetric transfer error — forward |x2 - π(H x1)| and backward |x1 - π(adj(H) x2)|, each side robustified per point). H is the seed 3×3 homography, cs the correspondences x1 => x2 of 2D image points (same coordinate frame as H — pixels for a pixel-frame H), and loss_width the loss's width on the one-sided transfer residual. Returns the refined HomographyMat.

loss is a VisualGeometryToolkitCore loss shape — TLSShape() (the default: the truncation min(r², w²), inliers r < w and outliers zero-weighted), HuberShape(), CauchyShape(), GaussianShape() (plain least squares, which takes no loss_width) — or LeZachTruncation(), the same truncation optimized by the Le & Zach TR-IRLS scheme. loss_width is the width w of that shape's closed forms (ρ(shape, r², w²)); PoseLib's loss_scale equals it for every bound loss, so it crosses unchanged. max_iter, the LM iteration budget, is the caller's configuration: it has no default.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, K1, K2, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Camera-aware robust-loss refinement (truncated by default: MSAC) (matches the RANSAC-Scoring reference): pose is the seed Rigid3, cs the correspondences x1 => x2 in each image's frame, and K1/K2 the intrinsics of THAT frame — pixels for pixel K, or any frame K is expressed in (LocalOptimizationDoneRight's refit layer supplies the pool frame's Kc = T·K). loss_width is the loss's width in the unit of that same frame. PoseLib calibrates internally through the cameras, so one width is valid even when the two focals differ. loss and loss_width are as in refine_homography; max_iter (the LM iteration budget) is the caller's configuration and has no default.

Each K reaches C++ as a SIMPLE_PINHOLE camera: focal (K₁₁ + K₂₂)/2 and principal point (K₁₃, K₂₃); the skew and any K₁₁ ≠ K₂₂ are dropped, so the model is exact only for a square-pixel, zero-skew K.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, cs::…StaticVector{2}…; max_iter, loss, loss_width)

Refused. Calibrated 2-vectors are coordinates on the z = 1 chart (GnomonicFrame), and that chart has no point for a ray at or beyond 90° — the rays this stack exists to calibrate. Relative pose is calibrated geometry, so it takes unit bearings (unit rays).

Use one of the two forms that do exist:

  • refine_relpose(pose, cs) with cs of unit bearings f₁ => f₂ carrying their M₁/M₂ backprojection Jacobians — PoseLib's tangent-Sampson refiner.
  • refine_relpose(pose, K1, K2, cs) with pixel points and the two intrinsics, which back-projects through the cameras inside PoseLib and reduces to exactly the same refiner.

backproject_with_jacobian(camera, u) produces the bearing and its Jacobian together.

PoseLib.refine_relpose — Method
refine_relpose(pose::Rigid3, cs; max_iter, loss = TLSShape(), loss_width) -> Rigid3

Bearing robust-loss (truncated by default: MSAC) Levenberg–Marquardt refinement of a relative pose, through PoseLib's tangent-Sampson refiner (refine_relpose(d1, d2, M1, M2, &pose, opt), bundle.cc:228 — FixCameraRelativePoseRefiner). pose is the seed Rigid3 and cs the correspondences f₁ => f₂ of unit bearings (StaticVector{3}), carrying their 3×2 backprojection Jacobians as the attribute COLUMNS M₁/M₂ (withattrs(cs; M₁, M₂)) — the pair VisualGeometryToolkitCore.backproject_with_jacobian(model, u) returns. Returns the refined Rigid3.

This is the calibrated entry point with no chart: a ray at or beyond 90° is an ordinary bearing here, where the z = 1 chart (GnomonicFrame) has no coordinate to name it with — which is why StaticVector{2} endpoints are refused, and why a 3-vector that is not unit-norm is refused too (a chart point lifted to (x, y, 1) satisfies the signature but is not a bearing).

The unit of loss_width

loss_width is the loss's width w (for the default truncation: inliers r < w, outliers zero-weighted) on the tangent-Sampson residual

r = (f₂ᵀ E f₁) / √(‖M₂ᵀ E f₁‖² + ‖M₁ᵀ Eᵀ f₂‖²)

whose denominator is exactly ‖∇C‖ of the epipolar constraint taken with respect to the coordinate M DIFFERENTIATES AGAINST. So r carries that coordinate's unit, and loss_width must be given in the same one: M picks the unit and the call cannot.

M isr and loss_width are in
∂f/∂u from backproject_with_jacobian (the stack's producer)pixels of u
an orthonormal basis of the tangent plane T_f S²radians

Bearings are unitless, so nothing else can set the scale: supplying a width scaled as if the bearings carried one is wrong by a factor of the focal length, and fails silently — a truncated loss simply keeps the wrong inliers.

Frames

Binding layer: pose, cs, M₁/M₂ and loss_width are all in the caller's frame and the refined Rigid3 comes back in it. Nothing here normalizes; the Jacobians are the caller's own, and whichever camera produced them fixes both the frame and the width's unit.
