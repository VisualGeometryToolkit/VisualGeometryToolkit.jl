Refiners

The four refiners run PoseLib's robust Levenberg–Marquardt (LM) optimization from a seed model. In the stack's naming, a refine_* function needs a starting guess and returns a model of the same kind. It does not sample hypotheses or decide inliers on its own; that is the job of a random sample consensus (RANSAC) estimator, which may call a refiner as its local optimization.

RefinerSeedCorrespondencesResidual
refine_homography(H, cs)HomographyMat2D x1 => x2symmetric transfer error
refine_fundamental(F, cs)FundMat2D x1 => x2Sampson error
refine_relpose(pose, K1, K2, cs)Rigid3pixel points x1 => x2tangent Sampson error
refine_relpose(pose, cs)Rigid3unit bearings f1 => f2 with Jacobianstangent Sampson error
refine_absolute_pose(pose, K, cs)Rigid33D to pixel X => ureprojection error

Every refiner takes the robust-estimation contract's keywords:

  • max_iter, PoseLib's Levenberg–Marquardt iteration budget. It has no default; the caller chooses it.
  • optimization_strategy, the strategy: VisualGeometryToolkitCore's Irls{K} with one of the shapes below, PoseLib's LeZach(), or nothing for plain least squares. It has no default either: the strategy of a robust estimate is the caller's configuration. (An Irls strategy's own max_iter, its reweighting count, is not read: PoseLib's budget is max_iter.)
  • exactly one of width = w, the width of the loss in the unit of the residual, and scale = σ, the noise scale (or an earlier robust result, whose noise_scale is handed on). Least squares takes neither.

The retired keywords loss and loss_width are refused with an ArgumentError naming their replacements.

Strategies

PoseLib's Levenberg–Marquardt weighs each residual by its loss weight ρ′ alone, without the ρ″ term, so its strategies are Irls{K}; a Triggs{K} (the ρ″-corrected LM of the stack's native refiners) is refused. Each shape is parametrized by one width w, and PoseLib's own loss_scale parameter equals that width for every loss bound here. The width reaches PoseLib unchanged.

optimization_strategyρ(r)
Irls{TLSShape}()min(r², w²)inliers have r < w; outliers get zero weight
Irls{HuberShape}()r² up to w, linear beyond
Irls{CauchyShape}()w² log(1 + r²/w²)
LeZach()min(r², w²)the truncated loss under Le and Zach's reweighting scheme; TOML type = "le_zach" (POSELIB_STRATEGY_TAGS)
nothingr²plain least squares; takes no scale or width

Given scale = σ, the loss runs at w = c·σ: c is the strategy's own efficiency constant, else VisualGeometryToolkitCore's efficiency_constant(shape, d) at the codimension d of the refiner's residual (1 for the Sampson and tangent-Sampson errors, 2 for the transfer and reprojection errors). A truncation (TLS, Le–Zach) has no efficiency constant, so it takes width.

The truncated loss with a fixed width is the cost that MSAC (M-estimator sample consensus) scores hypotheses with, so Irls{TLSShape}() optimizes what an MSAC-scored RANSAC loop measures.

Under a truncated loss, a correspondence with a residual above w contributes nothing. A seed far from the answer, with most residuals above the width, therefore comes back almost unchanged.

The result

Every refiner returns a VisualGeometryToolkitCore FitResult:

  • estimate(result), the refined model;
  • retcode(result), its termination record's ReturnCode: ReturnCode.Success (with stop_rule(result) == NoRule: PoseLib states no rule) when PoseLib stopped on its own tolerances, ReturnCode.MaxIters when it used the whole budget, and iterations(result), the iterations PoseLib took. Fewer correspondences than the model's minimal sample (4 for a homography, 7 for a fundamental matrix, 5 for a relative pose, 3 for an absolute pose) is ReturnCode.InitialFailure: the seed comes back unrefined after 0 iterations, and PoseLib is not called;
  • result.n, the number of correspondences refined over (all of them: PoseLib reports no weights, so this is not a weighted support), 0 below the minimal sample; rms(result) is NaN (PoseLib reports no residual summary);
  • the scale record in its metadata (PoseLibRefineMetadata): the scale it was given and its scale_source, and the width PoseLib ran at. noise_scale(result) hands a given scale to the next stage; a result run at a width or by least squares records none (ScaleNone) and refuses it.

Frames and units

The refiners follow the stack's rule that results come back in the frame the inputs came in. They hand the data to PoseLib as given and normalize nothing. The width is in the unit of the residual, which is the unit of the data:

  • A homography or fundamental matrix in pixels takes pixel points and a pixel width. A model in another frame takes points and width in that frame.
  • The camera-aware refine_relpose(pose, K1, K2, cs) and refine_absolute_pose(pose, K, cs) take the intrinsic matrices of the frame the points are in, and a width in that frame's unit. PoseLib back-projects through each camera, so one width serves two images even when their focal lengths differ.

Each intrinsic matrix reaches PoseLib as its SIMPLE_PINHOLE camera model: one focal length, (K₁₁ + K₂₂)/2, and the principal point (K₁₃, K₂₃). Skew and any difference between K₁₁ and K₂₂ are dropped. The model is exact only for square pixels and zero skew.

Relative pose on bearings

Calibrated geometry in this stack works on unit bearings, because the z = 1 image plane has no point for a ray at or beyond 90° from the optical axis. refine_relpose(pose, cs) takes bearings f1 => f2 together with the 3×2 Jacobians of the back-projection, as the attribute columns M₁ and M₂:

using VisualGeometryToolkitCore: backproject_with_jacobian

b1 = backproject_with_jacobian.(Ref(camera1), u1)   # (bearing, Jacobian) per point
b2 = backproject_with_jacobian.(Ref(camera2), u2)
cs = withattrs(Correspondences(first.(b1), first.(b2)); M₁ = last.(b1), M₂ = last.(b2))
refine_relpose(pose, cs; max_iter = 25, optimization_strategy = Irls{TLSShape}(), width = 2.0)

The residual is the tangent Sampson error

r = (f₂ᵀ E f₁) / √(‖M₂ᵀ E f₁‖² + ‖M₁ᵀ Eᵀ f₂‖²)

Its denominator is the gradient of the epipolar constraint with respect to the coordinates the Jacobians differentiate against. So the Jacobians set the unit of r, and of the width:

M isr and the width are in
∂f/∂u from backproject_with_jacobianpixels of u
an orthonormal basis of the tangent plane of the sphere at fradians

A width in the wrong unit is off by a factor of the focal length, and nothing reports it: a truncated loss simply keeps the wrong inliers.

With pixel points and pinhole cameras, the camera-aware form reduces to this one. PoseLib back-projects each point and runs the same refiner, and the two forms agree to rounding error.

What is refused

Both calibrated refiners refuse calibrated 2-vectors (points on the z = 1 plane) with an ArgumentError that names the supported form. refine_relpose(pose, cs) also refuses 3-vectors that are not of unit length. A point (x, y, 1) has the right type, and for a narrow field of view it even refines to a plausible pose, but it is not a bearing.

Absolute pose

PoseLib has no absolute-pose refiner on bearings: its residual is a reprojection error in the image. refine_absolute_pose(pose, K, cs) is therefore the only form, with pixel points and a pixel width. Only the six degrees of freedom of the pose are refined; K stays fixed. Because the camera is a pinhole, this package offers no correct absolute-pose refinement for a fisheye camera.

Poses

The pose refiners take, and return as their estimate, a Rigid3, an unlabeled rigid motion x ↦ R·x + t. EuclideanMap(R, t) builds one from a rotation and a translation. A labeled pose, such as the Extrinsics3 that P3P returns, becomes one through unlabel.
