RANSAC

Main Function

RobustVisualGeometry.ransac — Function
ransac(problem, scoring; local_optimization, config, workspace, rng) -> RansacEstimate

RANSAC on VisualGeometryCore's scoring and local-optimization contracts: the loop calls only the contract verbs, so any scorer composes with any local optimizer and any problem. The allocating convenience of ransac! (fresh result buffers, and a fresh workspace unless one is supplied).

For each minimal sample, fits θₜ, scores it, and takes the scorer's consensus set. Two independent best-so-far scores are maintained: Sgl gates entry into local optimization; Slo tracks the best locally optimized score. The adaptive trial count uses the hypergeometric distribution (the stopping criterion).

Arguments

  • problem::AbstractRansacProblem: Problem definition (data, solver, residuals)
  • scoring::AbstractScoring: any scorer of the contract — VisualGeometryCore's MsacScoring/RansacScoring at a threshold, or a scorer from another package (a paper's: RansacScoringDoneRight's Student-t + uniform marginal)

Keyword Arguments

  • local_optimization::AbstractLocalOptimization=default_local_optimization(scoring): the LO-RANSAC refinement strategy (default NoLocalOptimization()); dispatched in the loop's Phase 2 via locally_optimize!
  • config::RansacConfig=RansacConfig(): maxtrials, successprob η, min_trials
  • workspace::Union{Nothing,RansacWorkspace}=nothing: Pre-allocated workspace
  • rng::Random.AbstractRNG=Random.default_rng(): source of every random draw the loop makes (sample selection through draw_sample!). Supply a seeded rng (e.g. Xoshiro(seed)) for a bit-reproducible run that is independent of ambient RNG state; the default preserves the historical task-local behavior.
  • on_improvement=nothing: optional anytime-trace hook, called as on_improvement(trial::Int, score, ws::RansacWorkspace) exactly when the tracked best (the acceptance that also re-arms the adaptive trial count) is replaced — read ws.best_model / ws.best_lo_retcode inside the callback. Improvements are rare (≈ log-many per run), so a cheap callback keeps overhead negligible; nothing (production default) is specialized away at compile time.
  • score_guard::Bool=false: per-candidate ScoreGuarded acceptance — the in-loop analogue of locally_optimize(...; score_guard=true) (the review-requested LO-RANSAC score-monotone variant). When the refined model of a gate-satisfying candidate scores BELOW its own seed under the same scorer, the candidate re-enters the incumbent race as the RAW hypothesis (at its Phase-1 score) instead of the refined model; the race itself stays the standard monotone best-so-far comparison. A raw hypothesis kept this way is stamped lo_retcode = :guard_kept_seed on the result.

Returns

A RansacEstimate; iterations(result) is the number of trials (hypotheses drawn), whether the adaptive stop or max_trials ended the loop — both return :converged. Test it with VisualGeometryCore's converged(result) before reading the model: retcode(result) === :no_model (converged false) means NO hypothesis survived — there is no estimate, and estimate(result) is a zero(M) placeholder kept only for type stability, never a model (with quality = -Inf, an all-false inlier_mask, rms = sigma = NaN).

RobustVisualGeometry.locally_optimize — Function
locally_optimize(problem, θ₀; local_optimization, threshold | scoring,
                 workspace=nothing, score_guard=false) -> RansacEstimate

Refine a caller-supplied seed model θ₀ with one local-optimization run — the same score → locally_optimize! → re-score → test_consensus → _finalize machinery a RANSAC trial runs in _try_model!, driven by θ₀ instead of a minimal sample (no draw_sample!, no consensus search). Generic over the problem type. local_optimization is REQUIRED (no default: the strategy is the experiment's decision; the settled formulations live in the find_* pipelines). If the refined model fails test_consensus the seed is returned. Give exactly one of threshold (the default scoring's: MSAC at that threshold, in the problem's residual unit) and scoring; both is an ArgumentError. When score_guard=true the refined model is only accepted if it does not lower the seed's score (the seed is kept otherwise).

The local optimizer receives its loss width through its width mode (VGC loss_at): a consensus-anchored strategy (ScaleMultiple(m)) reads the consensus set's ŝ², an absolute one (LossWidth, see with_width) runs at the caller's width with the scoring untouched — the role-isolated validation controls (solo CV, oracle-scale) deploy the strategy that way — and a strategy with no width follows the scorer's inlier_threshold.

locally_optimize(problem, models::FixedModels; local_optimization,
                 threshold | scoring, workspace=nothing) -> RansacEstimate

Entry for solvers that return several candidate models (e.g. the two planar-pose ambiguity solutions). Each candidate is scored against the consensus set; the single highest-scoring one that succeeds at test_consensus is kept, and only that one is locally optimized. The candidates are never all optimized — selection is by consensus score, optimization is on the winner alone. Returns a :no_model result (converged false, no estimate) if no candidate clears consensus. threshold and scoring are exclusive, as in the single-seed method.

Problem Interface

RobustVisualGeometry.AbstractRansacProblem — Type
AbstractRansacProblem

Abstract type for RANSAC problem definitions.

A concrete subtype encapsulates the data, sampling strategy, minimal solver, and constraint derivatives for a specific estimation task.

Required Methods

  • minimal_sample_size(p)::Int — minimum data points for a minimal solve
  • data_size(p)::Int — total number of data points
  • codimension(p)::Int — constraint codimension d_g
  • model_type(::Type{<:P})::Type — concrete model type M (for workspace pre-allocation; defined on the TYPE, so RansacWorkspace(P, n) can read it)
  • solve(p, indices) — fit model(s) from sample indices; returns FixedModels{N,M} with count ∈ 0..N (0 means failure)
  • constraint_with_jacobians(p, model, i) — (g, ∂ₓg, ∂_θg) at data point i

Derived Automatically

  • residuals!(r, p, model) — Mahalanobis distance √(gᵀ Σ̃_g⁻¹ g) from constraint_with_jacobians

Optional Methods

  • draw_sample!(rng, indices, p) — custom sampling (default: uniform without replacement)
  • test_sample(p, indices) — degeneracy check (default: true)
  • test_model(p, model, indices) — feasibility check at sample points (default: true)
  • test_consensus(p, model, mask) — consensus set validation (default: true)
  • refine!(ws, p, θ, weights) — the local optimization's one weighted step from the current model θ (default: nothing)
  • solver_covariance(p, model, indices) + provides_solver_covariance(::Type{<:P}) = true — model parameter covariance for predictive scoring; nothing for a degenerate sample (the hypothesis is skipped). A problem without a provider is refused by a predictive scorer.
  • residuals!(r, p, model) — override the default if a faster batch implementation exists

Example

struct MyLineProblem <: AbstractRansacProblem
    points::Vector{SVector{2,Float64}}
end

minimal_sample_size(::MyLineProblem) = 2
data_size(p::MyLineProblem) = length(p.points)
codimension(::MyLineProblem) = 1
model_type(::Type{MyLineProblem}) = SVector{2,Float64}  # (a, b) for y = a + bx

function solve(p::MyLineProblem, idx)
    p1, p2 = p.points[idx[1]], p.points[idx[2]]
    b = (p2[2] - p1[2]) / (p2[1] - p1[1])
    a = p1[2] - b * p1[1]
    model = SVector(a, b)
    FixedModels{1, typeof(model)}(1, (model,))
end

@inline function constraint_with_jacobians(p::MyLineProblem, model, i)
    pt = p.points[i]; a, b = model
    g = pt[2] - a - b * pt[1]           # scalar constraint
    ∂ₓg = SA[one(eltype(pt))]             # ∂g/∂y = 1 (only y has noise)
    ∂_θg = SA[-one(eltype(pt)), -pt[1]]  # ∂g/∂(a,b)
    return (g, ∂ₓg, ∂_θg)
end

RobustVisualGeometry.fit_hypothesis — Function
fit_hypothesis(problem, θ, sample_indices) -> model | nothing

The hypothesis a minimal sample contributes, given a minimal solution θ of it (solve). For a problem whose minimal sample exactly determines the model this is θ itself (the default). VisualGeometryCore.test_sample — Function
test_sample(problem::AbstractRansacProblem, indices::AbstractVector{Int}) -> Bool

Check whether a sample is non-degenerate (e.g., points not collinear).

Default: true (no degeneracy check). Override for problem-specific checks.

test_sample(p::AbsolutePoseProblem, idx) -> Bool

Reject degenerate P3P minimal samples. Four checks, distinctness and collinearity in each of the two spaces:

  • world: the 3 control points distinct (_P3P_COINCIDENT_WORLD, in the caller's units) and non-collinear (thin_ratio > _P3P_DEGENERACY_TOL). Collinear control points ⇒ no unique P3P solution; this one earns its place.
  • image: the 3 image points distinct (_P3P_COINCIDENT_IMAGE, pixels) and their RAYS not coplanar (thinness > _P3P_DEGENERACY_TOL). P3P degenerates when the three rays lie in one plane through the centre. For a Pinhole that is exactly collinear pixels (the pixel plane is an affine image of the z = 1 chart), so the test is thin_ratio on the pixels, as it always was. For a DISTORTING lens it is not: a line of rays images as a curve, so pixel collinearity admitted coplanar rays and rejected well-spread rim rays that the lens had pulled into a line. There the test is _ray_thin_ratio on the context's back-projected rays — thin_ratio in the gnomonic chart tangent at their mean direction.

The image DISTINCTNESS check guards a premise that does not reproduce

It used to be justified here as "two detections at ~the same pixel (distinct world points projecting together) force a grazing, near-degenerate pose". That was constructed, not measured, and measurement does not support it. Sweeping image separation for two genuinely distinct world points (common ray, ≥0.5 world units apart): noise-free, median error stays at 0° and q95 under 6e-5° from 0 px to 40 px; at σ = 0.5 px, the median is 0.181° at EVERY separation from 0 to 150 px, q95 0.655–0.702°, with no failure to return a solution.

Flat at both noise levels including at separation zero, which is geometrically sensible: two world points at different depths along one ray is a well-posed P3P configuration. The second point adds no independent constraint, but the remaining correspondences still determine the pose. Two points projecting together is not by itself a degeneracy.

It is also UNREACHABLE. A near-duplicate pair makes every triangle through it thin, so the image collinearity check rejects first: measured, at any separation small enough for the distinctness check to fire (<1e-3 px) the image thin_ratio is already 3.1e-5, far under its 1e-2 bound; at 0.2 px, where thin_ratio is healthy at 0.0125, distinctness admits. There is no separation at which the image distinctness verdict decides anything.

So it is redundant against a premise that does not reproduce — vestigial, or guarding a configuration nobody has constructed. Note that "a nearly-collinear triple produces a grazing pose" is NOT the missing case: that is exactly what thin_ratio(u…) tests, one line below.

The tolerance was deliberately NOT raised. At 1e-3 px — sixty times below VisualGeometryFeatures' pinned 0.06 px worst-case refinement bound — its measured duplicate capture is 0%, flat across spreads. That is the same symptom B7 fixed for F, E and H but a different disease: those were frame-COUPLED, their threshold moving with the data's spread, while this one is correctly framed in pixels and simply too small. Raising it would make a dead gate live across six repos on an unreproduced premise. If it is ever revisited, do NOT borrow COINCIDENT_PX: 0.1 px answers "is this the same detection twice?", anchored on a refinement bound, and this check asks a different question — the constant does not transfer even though the units match.

What would settle it is a construction that produces the failure, or a decision that it is vestigial. Not a threshold.

Mirrors test_sample(::HomographyProblem, …), which had the same structure: its coincidence check sat inoperative while _not_collinear caught duplicates incidentally.

test_sample(::Type{<:RadialHomography}, cs, idx; target_tol = 1.0e-3) -> Bool

Degeneracy gate for the 5-point radial sample: the homography checks of the four fully-used correspondences (orientation, coincidence, collinearity — run on the distorted targets, an adequate proxy since the division model is locally orientation-preserving) plus pairwise distinctness of all five. Orientation and collinearity are scale-free; the SOURCE distinctness is a fixed separation 1e-3 in cs's units, and the TARGET distinctness is an absolute separation target_tol in cs's units — a caller holding the normalization converts a pixel separation through its scale (target_tol = τ_px * similarity_scale(target_map(normalization))), so the gate does not move with the frame.

test_sample(::Type{<:HomographyMat}, cs, idx) -> Bool

Reject degenerate 4-point homography samples: bow-tie (mixed orientation), coincident points, or any 3-of-4 (near-)collinear. An inner-loop gate.

UNITS ARE MIXED HERE, AND DELIBERATELY SO. The coincidence part takes cs in PIXELS and its tolerance is COINCIDENT_PX. The other two parts are frame-independent and take whatever frame they are given: _orientation_preserving is a SIGN, and _not_collinear is a RATIO (thin_ratio, ≈ 0.1% of the longest side), so neither has a unit to get wrong.

_not_collinear STAYS, although coincidence catches duplicate detections and it can look redundant: two near-identical points make every triangle through them thin, so it also rejects duplicates, incidentally. Genuine collinearity is a DIFFERENT degeneracy, the one it is for: a 3-of-4 collinear sample makes the homography's 3×3 LU systems rank-deficient regardless of how distinct the points are.

test_sample(::Type{<:FundMat}, cs, idx) -> Bool

Reject minimal F samples with coincident points — the only degeneracy gated pre-solve for the epipolar solvers, and unlike homography there is NO other check here, so this one carries the whole gate. Arity-agnostic (a 7- or 8-point sample alike); E has its own method below.

cs is in PIXELS and the tolerance is COINCIDENT_PX (see the note above COINCIDENT_PX). With no collinearity check behind it, a duplicate detection this gate admits goes straight into the solver.

test_sample(::Type{<:EssentialMat}, cs, idx; tol_px = COINCIDENT_PX) -> Bool

The same coincidence question for E on UNIT BEARINGS: are any two of the sample's bearings the same detection? Bearings are directions, so the comparison cannot be a distance between them — it is the angle, converted to pixels through each point's backprojection Jacobian.

cs carries M₁/M₂ as attribute COLUMNS (withattrs(cs; M₁, M₂)), the 3×2 Jacobians from backproject_with_jacobian; the pair's separation in pixels is estimated as angle(fₐ, f_b) / σ_max(M). Without those columns (any container without them, a plain Pair vector included) this takes the shared bearing-free path of the F method, because there is then no way to convert an angle into the caller's units — and guessing one would be a threshold with nothing behind it.

The estimate is CONSERVATIVE, and by how much

M is generally anisotropic: a pixel step produces a different angle along its major and minor singular directions. Dividing by σ_max therefore UNDER-states the separation of a pair displaced along the minor direction, by exactly the factor 1/aniso (aniso = σ_max/σ_min) — measured to five digits across a fisheye field. Rejection happens when the estimate falls below tol_px, so the gate actually rejects true separations up to tol_px × aniso: the effective threshold is tol_px along M's major axis and tol_px × aniso along its minor.

Larger, not smaller — so it never UNDER-rejects, which is the failure a deduplication backstop must not have. It begins over-rejecting genuinely DISTINCT features only when tol_px × aniso > d_min, i.e. aniso > d_min / tol_px — aniso > 10 for the default 0.1 px and features no closer than 1 px. A moderate KannalaBrandt fisheye (f = 300, k1 = −0.02) reaches aniso 1.48 at field radius 386 px, an effective 0.148 px: about 7× below where distinct features live. Stated because this stack exists for strongly distorted lenses, and a field-varying threshold is otherwise the kind of thing that resurfaces as unexplained behaviour at the periphery.

The tangency contract

M is tangent to its bearing — fᵀM = 0, measured to 4e-20 across the field — which is why no explicit projection onto the tangent plane appears here or in any consumer. It is a CONTRACT, not an observation: a violation would show up as slow drift rather than an error, so it is pinned at backproject_with_jacobian and depended on here.

VisualGeometryCore.test_model — Function
test_model(problem::AbstractRansacProblem, model, sample_indices::AbstractVector{Int}) -> Bool

Check whether a fitted model is feasible (e.g., positive focal length, non-degenerate local geometry at the sample points).

The sample_indices are the minimal sample indices used to fit the model, enabling point-specific validation (e.g., Jacobian determinant bounds at sample locations).

Default: true (no feasibility check). Override for problem-specific checks.

test_model(F::FundMat, u₁_sample, u₂_sample) -> Bool

Oriented epipolar constraint (Chum et al. 2004). For an exact correspondence, the epipolar line l₁ = Fᵀũ₂ and the line e₁ × ũ₁ are the same line in image 1 (both go through e₁ and ũ₁), so Fᵀũ₂ = μᵢ(e₁ × ũ₁) for some scalar μᵢ. The signum uses the dot product of all three components:

sᵢ = (Fᵀũ₂ⁱ) · (e₁ × ũ₁ⁱ) = μᵢ · ‖e₁ × ũ₁ⁱ‖²

Since ‖e₁ × ũ₁ⁱ‖² ≥ 0, sign(sᵢ) = sign(μᵢ). The code checks sᵢ · sⱼ > 0 for all pairs, i.e., that all μᵢ share the same sign. Using the full dot product (rather than a single component) avoids numerical instability when one component happens to be near zero.

This is a chirality parity check. The absolute sign of μᵢ is meaningless (F and e₁ are projective, defined up to scale), but if two correspondences give different signs, they cannot both be in front of both cameras. The test rejects F matrices that are algebraically valid (u₂ᵀFu₁ = 0) but geometrically inconsistent. An inner-loop gate: F and the points in the same frame, the estimator's normalization (sign-based, so any positive-scale normalization gives the same answer).

test_model(m::RadialHomography, cs, idx) -> Bool

Feasibility of a radial-homography candidate: SVD conditioning of the H part plus ray-space cheirality — the recentered H s̃ᵢ must be proportional to backproject(m, dᵢ) with a UNIFORM sign across the sample (m and cs in the same frame). Ray-based, so front/back hemisphere consistency is checked without any perspective division.

The conditioning bound (test_conditioning, κ ≤ 100) is a property of the frame m is written in, and it is calibrated for Hartley frames — the H/F convention. m and cs are therefore meant to be in the normalization of CspondNormalization(RadialHomography, cs; center): Hartley on both sides, the target about the distortion centre. (In a smaller-scale frame, e.g. the earlier full-diagonal target frame, κ rejected true-model candidates: measured 1 of 124.)

test_model(H::HomographyMat, cs, idx) -> Bool

Homography feasibility: SVD conditioning (κ ≤ 100) AND projective cheirality (uniform-sign λ) over the sample. Composes test_conditioning and test_cheirality. An inner-loop gate: H and cs are both in the estimator's normalization, CspondNormalization(HomographyMat, cs) — where the κ bound is calibrated.

(test_model(F::FundMat, cs, idx) — the oriented epipolar check — is defined in geometry/solvers/fundmat.jl.)

VisualGeometryCore.refine! — Function
refine!(lo_ws, problem, θ, weights) -> model or nothing

The local optimization's ONE step: the problem's model refined from the current model θ under per-datum weights, used by LO-RANSAC's update_model! and by direct callers (unit tests of the refit paths). The model follows the problem (the RANSAC-family order); lo_ws leads as the mutated workspace.

Routed by the refit_kind(p) Holy trait — NOT by the model's nominal type — through _refine!(::RefitKind, ws, p, θ, weights) (see refit_kind / RefitKind below):

  • NonlinLsq — every chart problem (chart_dof: H, F, E, the absolute pose, hand-eye, the radial homography and the radial camera) → THE chart LM from θ (_refine! above), on the problem's own chart and rows.
  • A problem whose step is not a chart LM carries its own refine!: the relative-pose bundle (a Schur-reduced full-3D BA, relpose_bundle.jl); a LINEAR problem's one-step algorithm under the weights, θ unread — LineFittingProblem (line.jl), a RelativeProblem handed a DltWorkspace (the weighted DLT, cspond.jl).
  • NoRefit (no chart) → nothing (no step in this shape).

lo_ws is the refit workspace (refine_workspace; a local optimizer holds it): a ManifoldLmWorkspace{N} for the chart problems (every _lm_size; used when its size matches, otherwise the one task-local reuse policy of _lm_workspace), a DltWorkspace for the algebraic DLT, or nothing for problems that allocate nothing ahead (line fitting). It is accepted for signature uniformity where unused.

Excluded points are encoded as weights[i] = 0 — there is no separate mask argument. Every step short-circuits (returns nothing) when too few points have non-zero weight to over-determine the model.

refine!(R, problem, θ, w) -> θ′ | nothing

The weighted refit of problem from θ under per-point weights w (w[1:data_size(problem)]), on the problem's refit workspace R (refine_workspace) — the model block of every IRLS-family local optimization. nothing means the solve failed (an underdetermined or singular system); the caller keeps its incumbent.

draw_sample!(rng::Random.AbstractRNG, indices::AbstractVector{Int},

VisualGeometryCore.constraint_with_jacobians — Function
constraint_with_jacobians(p::HandEyeProblem, X::Rigid3, i::Int)
    -> (g::SVector{6}, ∂ₓg::SMatrix{6,6}, ∂_θg::SMatrix{6,6})

Decoupled SE(3) hand-eye constraint and its derivatives.

For motion pair (A_ij, B_ij) = p.motions[i]:

g = [ L · Log(R_A R_X R_B^T R_X^T)
      R_A t_X + t_A − R_X t_B − t_X ]   ∈ ℝ⁶

(L = p.char_length, balancing rotation rad and translation length units.)

The model Jacobian ∂_θg uses the decoupled left-perturbation parameterization (δω, δt) ∈ ℝ⁶ matching AbsolutePoseProblem: RX ← R(δω) · RX, tX ← tX + δt. Under that convention, near the optimum:

∂_θg = [  L · (R_A − I)       0       ]   ← rotation block
       [   [R_X t_B]_×    (R_A − I)   ]   ← translation block

The measurement Jacobian ∂ₓg = I_6 reports the noise model directly on the constraint (the per-pair 6-vector is already in unit-balanced form), so the default residuals! produces ‖g‖.

constraint_with_jacobians(model::CameraModel, pose::EuclideanMap{3}, X, u)
    -> (e::SVector{2}, G_x::SMatrix{2,2}, G_θ::SMatrix{2,6})

The reprojection constraint of a FULL camera in RAW pixels: the residual e = project(model, R·X + t) − u between the observed pixel u and the world point X imaged through the intrinsics AND the lens, its measurement Jacobian G_x = ∂e/∂u = −I₂ (the observed pixel is the measurement, X is exact — the PnP model; the triple every constraint_with_jacobians returns, so a predictive whitening reads it like any other), and its Jacobian in the left-perturbation pose chart δ = (δω, δt) of the calibrated constraint_with_jacobians(pose, X, ray):

∂e/∂δ = ∂project/∂X_cam · [−[X_cam]×  I₃]

where the first factor is A · transform_deriv(lens, X_cam), the chain rule through the lens's ray-domain hook project(lens, X) — the same map the residual goes through. One residual currency — the pixels the detector measured — for every lens family, so a Student-t scale, a Welsch cutoff or an inlier gate mean the same thing at the rim of a fisheye as at its centre. For a Pinhole this is exactly A · g of the calibrated form. Directions the lens does not image (for a gnomonic-frame lens, every X_cam[3] ≤ 0) project to non-finite pixels; callers mask on isfinite, as with project.

constraint_with_jacobians(P::RadialCamera, X::SVector{2}, x::SVector{2})
    -> (g::T, G_x::SVector{2,T}, G_θ::SVector{6,T})

Radial-camera constraint of one correspondence (plane point X, RAW pixel x): g = x₁·(P₂·X̃) − x₂·(P₁·X̃) with x taken relative to the camera's center — the pixel lies on the radial line project returns. G_x = ∂g/∂x = (P₂·X̃, −P₁·X̃), so g/‖G_x‖ is exactly the perpendicular distance of the pixel from that line; G_θ = ∂g/∂vec(P) (column-major: P₁₁, P₂₁, P₁₂, P₂₂, P₁₃, P₂₃).

The centre lives on the camera, so correspondences stay in the frame they were measured in and no caller pre-centres them.

constraint_with_jacobians(pose::EuclideanMap{3}, X::SVector{3}, ray::SVector{3})
    -> (g::SVector{2}, G_x::SMatrix{2,5}, G_θ::SMatrix{2,6})

Compute the reprojection constraint and its derivatives for a 3D rigid pose.

The constraint is the perspective-projected residual in calibrated coordinates: g = π(R·X + t) − π(ray)

where π is perspective division [x,y,z] → [x/z, y/z] and ray is the backprojected observation (encodes camera calibration).

The model Jacobian G_θ uses the left-perturbation convention with a 6-DOF parameterization δ = (δω₁, δω₂, δω₃, δt₁, δt₂, δt₃): ∂g/∂δ = Jπ · [−[X_cam]× I₃]

where Jπ is the 2×3 perspective division Jacobian and [v]× is the skew-symmetric (cross-product) matrix of v.

Returns:

  • g::SVector{2,T} — reprojection residual (calibrated coordinates)
  • G_x::SMatrix{2,5,T} — ∂g/∂(X, ray₁, ray₂) measurement Jacobian
  • G_θ::SMatrix{2,6,T} — ∂g/∂(δω, δt) pose perturbation Jacobian
PINHOLE ONLY — this residual lives in the gnomonic chart

π divides by the third component, so this is the z = 1 chart (GnomonicFrame) and it exists only on the forward hemisphere. It is degenerate at 90° from the optical axis and cannot represent a ray with Z ≤ 0 at all. That is correct for a PINHOLE camera and wrong for a fisheye or omnidirectional one, whose rays routinely go past 90°.

It is legitimate where it is used — RobustVisualGeometry's Pinhole PnP LM — and must not become the general path. The camera-general route is the ray-domain pixel residual (constraint_with_jacobians(model, pose, X, u) in cameras/camera_models.jl), which projects through the camera's own lens and therefore never assumes the chart exists. Calibrated two-view geometry takes the same view: it acts on unit bearings (unit rays, StaticVector{3}), never on this chart.

constraint_with_jacobians(E::EssentialMat, f₁, f₂; M₁, M₂) -> (g, G_x, G_θ)

The epipolar constraint on UNIT BEARINGS and its Jacobians: g = f₂ᵀ E f₁, with

  • G_x = (f₂ᵀE·M₁, f₁ᵀEᵀ·M₂) — 1×4, in PIXEL coordinates, because M is the backprojection Jacobian ∂f/∂u from backproject_with_jacobian;
  • G_θ = vec(f₂ f₁ᵀ) — ∂g/∂vec(E), column-major, unchanged from the plane form and feeding the same covariance machinery.

M is TANGENT (fᵀM = 0), so no explicit projection onto the tangent plane is needed here or downstream — that is the property backproject_with_jacobian is built to guarantee.

Why the Jacobians are arguments rather than recomputed: they are per-point data, so they ride as attribute COLUMNS on the correspondence set (withattrs(cs; M₁, M₂)), per the correspondence standard. Recomputing them per residual would repeat a camera backprojection in the inner loop.

The plane sibling constraint_with_jacobians(F, u₁, u₂) is the same question in the z = 1 chart. Use that one for FundMat and this one for EssentialMat: F is a pixel-plane model, E is not.

The transfer constraint of the wrapped homography and its Jacobians: g = π(H·ũ₁) − u₂, the transfer error in the destination image, with G_x = [Jπ·H₁₂ −I₂] (2×4, over (x₁, y₁, x₂, y₂)) and G_θ = Jπ·(ũ₁ᵀ ⊗ I₃) (2×9, ∂g/∂vec(H) column-major), Jπ the perspective derivative at H·ũ₁ and H₁₂ the first two columns of H.

VisualGeometryCore.test_conditioning — Function
test_conditioning(H; max_cond=100) -> Bool

Reject homographies whose SVD condition number κ = σ₁/σ₃ exceeds max_cond.

Catches near-rank-deficient H — the same pathology PoseLib's post-solve |det(H_normalized)| < 1e-8 check rejects (since after Frobenius normalization det(H) = σ₁σ₂σ₃ and one vanishing singular value makes both κ → ∞ and det → 0), plus a broader class of numerically unstable but non-singular H's.

Matches Shekhovtsov's is_homography_ill_conditioned (decompose_homography.py:244) with the same default threshold κ = 100.

κ is a property of the frame H is written in, not of the map: the bound is calibrated for H between Hartley-normalized frames (both sides, as CspondNormalization builds them), so evaluate it on the normalized H, never on a pixel-frame one.

VisualGeometryCore.test_cheirality — Function
test_cheirality(H, cs, idx) -> Bool

Projective cheirality check, uniform-sign variant. For each correspondence (uᵢ, u′ᵢ) at the sample indices, compute the projective scale factor λᵢ such that ũ′ᵢ = λᵢ · H · ũᵢ in homogeneous coordinates, where ũ = [u; 1]. Accept iff all λᵢ share a sign.

Rationale — H is only defined up to a nonzero scalar (H and −H are the same mapping). Under H → −H, every λᵢ flips sign, so requiring a specific sign (e.g. the original Shekhovtsov rule: sign-normalize to det(H) > 0, then require λ > 0) amounts to picking a matrix representative by convention. That convention matches the image-to-image case (where both frames share 2D handedness) but fails for object-to-image homographies (e.g. a world y-up calibration board mapped to a y-down image), where the "in front" representative has det(H) < 0 — the strict rule then rejects every correct fit.

The mapping-level invariant is uniform sign across the λᵢ: mixed signs signal a bow-tie in projective depth (a real pathology that cannot be repaired by a matrix sign flip), while a shared sign — positive or negative — signals a consistent mapping (with the overall sign absorbed into the free scalar of H).

For each i: compute Hu = H · ũᵢ, pick the component k with the largest absolute value (numerical robustness), and set λᵢ = ũ′ᵢ[k] / Hu[k] (with ũ′[3] = 1). Reject the sample the moment a sign disagreement is seen. An inner-loop gate: H and cs in the same frame (sign-based, so any positive-scale normalization, or none, gives the same answer).

test_cheirality(pose::EuclideanMap{3}, f₁, f₂) -> Bool

Ray-domain cheirality: triangulate the bearing pair and require BOTH depths positive. The plane-free replacement for X[3] > 0, which assumes a forward hemisphere that a fisheye or omnidirectional camera does not have.

Parallel rays (no parallax) are rejected — NaN > 0 is false — which is the honest answer: nothing was triangulated.

VisualGeometryCore.whitened_residual — Function
whitened_residual(problem, ctx, i) -> Real

The whitened residual of data point i under model: the norm of L⁻¹gᵢ, where LLᵀ = Σ̃_{gᵢ} = ∂ₓgᵢ·Σ̃_x·∂ₓgᵢᵀ, so that its square is the Mahalanobis distance gᵢᵀ Σ̃_{gᵢ}⁻¹ gᵢ (~ χ²(d_g) under H₀). SIGNED for a scalar constraint (d_g = 1: gᵢ/√Σ̃_{gᵢ}), the non-negative norm for a vector one.

The default derives it from constraint_with_jacobians through whiten — the stack's one whitening path and its one Sampson degeneracy rule (±Inf for an unsatisfiable degenerate point, 0 for one that vanishes exactly). A problem overrides it when a cheaper Jacobian-free route to the SAME quantity exists; the override must keep the sign contract. residuals! is this per point, at ctx =residual_context(problem, model).

VisualGeometryCore.residual_context — Function
residual_context(problem, model) -> ctx

What residuals! computes ONCE per model before its per-point loop, and hands to every whitened_residual(problem, ctx, i). The default is the model itself, so a problem that defines neither hook scores exactly as before.

A problem overrides it when part of the residual depends on the model alone and is costly: a relative-pose bundle's cheiral pose decomposition and inverse intrinsics, an essential matrix widened to Float64 once rather than per point. It then defines whitened_residual(problem, ctx::C, i) for its context type C.

RobustVisualGeometry.residual_dof — Function
residual_dof(problem_or_type, n_in::Int) -> Int

Residual degrees of freedom on a fitted model with n_in inliers:

ν = (n_in − m) · d_g

where m = minimal_sample_size(P) and d_g = codimension(P).

Single source of truth for the per-pair scale-estimate denominator σ̂²_p = RSS / ν and for the score-equation ν. Use this anywhere the residual DOF appears so that the model class drives the formula rather than scattered magic constants (which historically drifted: an earlier Union{E, F} σ̂²p dispatch hard-coded m = 5, biasing F-matrix σ̂²p down by factor (nin − 7)/(nin − 5)).

Returns 0 when n_in ≤ m so callers can ν > 0 || return NaN cleanly.

RobustVisualGeometry.oracle_residual_dof — Function
oracle_residual_dof(problem_or_type, n::Int) -> Int

Residual DOF when residuals are measured against an oracle model that was NOT fitted to these n points (e.g. the COLMAP ground-truth pose evaluated on a pair's SfM-track keypoints): no parameters are consumed, so

ν = n · d_g          (vs `residual_dof`'s `(n − m)·d_g` for a *fitted* model)

Use this for σ̂²p = RSS/ν under the GT geometry. Subtracting the model DOF (as a fit would) biases σ̂²p up by n/(n−m) — a DLT remnant, not warranted for the oracle.

RobustVisualGeometry.AbstractSampler — Type
AbstractSampler

Abstract type for RANSAC sampling strategies.

Subtypes implement draw! and reset! to provide different sampling behaviors (uniform, PROSAC, NAPSAC, etc.). Problems store a sampler as a type-parameterized field for compile-time dispatch.

Required Methods

  • draw!(rng::Random.AbstractRNG, indices::AbstractVector{Int}, sampler) — fill indices with a random sample drawn from rng.   • reset!(sampler) — reset mutable state for reuse across ransac() calls

Optional

  • reset!(sampler, budget::Int) — reset, and take the run's trial budget (ransac supplies config.max_trials). The default ignores the budget; PROSAC schedules its pool growth over it.

RansacWorkspace{K, M, T, W, L} is the composed workspace of one RANSAC run: the score buffers (VisualGeometryCore's ScoreBuffers{T, W} — residuals, per-point scores, consensus mask and the scorer's workspace W), the local optimizer's workspace L (lo_workspace(P, T, lo, n)), the incumbent and the minimal sample. Build it from the scorer and the strategy it will run, RansacWorkspace(problem, scoring, local_optimization); RansacWorkspace(P, n) holds the default MSAC scorer's. The core strategies' workspace is LoBuffers: the refit workspace refine_workspace(P, n) — VisualGeometryCore's ManifoldLmWorkspace{N} for the chart-LM refits (e.g. N = 8 for HomographyProblem, 7 for FundMatProblem, 6 for AbsolutePoseProblem) — and the posterior-weight buffers. DltWorkspace selects the algebraic DLT step, refine!(ws::DltWorkspace, p, θ, weights) with θ unread, which LO does not call.

RobustVisualGeometry.RansacWorkspace — Type
RansacWorkspace{K, M, T, W, L}

The composed workspace of one RANSAC run, built once and reused across trials and calls: the scoring buffers buf (VisualGeometryCore's ScoreBuffers{T, W} — residuals, per-point scores, consensus mask, the scorer's workspace W and the evaluation epoch), the local optimizer's workspace lo_ws::L, the incumbent's buffers (best_*) and the minimal sample's indices. Every parameter is concrete, so the loop, the scorer and the local optimizer are all statically dispatched.

Type Parameters

  • K: Minimal sample size (compile-time constant)
  • M: Model type
  • T: Per-point STORAGE element type (default Float32). Residuals and soft weights only — the per-point scores and every statistic accumulated from them stay Float64 regardless of T.
  • W: the scorer's workspace type (scoring_workspace(scoring, n, d_g))
  • L: the local optimizer's workspace type (lo_workspace(P, T, lo, n))

Constructors

ws = RansacWorkspace(problem, scoring[, local_optimization][, T])
ws = RansacWorkspace(P, n_max, scoring, local_optimization; T = Float32)

Reuse

Supply a workspace to ransac(; workspace = ws) (or ransac!) to avoid allocation across calls; a workspace sized for a larger problem is trimmed to each call's data size.

RobustVisualGeometry.RansacResultBuffers — Type
RansacResultBuffers{T}(n)

The per-point arrays of a RansacEstimate — inlier_mask, residuals and the soft weights — preallocated, so that ransac! writes its result into them with no allocation. The returned estimate's metadata holds THESE arrays: the next ransac! into the same buffers overwrites it.

RobustVisualGeometry.LoBuffers — Type
LoBuffers{R, T, S}

The local-optimization workspace of every strategy this package hosts (VisualGeometryCore's lo_workspace), built once per composed workspace: the problem's refit workspace refine (refine_workspace: a ManifoldLmWorkspace{N} for the chart problems, nothing for a problem whose refit pre-allocates nothing) and the per-point buffers of the posterior-weight iteration (posterior_w, posterior_inlier, posterior_sq_r, Float64) and of the IRLS residual block (lo_residuals, lo_best_residuals, storage T). The per-call states live here too, reset by every call instead of built: posterior, the PosteriorWeightState on the posterior buffers (re-seeded by consensus_posterior), and irls::S, the posterior-weight iteration's PosteriorIrlsState on the residual buffers.

Benchmark pools

A scoring pool (VisualGeometryCore Pools.PoolPair, stored in NormalizedImageFrame) is written here. draw_hypotheses repeats the RANSAC trial — the same draw, sample gate, solve and model gate ransac runs — with no scoring. The record's constructor PoolPair(rng, problem, raw; target, max_trials, variance) draws the hypotheses of a pixel-frame problem on a raw pair, carries them into the pool frame once, and returns the record with its residual matrix; EssentialProblem(pair), FundMatProblem(pair) and HomographyProblem(pair) are the record's pool-frame problems; the essential one's sample gate reads 0.1 px through pool_pixel_scale(pair) (F's and H's read the scale-free tolerance on their normalized view).

RobustVisualGeometry.draw_hypotheses — Function
draw_hypotheses(rng, problem; target, max_trials) -> Hypotheses

Draw minimal samples with the problem's own sampler until target samples have each produced at least one model the problem's test_model accepts, or max_trials draws have been made. Every sibling solution of an accepted sample is kept, the last accepted sample's included. No scoring, no consensus, no local optimization.

Each trial is the RANSAC trial, the one code path: draw_sample!, the problem's test_sample, solve, then per solution fit_hypothesis and test_model. The sampler is prepared for the run as ransac prepares it (reset!(sampler, max_trials): a PROSAC schedule spans max_trials). Every draw comes from rng, so a seeded rng makes the result a pure function of the seed and the problem.

Against the retired pool generator (pool format ≤ 3)

Same stopping rule, sibling layout and sample_indices columns; the one difference is the model gate. The old generator applied test_model to H only, while here every family is gated by its problem's own: F's oriented epipolar gate now applies (measured on a PhotoTourism pair under a uniform sampler, it accepts 76 of 510 F solutions), E has no post-solve gate (an E stream is unchanged), H is unchanged. A pool drawn here therefore differs from an F pool drawn there (accepted with pool format 4). A PROSAC sampler's growth horizon is now the run's max_trials (it was the generator's own prosac_T_N).

  • models::Vector{M}: every solution the problem's test_model accepted, sibling solutions of one sample adjacent and in solver order;
  • sample_indices::Matrix{Int}: (m, length(models)), the minimal sample each model was solved from (repeated across siblings);

PoolVariance

How a pool record's gt_variance (σ̂², pool units²) is measured — a dataset fact, chosen by the pool's producer:

RobustVisualGeometry.InlierVariance — Type
InlierVariance(; min_inliers)

σ̂² over the raw pair's GT-inlier correspondences, in the pool frame, with the fitted-model residual DOF (residual_dof): for E and F the RSS of the ORACLE model (the GT pose) in the family's own residual (E: tangent Sampson on the record's EssentialProblem; F: plane Sampson); for H, which has no oracle model, the RSS of an unconstrained DLT refit to the GT inliers (NaN when the masked design matrix fails VGC's test_dlt_conditioning). RobustVisualGeometry.TrackVariance — Type
TrackVariance(source, target)

σ̂² over separate pixel point pairs source[i] => target[i] (e.g. SfM-track keypoints, independent of the matcher's correspondences), carried into the pool frame by the raw pair's normalization: the RSS of the ORACLE model (the GT pose) in the family's own residual, over the ORACLE DOF (oracle_residual_dof, n·d_g: nothing is fitted). E and F only. A minimum point count is the reader's policy (it drops the pair); with no points σ̂² is NaN.

Configuration

configs/default.toml is the config of record: RansacConfig(), every core local-optimization strategy's keyword defaults, and every find_* pipeline's threshold and local_optimization read it at precompile time, so there is no second set of Julia literals to drift from it. Single values are overridden by keyword. RansacConfig(path) loads another file's [ransac] table over the shipped one and local_optimization_from_toml builds a strategy from its table — absent keys inherit, present keys override, unknown keys or tags are refused.

A strategy is selected in TOML by tag:

[pipelines.homography]
threshold          = 3.0                                 # px, the default MSAC scorer's
local_optimization = { type = "irls", loss = "tls" }     # no width key: follow the scorer
# explicit widths: { type = "irls", loss = "welsch", scale_multiple = 2.5 }
#              or  { type = "irls", loss = "welsch", loss_width = 2.0 }   (both keys: ArgumentError)

type is a tag of the strategy registry — the core LO_TAGS ("no_local_optimization", "irls"), or its explicit merge with a downstream package's — and loss a tag of LOSS_TAGS. The registries are VisualGeometryCore TagRegistry values; a retired tag is refused with its successor's name. The paper strategies and their cross-validated operating points (scale_multiple = "cross_validated") are LocalOptimizationDoneRight's:

using RobustVisualGeometry: local_optimization_from_toml, LO_TAGS
import LocalOptimizationDoneRight

lo = local_optimization_from_toml(table; class = :homography,
                                  tags = merge(LO_TAGS, LocalOptimizationDoneRight.LO_TAGS))
