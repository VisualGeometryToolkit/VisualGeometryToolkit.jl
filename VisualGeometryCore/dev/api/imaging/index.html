Imaging Chain and Stereo API

The framed imaging chain (frame-to-frame stages, ray maps, frame transitions) and stereo rigs. See the The Framed Imaging Chain, Ray Maps and Frame Transitions, and Stereo Rigs and Uncertainty guides.

The Framed Imaging Chain

VisualGeometryCore.Cameras.CameraCalibrationMat — Method
CameraCalibrationMat(m::FramedAffine) -> CameraCalibrationMat

The intrinsics whose calibration stage is m, K = [A t; 0 0 1] — the inverse of calibration_stage. A K solved in the NormalizedImageFrame comes back in pixels as CameraCalibrationMat(inv(norm) ∘ calibration_stage(DistortedFrame{id}, NormalizedImageFrame{id}, LogicalIntrinsics(K_norm))) (framed affines fuse under ∘, the junction checked). The lens coefficients need no conversion: they live in K⁻¹·pixel, which the normalization leaves where it was. Checked as any K is (positive focals, upper-triangular): a rotated stage is an ArgumentError.

VisualGeometryCore.Cameras.FrameTransition — Type
FrameTransition{Src <: RetinalFrame, Dst <: RetinalFrame}

The framed transition map between two retinal frames of the SAME view, {Src → Dst} — a pure radial reparameterization of the viewing sphere, computed once through the sphere as the conjugation

section(Dst) ∘ lift(Src)

so every pair among the five frames (GnomonicFrame, EquidistantFrame, StereographicFrame, EquisolidFrame, OrthographicFrame) is served by ONE implementation, with no per-pair closed forms to keep consistent. Azimuth is preserved; the radial profile map is profile_Dst(profile_Src⁻¹(r)).

Mint with frame_transition; inv is the reverse pair (an honest inverse — on the sphere the frame projections are invertible sections). As a FramedStage it composes junction-checked with the rest of the framed surface, and being isbits it composes into a per-point map that pointwise! runs over a batch.

Domain: the intersection of the two frames' honest domains, enforced — points outside Src's frame radius (equisolid r > 2, orthographic r > 1) and rays outside Dst's domain (gnomonic Z ≤ 0, orthographic Z < 0, the stereographic/equidistant antipode) map to NaN at the edge rather than aliasing.

source
VisualGeometryCore.Cameras.FramedAffine — Type
FramedAffine{Src <: Frame{2}, Dst <: Frame{2}, T}

Framed 2D affine stage x ↦ A·x + t — the calibration stage of the imaging chain, {DistortedFrame{id} → ImageFrame{id}} (or {ray frame → ImageFrame{id}} under the no-distortion frame collapse; the identity-K logical case is just A = I, t = 0). Same arithmetic as the AffineMap in the legacy imaging_transform; the frames are the addition. inv swaps the frames around the inverse affine. Mint with calibration_stage.

source
VisualGeometryCore.Cameras.FramedAffine — Method
FramedAffine(ImageFrame{id}, NormalizedImageFrame{id}, sz::Size2) -> FramedAffine
FramedAffine(PixelFrame{O}, NormalizedImageFrame{id}, sz::Size2) -> FramedAffine

The normalization map of an image of size sz (pixels, plain or px): x ↦ (x − c) / s, c the image centre and s = hypot(width, height) / 2 the half-diagonal — DiagonalNormalization, framed — so the image corners land at unit radius. The storage frame of the benchmark pools, where one noise level and one threshold must mean the same across resolutions; estimation normalizes by HartleyNormalization. The centre is written in the source's convention: (width/2, height/2) for an ImageFrame (always read :colmap), moved by EuclideanMap(PixelFrame{:colmap}, PixelFrame{O}) for a PixelFrame{O}, so every convention lands on the same normalized point. inv de-normalizes. The view ids must agree (a MethodError otherwise).

VisualGeometryCore.Cameras.FramedChain — Type
FramedChain{Src <: Frame, Dst <: Frame, T <: Tuple} <: FramedStage{Src, Dst}
FramedChain(stages::FramedStage...)

Composite of framed stages, applied FIRST-TO-LAST (stages[1] innermost): a FramedChain consumes src_frame(stages[1]) coordinates and produces dst_frame(stages[end]) coordinates, and is itself a FramedStage — so chains compose with stages and with each other under the same checked ∘, flattening (no nested chains from composition).

The vararg constructor checks EVERY inner junction under the standing wildcard truth table and throws an ArgumentError naming the first mismatched junction; ∘ between stages performs the same check as a MethodError (the house composition idiom). The callable unrolls at compile time. inv inverts and reverses the stages (frames swap) — and is therefore a MethodError for chains containing a ray projection, whose fiber collapse has no inverse.

VisualGeometryCore.Cameras.FramedDistort — Type
FramedDistort{Src <: Frame{2}, Dst <: Frame{2}, L <: AbstractLensModel}

Framed forward-distortion stage {ray frame → DistortedFrame} wrapping a lens model. The math dispatches on the Src frame KIND:

  • Src <: GnomonicFrame: the wrapped lens callable itself — the lens contract already IS a map on the gnomonic frame.
  • Src <: EquidistantFrame: the model's radial map in θ (KannalaBrandt's polynomial; COLMAP's thin-prism fisheye's additive terms evaluated on equidistant-frame coordinates, COLMAP's convention).

Mint with distort_stage (which tags the honest frame via distortion_frame); inv yields the matching FramedUndistort with the frames swapped. Direct type-parameter construction is an unchecked expert surface, like relabel.

source
VisualGeometryCore.Cameras.FramedEquidistantProjection — Type
FramedEquidistantProjection{Src <: Frame{3}, Dst <: Frame{2}}
FramedEquidistantProjection(; id::Symbol = :_)

The framed EQUIDISTANT-AZIMUTHAL ray-frame projection: a 3D direction at polar angle θ = atan(√(X²+Y²), Z) and azimuth ψ maps to θ·(cos ψ, sin ψ) on the view's EquidistantFrame. Well-defined for θ ∈ [0, π) — including Z ≤ 0 rays, where the gnomonic frame fails — with the azimuth convention ψ = 0 at the on-axis poles (X = Y = 0). The keyword constructor mints FramedEquidistantProjection{ViewFrame{id}, EquidistantFrame{id}}().

Serves the omnidirectional lenses (distortion_frame(lens) === EquidistantFrame): KannalaBrandt, the pure equidistant lens, COLMAP's thin-prism fisheye. Like FramedPerspective it is a fiber collapse with no inv; its sections are unproject/backproject on the owning camera model.

source
VisualGeometryCore.Cameras.FramedEquisolidProjection — Type
FramedEquisolidProjection{Src <: Frame{3}, Dst <: Frame{2}}
FramedEquisolidProjection(; id::Symbol = :_)

The framed EQUISOLID (Lambert equal-area) ray-frame projection: a 3D direction at polar angle θ and azimuth ψ maps to 2·sin(θ/2)·(cos ψ, sin ψ) on the view's EquisolidFrame. Well-defined on the WHOLE sphere θ ∈ [0, π] — the only member of the projection family with no excluded ray; the antipode maps to radius 2 under the pole azimuth convention ψ = 0. The keyword constructor mints FramedEquisolidProjection{ViewFrame{id}, EquisolidFrame{id}}().

Serves Lens(Equisolid()) (distortion_frame(lens) === EquisolidFrame). Like FramedPerspective it is a fiber collapse with no inv.

source
VisualGeometryCore.Cameras.FramedLensProjection — Type
FramedLensProjection{Src <: Frame{3}, Dst <: Frame{2}, L <: AbstractLensModel}
FramedLensProjection(lens; id::Symbol = :_)

The fused MODEL-CARRYING ray projection of a lens whose projection has no fixed frame (a DoubleSphere, Unified or ExtendedUnified projection): {ViewFrame{id} → DistortedFrame{id}} in ONE stage, project(lens, X) on ray representatives — the lens's whole valid field of view, Z ≤ 0 rays included, NaN outside it. imaging_chain composes it with the framed K-affine:

ViewFrame{id} ─ FramedLensProjection(lens) → DistortedFrame{id}
              ─ calibration_stage(K)       → ImageFrame{id}

Like the other ray projections it is a fiber collapse — no inv (a MethodError by design); the closed-form inverse is backproject.

source
VisualGeometryCore.Cameras.FramedOrthographicProjection — Type
FramedOrthographicProjection{Src <: Frame{3}, Dst <: Frame{2}}
FramedOrthographicProjection(; id::Symbol = :_)

The framed ORTHOGRAPHIC (sine-law) ray-frame projection: a 3D direction at polar angle θ and azimuth ψ maps to sin θ·(cos ψ, sin ψ) on the view's OrthographicFrame — parallel projection of the ray sphere onto the equatorial plane.

Honest domain: θ ∈ [0, π/2] only. The frame FOLDS at the equator (r = sin θ is non-injective past 90°), so backward rays (Z < 0) are OUTSIDE the frame and map to NaN — they are not "large radii", and silently aliasing them onto forward rays is exactly the bug the honest-domain discipline exists to prevent (see OrthographicFrame). The keyword constructor mints FramedOrthographicProjection{ViewFrame{id}, OrthographicFrame{id}}().

Serves Lens(Orthographic()) (distortion_frame(lens) === OrthographicFrame). Like FramedPerspective it is a fiber collapse with no inv.

source
VisualGeometryCore.Cameras.FramedPerspective — Type
FramedPerspective{Src <: Frame{3}, Dst <: Frame{2}}
FramedPerspective(; id::Symbol = :_)

The framed GNOMONIC ray-frame projection: perspective division (X, Y, Z) ↦ (X/Z, Y/Z) from the 3D view frame onto the view's GnomonicFrame. The math is the lens contract's Gnomonic frame projection (lens_rays.jl) — one definition of the gnomonic map; this stage wears the frames. The keyword constructor mints FramedPerspective{ViewFrame{id}, GnomonicFrame{id}}() (anonymous view :_ by default — see DistortedFrame).

No inv — deliberate

Perspective projection collapses each ray (a 1-parameter fiber) to a point: a 3D → 2D fiber collapse has no inverse, so inv is absent by design (a MethodError, pinned by test). The right-inverses — the SECTIONS of the projection, each selecting one point per fiber via a depth — are unproject (pixel + depth → 3D point) and backproject (pixel → unit ray, the norm-one section); use those to go back.

Serves the lenses whose distortion is defined on the perspective plane (distortion_frame(lens) === GnomonicFrame). Omnidirectional models use FramedEquidistantProjection instead.

source
VisualGeometryCore.Cameras.FramedStage — Type
FramedStage{Src <: Frame, Dst <: Frame} <: Transformation

Abstract supertype of the framed imaging-chain stages: a map consuming Src-frame coordinates and producing Dst-frame coordinates (same tag semantics as EuclideanMap/HomographyMap). Concrete stages: FramedPerspective, FramedEquidistantProjection, FramedStereographicProjection, FramedEquisolidProjection, FramedOrthographicProjection (3D → 2D ray projections), FramedLensProjection (the fused model-carrying 3D → 2D projection of a lens with a parametric projection), FramedDistort, FramedUndistort, FramedAffine, FrameTransition (2D → 2D), the sphere self-maps RayMap/InverseRayMap (3D → 3D), and the composite FramedChain.

∘ between framed stages is junction-checked under the standing wildcard truth table (see Base.:∘ at EuclideanMap) and produces a flat FramedChain; a labeled junction mismatch is a MethodError. Composing with a foreign (unframed) Transformation falls through to CoordinateTransformations' lazy composition — gradual, as always.

source
VisualGeometryCore.Cameras.FramedStereographicProjection — Type
FramedStereographicProjection{Src <: Frame{3}, Dst <: Frame{2}}
FramedStereographicProjection(; id::Symbol = :_)

The framed STEREOGRAPHIC ray-frame projection: a 3D direction at polar angle θ and azimuth ψ maps to 2·tan(θ/2)·(cos ψ, sin ψ) on the view's StereographicFrame — projection of the ray sphere from its backward pole, the conformal member of the fisheye family. Well-defined for θ ∈ [0, π); the exact antipode is outside the frame, where the stage answers NaN, as the lens contract does (the stereographic radius diverges there). The keyword constructor mints FramedStereographicProjection{ViewFrame{id}, StereographicFrame{id}}().

Serves Lens(Stereographic()) (distortion_frame(lens) === StereographicFrame). Like FramedPerspective it is a fiber collapse with no inv.

source
VisualGeometryCore.Cameras.FramedUndistort — Type
FramedUndistort{Src <: Frame{2}, Dst <: Frame{2}, L <: AbstractLensModel}

Framed inverse-distortion stage {DistortedFrame → ray frame} — the frames-swapped inverse of FramedDistort, minted by undistort_stage or inv. Math dispatches on the Dst frame kind: undistort_normalized(lens, ·) toward a GnomonicFrame; the closed-form/Newton θ-inverse toward an EquidistantFrame.

Feeding stages the wrong way around — e.g. composing an undistort stage directly after another undistort stage, or after the ray projection (which lands on the ray frame, not the distorted frame) — is a junction mismatch and throws a MethodError: distort-vs-undistort DIRECTION is what the frame tags check, view identity or not.

source
VisualGeometryCore.Cameras.InverseRayMap — Type
InverseRayMap{F <: Frame{3}, C <: RetinalFrame, L <: AbstractLensModel}

The inverse sphere self-map D⁻¹: S² → S² — the undistort conjugation lift ∘ undistort ∘ section, minted by inv of a RayMap (and inverting back). Same frame typing, ray semantics, unit-norm output, and frame-domain behavior as RayMap.

source
VisualGeometryCore.Cameras.RayMap — Type
RayMap{F <: Frame{3}, C <: RetinalFrame, L <: AbstractLensModel}

The lens's SPHERE SELF-MAP D: S² → S² as a framed stage {ViewFrame{id} → ViewFrame{id}}: the lens's forward distortion free of any image frame, computed as the conjugation

D = lift ∘ distort ∘ section

where section is the projection onto the lens's defining frame (distortion_frame) restricted to the unit sphere and lift is its inverse. C records the defining frame the conjugation runs through; D itself needs no 2D frame tag — its input and output are rays of the view's 3D frame.

Acts on RAYS: any 3D representative may be supplied (the input norm is irrelevant — both frame projections are scale-invariant on ray representatives), and the output is always the UNIT bearing vector of the re-oriented ray.

Restricted to the sphere the frame projections are sections — invertible, unlike the fiber-collapsing full projections FramedPerspective / FramedEquidistantProjection — which is why RayMap has an honest inv (the InverseRayMap undistort conjugation) while the projection stages deliberately have none.

Domain: the conjugation is defined exactly where the defining frame is — the forward hemisphere Z > 0 for gnomonic-frame lenses, θ ∈ [0, π) (all but the exact backward ray) for equidistant-frame lenses. Rays outside the frame's domain map to NaN.

Mint with ray_map; direct type-parameter construction is an unchecked expert surface, like relabel.

VisualGeometryCore.Cameras.calibration_stage — Method
calibration_stage(intrinsics::AbstractIntrinsics; id::Symbol = :_) -> FramedAffine
calibration_stage(Src::Type{<:Frame{2}}, Dst::Type{<:Frame{2}}, intrinsics)

Mint the framed calibration stage of intrinsics: the affine action of K (A = K[1:2, 1:2], t = K[1:2, 3] — bit-identical to the legacy imaging_transform's AffineMap), labeled {DistortedFrame{id} → ImageFrame{id}}. VisualGeometryCore.Cameras.distort_stage — Method
distort_stage(lens::AbstractLensModel; id::Symbol = :_) -> FramedDistort

Mint the framed forward-distortion stage of lens, {distortion_frame(lens){id} → DistortedFrame{id}}, with the honest frame tag read from distortion_frame. For COLMAP's thin-prism fisheye the stage's math is its additive bundle, read in the equidistant frame (the equidistant half is the stage-1 ray projection, not distortion). Errors for lenses with no distortion stage: identity-in-frame models (Pinhole, a pure Lens(Equidistant()) — the chain collapses instead, see DistortedFrame) and scoped-out models (a parametric projection, which has no frame split).

source
VisualGeometryCore.Cameras.distortion_frame — Method
distortion_frame(lens::AbstractLensModel) -> Type{<:RetinalFrame} | nothing

The ray frame a lens model's distortion is DEFINED in — the Src frame kind of its framed distortion stage, and the frame the stage-1 ray projection of imaging_chain must land on. For a Lens it is its projection's frame (projection_frame): GnomonicFrame for the perspective projection, EquidistantFrame for the equidistant one (Kannala–Brandt's θ_d = θ·(1 + k₁θ² + …) is a radial factor there), and so on. A LiftLens is read on the gnomonic frame. nothing for a parametric projection, whose frame its coefficients define — ModelDefined in the FrameDependence vocabulary, which no Symbol tag can carry — so there is no frame + distortion SPLIT; imaging_chain serves such a lens through the fused model-carrying FramedLensProjection onto DistortedFrame{id}.

Relation to the Bool capability traits: has_distortion(lens) == false means the distortion is the identity in this frame, and the chain collapses the ray frame onto DistortedFrame (no distortion stage) — see the collapse rule there. All these frames assume a single center of projection.

source
VisualGeometryCore.Cameras.frame_transition — Method
frame_transition(C1::Type{<:RetinalFrame{id}}, C2::Type{<:RetinalFrame{id}}) -> FrameTransition

Mint the framed transition map {C1 → C2} between two retinal frames of view id (the id must MATCH — a transition between frames of different views is a MethodError, the labeled-junction rule):

t = frame_transition(EquidistantFrame{:_}, GnomonicFrame{:_})
t(Vec2(θ, 0.0))            # == Vec2(tan(θ), 0.0)
inv(t)                     # the reverse transition {Gnomonic → Equidistant}

This makes a first-class named object of what production code usually hides in an inline expression: OpenCV's cv::fisheye::undistortPoints ends with the line scale = tan(θ)/θ_d — that line IS frame_transition(EquidistantFrame{id}, GnomonicFrame{id}), the equidistant → gnomonic frame change applied after the polynomial θ-inverse, unnamed and unchecked in the C++. Here the same reparameterization is a framed stage with checked junctions and honest domain edges (see FrameTransition).

source
VisualGeometryCore.Cameras.imaging_chain — Method
imaging_chain(intrinsics, lens; id::Symbol = :_) -> FramedChain
imaging_chain(model::CameraModel; id::Symbol = :_)

Mint the fully-typed framed imaging composite {ViewFrame{id} → ImageFrame{id}} — the frame-checked counterpart of imaging_transform's frame-free AffineMap(K) ∘ lens. Every inner junction is checked at construction:

ViewFrame{id} ─ ray-frame projection → distortion_frame(lens){id}
              ─ distort_stage(lens)  → DistortedFrame{id}
              ─ calibration_stage(K) → ImageFrame{id}

Stage 1 is FramedPerspective for perspective-plane lenses and FramedEquidistantProjection for equidistant-frame (omnidirectional) lenses — see distortion_frame. When the lens is the identity in its defining frame (Pinhole; a pure Lens(Equidistant())), the distortion stage is omitted and K consumes the ray frame directly (frame collapse — see DistortedFrame). A lens with a parametric projection is served by one fused FramedLensProjection onto DistortedFrame{id}.

The id keyword threads the view identity; the default is the reserved anonymous view :_ (junctions then check by frame KIND — the distort-vs-undistort direction check needs no view identity). Rig-derived chains label from the rig's minted ids:

a, b = ids(rig)
chain₁ = imaging_chain(model(source(rig)); id = a)   # {ViewFrame{a} → ImageFrame{a}}

Numerically the chain matches imaging_transform: bit-identical for perspective-plane lenses (identical operations in identical order); equivalent to floating-point round-off for equidistant-frame lenses, whose framed route works in the model's defining frame instead of hopping through the gnomonic plane (atan/tan cancellation — the legacy callable's route).

source
VisualGeometryCore.Cameras.ray_map — Method
ray_map(lens::AbstractLensModel; id::Symbol = :_) -> RayMap

Mint the lens's sphere self-map D: S² → S² as the framed stage {ViewFrame{id} → ViewFrame{id}} — what a central lens actually does, stated with no image frame: it RE-ORIENTS rays. The familiar 2D distortion polynomial is the conjugation section ∘ D ∘ section⁻¹ in the lens's defining frame (distortion_frame); ray_map returns D itself.

Input is any 3D ray representative (norm irrelevant); output is the unit bearing vector of the re-oriented ray. inv yields the undistort conjugation (InverseRayMap) — honest, because on the sphere the frame projections are invertible sections. Rays outside the defining frame's domain (gnomonic: Z ≤ 0; equidistant: the exact backward ray) map to NaN — see RayMap.

For lenses whose distortion is the identity in their defining frame (Pinhole, a pure Lens(Equidistant())), D is the identity map — still framed, still returning the unit representative. For COLMAP's thin-prism fisheye the conjugation runs through its equidistant frame, where its distortion is the additive bundle. A lens with a parametric projection has no frame split and is scoped out (ArgumentError), exactly like distort_stage.

D exists only for CENTRAL lenses (single center of projection, which every VisualGeometryCore lens model satisfies): a finite or thick pupil has no sphere self-map, because its rays do not share a center — that regime is ray tracing, downstream.

source
VisualGeometryCore.Cameras.similarity_scale — Method
similarity_scale(m::FramedAffine) -> Real
similarity_scale(a::AffineMap) -> Real

The isotropic scale σ of a (framed) similarity x ↦ σ R x + t — a Hartley normalization's side included: lengths in Src are σ times as long in Dst, so a pixel threshold τ is σ τ after the map (and τ / σ back through inv(m)). For the NormalizedImageFrame map σ = 1/s, the inverse half-diagonal. Throws an ArgumentError unless m is a similarity (AᵀA = σ² I to rounding): a sheared or anisotropic map has no single scale.

Targets

A calibration target is a MODEL, the analogue of a camera model: AbstractTarget promises points(target) in its own TargetFrame{id}; PointTarget holds explicit (nominal or estimated) points, PlanarTarget a design — its nominal points, or the reference they are resolved from — and a warp (Rigid today). A target whose geometry an estimator refines implements the calibratable-target protocol (target_parameters, with_parameters, minimal_manifold, regularizer).

VisualGeometryCore.Cameras.AbstractTarget — Type
AbstractTarget

A calibration target as a model: points(target) returns its points in its own frame TargetFrame{id} — 2-vectors on the plane z = 0 for a planar target, 3-vectors for a solid one — plain or Uncertain. See the header of targets.jl for the calibratable-target protocol.

source
VisualGeometryCore.Cameras.AbstractWarp — Type
AbstractWarp

The deformation of a planar target's nominal design: a map of plane points w(p), with the warp protocol warp_parameters, warp_parameter_names, with_parameters(w, θ), warp_jacobian(w, x) (∂w(x)/∂θ, 2 × n) and regularizer(w). Rigid is the one shipped.

source
VisualGeometryCore.Cameras.PlanarTarget — Type
PlanarTarget(nominal; warp = Rigid())                  a design given by its points
PlanarTarget(design::Symbol; nominal = nothing, warp = Rigid())   a content-addressed design

A planar target: a DESIGN — its nominal plane points, and/or the reference design they are resolved from (a BlobBoards board uid) — and a warp W taking the design to the physical target, points(t) = W.(nominal) (2-vectors on the plane z = 0). An unresolved target (a reference, no nominal points yet) is a pose-only board; resolve supplies its points, and its points is an error until then. VGC never parses a design file: the design's package resolves the reference.

Rigs

A Rig is members with fixed poses in one frame, each a (model, mount) pair: a camera (its model and rig-relative extrinsics) or a Mounted target. Sensors only, targets only, or both (a camera rig carrying its marker constellation).

VisualGeometryCore.Cameras.Mounted — Type
Mounted(target::AbstractTarget, mount)

A target as a Rig member: the TARGET — its geometry, an AbstractTarget, independent of where it is mounted, so the same target can sit in several rigs — and its MOUNT, the rigid map taking target-local coordinates (the pattern plane z = 0 for a planar target) into the rig frame, stored unlabeled (the rig mints TargetFrame{id} → F on access). The mount may be Uncertain (an estimated mount, its 6×6 covariance in the RigidExpManifold6 chart, rotation first); the rig hands it back uncertain, its covariance unchanged by the labels. points(m) are the target's own points; pose(m) is the mount.

source
VisualGeometryCore.Cameras.Rig — Type
Rig{F, M}

A rigid assembly: members with FIXED poses in a common frame F, each a (model, mount) pair. Three storages, one interface:

  • M <: Tuple{Vararg{AbstractCamera}} — a physical multi-sensor rig. Sensor i's extrinsics is the labeled map F → ViewFrame{idᵢ}, stored inside the camera (a camera IS its model and its mount); the ids, the reference frame and every relative transform are read off those labels — there is no cached inverse, no id tuple, no second copy to drift. The tuple makes the sensor count static: StereoRig IS the 2-tuple case, dispatchable with no runtime length check. Many views over time are NOT a rig — they are frames of one (see the header comment) — which is why a Vector of hundreds of cameras is not accepted.
  • M <: AbstractDict{Symbol, <:Mounted} — a rig of targets: each a Mounted target keyed by identity, its mount stored unlabeled and minted TargetFrame{id} → F on access.
  • M <: NamedTuple{(:sensors, :targets)} — both: a sensor tuple and a target dictionary posed in one frame (a camera rig carrying its motion-capture marker constellation, on BodyFrame{:camera_rig}). Built by Rig{F}(sensors, targets); sensor_rig and target_rig are its two halves as rigs of their own. Ids are distinct across the two.

Type parameters

  • F <: Frame{3}: the frame every member is posed in. THE FRAME IS THE GAUGE: when F is a member's own frame — ViewFrame{id₁} for a stereo rig built by the StereoRig constructors, TargetFrame{uid} for a calibration target gauged on board uid — that member's pose is the identity, checked at construction. A rig posed in an external frame (a body frame, the world, a tracker's room) names that frame instead and has no gauge member.
  • M: the storage, above.

Accessors

ids, pose(rig, id) / extrinsics(rig, id) (label-minting or label-preserving per storage; sensors also by position), rig[id], length, haskey; view_frames / image_frames on sensor rigs, target_frames and points(rig, id) — the target's points in the rig frame, the WORLD POINTS of the assembly — on target rigs; the stereo surface (source, target, extrinsics(rig), pose(rig)) on the 2-sensor alias.

VisualGeometryCore.Cameras.StereoRig — Type
StereoRig{F, U, V} = Rig{F, Tuple{U, V}}

Stereo camera pair — the 2-sensor specialization of Rig: a stereo rig IS a rig whose camera container is a 2-tuple, so the pair's length is in the type and the stereo surface dispatches on it with no runtime check.

Since 0.16 there are NO source/target/extrinsics FIELDS: the rig stores its two cameras rig-relative (reference frame F = ViewFrame{id₁}; camera 1's stored extrinsics is the identity, camera 2's is the labeled relative transform ViewFrame{id₁} → ViewFrame{id₂}), and the old fields are method-form accessors:

  • source(rig) / target(rig): the two cameras (rig-relative — the constructors re-express world-posed inputs).
  • extrinsics(rig): the relative rigid transform (monogram X_{V₂V₁}), DERIVED from the stored per-camera maps as extrinsics(rig, 2) ∘ pose(rig, 1) — it consumes source-view (ViewFrame{id₁}) coordinates and produces target-view (ViewFrame{id₂}) coordinates, i.e. X₂ = R·X₁ + t.
  • pose(rig): inv(extrinsics(rig)) (the typed algebra swaps the frames, X_{V₁V₂}).
  • ids(rig): the identity symbols, read off the stored labels.

The labels ARE the single source of truth — the twin-typing and id-duplication policy violations of 0.6–0.8 remain unrepresentable, and the 0.9-era separately-stored relative transform is gone too (one authority: the per-camera rig-relative maps).

Constructors

StereoRig(left_camera, right_camera)   # Computes relative transform
StereoRig(source, target, extrinsics)  # Explicit transform, CHECKED against
                                       # the cameras (check = false to skip)
StereoRig(left, right; ids = (:left, :right))  # Mint per-view identities

The ids keyword mints the view identities at construction (label-at- source: the constructor re-expresses the cameras in the rig frame ViewFrame{id₁} and labels the relative transform ViewFrame{id₁} → ViewFrame{id₂}, overriding whatever frames the inputs carried — the rig's ids are authoritative for its own transforms). The labeled per-view tags are exposed by view_frames (3D ViewFrame{id}) and image_frames (2D ImageFrame{id}); essential_form / EpipolarForm(rig) mint the labeled epipolar forms. Purely additive: nothing in the rig forces identities onto callers who ignore them.

The 3-arg constructor validates the given transform against extrinsics(target) ∘ pose(source) computed from the GIVEN cameras (check = true by default, atol tolerance on the rotation angle and the relative translation deviation). Supply check = false for synthetic rigs whose cameras are placeholders and do not encode the relative geometry.

VisualGeometryCore.Cameras.depth_transfer — Method
depth_transfer(source::Camera, target::Camera, extrinsics)
depth_transfer(rig::StereoRig)

Depth-ASSUMED point transfer from the source camera to the target camera: returns a closure mapping a source pixel to a target pixel by backprojecting to a ray, fixing unit depth in the source camera frame, transforming through extrinsics, and projecting into the target image.

WARNING: this is a point-to-point transfer under an arbitrary depth assumption — it is NOT the epipolar correlation. Without depth, a pixel backprojects to a ray, not a point; the honest depth-free two-view object is the point-to-LINE map of an EpipolarForm (see epipolar_map, which since 0.8 names only that action). For real transfer with known depth, use transfer with a depth-attributed point; for correspondence search, use triangulation with matched features.

Renamed from epipolar_map in 0.8 — the old name promised a correlation and delivered a transfer.

Arguments

  • source::Camera: Source camera
  • target::Camera: Target camera
  • extrinsics::EuclideanMap: Relative transform from source to target

Returns

  • Function mapping pixel coordinates from source to target camera

VisualGeometryCore.Cameras.validate_gt_metric — Method
validate_gt_metric(rig, csponds, depth_src, depth_tgt;
                   rel_tol = 0.05, gross_outlier_pixel_frac = 0.01,
                   bidirectional_depth = true)
    -> (residuals::Vector{Vec3{Float64}}, valid::BitVector)

Geometric pre-validation in metric space, without any pixel-residual threshold. A cspond is valid when it satisfies, in order:

  1. a gross-outlier gate: its GT-pose Sampson distance is at most gross_outlier_pixel_frac × the target image diagonal (pose only, no depth);
  2. depth_src is finite at p_A and depth_tgt is finite at p_B;
  3. the forward warp of p_A lands where depth_tgt is finite, and the predicted and observed target depths agree within rel_tol (relative);
  4. with bidirectional_depth, warping p_B back at its observed depth agrees with depth_src the same way.

The residual is 3D, in meters: forward, in the target camera frame,

residuals[i] = unproject(tgt, p̂_B, d̂_B) − unproject(tgt, p_B, d_obs)

and, with bidirectional_depth, the longer of that and the backward residual (in the source camera frame), so ‖residuals[i]‖ is the worse-direction metric disagreement at the surface. Used by calibrate_metric_tol to estimate the noise floor without applying a tolerance gate.

VisualGeometryCore.Cameras.rectify — Method
rectify(rig::StereoRig; K = nothing) -> (; rig, R, K)
rectify([T = Float64], rig::StereoRig, images::Tuple; K = nothing, out_size = nothing, scale = 1)
    -> (; rig, R, K, images::NTuple{2, FramedImage})

Epipolar rectification of a stereo rig.

Geometry form: computes the rectifying rotations R = (Q₁, Q₂) (RotMatrix3s, original view-i orientation → the common rectified orientation, Q₂ = Q₁·R_relᵀ), the shared pinhole calibration K (SMatrix{3,3}; default: mean focal of the two views, mean principal point, zero skew), and the RECTIFIED rig — a StereoRig of two pinhole cameras with the same ids whose relative transform is the pure baseline translation. Rectified frames are NEW frames; the returned rig's ViewFrame{id}s label those, not the input views.

Image form: additionally resamples the two source images into the shared rectified pixel frame — for each output pixel, K⁻¹ → rotate the ray by Qᵢᵀ → project through view i's OWN lens model → sample: distortion and rectification in ONE fused warp per view, any AbstractLensModel. Returns two FramedImages over the same window Rect(0, 0, W, H) of the rectified pixel frame (out_size = (W, H), default: the elementwise max of the input sizes; scale downsamples like the rect form of undistort). After rectification, corresponding points share a row and disparity = fx·B/z.

KernelAbstractions end to end: the destination is allocated with similar, so it lives on the SOURCE images' backend — supply CuArrays and the fused warp (one bilinear kernel; the isbits chain evaluated per output pixel on the device, no remap grid) runs on the GPU. rectify(Float32, rig, images) keeps the warp math single-precision for GPU throughput (the type leads, as in Base's zeros(Float32, n)).

The construction assumes a predominantly HORIZONTAL baseline (the new x-axis is sign-fixed toward +x); a vertical rig wants the transposed convention. Throws for a near-zero baseline.
