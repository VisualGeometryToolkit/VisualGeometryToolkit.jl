Robust Losses API

The robust-loss family and the width axes a scorer or a local optimizer is built at. The contracts that use them are on the Robust Estimation API page.

Robust Losses

VisualGeometryCore.AnyLoss — Type
AnyLoss

A loss that KNOWS ITS OWN WIDTH — deployed, or deployed and annealed.

The one-argument verbs below are written against this, ONCE. Every one of them is <shape math>(loss_shape(loss), …, sq_loss_width(loss)), and both members answer those two accessors, so nothing in a verb body is per-type.

A future wrapper (censored, per-point-scaled) joins the family by defining loss_shape and sq_loss_width, not by copying nine one-liners.

source
VisualGeometryCore.AbstractLossShape — Type
AbstractLossShape

Tag-type root of the unified robust-loss family: a normalized scale family ρ_w(r) = w²·ρ₁(r/w) whose scale parameter w is the loss_width, the residual scale at which the loss leaves the shared quadratic regime (see LOSSES.md and the header of robust/losses.jl). A shape carries no width; deploy gives it one.

source
VisualGeometryCore.AbstractMEstimator — Type
AbstractMEstimator <: AbstractLossShape

A robust loss whose WIDTH is set by asymptotic efficiency at the Gaussian. Subtyping this is a promise, and the promise costs exactly one method.

Interface

A subtype MUST define one method:

efficiency_constant(::Type{MyShape}) -> Float64

its tuning constant at codimension 1 — the solution of eff(m, 1) = 0.95 for that shape's psi. It takes the TYPE, not an instance: the constant is a property of the shape, and a deployment is built FROM it. Failing to define it is a MethodError on the first call, deliberately NOT caught by a catch-all, so hasmethod(efficiency_constant, (Type{MyShape},)) answers honestly.

From that single number every other method is inherited and guaranteed:

inheritedwhat it gives
efficiency_constant(K, d)the constant at codimension d
codimension_factor(K, d)its ratio to the d = 1 constant
sq_loss_width(loss)scale_multiple^2 * s2, the squared width it runs at
loss_width(loss)scale_multiple * sqrt(s2), derived

Note sq_loss_width/loss_width are methods of a DEPLOYMENT (deploy(shape, s2; scale_multiple)), not of the shape: a bare shape has no width.

The noise level is an INPUT. This interface turns one into a width; it does not estimate the noise, and nothing here should. How a strategy obtains its scale is a separate axis with its own vocabulary — see ScaleInterface (ConsensusAnchored, FixedScale, FollowsScorer, SelfScaling, NoScale) in robust/estimation.jl — and the estimator is a real choice (MAD, RMS, median-of-norms, Qn, …) that belongs to the caller, not to the loss.

A subtype MAY also define _solved_constants(::Type{MyShape}), a tuple of the constants for d = 1, 2, … (entry 1 equal to its efficiency_constant) at each codimension where eff(m, d) = 0.95 has actually been SOLVED, replacing the generic chi lift sqrt((d+2)/3) with those solved numbers. It is an optimisation of accuracy, never a requirement — see the note under codimension_factor.

Who is deliberately NOT here

Losses that efficiency does not parameterise stay directly under AbstractLossShape, and calling loss_width on one is a MethodError by design: GaussianShape has no width to set, TLSShape is a hard truncation with no influence function, and BarronShape's shape is itself fitted — deriving a fixed constant for it would contradict the fit.

SmoothTLSShape is the one shape that sits outside this hierarchy yet DOES carry constants. It is a truncation, so it ships no default scale_multiple and subtyping AbstractMEstimator would wrongly promise one — but eff(m, d) = 0.95 is genuinely solvable for its psi, so efficiency_constant(SmoothTLSShape) and its whole solved column exist and are supported. Read the subtype relation as "has a default scale_multiple", NOT as "has a constant": a caller wanting the efficiency-matched truncation asks efficiency_constant directly. This is why efficiency_constant(K, d) and codimension_factor(K, d) below take Type{<:AbstractLossShape} and not Type{<:AbstractMEstimator}.

VisualGeometryCore.DeployedLoss — Type
DeployedLoss

A shape together with the width it runs at: Attributed(shape, (scale_multiple, s2)), the multiple of the noise scale and the noise VARIANCE. This is the homotopy's TARGET — anneal wraps one to move along the path, and target_loss unwraps back to it.

isbits and 16 bytes: the shape is a zero-byte tag, so a deployment is two Float64s and costs a stack write.

VisualGeometryCore.HuberShape — Type
HuberShape <: AbstractLossShape

Huber tag: quadratic core with a LINEAR tail past the elbow — monotone ψ (influence constant, never vanishing, beyond the elbow), hence unbounded and not redescending; not liftable (w_max is finite but the GR dual adds nothing over plain IRLS). Facet tag only — names the objective of the static-IRLS strategy vocabulary (Irls{HuberShape}).

source
VisualGeometryCore.MuScaled — Type
MuScaled <: GncSurrogate

The families whose μ multiplies the squared width (c²_μ = μ·c̄²). They differ in what μ MEANS — a width for Welsch, convexity for Geman–McClure — and so in gnc_mu0 and gnc_target, but not in how it enters the weight, so that half of the trait is written once against this supertype.

An ABSTRACT TYPE, not a Union: a downstream shape whose μ scales the squared width joins by subtyping this, the way a downstream M-estimator joins by subtyping AbstractMEstimator. A Union would have made the new extension point closed — joining would mean editing a Union inside VGC.

VisualGeometryCore.TLSShape — Type
TLSShape <: AbstractLossShape

HARD truncated-least-squares tag: ρ(r) = min(r², c²) — the discontinuous-influence truncation (shape g(u) = min(u, 1)). Facet tag only: NOT liftable (the truncated quadratic has no Geman–Reynolds dual — its graduation is the Black–Rangarajan outer bound, gnc_tls_weight below, not a width anneal), so it ships no lift_* closed forms. Names the objective of the truncated/GNC-TLS strategy vocabulary (e.g. Gnc{Irls{TLSShape}} in RobustVisualGeometry).

VisualGeometryCore.band_signal — Method
band_signal(surrogate, w) -> Int

The per-residual rung-advance signal a GNC engine counts: 1 when the weight lies in the OPEN band 0 < w < 1, 0 otherwise — and identically 0 for every family whose graduation has no band.

A TRAIT VERB rather than an isa BandAnnealed test inside the accumulation loops (LocalOptimizationDoneRight's lift core). Those loops are generic over the family, so they name no family: a new surrogate family declares its own signal instead of editing the loop.

Returns an Int so the loops accumulate unconditionally; where the answer is the constant 0 the whole term folds away.

VisualGeometryCore.bounded — Method
bounded(shape::AbstractLossShape) -> Bool

Whether the shape is bounded (sup g = 1, so ρ(∞) = Δ): the potential redescends to a positive density floor e^{−Δ} and is therefore NOT normalizable on an unbounded domain — usable as evidence only through a truncated normalizer Z̃, and never likelihood-grade at frozen scale (aligns with the NormalizedWeightPolicy boundary in robust/estimation.jl).

source
VisualGeometryCore.chisq_median — Method
chisq_median(codim::Integer) -> Float64

Median of chi^2_d, for ANY codimension: 0.4549 at d = 1, 2 log 2 = 1.3863 at d = 2. Its square root is 0.6745 at d = 1 and 1.1774 (the Rayleigh median) at d = 2.

0.6745 is Phi^-1(0.75), the SAME constant that scales a MAD — but sharing a constant is not being the same estimator; see noise_sigma.

Answers for every d on purpose — a hand-tabulated d ∈ {1, 2} would throw on the very call pattern this interface exists for, noise_sigma(norms, codimension(problem)), where a hand-eye problem reports d = 6.

source
VisualGeometryCore.codimension_factor — Method
codimension_factor(K::Type{<:AbstractLossShape}, codim::Integer) -> Float64

How much wider the width must be for a codim-dimensional residual than for a scalar one, at equal efficiency: efficiency_constant(K, d) / efficiency_constant(K), and 1.0 at codimension 1 by construction.

DERIVED, not stored — efficiency_constant(K, d) is the primitive, because the constant is what gets solved. Where eff(m, d) = 0.95 has actually been solved the ratio comes out of that solved number; everywhere else it is the chi-distribution rule sqrt((d+2)/3), which is exact at d = 1, a good approximation elsewhere, and makes a new loss work from its 1-D constant alone. The solved values run 3.8-7.5% under the generic 1.1547 at d = 2 (Huber 1.1109, GM 1.0814, Welsch 1.0893, Cauchy 1.0686).

source
VisualGeometryCore.conjugate — Method
conjugate(loss, w, sq_loss_width) -> Float64

Geman–Reynolds penalty conjugate(w) on the UNNORMALIZED weight w ∈ (0, w_max], so that ρ(r) = min_w [w·r² + conjugate(w)] (verified numerically in the RVG tests).

Two psis, and this is not the one

The half-quadratic literature (Geman–Reynolds, Black–Rangarajan) writes this penalty ψ; M-estimation writes ψ for the INFLUENCE FUNCTION ρ′(r). This package needs both, so the influence function keeps the symbol — it is the one efficiency_constant is solved against — and the penalty is named for what it IS: the Legendre conjugate of ρ in w.

Tell them apart by the argument: conjugate(shape, w, sq_loss_width) takes a WEIGHT, ψ and weight take a residual and a squared residual.

source
VisualGeometryCore.conjugate_curvature — Method
conjugate_curvature(loss, w, sq_loss_width) -> Float64

w·κ²″(w), the scaled second derivative of the Geman–Reynolds conjugate κ²(w) in the unnormalized weight w — the z-block curvature of a Newton lift in w = z². Since κ²′(w) = −s(w) (s the squared residual whose weight is w), it is −w/ω′(s(w)). Closed forms, each pinned against a central difference of conjugate:

shapeκ²(w)w·κ²″(w)
Welschc²(w ln w − w + 1)c²
Geman–McClurec²(√w − 1)²c²/(2√w)
Cauchyc²(w − 1 − ln w)c²/w
smooth TLSc²(1 − w/2)²c²w/2
Barron(α)see BarronShape2c²·w^{2/(α−2)}

Defined for the liftable shapes only, as conjugate is.

Loss M-estimator cost Σᵢ ρ(rᵢ; c) over r[1:n] — the best-tracking objective of the lifted LO, scaled by the shape's cost_scale.

VisualGeometryCore.cost_scale — Method
cost_scale(shape) -> Float64

The shape's historical COST CONVENTION: the constant its tracked objective is scaled by, 1.0 for everything but Welsch, whose tracker carries a ½.

A pure rescaling — monotone-equivalent, so it cannot change which model wins — and therefore a property of the SHAPE's history, not of its math. It is a trait of its own precisely because it is not deducible from anything else, and it is per-SHAPE so that no graduation family inherits Welsch's ½: a future width-annealed shape carries its own convention, not Welsch's.

Multiplying by ½ is exact in binary floating point.

source
VisualGeometryCore.decision_width — Function
decision_width(m, decision_threshold) -> Float64

The native width of m whose inlier/outlier decision flips at the residual decision_threshold — THE one conversion behind every "same decision point" comparison across methods (the evaluation's fairness axis, where decision_threshold = scale_multiple · ŝ). Each owner defines its own method:

  • a loss shape: the loss_width at which the shape's NORMALIZED IRLS weight at decision_threshold is exactly ½, ω(t²; w²)/w_max = ½ (the half-weight decision of a reweighting loss);
  • TLSShape: the identity — a hard truncation decides at its own width;
  • RansacScoringDoneRight's GauInlier: the Student-t marginal's outlier half-width whose MAP boundary sits at decision_threshold.

Closed forms for the shapes (t the decision threshold, w the loss width):

  • Welsch: e^{−t²/w²} = ½ ⇒ w = t/√(ln 2)
  • Geman–McClure: (1+t²/w²)^{−2} = ½ ⇒ w = t/√(√2 − 1)
  • Cauchy: (1+t²/w²)^{−1} = ½ ⇒ w = t
  • smooth-TLS: 1 − t²/w² = ½ ⇒ w = √2·t (hard cutoff at √2·t)
  • TLS: w = t
source
VisualGeometryCore.deploy — Method
deploy(shape, s2; codim = 1, scale_multiple = efficiency_constant(typeof(shape), codim))

A SHAPE at the width it runs at — the pairing every consumer was assembling by hand. Returns a DeployedLoss whose loss_width is scale_multiple * sqrt(s2).

s2 is the noise VARIANCE (sigma squared), not sigma. The whole robust layer speaks squared scale — LossWidth(m, s2), FixedS2(s2), scale_s2(cs), and every shape closed form takes a squared width — so storing the square is what makes sq_loss_width exact: scale_multiple^2 * s2 is the arithmetic the call sites already do, bit for bit. Storing a linear sigma instead would force a sqrt in and a square out, and the two disagree in the last ulps on 61% of inputs.

It is the CALLER's: this package does not estimate it (see ScaleInterface in robust/estimation.jl for the axis that decides how). From a linear sigma, square it at the call: deploy(shape, noise_sigma(norms, 2)^2; codim = 2).

scale_multiple is the width as a dimensionless multiple of the noise scale, defaulting to the shape's efficiency constant at codim and overridden by a caller that cross-validates its own operating point.

The two are kept APART, never multiplied into a stored width: a SelfScaling strategy re-estimates the variance every iteration while scale_multiple is fixed, so rescale replaces one and leaves the other.

deploy(WelschShape(), 0.37^2; codim = 2)                         # from efficiency -> 3.2510
deploy(WelschShape(), 0.37^2; codim = 2, scale_multiple = 1.597) # a CV'd operating point
source
VisualGeometryCore.efficiency_constant — Function
efficiency_constant(K::Type{<:AbstractMEstimator}) -> Float64
efficiency_constant(K::Type{<:AbstractLossShape}, codim::Integer) -> Float64

The loss's width as a MULTIPLE OF THE NOISE SIGMA. The one-argument form is the shape's own constant at codimension 1 — a property of its psi, like its influence function — and is what a loss must define to join this interface. The two-argument form lifts it to codimension d through codimension_factor.

TAKES THE TYPE, not an instance. The constant is a property of the SHAPE, and a deployed loss carries scale_multiple as a field — so an instance method would be circular: you would need a loss to obtain the constant used to build one. (Contrast lift_*, which must take an instance: BarronShape's α is a field, so its type carries strictly less information than its value.)

The DEFAULT for a deployed scale_multiple, not the only legitimate value. It solves eff(m, d) = 0.95 at the GAUSSIAN — the width that minimises variance inflation on CLEAN data. A stage running under real contamination may legitimately cross-validate its own operating point, and will land tighter: RobustVisualGeometry deploys a scale multiple ≈ 1.6 per model class where this returns ≈ 3.25, trading efficiency for breakdown. Both are right for their stage.

Defined only for losses that efficiency parameterises: GaussianShape has no width and BarronShape's shape is itself fitted, so neither has one; those raise a MethodError by design. TLSShape likewise. SmoothTLSShape is a truncation rather than an influence function and ships no default scale_multiple in its constructor, but eff(m, d) = 0.95 IS solvable for its psi, so it does carry a tabulated constant for a caller that wants the efficiency-matched truncation.

VisualGeometryCore.gnc_entry_mu0 — Method
gnc_entry_mu0(loss, r2max, entry) -> Float64

Entry-breadth policy (smooth-and-lift dose axis 1): entry = NaN is the seed-extreme Yang–Carlone init (gnc_mu0 — the rmax entry); a numeric entry = m starts the anneal at m× the TARGET WIDTH, i.e. μ₀ = max(m², 1) (μ multiplies the SQUARED scale c²μ = μ·c̄²). m = 1 is the static limit. Only WidthAnnealed consumes numeric entries — for the other families μ is a convexity or band parameter, not a width.

source
VisualGeometryCore.gnc_mu0 — Method
gnc_mu0(loss, r2max) -> Float64

Yang–Carlone μ₀ from the SEED residual extreme r2max = r²_max: ConvexityAnnealed (GM) μ₀ = max(2r²max/c̄², 1) (convex start; already ≤ 1 ⇒ true GM); WidthAnnealed (Welsch) μ₀ = max(r²max/c̄², 1) (c₀² = r²max ⇒ min weight e^{−1}); BandAnnealed (TLS) μ₀ = c̄²/(2r²max − c̄²), guarded to the μ cap when r²_max ≤ c̄²/2 (no graduation needed — start effectively hard).

VisualGeometryCore.gnc_target — Method
gnc_target(loss, x) -> Float64

TARGET (non-surrogate) loss the GNC engine best-tracks on: the shape's own ρ at the terminal width c̄², scaled by its cost_scale — which is 1.0 for every shape but Welsch, whose tracker carries a ½ (exact; the ×½ scaling is bitwise).

ONE expression for all three families. The ½ is Welsch's cost convention, a property of the shape (cost_scale), not of its graduation family; TLS routes through ρ like every other shape.

The dispatch exists ONLY to refuse: a NoSurrogate shape gets no method and raises a MethodError, like every other gnc_* verb, rather than best-tracking a graduation it does not have.

source
VisualGeometryCore.gnc_tls_weight — Method
gnc_tls_weight(x, sq_loss_width, μ) -> Float64

The Black–Rangarajan GNC-TLS surrogate weight at squared residual x = r², truncation bound sq_loss_width = c̄², continuation parameter μ:

w = 1                          x ≤ (μ/(μ+1))·c̄²
w = c̄·√(μ(μ+1))/|r| − μ        in the middle band
w = 0                          x ≥ ((μ+1)/μ)·c̄²

Continuous across the band edges (w → 1 below, w → 0 above). μ → ∞ recovers hard truncated least squares; the middle band is the graduation. Points with 0 < w < 1 are the OPEN band — a GNC engine keeps graduating only while the band is populated (the open observation of the LoSchedule contract).

VisualGeometryCore.zblock — Method
zblock(shape, w̄, sq_loss_width) -> (rinv2, hreg)

The two z-block quantities of the joint-(θ,z) Gauss-Newton step at normalized weight w̄ = z² (the lift keeps w̄ ∈ (0, 1]; the forms are also valid on the continuation w̄ > 1), scale sq_loss_width = c²:

  • rinv2 = −κ̄²′(w̄) — the inverse-weight map r²(w̄) (≥ 0 on w̄ ≤ 1), where κ̄²(w̄) = conjugate(w_max·w̄)/w_max is the normalized conjugate; enters the z-gradient gz = z(r² − rinv2).
  • hreg = w̄·rinv2²/κ̄²(w̄) — the GN z-block Hessian (dκ/dz)²; enters the Schur pivot dᵢ = 1/(r² + hreg + μ).

Losses with a cancelling ratio return the simplified closed form (Geman–McClure: hreg = c² constant; smooth-TLS: hreg = 2c²w̄). For Welsch, Cauchy and Barron both rinv2 and κ̄² vanish at w̄ = 1 while hreg tends to a POSITIVE limit, 2κ̄²″(1) (2c² for Welsch and Cauchy, 4c²·b/(2 − α) for Barron); near w̄ = 1 they evaluate the ratio from its series, so hreg is accurate there and exact at w̄ = 1, where the lift's z clamp puts every confident inlier. That value is Zach & Bourmaud's Taylor limit 2γ″(1) of the lifted Gauss-Newton block (ECCV 2018, Eq. 10; γ = κ̄²/2), the same for every shape, so Barron's anchors (α → −∞ ≡ Welsch, α = −2 ≡ Geman–McClure, α = 0 ≡ Cauchy) hold for zblock at the clamp as everywhere else.

source
VisualGeometryCore.ρ — Method
ρ(loss, s, sq_loss_width) -> Float64

Loss value ρ at squared residual s = r², scale sq_loss_width = c² — the LOSS a residual pays, in the convention ρ′(0) = w_max.

TOTAL over the family. For the liftable shapes ρ is also the Geman–Reynolds envelope min_w [w·s + conjugate(w)], but nothing about a loss REQUIRES a lift — GaussianShape is s, HuberShape is the monotone elbow, TLSShape is the hard truncation min(s, sq_loss_width). Scoping ρ to the liftable ones made ρ(GaussianShape(), …) throw while ψ(GaussianShape(), …) answered, which is incoherent: ψ is ρ′. Only conjugate and zblock stay lift-only, because only they need the auxiliary variable to exist.

The bounded shapes saturate at sq_loss_width — the well depth — so 1 - ρ/sq_loss_width is a normalised quality in [0, 1]. GaussianShape and HuberShape are unbounded and have no depth.

VisualGeometryCore.ψ — Method
ψ(loss, r, sq_loss_width) -> Float64

INFLUENCE FUNCTION ρ′(r) at residual r (NOT squared) and scale sq_loss_width = c² — ψ in the M-estimation sense (Huber, Hampel, Maronna–Martin–Yohai).

This is the function the width contract is defined against: a shape's efficiency_constant is the c solving eff(m, 1) = 0.95 for

eff(m, d) = E[ψ′ + (d-1)ψ/r]² / (d · E[ψ²]),   r ~ chi_d

so the solved table (Welsch 2.9846, Geman-McClure 3.7874, Cauchy 2.3849, …) is a claim ABOUT THIS FUNCTION, and exposing it is what makes that claim checkable rather than a comment.

Derived, never a second closed form per shape, via the defining relation of IRLS: the weight IS w(r) = ψ(r)/r, so ψ(r) = r·w(r). Built directly on weight, which covers the whole family.

Constant factors do not matter here: eff is invariant under ψ → αψ (the numerator is squared, the denominator is E[ψ²]), which is why the table holds despite ρ carrying this package's depth convention rather than the classical one.

Not to be confused with conjugate, the half-quadratic penalty that the Geman–Reynolds literature also calls ψ — that one takes a WEIGHT.

VisualGeometryCore.WidthAxis — Type
WidthAxis

The width quantity a value is expressed in — the axis it is tuned on and persisted under:

  • ScaleMultiple: a width as a multiple of the estimated scale ŝ, dimensionless (width = scale_multiple · ŝ), partition-anchored;
  • LossWidth: a robust loss's scale parameter (loss_width), the residual scale where the loss leaves its quadratic regime — a threshold score's threshold is its truncated loss's width;
  • OutlierHalfwidth: the Student-t marginal's uniform outlier half-width.

width_axis reads one from its persisted name and width_axis_name writes it; to_native maps a scale multiple onto a native axis.

VisualGeometryCore.to_native — Function
to_native(axis::WidthAxis, scale_multiple, scale; d_g) -> Float64

A scale multiple as a method's NATIVE width at the estimated scale: the width on axis whose inlier/outlier decision flips at the residual scale_multiple · scale — one conversion, decision_width, of the axis's decision model. Each native axis's method lives with its model:

  • LossWidth (here): the truncated loss TLSShape(), which flips at its width, so the native width is scale_multiple · scale itself (MSAC, RANSAC, GaU, MAGSAC++, PoseLib's truncation);
  • OutlierHalfwidth: through GauInlier (the Student-t marginal's crossover).

d_g is the residual codimension of the problem (1 for E and F, 2 for H). It has NO default: a native grid and the window cut inside it must be cut at the same d_g, so every caller states it. The loss-width axis does not depend on it; the outlier half-width does.

VisualGeometryCore.to_native — Method
to_native(::OutlierHalfwidth, scale_multiple, scale; d_g) -> Float64

A scale multiple as the Student-t marginal's native width: the outlier half-width whose MAP inlier/outlier decision flips at the residual scale_multiple · scale — decision_width of the Gaussian-uniform mixture GauInlier(scale²; d_g), the stack-wide definition of the crossover (moved from RansacScoringDoneRight). scale is the estimated inlier scale (linear, in the units of the residuals), and the result is in those units.

d_g is the residual codimension (1 for E and F, 2 for H) and has no default: it is the EXPONENT of the outlier density, so it moves the outlier half-width by decades (at scale = 1, a scale multiple of 6 maps to 8.2293e7 at d_g = 1 and to 1.0156e4 at d_g = 2).
