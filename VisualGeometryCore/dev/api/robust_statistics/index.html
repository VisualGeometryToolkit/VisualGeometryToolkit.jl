Robust Statistics and Solvers API

The robust-statistics toolkit, the generic block-coordinate-descent loop, the chart-rows contract and the chart LM (FastLevenbergMarquardt lmsolve!): the shared machinery under the contracts of the Robust Estimation API page.

Robust-Statistics Toolkit

The consensus scale, the Student-t + uniform mixture and its posterior-weight state, shared by the scorers, the local optimizers and the mixture fits.

VisualGeometryCore.IGPrior — Type
IGPrior(alpha0, beta0)

Inverse-Gamma prior on σ²: π(σ²) ∝ (σ²)^{-(α₀+1)} exp(-β₀/σ²). Conjugate to the Gaussian inlier likelihood, so the marginal reduces to a closed-form sweep update.

The Jeffreys prior π(σ²) ∝ 1/σ² is the limiting α₀ = β₀ = 0 case, built by JeffreysPrior() (or IGPrior()); one struct handles both.

Fields

  • alpha0::Float64 — shape hyperparameter (0 ⇒ Jeffreys)
  • beta0::Float64 — scale hyperparameter (0 ⇒ Jeffreys)

JeffreysPrior() -> IGPrior

The Jeffreys scale prior π(σ²) ∝ 1/σ²: IGPrior(0.0, 0.0), the default prior of every scale estimator and scorer in the stack. A function returning the value, not a second name of the type — test alpha0 == 0 rather than dispatching on a name.

VisualGeometryCore.fit_scale — Method
fit_scale(prior::IGPrior, rss, dof) -> s2

Fit the squared scale ŝ² as the inverse-gamma MAP, (rss + 2β₀)/(dof + 2α₀).

Returns ŝ², the SQUARED scale — never a linear σ̂.

ŝ² is PER COMPONENT: rss sums squared NORMS of dg-vector residuals, so dof counts components — `νdata = (k − modeldof)·dgfor a hard partition, ordg·Σπᵢin the IRLS M-step (updatescale!). The2α₀/2β₀pseudo-counts make a refinement inherit the scoring prior (β₀floors ŝ² at low inlier counts);IGPrior(0, 0)(Jeffreys) givesrss/dof`.

The first argument is THE ESTIMATOR: IGPrior selects the inverse-gamma MAP, its prior being that estimator's parameters. The residuals are TAKEN as inliers, no initial guess is needed, and no inlier decision is made here.

The result is floored at eps(), so a zero rss under Jeffreys returns eps(), not a NaN. A caller that would rather HOLD its previous scale in that case must test the dof itself at the call site.

partition_rss(order, residuals, k) -> Float64

The residual sum of squares of the partition order[1:k]: Σ_{j ≤ k} residuals[order[j]]², from UNSQUARED residuals (signed scalars or norms), accumulated in Float64 whatever their storage eltype. order is a scorer's consensus_order (or a copy of it).

VisualGeometryCore.partition_student_t — Method
partition_student_t(prior::IGPrior, rss, k; model_dof, codimension = 1) -> (ν, ŝ²)

The Student-t of a hard partition of k points with residual sum of squares rss. It is the scoring marginal's posterior predictive over it under prior, and THE seed of every Student-t in the stack: counted dof ν_data = (k − model_dof)·codimension, then

ν  = max(ν_data + 2α₀, 2),     ŝ² = fit_scale(prior, rss, ν_data).

The ν ≥ 2 clamp keeps the seed's variance finite (a Student-t has one only for ν > 2) at a thin partition, and fit_scale floors the QUOTIENT at eps. One rule for every caller: both PosteriorWeightState seeds, the partition mixture of posterior_weights!/posterior_inlier_probs!, the consensus scale consensus_s2 and a RANSAC result's σ̂. model_dof is the caller's: the sweep's minimal_sample_size for the scoring marginal, one more for a local-optimization seed that also estimates the scale.

square_residuals!(sq, r, n) -> sq

THE one residual-squaring loop of the stack — the refill of a PosteriorWeightState's sq_residuals, the per-point scores a scorer sweeps, and the pool staging.

VisualGeometryCore.weighted_rss — Method
weighted_rss(w, sq_residuals, n) -> Float64

The weighted residual sum of squares Σ_{i ≤ n} wᵢ·rᵢ² of SQUARED residuals, accumulated in Float64 left to right from 0.0. A zero-weight term contributes exactly 0: an excluded point may carry an infinite squared residual (the Sampson degeneracy rule — a vanishing projected variance), and 0·Inf = NaN would poison the sum and everything read from it (the ŝ² M-step of update_scale!, an IRLS cost and its stop rule).

weighted_sq(w, sq_r) -> w·sq_r, exactly 0 at w = 0

One term of weighted_rss, for a caller summing weights it computes on the fly rather than holding in a buffer (an ECM scale over a loss's own IRLS weights). A zero weight contributes exactly 0 even against an infinite squared residual, where 0·Inf = NaN.

VisualGeometryCore.GauInlier — Type
GauInlier(s2; nu = Inf, gamma = 1/2, d_g)

Everything the Gaussian-uniform mixture needs EXCEPT the outlier half-width — the half both directions of the boundary share.

  • s2 inlier variance sigma^2
  • nu effective dof: Inf is the Gaussian inlier, a finite value the scale-marginalised (Student-t) one. The Gaussian IS the nu -> Inf limit, and the two closed forms below agree there.
  • gamma the label prior Pr(z_i = 1); a general gamma adds log(gamma/(1-gamma)) to the boundary.
  • d_g the codimension, REQUIRED. It enters the outlier density as the EXPONENT (2·outlier_halfwidth)^-d_g, so no value of it is a safe default.
source
VisualGeometryCore.StudentTMixture — Type
StudentTMixture(ν, s_hat_sq, log_two_outlier_halfwidth, d_g[, inlier_prior = 1/2])
StudentTMixture{T}(m::StudentTMixture)

The Student-t inlier + uniform outlier mixture of one E-step, with every per-residual constant precomputed. Its parameters are ν degrees of freedom, squared scale ŝ² = s_hat_sq, outlier support of half-width outlier_halfwidth per axis (log_two_outlier_halfwidth = log(2·outlier_halfwidth), density p_out = (2·outlier_halfwidth)^-d_g), inlier mixing proportion π = inlier_prior. The loggammas are evaluated HERE, once.

An immutable isbits value, so it can be an argument of a KernelAbstractions kernel, and the three scalar functions of it — inlier_posterior, posterior_weight, mixture_nll — are allocation-free plain functions of a squared residual, callable inside a kernel as VGC's ρ is. StudentTMixture{Float32}(m) converts the constants for a Float32 kernel.

These are THE formulas of the mixture: soft_posterior_weights! (the E-step over a buffer) and posterior_weights!/posterior_inlier_probs! (over a partition) build one of these and call the same scalar kernel.

VisualGeometryCore.decision_threshold — Method
decision_threshold(m::GauInlier, outlier_halfwidth) -> Float64

The residual at which the MAP rule flips between inlier and outlier: z* = 1 iff gamma*f_in > (1-gamma)*f_out holds exactly when norm(r) is below it.

Returns 0.0 when the outlier component already explains every residual at least as well (the mixture admits nothing), rather than a negative root.

source
VisualGeometryCore.decision_width — Method
decision_width(m::GauInlier, threshold) -> outlier_halfwidth

The mixture's method of decision_width, and the inverse of decision_threshold: the per-axis outlier half-width that puts the MAP boundary at threshold. A HALF-WIDTH and not a radius — the outlier support is a box, a product of intervals, never a ball, which is why the codimension enters as the exponent.

inlier_posterior(m::StudentTMixture, sq_r) -> P(inlier | r)

VisualGeometryCore.mixture_nll — Method
mixture_nll(m::StudentTMixture, sq_r) -> −log(π·t_ν(r; ŝ²) + (1−π)·p_out)

The negative log-density of the mixture at one residual — the per-point summand of the mixture NLL. Computed against the outlier term in log space, −(log((1−π)p_out) + softplus(log π·t − log((1−π)p_out))), so it is finite for an infinite residual (it is the outlier term's) and for an exact inlier. Scalar and kernel-callable.

VisualGeometryCore.next_nu — Method
next_nu(ν, sq_residuals, s_hat_sq, w_fixed, n; d_g=1, kwargs...) -> ν_new

M-step: Newton update for ν maximizing the EM Q-function with fixed E-step weights.

Maximizes Q(ν) = Σ wi · log t{dg}(ri; ν, ŝ²) w.r.t. ν, where wi are the fixed posterior inlier probabilities from the E-step (not recomputed), ri² the squared NORM of a d_g-vector residual and ŝ² the per-component scale:

log t_d(r; ν, ŝ²) = logΓ((ν+d)/2) − logΓ(ν/2) − (d/2)·log(νπŝ²) − ((ν+d)/2)·log(1 + z), z = r²/(νŝ²)

∂Q/∂ν = Σ wi · [½ψ((ν+d)/2) − ½ψ(ν/2) − d/(2ν) − ½log(1 + zi) + (ν+d)zi/(2ν(1+zi))]

∂²Q/∂ν² = Σ wi · [¼ψ₁((ν+d)/2) − ¼ψ₁(ν/2) + d/(2ν²) + zi/(2ν(1+zi)) − zi(ν + 2d + d·zi)/(2ν²(1+zi)²)]

with z_i the SCALE-NORMALISED squared residual.

Up to max_newton Newton steps from the current ν, each clamped to [ν_min, ν_max]. Newton is taken only where Q is concave (∂²Q < 0), where its step is uphill; elsewhere the step is geometric, uphill along the gradient — ν ← 2ν if ∂Q/∂ν > 0, ν ← ν/2 otherwise.

VisualGeometryCore.posterior_weight_derivative — Method
posterior_weight_derivative(m::StudentTMixture, sq_r) -> dw/d(sq_r)

The slope of posterior_weight in the squared residual, −w/(ν·ŝ² + r²) · (1 + (ν + d_g)/2 · (1 − P(inlier | r))) — the Student-t weight's own decay plus the responsibility's. w is strictly decreasing in sq_r, so this is negative wherever w > 0; it is what a Newton inversion of the weight (a tabulated half-quadratic conjugate, LocalOptimizationDoneRight's TabulatedLift) needs. Scalar and kernel-callable.

VisualGeometryCore.soft_posterior_weights! — Function
soft_posterior_weights!(w, inlier_posterior, sq_residuals, ν, s_hat_sq, log_two_outlier_halfwidth, n, d_g=1[, inlier_prior=1/2])

E-step: compute posterior inlier probability and combined IRLS weight.

Stores inlier_posterior[i] = P(inlier | r_i) separately for the ν M-step, and w[i] = inlier_posterior[i] · u_i (combined weight for the θ solve).

d_g is the constraint codimension (1 for scalar residuals, 2 for 2D).

The separation is critical: the ν Newton update must use fixed E-step weights (not recomputed from the changing ν), otherwise ν and inlier_posterior couple in a positive feedback loop that drives ν → ∞.

source
VisualGeometryCore.ConsensusDof — Type
ConsensusDof()

The update policy of a Student-t dof HELD at the value its consensus seed gave it: the posterior-predictive dof of the scorer's consensus set, ν = 2α₀ + (k* − model_dof)·d_g (partition_student_t, with its ν ≥ 2 floor), where α₀ is the scale prior's shape (0 under Jeffreys). The seed sets it once; the ν block never moves it afterwards.

Why hold it there: a Gaussian whose scale carries an inverse-gamma posterior marginalizes to a Student-t with exactly that dof — ν measures how well the consensus set DETERMINES σ, not the shape of the inlier tail. Estimating ν instead lets the fit trade one for the other: on a contaminated set a heavy inlier tail (ν → 2) absorbs the outliers — the identifiability collapse this policy prevents.

VisualGeometryCore.mixture_ecm! — Method
mixture_ecm!(pws, r, n)

One ECM cycle of the Student-t + uniform mixture with the mixing proportion ESTIMATED (ν held fixed), from the residuals r[1:n] (unsquared). It squares them into sq_residuals(pws), then runs the E-step (update_weights!), the scale block (update_scale!) and the inlier-prior block (update_inlier_prior!), in that order. VisualGeometryCore.update_scale! — Method
update_scale!(pws, n)

M-step, scale block: overwrite ŝ² from the E-step's weights and the current squared residuals, and nothing else. Call after the residual block fills sq_residuals(pws); the ν block is update_nu!, called after this.

ŝ² is the ECM step of the d_g-variate Student-t with scale ŝ²·I:

ŝ²_new = Σ πᵢ uᵢ rᵢ² / (d_g · Σ πᵢ),     uᵢ = (ν + d_g)/(ν + rᵢ²/ŝ²),

with πᵢ the inlier posteriors and rᵢ² squared NORMS. The E-step's weight is precision-scaled, wᵢ = πᵢ·(ν + d_g)/(νŝ² + rᵢ²) = πᵢuᵢ/ŝ², so the numerator is ŝ²·Σwᵢrᵢ² at the ŝ² that E-step used, and the inverse-gamma prior enters as fit_scale(prior, ŝ²·Σwᵢrᵢ², d_g·Σπᵢ). Returns ŝ².

VisualGeometryCore.truncated_log_normaliser — Method
truncated_log_normaliser(shape, sq_loss_width, depth, r_max) -> Float64

log Z̃ = log ∫_{−r_max}^{r_max} exp(−depth·ρ(shape, r²/sq_loss_width, 1)) dr — the normaliser of the density a loss shape induces on the truncated domain [−r_max, r_max], as log 2∫₀^{r_max} (the integrand is even), by adaptive Gauss–Kronrod (QuadGK) at rtol 1e-12. The integrand is a well of width c = √sq_loss_width on a flat floor, so for c ≪ r_max an unsplit rule never samples the well: the domain is split at c·4ᵏ < r_max, which holds the result to ≲1e-12 relative over every width and depth in use.

Block Coordinate Descent

VisualGeometryCore.AbstractBlockCoordinateMethod — Type
AbstractBlockCoordinateMethod

Abstract type for the problem side of block_coordinate_descent!: the model block, its residuals, and the per-iteration bookkeeping.

Each concrete subtype defines extension points:

  • init_state!(method, prob, θ₀) — build the state and compute the initial r/σ/w. It carries ! because a method may fill buffers its own workspace holds (RobustVisualGeometry's posterior IRLS seeds method.ws's residual buffers, which the iterations then read); the method is the mutated argument
  • update_model!(state, method, prob, θ) — the model block: one weighted update of θ (weighted least squares, LM, Newton), or θ unchanged; nothing when there is no update to make (the run stops with :solve_failed)
  • update_residuals!(state, method, prob, θ) — compute residuals + sq_residuals from θ
  • post_iteration!(state, method, prob, θ, iter) — per-iteration bookkeeping (best-tracking, counters the stopping criteria read)
  • stopping_criterion(method) — the method's own StoppingCriterion (default StopNever)
  • block_coordinate_result(state, method, prob, θ, stop_reason, final_iter) — package result

VisualGeometryCore.StoppingCriterion — Type
StoppingCriterion

When a block_coordinate_descent! run ends, and why. A criterion is an immutable, concretely typed value; it answers through stop_reason(criterion, state, method, prob, θ, θ_old, iter), which returns :continue or the reason the run ends (:converged, :max_iterations, :solve_failed, or any instance's own Symbol such as :left_basin). Nothing is stored in the criterion: the counters a criterion reads live in the solver state, written by post_iteration!.

Criteria compose with | into a StopWhenAny, evaluated left to right; the first reason other than :continue wins. The tuple is part of the type, so the composed check compiles to the chain of branches it stands for.

The Manopt.jl correspondence: Manopt's criteria are mutable functors that store their reason; these are pure, and the reason is the return value.

VisualGeometryCore.block_coordinate_descent! — Method
block_coordinate_descent!(likelihood, method, prob, θ₀; max_iter) -> result

Block coordinate descent on a negative log-likelihood, over three blocks:

  • model — update_model! (the method): weighted least squares, LM, Newton, or nothing at all (a fixed-model method such as a seed EM, which returns θ unchanged);
  • nuisance — update_nuisance! (the likelihood): scale, mixing proportion, ν, Barron α, or nothing;
  • weights — update_weights! (the likelihood): EM responsibilities, loss weights, or GNC surrogate weights.

update_residuals! is bookkeeping between the model and nuisance blocks: it recomputes the residuals block from the new model and descends on nothing. One iteration (step_solver!) is one cycle through every block, in the order model → residuals → nuisance → weights, then post_iteration!. See update_nuisance! for why the nuisance block is not named "scale".

Stopping

The run's criterion is

StopWhenSolveFailed() | stopping_criterion(method) | StopAfterIteration(max_iter)

evaluated in that order by stop_solver! after every iteration: a failed model block ends the run at once (:solve_failed, no other block run); otherwise the method's own criterion is read after post_iteration!, and only then the budget — on the last iteration a method's reason wins over :max_iterations. max_iter ≤ 0 runs no iteration. The result is block_coordinate_result(state, method, prob, θ, reason, iterations) with θ the last model the model block produced (θ₀ if none).

Monotonicity

Instances: EM (under the Neal–Hinton free-energy view EM is coordinate ascent on the free energy, i.e. descent on its negative); IRLS / half-quadratic (RobustVisualGeometry's Irls{K} LO strategy is one — the strategy, not this loop); Barron-adaptive; GNC.

"Descent" is on the negative log-likelihood, and monotonicity is each INSTANCE's claim, not the loop's: the best iterate is kept (a method tracks it in post_iteration! with keep_best and returns it from block_coordinate_result), but the loop never rejects a step. An instance proves monotonicity through its post_iteration! trace. GNC is the declared exception — it changes its objective between iterations.

VisualGeometryCore.lmsolve_rows! — Method
lmsolve_rows!(buffers::FastLevenbergMarquardt.LMWorkspace, solver, lm; stationarity_tol, kw...)
    -> (x, F, converged, iterations)

THE stack's LM run: FastLevenbergMarquardt's in-place lmsolve! minimizing ‖r(x)‖² with r the residual_rows! of the linearization state lm and its Jacobian residual_jacobian_rows!, from buffers.x, with FLM's normal-equation solver (a CholeskySolver, or a caller's FastLevenbergMarquardt.AbstractSolver). stationarity_tol is the stall postcondition's tolerance (_lm_stationary) — required: the caller's configuration owns it. The other keywords are FLM's (maxit, ftol, xtol, gtol, …; FLM's defaults). x IS buffers.x, overwritten by the next run on these buffers; converged is FLM's code, or _LM_STALLED when the postcondition fails (lm_retcode reads either), and iterations its LM iteration count (accepted and rejected steps alike; 0 when the start already meets a tolerance).

THE STALL POSTCONDITION. FLM's step-size stop does not prove convergence: in FLM 0.1.0 its test runs on REJECTED steps too, so a run whose damping grew until no step could reduce the cost (a wrong-sign Jacobian; a NaN wall the minimizer lies behind) stops with code 2 at a non-stationary point, and the upstream fix (FastLevenbergMarquardt.jl issue #4 / PR #5) reports that case as code 4. So when the code is 2 or 4 — and only then, the one extra Jacobian evaluation is paid by those runs alone — stationarity is TESTED at the returned x (_lm_stationary, with FLM's ftol).

VisualGeometryCore.residual_jacobian_rows! — Function
residual_rows!(r, lm, θ) -> r
residual_jacobian_rows!(J, lm, θ) -> J

THE CHART-LM PROTOCOL — one pair for every model: the residual and Jacobian rows FastLevenbergMarquardt minimizes in lmsolve_rows!.

lm is the per-call LINEARIZATION STATE a refit builds once: the anchor the chart is centred on, the whitening frozen there, the data views and the √weights. θ is the CHART vector, not a model. The rows are √w-WEIGHTED and live in chart coordinates — a different currency from a RANSAC problem's UNWEIGHTED residuals!(r, problem, model) in data units. Two names, because one name with two currencies is what the frame-in = frame-out rule exists to prevent.

Ceres analogue: together they are what a CostFunction::Evaluate fills — residual_rows! the residuals buffer, residual_jacobian_rows! the jacobians — with the manifold's retract_jacobian (Ceres' PlusJacobian) already folded into the chart directions. GTSAM's nearest equivalent is a factor's linearize(values), which returns the same rows and Jacobian as a JacobianFactor at the linearization point rather than filling caller buffers.

Both write into caller-owned buffers and return them; neither allocates. Methods live with the models (RobustVisualGeometry's problems).
