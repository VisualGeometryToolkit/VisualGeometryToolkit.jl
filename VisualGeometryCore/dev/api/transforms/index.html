Framed Maps

VisualGeometryCore.CameraExtrinsics — Type
CameraExtrinsics

Frame-pair alias for camera EXTRINSICS (world-to-camera transform): CameraExtrinsics{T, R, V} = EuclideanMap{3, T, R, V, WorldFrame, CameraFrame} (monogram X_CW). The typed counterpart of CameraPose; inv(::CameraExtrinsics) -> CameraPose via the frame swap. Not a wrapper — a CameraExtrinsics IS an EuclideanMap.

CameraExtrinsics(m::EuclideanMap{3}) labels m as extrinsics (an explicit relabel, overriding whatever frames m carried). Camera(model, ::CameraExtrinsics) stores it directly in the extrinsics slot.

source
VisualGeometryCore.CameraPose — Type
CameraPose

Frame-pair alias for a camera POSE (camera-to-world transform): CameraPose{T, R, V} = EuclideanMap{3, T, R, V, CameraFrame, WorldFrame} (monogram X_WC). Not a wrapper — a CameraPose IS an EuclideanMap, so .R/.t, point application, and composition all apply directly.

CameraPose(m::EuclideanMap{3}) labels m as a pose (an explicit relabel, overriding whatever frames m carried).

The typed algebra subsumes the former wrapper machinery: inv(::CameraPose) -> CameraExtrinsics (and back) via the frame swap, and Camera(model, ::CameraPose) inverts internally into the extrinsics slot, so handing a pose where extrinsics are expected is unrepresentable.

See also CameraExtrinsics, lookat_pose, Frame.

VisualGeometryCore.EuclideanMap — Type
EuclideanMap{N,T,R<:Rotation{N,T},V<:StaticVector{N,T},Src<:Frame{N},Dst<:Frame{N}} <: Transformation

Rigid transformation x ↦ R*x + t in N dimensions, combining rotation and translation.

This represents a Euclidean (rigid body) transformation that preserves distances and angles. It consists of a rotation R followed by a translation t.

The trailing Src/Dst parameters are coordinate-Frame tags: the map consumes Src-coordinates and produces Dst-coordinates (Drake monogram: X_AB ≙ Src = B, Dst = A). All constructors that do not state frames produce Src = Dst = UnlabeledFrame{N} — labels are opt-in and never viral. inv swaps the frames; ∘ checks the junction frame between two labeled maps (see the truth table at that method) and throws a MethodError on a labeled mismatch. Use relabel/unlabel as explicit escape hatches.

Fields

  • R::Rotation{N,T}: Rotation component (from Rotations.jl)
  • t::StaticVector{N,T}: Translation vector

Constructors

# From rotation and translation vector
R = RotMatrix{2}(π/4)  # 45° rotation
t = [2.0, 1.0]         # translation
euclidean = EuclideanMap(R, t)

# From MRP (Modified Rodrigues Parameters) for 3D
mrp = MRP(0.1, 0.2, 0.3)
euclidean_3d = EuclideanMap(mrp, [1.0, 2.0, 3.0])

# From tuple
euclidean = EuclideanMap((R, t))

Usage

# Apply transformation to points
point = Point2f(1.0, 0.0)
transformed = euclidean(point)

# Compose transformations
combined = euclidean2 ∘ euclidean1

# Inverse transformation
inverse_euclidean = inv(euclidean)

EuclideanMap(qw, qx, qy, qz, tx, ty, tz) -> EuclideanMap{3,Float64,…}
EuclideanMap(quat::AbstractVector, t::AbstractVector) -> EuclideanMap{3,Float64,…}

COLMAP-style 3D rigid transform from a unit quaternion (qw, qx, qy, qz) and a 3-vector translation (tx, ty, tz). Used by SfM-format readers (ETH3D, IMC PhotoTourism, ScanNet++, custom COLMAP exports) where pose data arrives as raw scalars on a per-line basis.

Rotations.QuatRotation auto-normalizes the quaternion, so callers don't need to pre-normalize — the resulting rotation is always a valid SO(3) element.

# Vector form (typical when receiving npz arrays)

VisualGeometryCore.EuclideanMap — Method
EuclideanMap(R::SMatrix{3,3,T,9}, t::StaticVector{3};
             check=true, project=false) -> EuclideanMap

Construct a rigid-body transform directly from a 3×3 SMatrix (not already a Rotation type). This is the boundary constructor — the entry point at which raw 3×3 numerical data crosses into the typed EuclideanMap. All other constructors take a typed Rotation{N,T} whose invariants are enforced by Rotations.jl.

Validation policy

checkprojectsemanticstypical caller
truefalsestrict — must already be a rotationmath you trust
truetruesnap-to-nearest then verifydataset loaders
falsefalsetrusted — skip everythinginternal algebra
falsetruesnap, no verifyvery dirty inputs

project=true snaps R to the nearest proper rotation via SVD (U·Vᵀ, with a sign flip if the result has determinant −1). Floating-point drift from text-file roundtrip or naive inv(T_B)·T_A composition typically sits at 1e-6-ish, well within the snap-then-verify regime.

Extrinsics3

Concrete LABELED CameraExtrinsics alias: CameraExtrinsics{Float64, RotMatrix{3,Float64,9}, Vec{3,Float64}}, i.e. EuclideanMap{3, Float64, …, Src = WorldFrame, Dst = CameraFrame} (monogram X_CW, applies as x_cam = R·X_world + t).

VisualGeometryCore.constraint_with_jacobians — Method
constraint_with_jacobians(pose::EuclideanMap{3}, X::SVector{3}, ray::SVector{3})
    -> (g::SVector{2}, G_x::SMatrix{2,5}, G_θ::SMatrix{2,6})

Compute the reprojection constraint and its derivatives for a 3D rigid pose.

The constraint is the perspective-projected residual in calibrated coordinates: g = π(R·X + t) − π(ray)

where π is perspective division [x,y,z] → [x/z, y/z] and ray is the backprojected observation (encodes camera calibration).

The model Jacobian G_θ uses the left-perturbation convention with a 6-DOF parameterization δ = (δω₁, δω₂, δω₃, δt₁, δt₂, δt₃): ∂g/∂δ = Jπ · [−[X_cam]× I₃]

where Jπ is the 2×3 perspective division Jacobian and [v]× is the skew-symmetric (cross-product) matrix of v.

Returns:

  • g::SVector{2,T} — reprojection residual (calibrated coordinates)
  • G_x::SMatrix{2,5,T} — ∂g/∂(X, ray₁, ray₂) measurement Jacobian
  • G_θ::SMatrix{2,6,T} — ∂g/∂(δω, δt) pose perturbation Jacobian
PINHOLE ONLY — this residual lives in the gnomonic chart

π divides by the third component, so this is the z = 1 chart (GnomonicFrame) and it exists only on the forward hemisphere. It is degenerate at 90° from the optical axis and cannot represent a ray with Z ≤ 0 at all. That is correct for a PINHOLE camera and wrong for a fisheye or omnidirectional one, whose rays routinely go past 90°.

It is legitimate where it is used — RobustVisualGeometry's Pinhole PnP LM — and must not become the general path. The camera-general route is the ray-domain pixel residual (constraint_with_jacobians(model, pose, X, u) in cameras/camera_models.jl), which projects through the camera's own lens and therefore never assumes the chart exists. Calibrated two-view geometry takes the same view: it acts on unit bearings (unit rays, StaticVector{3}), never on this chart.

VisualGeometryCore.relabel — Method
relabel(Src::Type{<:Frame{N}}, Dst::Type{<:Frame{N}}, m::EuclideanMap{N}) -> EuclideanMap

Return m with its frame tags replaced by Src/Dst (map consumes Src-coordinates, produces Dst-coordinates). Zero-cost: the rotation and translation are reused bit-for-bit; only the type changes.

This is a DELIBERATE escape hatch: it overrides whatever frames m carried, with no check. Use it at trust boundaries (dataset loaders, solver outputs) where the caller — not the type system — knows the frames. Attaching a frame of the wrong dimension (e.g. a Frame{2} to an N = 3 map) is a type error (MethodError).

See also unlabel, Frame.

VisualGeometryCore.skew — Method
skew(v::AbstractVector) -> SMatrix{3,3,Float64,9}

Skew-symmetric (cross-product) matrix [v]_× such that [v]_× w = v × w for all w ∈ R³. Used in essential-matrix construction E = [t]_× R and in pose-perturbation Jacobians (see constraint_with_jacobians).

GTSAM spells this skewSymmetric; Sophus spells it SO3::hat (with vee for the inverse).

Errors if length(v) != 3.

Example

t = SVector{3,Float64}(1.0, 2.0, 3.0)
S = skew(t)        # 3×3 SMatrix
S * SVector(0.0, 1.0, 0.0) ≈ cross(t, SVector(0.0, 1.0, 0.0))   # true

VisualGeometryCore.HomographyMap — Type
HomographyMap{N,T,M<:StaticMatrix{N,N,T},Src<:Frame,Dst<:Frame} <: Transformation

Projective transformation with cached inverse for efficient covariant (points) and contravariant (lines, conics) transformations.

Sub-projective transforms (Translation, LinearMap, AffineMap) can act directly on Circle, Ellipse, and Line2D via ct_contravariant.jl. Use HomographyMap when you need a full projective (HomographyMat) wrapper.

Type Parameters

  • N: Matrix dimension (3 for 2D projective, 4 for 3D projective)
  • T: Element type
  • M: Matrix type (HomRotationMat, HomAffineMat, HomographyMat, etc.)
  • Src/Dst: coordinate-Frame tags of the point FRAMES the map connects — Frame{N-1}, since the N×N matrix acts on (N-1)-dimensional frames (a 3×3 homography is 2D↔2D projective: Frame{2} on both sides). Same design as EuclideanMap: the map consumes Src-frame coordinates and produces Dst-frame coordinates (Drake monogram H_AB ≙ Src = B, Dst = A), every frame-free constructor defaults both tags to UnlabeledFrame{N-1}, inv swaps the tags, and ∘ checks a labeled junction (identical wildcard truth table — see Base.:∘ below).

HomographyMat and the rest of the AbstractHomMat hierarchy stay frame-FREE algebra; frames are declared at the Mat → Map lift:

H = HomographyMap{TargetPlaneFrame, PixelFrame{:colmap}}(H_mat)   # labeled lift
H = HomographyMap(H_mat)                                    # unlabeled lift

relabel/unlabel are the same explicit escape hatches as for EuclideanMap.

Transformation Rules (Hartley & Zisserman conventions)

  • Points (covariant): p' = H·p
  • Lines (contravariant): l' = H^{-T}·l
  • Conics (contravariant): Q' = H^{-T}·Q·H^{-1}

Dimension Convention

  • N×N matrix operates on (N-1)-dimensional Euclidean space
  • Point{N-1} → Euclidean input, lifted via to_affine
  • Point{N} → Homogeneous input, used directly

Examples

# Create from any homogeneous matrix type
h = HomographyMap(HomographyMat(camera))
h = HomographyMap(HomRotationMat(RotMatrix{2}(θ)))
h = HomographyMap(HomAffineMat(...))

# Transform points (Euclidean → homogeneous output)
p′ = h(Point2(100, 200))  # → Point3 (homogeneous)

# Transform points (homogeneous → homogeneous output)
p′ = h(Point3(100, 200, 1))  # → Point3

# Transform conics: the result type follows the matrix class
h(circle)   # Circle under a similarity, HomEllipseMat under an affinity, Conic otherwise
h(ellipse)  # HomEllipseMat under an affinity (similarities included), Conic otherwise

# Transform lines
l′ = h(Line2D(1.0, -1.0, 0.0))  # → Line2D

# Composition
h_composed = h1 ∘ h2

# Inverse is O(1) - just swaps stored matrices
h_inv = inv(h)

VisualGeometryCore.HomographyMap — Method
(h::HomographyMap{3})(c::Circle) -> Circle, HomEllipseMat or Conic

Transform a circle through a homography map.

Returns:

  • a Circle for similarity-preserving transforms (rotation, translation, isotropic scale)
  • HomEllipseMat for other affine transforms (an affine image of a circle is an ellipse)
  • Conic for a general projective transform

A returned conic matrix could be:

  • An ellipse (most common for camera projections of visible circles)
  • A hyperbola (circle partially behind camera)
  • A parabola (circle tangent to plane at infinity)
  • A degenerate conic (point or lines)

Use classify_conic() to determine the conic type, then construct the appropriate geometric primitive:

H = HomographyMap(HomographyMat(camera))
circle = Circle(Point2(100.0, 100.0), 50.0)
Q′ = H(circle)  # a Conic under a camera homography

trait = classify_conic(Q′)
if trait isa EllipseTrait
    ellipse = Ellipse(Q′)  # Construct geometric primitive
elseif trait isa HyperbolaTrait
    # Handle hyperbola case
end

Example: Filter to valid ellipses

H = HomographyMap(HomographyMat(camera))
conic_matrices = H.(circles)
ellipses = [Ellipse(Q) for Q in conic_matrices if classify_conic(Q) isa EllipseTrait]

VisualGeometryCore.transfer_ellipse — Method
transfer_ellipse(T::Transformation, shape::Union{Circle, Ellipse}) -> Ellipse | nothing

The ellipse-PRESERVING transfer of a circle/ellipse through any 2-D map of the warping paradigm. A homography carries the conic exactly (the method above); every other map is replaced by its local affinity at the shape's centre — c′ = T(c), Σ′ = J·Σ·Jᵀ with J = transform_deriv(T, c) — the same linearisation a detection's shape gets when it is carried across an undistortion. A ComposedTransformation transfers stage by stage, so the exact stages stay exact and only the non-projective ones linearise: for a lens camera, distortion_map(model) ∘ HomographyMap(pinhole camera) pushes the conic through the plane homography exactly and applies the lens's affinity at the transferred centre (see transfer_ellipse(::Camera, _)). nothing where the map is not defined or not finite at the centre (a lens fold, the line at infinity).

VisualGeometryCore.WhiteningPolicy — Type
WhiteningPolicy

How an algebraic constraint g(θ, x) = 0 with derivatives (g, G_x, G_θ) from constraint_with_jacobians becomes the residual/Jacobian rows a least squares sees — the estimator's residual CURRENCY. Orthogonal to the robust AbstractWeightPolicy (which weights rows by their size); the two compose: whiten first (currency), weight second (robustness). One verb, whitened_rows, for every estimator in the family — the Sampson error of F/E, the whitened transfer error of H, the point–radial-line distance of the radial camera, the pixel currency of the division lift.

  • NoWhitening — the algebraic rows as they are.
  • SampsonWhitening — Cholesky-whiten by the propagated unit isotropic measurement noise G_x·G_xᵀ: first-order geometric error.

VisualGeometryCore.constraint_rounding_scale — Method
constraint_rounding_scale(M, u₁, u₂) -> NamedTuple{(:gradient, :value)} | nothing

The rounding scales of the constraint g(M; u₁, u₂) at a correspondence — the one input the Sampson degeneracy rule needs beyond (g, G_x): gradient, below which the measurement gradient ‖G_x‖ is rounding (DEGENERATE), and value, below which |gᵢ| is rounding (the constraint VANISHES; a scalar, or one per component). Relative to the model's and the points' own magnitudes, so a model's homogeneous scale never decides. whiten consumes it; the default, nothing, makes only an exactly zero gradient degenerate and an exactly zero g vanishing. The epipolar models return epipolar_rounding's scales, a homography its rows' term-by-term bound.

source
VisualGeometryCore.propagate — Method
propagate(J, Σ)

Propagate covariance Σ through the linear map with Jacobian J:

propagate(J, Σ) = J * Σ * Jᵀ

Specializations:

  • Σ = I (UniformScaling{Bool}): returns J * Jᵀ
  • Σ = λI (UniformScaling): returns λ * (J * Jᵀ)
  • Σ = diag(...) (Diagonal): returns J * Σ * Jᵀ via column scaling
  • General matrix: full sandwich product J * Σ * Jᵀ
  • Static J with a dense Σ (Matrix, Symmetric, Diagonal{Vector}): Σ is converted once to its static size, so the result is static like J

One of three covariance verbs: propagate goes THROUGH A MAP (its Jacobian, or a framed map carrying its frames), transform_covariance BETWEEN CHARTS of one model, implicit_covariance of an ESTIMATE.

GTSAM equivalent: a function's OptionalJacobian H, with the caller forming H·Σ·Hᵀ.

VisualGeometryCore.whiten — Method
whiten(g::T, G_x::SVector{nx}, G_θ::SVector{nθ}, Σ_x = I, ρ = nothing)
    -> (r::T, J_w::SVector{nθ}, ℓ::T)

Scalar whitening for d_g = 1 constraints.

Returns (g/√c, G_θ/√c, log(c)) where c = G_xᵀ Σ_x G_x. When the gradient is degenerate — c is not positive, or ‖G_x‖ is below the rounding scale ρ (constraint_rounding_scale) — the one Sampson degeneracy rule applies, as in the vector method: residual 0 when g vanishes (at ρ; exactly without one), ±Inf otherwise, zero Jacobian, ℓ = 0. Without ρ a sum of squares has no cancellation to measure, so only an exactly vanishing gradient is degenerate: a small c is a legitimately small (e.g. rescaled) model, whose whitened residual is scale-free. NaN propagates. Generic in the element type (T <: Real), so ForwardDiff duals flow through a scalar constraint's rows.

VisualGeometryCore.whiten — Method
whiten(g::SVector{dg}, G_x::SMatrix{dg,nx}, G_θ::SMatrix{dg,nθ}, Σ_x = I, ρ = nothing)
    -> (r::SVector{dg}, J_w::SMatrix{dg,nθ}, ℓ::T)

Cholesky-whiten a vector constraint (d_g ≥ 2).

Returns (L⁻¹g, L⁻¹G_θ, log|Σ_g|) where LLᵀ = Σ_g = propagate(G_x, Σ_x). A degenerate Σ_g (Cholesky fails, or it loses rank to rounding relative to its diagonal) follows the one Sampson degeneracy rule: the residual is 0 when g vanishes and ±Inf otherwise (no nearby measurement satisfies the constraint), the Jacobian rows are zero and ℓ is 0. "Vanishes" is at the rounding scale ρ (constraint_rounding_scale), exactly zero without one. A scorer reads it as an outlier; a fit that takes it as an inlier fails loudly on the non-finite row.

VisualGeometryCore.propagate — Method
propagate(m::EuclideanMap{N}, Σ::CovMat{N})  -> CovMat{N, ..., Dst}
propagate(m::EuclideanMap{N}, Λ::PrecMat{N}) -> PrecMat{N, ..., Dst}

Checked, frame-labeled propagation of a statistical form through a framed rigid map. The map's action on points is affine with constant Jacobian J = R, so no evaluation point is needed. The form's frame must meet the map's Src under the standing wildcard truth table (a labeled mismatch is a MethodError; UnlabeledFrame on either side is unchecked), and the result carries the map's Dst as-is.

The law dispatches on the REPRESENTATION — this is the point of the types:

  • covariance, a (2,0) tensor, pushes forward: Σ ↦ J Σ Jᵀ
  • precision, a (0,2) bilinear form, pulls back: Λ ↦ J⁻ᵀ Λ J⁻¹

(For a rigid map the two conjugations coincide numerically because R is orthogonal; the code follows the honest law per type so the invariant propagate(m, inv(Σ)) == inv(propagate(m, Σ)) holds by construction, not by coincidence.)

The raw-Jacobian layer propagate(J, Σ) is unchanged and unlabeled — use it when no framed map is in hand.

propagate(h::HomographyMap{3}, u::Uncertain{<:StaticVector{2}}) -> Uncertain

Transport an uncertain 2D point through a framed collineation. The projective point action x ↦ π(H·x̃) is nonlinear, so the Jacobian is evaluated at the point — which is why the HomographyMap overloads take the measurement (Uncertain), not a bare statistical form. Frame checking and labeling follow the framed-map contract (frame meets Src under the wildcard truth table; result carries Dst), and the law dispatches on the representation: covariance pushes forward Σ ↦ JΣJᵀ, precision pulls back Λ ↦ J⁻ᵀΛJ⁻¹ with the 2×2 point Jacobian J.

Measurement Noise

A plain point is unit isotropic noise, an Uncertain point carries its covariance, an exact point has none (the Conventions page, "Measurement noise").

VisualGeometryCore.exact — Method
exact(p::StaticVector) -> Uncertain

The measurement p known EXACTLY: p with a ZERO covariance, the third case of the measurement-noise rule (a plain point is unit isotropic noise, an Uncertain carries its own covariance). For data with no measurement error in its frame — a calibration board's points in metres, a world point. Board → image correspondences built as exact.(board) .=> pixels score the transfer error in the image's pixels, whatever the board's units.

A correspondence needs one noisy endpoint: an estimator refuses a correspondence whose two endpoints are both exact (nothing to whiten).

The zero covariance is an ordinary CovMat — no second representation. It is read once, where an estimator's constructor turns endpoints into its covariance columns (noise_columns); the per-point matrices cost 4 numbers each at that boundary and nothing in the inner loop, where the columns are what is read.

VisualGeometryCore.noise_columns — Method
noise_columns(sources, targets) -> NamedTuple

The covariance columns of a correspondence set whose endpoints may be Uncertain (or exact): (; Σ₁, Σ₂), each a vector of static 2×2 covariances in the endpoints' own frame, with a side whose endpoints are all plain LEFT OUT (an absent column is unit isotropic noise) — so a plain set gives (;) and its estimator runs exactly as without. VisualGeometryCore.exp_so3 — Method
exp_so3(ω::SVector{3,T}) -> SMatrix{3,3,T,9}

Rodrigues exponential map so(3) → SO(3): R = I + a·[ω]× + b·[ω]×² with the second-order Taylor branch below the per-type small-angle threshold.

Plain SMatrix arithmetic — safe inside Zygote-tracked code (unlike RotMatrix(RotationVec(ω...)), which reverse-mode AD cannot penetrate) and generic over Real, so ForwardDiff Duals flow through it too. See also skew, left_jacobian, exp_se3.

GTSAM spells this Rot3::Expmap (and log_so3 is Rot3::Logmap), Sophus SO3::exp / SO3::log. Manifolds.jl's name is exp_lie(G, X) / log_lie: its exp(M, p, X) is the exponential at a BASE POINT, while this is the Lie-group exponential at the identity — which is why the group is not a first argument here.

source
VisualGeometryCore.left_jacobian — Method
left_jacobian(SO3, ω::SVector{3,T}) -> SMatrix{3,3,T,9}

Left Jacobian of SO(3): J = I + a·[ω]× + b·[ω]×² with a = (1−cosθ)/θ², b = (θ−sinθ)/θ³, Taylor branch near zero. Maps a rotation-vector perturbation to the translation part of the SE(3) exponential: t = J(ω)·ρ. Not provided by Rotations.jl.

This is Sophus' SO3::leftJacobian. GTSAM's Rot3::ExpmapDerivative is its TRANSPOSE, the RIGHT Jacobian Jr(ω) = Jl(ω)ᵀ = Jl(−ω), because GTSAM retracts by right multiplication — do not equate the two. Measured here (2026-09-22): the left perturbation identity exp(ω+δ) = exp(Jl(ω)·δ)·exp(ω) holds to 5.8e-13 while the right-multiplied one is off by 1.8e-6, and Jl(ω) = Jl(−ω)ᵀ to 0.0.

VisualGeometryCore.log_so3 — Method
log_so3(R::StaticMatrix{3,3,T}) -> SVector{3,T}

Rotation vector (axis · angle, angle ∈ [0, π]) of R — the SO(3) logarithm: the unit quaternion (w, v) of R by Shepperd's method (the largest of w, x, y, z computed from the diagonal, so every branch, the near-π one included, divides by a number ≥ ½), sign fixed to w ≥ 0, then 2·atan(‖v‖, w)·v/‖v‖ — with its Taylor series (2/w)(1 − ‖v‖²/(3w²))·v below the per-type small-angle threshold, so the derivative at the identity is exact. Generic over Real: ForwardDiff Duals flow through (within 2.5 ulp of Rotations' RotationVec, measured 2026-09-22).

VisualGeometryCore.kabsch — Method
kabsch(cs) -> RotMatrix{3, T}

Kabsch/Wahba: the rotation minimizing Σᵢ ‖bᵢ − R·aᵢ‖² over the vector pairs cs (aᵢ => bᵢ, StaticVector{3} each side; any sources/targets container, a Csponds preferred): one closed-form step, Rotations.nearest_rotation of the cross-covariance Σ bᵢaᵢᵀ (an SVD with the determinant-sign correction). VisualGeometryCore.mirror — Method
mirror(pose, plane_point; normal = SVector(0., 0., 1.)) -> EuclideanMap

The second branch of the planar two-fold pose ambiguity: for a PLANAR target (world-plane normal normal, any point plane_point on it — conventionally the target center), the pose whose plane normal is reflected about the viewing ray to plane_point. Under weak perspective this mirror pose predicts image positions that agree with pose to second order, so the two tie on reprojection consensus; the rotation between them is twice the viewing tilt. Total: at a frontal view the reflection is (numerically) the identity and the returned pose coincides with pose — gate on rotation_angle(RotMatrix{3}(mirror.R' * pose.R)) if the degenerate case must be skipped.

Translation is carried over unchanged (same center ray and apparent size ⇒ same depth to first order); the result is a first-order INIT for the second basin, to be refined before any comparison.
