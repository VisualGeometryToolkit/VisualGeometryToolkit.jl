Warping API

VisualGeometryCore.EuclideanMap — Method
EuclideanMap(::Type{PixelFrame{From}}, ::Type{PixelFrame{To}}) -> EuclideanMap{2}

Origin-convention conversion between two pixel frames, as a LABELED rigid map: identity rotation, constant translation, Src = PixelFrame{From}, Dst = PixelFrame{To} (monogram X_{To,From}). Registered origins: :opencv, :colmap, :julia — see the table in the PixelFrame docstring. This constructor-as-factory on the frame TYPES is the only origin-conversion API (the 0.6-era ImageOrigin value surface is removed in 0.7).

The returned map is UNITLESS (Vec2{Float64} translation): origin conversion is a compute-side operation and compute runs on stripped values (units are enforced at construction and stripped at the region gate). Apply it to plain-Float64 points; strip united data first (ustrip.(px, ...)).

For identical frames the translation is zero (≡ identity). inv swaps the frames; composition against other labeled 2D maps is frame-checked, and the map fuses in image_warp chains like any EuclideanMap{2}.

Examples

T = EuclideanMap(PixelFrame{:colmap}, PixelFrame{:julia})
T.t == Vec2(0.5, 0.5)              # true
pt_julia = T(pt_colmap)            # pt_colmap unitless

inv(T) isa EuclideanMap{2, <:Any, <:Any, <:Any, PixelFrame{:julia}, PixelFrame{:colmap}}

VisualGeometryCore.logpolar_map — Method
logpolar_map(geometry::Union{Circle, Ellipse}, logpolar_rect::HyperRectangle{2}, inner_radius::Real) -> Function

Create a composed transformation that maps from log-polar patch coordinates to image coordinates via a circle or ellipse.

This is a convenience function that composes three transformations:

  1. logpolar_rect → CANONICAL_SQUARE (normalize patch coordinates)
  2. CANONICAL_SQUARE → UNIT_CIRCLE via log-polar transform
  3. UNIT_CIRCLE → geometry (map to target circle/ellipse in image)

The resulting transformation can be used with warp to extract log-polar patches.

Arguments

  • geometry::Union{Circle, Ellipse}: Target geometry in image coordinates
  • logpolar_rect::HyperRectangle{2}: Rectangle defining the log-polar patch domain
  • inner_radius::Real: Minimum radius for log-polar transform (avoids singularity at origin)

Returns

  • Function: Composed transformation logpolar_rect → geometry

Broadcasting

This function is designed to be broadcastable across multiple geometries:

# Extract patches from multiple circles
transforms = logpolar_map.(circles, Ref(logpolar_rect), Ref(inner_radius))

Example

using VisualGeometryCore
using GeometryBasics: Circle, Point2

# Define target circle and log-polar patch size
circle = Circle(Point2(100.0, 200.0), 50.0)
ix, iy = 1:512, 1:256  # x-axis (scale), y-axis (rotation)
logpolar_rect = Rect((ix..., iy...))
inner_radius = 0.01

# Create transformation and resample through the fused warp
transform = logpolar_map(circle, logpolar_rect, inner_radius)
bm = image_warp(transform, Rect(0, 0, 512, 256))
patch = Matrix{Float32}(undef, 256, 512)
image_warp!(patch, bm, image; fillvalue=0.5f0)

See Also

  • AffineMap: canonical → primitive coordinate mapping (constructor)
  • logpolar_to_cartesian: Log-polar to Cartesian transformation

VisualGeometryCore.logpolar_to_cartesian — Function
logpolar_to_cartesian(inner_radius=0.01) -> LogPolarToCartesian

Construct a LogPolarToCartesian transformation. Maps points in unit space [-1,1]² interpreted as (log_r, θ) to Cartesian (x, y) in the unit circle.

Coordinate Convention

  • x-axis (horizontal/columns) = scale (radius)
  • y-axis (vertical/rows) = rotation (angle)

Mapping

  • Input x-coordinate in [-1,1] → radius from inner_radius to 1.0 (logarithmically)
  • Input y-coordinate in [-1,1] → angle from 0 to 2π
  • Output: Cartesian (x, y) in unit circle (radius ≤ 1.0)

Arguments

  • inner_radius::Real: Minimum radius (default: 0.01, avoids singularity at origin)

Example

transform = logpolar_to_cartesian()
transform(Point2(0.0, 0.0))   # mid-radius, π angle
transform(Point2(-1.0, -1.0)) # min radius, 0
transform(Point2(1.0, 1.0))   # max radius (1.0), 2π

Image Warping

VisualGeometryCore.FramedImage — Type
FramedImage(data, rect)

A resampled canvas TOGETHER with its placement: rect is the window of the source pixel frame (COLMAP convention — origin at the window's top-left corner, widths its footprint) that data covers; the sampling density is widths(rect) ./ size(data) (reversed: array is row-major). Named rect — not extent — deliberately: VGC's extent(camera) is a SIZE (Size2{Int}), while this is a POSITIONED window. This is the warp layer's currency at the return boundary — a bare matrix loses exactly the information every consumer then has to carry by hand (the ext + σ pair the rect form of undistort used to drop), and misplacing a rectified image by its offset or scale is the half-pixel bug class the frame conventions exist to kill.

imshow(pos, ci::FramedImage) (Makie extension) is self-placing: it draws data over rect, so a rectified view lands in the same axes as the raw frame — principal point, footprint and all — with nothing supplied alongside.

Produced by the rect form of undistort; construct directly for any canvas rendered over a known window of a pixel frame.

source
VisualGeometryCore.bilinear_sample_clamped — Method
bilinear_sample_clamped(::Type{Ta}, img, yf, xf, H::Int32, W::Int32) -> (in_bounds::Bool, value::Ta)

Bilinear sample of img at the 1-based array position (yf, xf) with the OTHER boundary policy from _bilinear_sample's fill: a position whose floor cell lies outside 1:H × 1:W is rejected ((false, 0)), and the +1 neighbour is clamped to the last row/column, so the border pixel is sampled exactly rather than blended with a fill value. Exact (no interpolation error) at integer positions, which is what keeps an integer-step scan bit-identical to a pixel loop. Device-safe (Int32 indices, no allocation); hoisted verbatim from BlobBoards' adaptation kernels (2026-09).

source
VisualGeometryCore.fuse — Method
fuse(t) -> Transformation

Flatten every run of matrix-representable links in a composition chain into a single link. Translation/LinearMap/AffineMap/EuclideanMap/RCSwap runs merge into one AffineMap; runs containing a HomographyMap merge into one HomographyMap; an affine link immediately left of a PerspectiveMap is pulled through the division into the homography. Nonlinear links (log-polar, lens models, …) are preserved in place. Semantically a no-op; structurally the difference between five closure calls per pixel and one matrix multiply.

fuse(bm::BoundedMap) fuses the wrapped map and keeps the rect.

source
VisualGeometryCore.image_warp! — Method
image_warp!(dst, bm::BoundedMap, src; fillvalue=0) -> dst

Resample src into dst through the warp bm (built by image_warp): for each (row, col) of dst, bilinearly sample src at bm((row, col)). Runs the shared KernelAbstractions kernel on the backend that owns dst — supply CuArrays for GPU execution (the warp math evaluates on-device; bm is isbits).

dst and src may differ in eltype: samples accumulate in float and store back through the destination eltype (UInt8 rounds saturating, colorants clamp to [0, 1]). fillvalue is the out-of-bounds tap value, in the float accumulation domain.

source
VisualGeometryCore.image_warp — Method
image_warp([T=Float64], math, n::Integer) -> BoundedMap

Convenience overload for a square n × n output array. Equivalent to image_warp(T, math, Rect(0, 0, n, n)). Typically paired with the size-form math builders (canonical_map(geom, n; …), logpolar_map(geom, n, r; …)) for the common case where the patch domain and output array share n.

source
VisualGeometryCore.image_warp — Method
image_warp([T=Float64], math, output_rect::Rect{2}) -> BoundedMap

Wrap a math-space Transformation into a fused BoundedMap callable from Julia array indices. Composes (left-to-right when reading a call sequence):

_RC_SWAP ∘ _OUT_BRIDGE ∘ math ∘ _IN_BRIDGE ∘ _RC_SWAP

then flattens the chain with fuse. Perspective division is injected automatically when math is projective (is_projective) and doesn't already divide.

The output BoundedMap consumes (row, col) indices into the OUTPUT array and returns (sr, sc) indices into the SOURCE array — both Julia 1-indexed. The internal bridge pair — the typed frame maps EuclideanMap(PixelFrame{:julia}, PixelFrame{:colmap}) and its reverse — converts to/from VGC's package-wide COLMAP math convention.

Arguments

  • T — optional leading element type of the fused warp math (the standard rand(Float32, …)-style convention). image_warp(Float32, …) keeps the per-pixel math single-precision on GPU backends.
  • math — any CoordinateTransformations.Transformation. Assumed COLMAP-math.
  • output_rect::Rect{2} — the output region in array coords (e.g., Rect(0, 0, width, height)).

Example

math = canonical_map(ellipse, 64; bound=1.0)
bm   = image_warp(math, 64)
patch = Matrix{Float32}(undef, 64, 64)
image_warp!(patch, bm, img_f32; fillvalue=0.5f0)
source
VisualGeometryCore.image_warp_batch_to! — Method
image_warp_batch_to!(out, warps, src; fillvalue=0) -> out

Sample src once per output pixel of every warp in warps, writing into the pre-allocated 3D stack out::AbstractArray{T, 3} of shape (P_r, P_c, N) where N = length(warps). Each warps[k] is a BoundedMap produced by image_warp. Same kernel and backend dispatch as image_warp! — supply CuArrays (including the warp vector) for GPU execution.

Example (CPU)

warps = [image_warp(canonical_map(d, 64; bound=1.0), 64) for d in discs]
out   = Array{Float32}(undef, 64, 64, length(warps))
image_warp_batch_to!(out, warps, src; fillvalue=Float32(0.5))

Example (GPU)

d_warps = CuArray(warps)
d_src   = CuArray(src_f32)
d_out   = CUDA.zeros(Float32, 64, 64, length(warps))
image_warp_batch_to!(d_out, d_warps, d_src; fillvalue=0.5f0)

VisualGeometryCore.is_projective — Method
is_projective(t) -> Bool

true when t contains a projective stage (a HomographyMap) anywhere in its composition tree — i.e. its output is only defined up to scale unless a perspective division is applied somewhere downstream. Recurses through BOTH sides of Base.ComposedFunction and CT.ComposedTransformation (the predecessor needs_perspective_division only checked the inner side, and missed CT-typed compositions entirely).

source
VisualGeometryCore.BoundedMap — Type
BoundedMap{M<:CT.Transformation, R<:Rect{2,Int}} <: CT.Transformation

Decorator that pairs a CT.Transformation with an output Rect{2,Int}. The rect is the codomain extent — typically the destination region of a warp or the valid pixel area of a homography.

Fields

  • map::M — the inner transform (the math)
  • rect::R — the output region (decoration)

Trait

bounds_trait(::BoundedMap) = HasBounds(). extent(bm) returns bm.rect.

Example

H  = HomographyMap(K * [r1 r2 t])
bm = BoundedMap(H, Rect(0, 0, 1920, 1080))
extent(bm)               # Rect(0, 0, 1920, 1080)
to_homogeneous(bm) === H.forward   # forwards through
