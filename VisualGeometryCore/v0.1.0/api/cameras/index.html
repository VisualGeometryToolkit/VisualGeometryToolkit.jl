The generic (grid) camera models are on the Generic Camera Models API page; calibration (the radial camera, intrinsics from homographies, view-angle limits) is on the Calibration API page; lens models and the lens contract with its batched surfaces are on the Lenses API page; the framed imaging chain, ray maps, and stereo rigs are on the Imaging Chain and Stereo API page. Cameras and Camera Models

VisualGeometryCore.Cameras — Module
Cameras

Camera system submodule for VisualGeometryCore.

Provides complete camera modeling including:

  • Sensors: Physical CMOS sensor specifications
  • Intrinsics: Calibration matrices and intrinsic parameters (physical/logical)
  • Lens Models: forward lenses (Lens: a projection + a distortion in its frame) and lifts (LiftLens)
  • Camera Models: Composable camera models (intrinsics + lens)
  • Cameras: Complete cameras in 3D space (model + pose)
  • Stereo: Stereo camera rigs and epipolar geometry
  • Utilities: Helper functions (focal_length, lookat, P3P solvers)

Main Types

  • Camera, PinholeCamera
  • CameraModel
  • LogicalIntrinsics
  • Lens, LiftLens, Pinhole, KannalaBrandt, Division
  • Sensor, CMOS_SENSORS
  • StereoRig

Main Functions

  • project, backproject, unproject
  • focal_length, lookat, pose
  • p3p, sample_p3p
  • default_frustum_depth

Example

using VisualGeometryCore
using VisualGeometryCore.Cameras

s = sensor("Sony", "IMX174")
f = focal_length_for_fov(s, deg2rad(40.0))
model = CameraModel(f, s.pitch, centroid(Rect(s)) .* px)
camera = Camera(model, lookat(...))

VisualGeometryCore.Cameras.BoundedCamera — Type
BoundedCamera{C<:AbstractCamera} <: AbstractCamera

A wrapper around any AbstractCamera that adds pixel-space image bounds (width × height) without disturbing the underlying camera's intrinsics or units. Used by SfM/MVS dataset readers (ETH3D, ScanNet, COLMAP exports) where the camera is described by its calibration plus an explicit image extent — information the bare Camera type doesn't retain.

The wrapped camera may be UNPOSED — a bare AbstractCameraModel — which is COLMAP's "camera" row (intrinsics, lens and image size, no pose) and the element of a stored camera collection (VisualGeometryIo's cameras kind). BoundedCamera(Camera(model(bc), pose), bc.extent) is its posed counterpart; the pose accessors of an unposed one are a MethodError.

Field access

  • bc.camera, bc.extent — direct fields.

Method delegation (via MacroTools.@forward)

The standard Camera accessors (intrinsics, lens, pose, extrinsics, focal_length, model, calibration_matrix) and the projection verbs are forwarded to the wrapped camera, so intrinsics(bc) === intrinsics(bc.camera) etc.; is_in_front(bc, p) too.

Trait

bounds_trait(::BoundedCamera) = HasBounds() — methods that need image extent dispatch on BoundsTrait. See extent(::BoundedCamera) = bc.extent.

Example

inner = Camera(CameraModel(K; lens=Pinhole()), pose)
bc    = BoundedCamera(inner, Size2(6048, 4032))
intrinsics(bc)     # forwarded → CameraCalibrationMat
bc.extent          # Size2(6048, 4032) — direct field
extent(bc)         # same, via trait-dispatched accessor

VisualGeometryCore.Cameras.Camera — Type
Camera{M, Rt} <: AbstractCamera

A camera in 3D space, consisting of a camera model (intrinsics + lens) and extrinsics (pose).

Dispatch on the lens through the model parameter: Camera{<:CameraModel{<:Any, <:MyLens}} (the PinholeCamera alias is that form for Pinhole).

Use project(camera, X) to map a 3D world point to 2D pixel coordinates, and backproject(camera, u) / unproject(camera, u, depth) for the inverse directions. The transform is computed on demand and inlined.

Type parameters

  • M <: AbstractCameraModel: camera model type (CameraModel, or a grid model)
  • Rt <: EuclideanMap: extrinsics type

Fields

  • model::M: Camera model (intrinsics + lens)
  • extrinsics::Rt: Camera extrinsics (world-to-camera transform)

Examples

# Create camera with logical intrinsics
model = CameraModel(800.0px, [320.0px, 240.0px])
extrinsics = EuclideanMap(RotMatrix(I), [0.0, 0.0, 0.0])
camera = Camera(model, extrinsics)

# Dispatch on lens (via the model parameter; PinholeCamera is the
# ready-made alias for the Pinhole case)
foo(::PinholeCamera) = "pinhole path"
foo(::Camera{<:CameraModel{<:AbstractIntrinsics, <:KannalaBrandt}}) = "fisheye path"

# Project a world point
X_world = SVector(1.0mm, 2.0mm, 10.0mm)
u = project(camera, X_world)

VisualGeometryCore.Cameras.Camera — Method
Camera(model::CameraModel, e::CameraExtrinsics) -> Camera
Camera(model::CameraModel, p::CameraPose) -> Camera

Construct a Camera from a frame-labeled map, so the caller states which frame it holds instead of relying on the positional convention.

The bare positional constructor Camera(model, extrinsics::EuclideanMap) with an UNLABELED map takes the world-to-camera map (documented convention, unchecked); a caller holding a camera-to-world map (a lookat-style pose, a renderer's sensor.to_world) who supplies it positionally stores the WRONG map without any error — every accessor then silently answers for the inverse camera. With frame labels that mistake is unrepresentable: CameraExtrinsics (being the extrinsics-labeled EuclideanMap) stores directly into the extrinsics slot via the default constructor, CameraPose inverts internally, and pose(Camera(model, P::CameraPose)) ≈ P.

VisualGeometryCore.Cameras.DEFAULT_MAX_FOV — Constant
DEFAULT_MAX_FOV

Recommended half-angle cap for flattening a view onto a perspective plane, as the max_fov of undistorted_rect. 70° gives tan θ ≈ 2.75, so the rectified plane stays a small multiple of the frame; past ~80° (tan 5.7) it grows faster than the detail it reveals, and the last degree before 90° is unbounded.

VisualGeometryCore.Cameras.CameraModel — Method
CameraModel(model::CameraModel, K′::CameraCalibrationMat) -> CameraModel

The same camera with intrinsics K′: the lens re-expressed under the new intrinsics matrix sharing the principal point, so the pixel map is unchanged: normalized′ = normalized / s with s = f′/f, so a scale-covariant radial lens transforms its coefficients by the law aᵢ → aᵢ·s^(2i), bⱼ → bⱼ·s^(2j) (the generalized k′ = k·s²). Throws for a moved principal point (the lens center is data, not a frame choice), for anisotropic rescaling of a radial lens (radial symmetry would be broken), and for families whose coefficients are only meaningful under a metric K.

VisualGeometryCore.Cameras.backproject_with_jacobian — Method
backproject_with_jacobian(model::CameraModel, u::StaticVector{2}) -> (f, M)

The unit bearing of pixel u and its 3×2 Jacobian M = ∂f/∂u, in ONE evaluation. f is what backproject returns; M is what propagates a PIXEL covariance onto the sphere, so the pair is the entry point for calibrated two-view geometry on bearings (the tangent Sampson residual and its rows).

M is TANGENT by construction: fᵀM = 0 to rounding, because it is built in a tangent basis rather than by differentiating a normalization. Consumers therefore need no explicit projection onto the tangent plane — which is what keeps an inner loop free of the allocation such a projection would cost.

The tangency assertion is LOAD-BEARING — do not simplify it away

fᵀM = 0 is not decorative, and it is not merely an internal consistency check. It is the ONLY test in the suite that catches a correspondence whose two views' Jacobians have been SWAPPED — M₂ handed where M₁ belongs, the natural mistake when porting a residual onto bearings.

Nothing else sees it, and that is measured rather than assumed (test/essential_tangent_mc_tests.jl). The swap is very nearly norm-preserving: the two halves of the tangent Sampson's G_x are scaled by |Eᵀf₂| and |Ef₁|, whose ratio has median 1.018 and 5–95% range [0.972, 1.066], so ‖G_x‖ barely moves and the residual stays plausible. Every Monte Carlo calibration cell keeps reporting NEES ≈ 1 — the best of them gets to 0.970, inside its own 4 SE band. Tangency, by contrast, fails loudly: fᵀM measures 4.8e-19 with the right Jacobian against 1.0e-3 with the swapped one, a factor of 2e15.

So a future cleanup that reads the tangency assertion as redundant with the statistical gates would delete the one check that catches a view swap, and the statistical gates would go on succeeding while it did.

Construction, given that a camera's forward map is the differentiable one: with B an orthonormal basis of T_f S² (s2_tangent_basis, shared with EssentialManifold5 rather than re-derived) and A = ∂project(model, ·)/∂f · B the 2×2 restriction of the projection differential to that plane, M = B·A⁻¹. The projection differential is taken by automatic differentiation through the camera's OWN project, so every lens — division, Kannala-Brandt, double sphere, a generic grid — is covered without a per-model derivation, the same derivation-risk-free stance retract_jacobian takes.

This is PoseLib's unproject_with_jac; GTSAM's nearest relative is PinholeBase::backprojectPointAtInfinity(p, Dresult_dpose, Dresult_dpoint), which returns a Unit3. GTSAM spells the pixel → calibrated step calibrate, which collides with THIS stack's task verb calibrate (estimating a camera), so the name here stays backproject.

Returns (NaN bearing, NaN Jacobian) wherever backproject does — outside the lens's domain, past a fold, or where the tangent restriction A is singular (a ray the camera cannot resolve in two directions). Never throws.

VisualGeometryCore.Cameras.division_bounded — Method
division_bounded(k, center, sz; margin = HORIZON_MARGIN) -> Bool

Whether the perspective (undistorted) image of a frame of size sz = (width, height) is BOUNDED under a division model k about center (all in the same pixel units — e.g. a RadialHomography's k/center). For k < 0 the undistorted radius r_u = r_d/(1 + k r_d²) diverges at the 90° circle r_∞ = 1/√(−k): content at or beyond it undistorts to infinity, and no finite canvas holds it. True iff the farthest image corner's distorted radius stays inside margin·r_∞ (k ≥ 0 is always bounded).

When true, the corner stretch factor is 1/(1 + k·r_max²) — the canvas scale an undistorted image needs to keep every input pixel in bounds.

VisualGeometryCore.Cameras.horizon_radius — Method
horizon_radius(model) -> Float64

The PIXEL radius of the camera's horizon: the circle at which rays reach the lens's monotone limit, beyond which nothing can be placed on a perspective plane at all. Inf for a lens with no such limit (a pinhole, a mild polynomial). This is the circle plot_rectification draws on the raw panel, and the guide for how much of a frame it is meaningful to rectify.

It is NOT a safe rectification bound by itself. The distorted radius is very nearly linear in the view angle, while the perspective magnification is tan θ, so a generous FRACTION of this radius is still a fraction of a degree from the pole: for a 927 px fisheye with a 1419 px horizon, 92% of it is θ ≈ 89.7°, tan θ ≈ 199, and the rectified plane comes out 369 000 px wide. Bound the ANGLE instead — see undistorted_rect's max_fov.

VisualGeometryCore.Cameras.undistorted_rect — Method
undistorted_rect(m::RadialHomography, (width, height); margin = HORIZON_MARGIN, max_fov = Inf) -> Rect

The undistorted-plane extent of a width×height frame under m's division model: the frame boundary undistorted in closed form (u = c + (d − c)/(1 + k‖d − c‖²)), with boundary radii at or beyond margin·r_∞ (the 90° divergence circle, r_∞ = 1/√(−k)) clipped to it — the honest cap when division_bounded is false and the true extent is infinite. Feed the rect to the rect form of undistort/undistort!:

ext = undistorted_rect(m, (w, h))
canvas = undistort(CameraModel(m), img, ext;
                   scale = max(1, GeometryBasics.widths(ext)[1] / 5000))

max_fov (radians) additionally bounds the extent by FIELD OF VIEW, capping it at the bounding square of that cone about the principal point. Inf, the default, leaves the frame's own field alone; a finite value is what makes a fisheye — whose horizon can sit inside the frame — rectify to a usable plane at all, since tan θ is unbounded in the last degree before the pole. DEFAULT_MAX_FOV is the recommended cap.

Create a camera extrinsics transform that looks from eye position toward target.

Unitless version for internal use and backwards compatibility.

  • target::StaticVector{3}: Point to look at in world coordinates (unitless, assumed mm)

VisualGeometryCore.p3p — Method
p3p(model::CameraModel, csponds) -> FixedModels{4, Extrinsics3}

Solve the Perspective-3-Point (P3P) problem using correspondences.

This is a thin wrapper around the core p3p(rays, X) solver that accepts correspondences directly. It extracts the 3D world points and 2D image points from the correspondences, backprojects the image points to rays, and calls the core solver.

Arguments

  • model::CameraModel: Camera model for backprojecting image points to rays
  • csponds: Correspondence container with exactly 3 point pairs (3D world → 2D image); any container satisfying the sources/targets protocol (Csponds, StructArray of Pairs, plain Pair vector)

Returns

  • FixedModels{4, Extrinsics3}: Stack-allocated container of 0–4 rigid poses. Empty (length == 0) if no valid solution exists. Iterate with for ext in result ... end or collect(result).

Examples

# Setup camera
s = sensor("Sony", "IMX174")
sensor_bounds = Rect(s)
f = focal_length_for_fov(s, deg2rad(40.0); dimension=:horizontal)
pp = centroid(sensor_bounds) .* px
model = CameraModel(f, s.pitch, pp)

# Create correspondences (3D world points → 2D image points)
X3 = [Point3(100.0, 100.0, 0.0), Point3(200.0, 150.0, 0.0), Point3(150.0, 200.0, 0.0)]
u3 = [Point2(640.0, 480.0), Point2(700.0, 500.0), Point2(680.0, 550.0)]
cs = csponds(X3, u3)

# Solve P3P — always a FixedModels; empty (length 0) when no valid pose
result = p3p(model, cs)
cameras = Camera.(Ref(model), collect(result))

See Also

  • sample_p3p: Sample valid camera poses by randomly sampling correspondences

VisualGeometryCore.Cameras.sample_p3p — Method
sample_p3p(model, X3::SVector{3}, sensor_bounds, plane::Plane3D; max_retries=1000)

Sample a P3P configuration using 3 fixed world points with winding-consistent image sampling.

Given 3 world points (e.g., board corners), samples 3 random image points and sorts them with consistent winding (world CCW, image CW due to y-axis flip). This ensures:

  • Deterministic scale: World point distances define the scale
  • Consistent orientation: Matching winding prevents reflected/flipped solutions

Points can be supplied in any order - the function sorts world points to CCW and image points to CW (matching winding due to y-axis inversion between coordinate systems).

Arguments

  • model::CameraModel: Camera model
  • X3::SVector{3,Point3}: 3 world points (any order, will be sorted to CCW)
  • sensor_bounds::Rect: Sensor bounds for sampling image points
  • plane::Plane3D: Reference plane for chirality test

Returns

  • (camera, csponds): Camera and the 3 correspondences used (in CCW order)

Example

# Board corners in world coords (centered, y-up, z=0)
board_rect = Rect(bundle, :world)
corners = coordinates(board_rect)  # 4 corners
X3 = SVector{3}(Point3.(vcat.(corners[[1,2,3]], 0.0)))  # any 3 corners

camera, csponds = sample_p3p(model, X3, sensor_bounds, Plane3D())

VisualGeometryCore.Cameras.sample_p3p — Method
sample_p3p(model, X, sensor_bounds; max_retries=1000)
sample_p3p(rng, model, X, sensor_bounds; max_retries=1000)

Sample a random P3P configuration by sampling from world points X and random image points.

Creates 3D-2D correspondences by:

  1. Sampling 3 random points from X (world coordinates)
  2. Sampling 3 random 2D image points in sensor bounds
  3. Pairing them as correspondences and solving P3P

Takes a logical camera (CameraModel{<:LogicalIntrinsics}): X and the sensor bounds are unitless (the construction boundary stripped units).

Arguments

  • rng=Random.default_rng(): Random number generator (optional first positional argument)
  • model::CameraModel: Camera model
  • X::Vector{<:StaticVector{3,Float64}}: 3D world points, unitless
  • sensor_bounds::Rect: Sensor bounds for sampling image points (unitless, in pixels)

Keyword Arguments

  • max_retries=1000: Maximum number of sampling attempts

Returns

  • (extrinsics, csponds): Tuple containing:
    • extrinsics::Vector{Extrinsics3}: Camera extrinsics (world-to-camera transforms) for valid P3P solutions
    • csponds::StructArray{Pair{Point3, Point2}, 1, ...}: The 3 correspondences used for P3P, backed by SVector{3} columns

Throws an error if no valid configuration is found after max_retries attempts.

Examples

# Setup camera
s = sensor("Sony", "IMX174")
sensor_bounds = Rect(s)
f = focal_length_for_fov(s, deg2rad(40.0); dimension=:horizontal)
pp = centroid(sensor_bounds) .* px

# 3D points (planar points at z=0)
X = [Point3(100.0, 100.0, 0.0), Point3(200.0, 150.0, 0.0), ...]

# With explicit RNG for reproducibility
rng = Random.MersenneTwister(12345)
extrinsics, csponds = sample_p3p(rng, model, X, sensor_bounds)

# Access correspondence data (StructArray interface)
X_used = csponds.first   # All 3D points
u_used = csponds.second  # All 2D image points
# Or index individual correspondences: csponds[1].first, csponds[1].second

best_camera = cameras[1]  # Or select based on reprojection error
