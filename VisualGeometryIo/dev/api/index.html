VisualGeometryIo.UnitContract — Type
UnitContract(; world = mm)
UnitContract(world)

Declares the unit a file's world magnitudes — translations and 3D points — are expressed in (a length unit). Image magnitudes need no declaration: pixels are the only image unit. Persisted with the data it governs — inline fields in vgio JSON records, a vgio_units.json sidecar for COLMAP model directories — so files stay self-describing.

VisualGeometryIo.UnknownScale — Type
UnknownScale()

The contract of a model whose world has NO unit: a structure-from-motion reconstruction without metric control (PhotoTourism, any plain COLMAP run) is fixed only up to a similarity, so its translations and 3D points are numbers in the reconstruction's own arbitrary scale. Declaring mm or m for them would be false, and nothing declares this either unless someone says so: the caller states it (load(ColmapModel, dir; contract = UnknownScale())), or the model's vgio_units.json sidecar does ("world": "unknown", written by save for such a model). It is never a default.

Under it the wire values stay what they are, plain numbers (ColmapImage.tvec, ColmapPoint3D.xyz), and anything that needs a length unit refuses: rigid_transform(image, contract) (a metric EuclideanMap) and colmap_image(pose, …; contract) (a metric pose written into the model) throw an ArgumentError. What does not depend on scale is read from the wire as usual: the rotation qvec, and translation directions.

VisualGeometryIo.colmap_cameras — Method
colmap_cameras(cameras::AbstractDict{Symbol}) -> (cameras::Vector{ColmapCamera}, ids::Dict{Symbol, Int})

Project a camera store onto COLMAP camera rows, for feeding a ColmapModel. Ids are assigned 1..n in name order.

TWO LOSSES, both deliberate and both surfaced rather than papered over:

  1. Names do not survive. COLMAP has no camera name field, so the identity a config refers to is gone on the far side. The returned ids map is the remainder — persist it beside the model if anything downstream needs to get back to a name.
  2. Inexpressible cameras throw. VisualGeometryIo.load_matlab_calibration — Method
load_matlab_calibration([file_frame = PixelFrame{:julia},] path; file_unit, target = "calibration_target")
    -> ExternalCalibration

Read a MATLAB Computer Vision Toolbox calibration export. The radial/tangential files (fx, fy, cx, cy, r1, r2, r3, t1, t2) state OpenCV's polynomial term for term, so the camera is OpenCV's five-coefficient model, opencv_lens([r1, r2, t1, t2, r3]). The fisheye file (mapping_coeffs, distortion_center, stretch_matrix, MATLAB's fisheyeIntrinsics) is Scaramuzza's model: the sensor-plane point (u′, v′) reaches the image as stretch_matrix · (u′, v′) + distortion_center and back-projects to the ray (u′, v′, a0 + a2·ρ² + a3·ρ³ + a4·ρ⁴) in the sensor-plane pixel radius ρ, so a0 is the focal length, the stretch and the centre are K, and the polynomial normalized by a0 is VGC's Scaramuzza (aᵢ ↦ aᵢ·a0^(i−1)). K must be upper triangular and the stretch matrix is not: its RQ factorization S = U·Q puts a0·U in K and Q, a rotation of the sensor plane, into the camera frame — a rotation about the optical axis (a fraction of a degree on this capture) that every returned pose carries, so the camera and its poses stay one consistent model. That rotation is part of the difference between this camera's frame and an OpenCV fit's, and shows in a mount compared across the two. mean_error is the file's statistic — a MEAN reprojection error, not an rms (error_statistic == :mean).

file_frame is the pixel frame of the file's centre and principal point: MATLAB's documented convention, PixelFrame{:julia} (top-left pixel centre at (1, 1)), by default — a fitted principal point cannot tell it from an exporter's shift to OpenCV's, so override it only for a file verified to be in another frame. file_unit is the world unit the toolbox was given the pattern in (mm for a pattern typed in millimetres) — tvec is in it; there is no default. MATLAB's board frame has x and y exchanged relative to OpenCV's for the same pattern: the poses are returned in MATLAB's own board frame, so name its target apart from an OpenCV calibration's. target names the pattern in the pose records (target → camera_optical).

source
VisualGeometryIo.load_opencv_calibration — Method
load_opencv_calibration([file_frame = PixelFrame{:opencv},] path; file_unit, target = "calibration_target")
    -> ExternalCalibration

Read an OpenCV calibration export: fx, fy, cx, cy; the distortion vector by name — k1, k2, p1, p2 required, k3–k6, s1–s4 and the tilt tilt_x, tilt_y (OpenCV's τx, τy) as the file names them — read as the lens computing OpenCV's model for the shortest distortion vector holding every named coefficient (opencv_lens), the unnamed ones zero; an unknown key is refused, never ignored (a dropped tilt would be a different camera); rms in pixels; poses, one {rvec, tvec} per image (null allowed); and images, the name of each pose's image, when the file names them (this package's writer does; a third-party export does not, and its join with the images is positional and the caller's).

The two arguments are statements about the FILE — what a third-party export does not declare — never labels on data: file_unit is the length unit of tvec (the object points' unit, m or mm), and file_frame the pixel frame of cx, cy, OpenCV's own PixelFrame{:opencv} by default (a type, it leads). The camera returned is in VGC's canonical frame by construction and the poses in millimetres, so nothing downstream restates either. target names the pattern in the pose records (target → camera_optical).

Most third-party exports declare neither and are read as stated; some declare tvec_unit. A file written by save_opencv_calibration declares both (unit, image_origin), and a declaration that differs from the caller's is an ArgumentError, never a silent rescale: a metre file read as millimetres puts every target a thousand times too near.

VisualGeometryIo.migrate_matlab — Method
migrate_matlab([file_frame = PixelFrame{:julia},] path; images, image_size, file_unit = nothing,
               target = "calibration_target", out = dirname(path), dry_run = false) -> NamedTuple

Convert a third-party MATLAB calibration export (calibration_matlab_*.json: the radial/tangential camera fx, fy, cx, cy, r1…r3, t1, t2, or the fisheye mapping_coeffs, distortion_center, stretch_matrix; mean_error; one {rvec, tvec} per image) into the same native files as migrate_opencv, which it mirrors: <stem>_cameras.json (the camera as load_matlab_calibration reads it — MATLAB's polynomial lens, or the fisheye as Scaramuzza with its stretch in K; provenance records the reprojection_error with error_statistic = "mean", MATLAB's statistic, not an rms) and <stem>_poses.json (target:<target> → view:<image> per posed image, in millimetres — the fisheye's frame twist applied, as the reader applies it). MATLAB's board frame has x and y exchanged relative to OpenCV's for the same pattern, and the poses are carried in MATLAB's own board frame, unchanged: give target a name that keeps them apart from an OpenCV calibration's.

VisualGeometryIo.migrate_opencv — Method
migrate_opencv([file_frame = PixelFrame{:opencv},] path; images, image_size,
               file_unit = nothing, target = "calibration_target",
               out = dirname(path), dry_run = false) -> NamedTuple

Convert a third-party OpenCV calibration export (calibration_opencv_*.json: fx, fy, cx, cy, named distortion coefficients, rms, one {rvec, tvec} per image) into native files (cameras v3, transforms v2), where everything the export leaves implicit is declared. The original is never touched. Written to out:

  • <stem>_cameras.json — a vgio/cameras/v3 store holding one camera named <stem>: width/height from image_size, K in the canonical pixel frame, and the lens record of opencv_lens for the export's distortion vector (the terms its length evaluates). The export's reprojection statistic is its provenance (reprojection_error, error_statistic = "rms", source = "opencv", migrated_from).
  • <stem>_poses.json — a vgio/transforms/v2 file, one record per image the solver posed, NAMED by that image: from = "target:<target>", to = "view:<image>" — the target in the camera frame of that view, x_view = R x_target + t, in millimetres. An image whose pose the export has as null has no record.

images is REQUIRED — one unique, non-empty name per entry of the export's poses, in the export's order — and replaces the positional join the export leaves to its reader. image_size (width, height) is required because a camera is not sufficient without its extent and an OpenCV export does not record it.

file_unit is the unit of tvec: taken from the file's tvec_unit (or this package's own unit) when it declares one — and then a stated file_unit must agree — and otherwise REQUIRED; there is no default.

file_frame is the pixel frame of cx, cy, and the ONLY place a pixel frame is stated by hand: by the user's rule OpenCV's own, the top-left pixel's centre at (0, 0) (PixelFrame{:opencv}). Override it only for a calibration VERIFIED to be in another frame. A type, it leads, as a type does in a non-mutating call. Everything downstream carries the frame in its type: the camera read is canonical by construction, and the files declare what their types say.

The conversion is verified before anything is written to out: the v2 files, written to a temporary directory, must read back equal to the OpenCV read — the camera ==, every pose's translation bit for bit and its rotation to the quaternion encoding's precision (_qvec). With dry_run nothing is written to out. Returns (; path, cameras, poses, n_posed, n_unposed), the output paths nothing in a dry run.

VisualGeometryIo.save_opencv_calibration — Method

Write an OpenCV-shaped calibration export — THE INVERSE of load_opencv_calibration, and the only writer for that shape, so the two cannot drift: fx, fy, cx, cy, the twelve distortion coefficients by name (k1–k6, p1, p2, s1–s4, each written even when zero, which is what makes a default, rational or thin-prism fit one file shape), rms in pixels, one {rvec, tvec} per image — null for an image with no pose — and images, the name of each pose's image, REQUIRED: a positional join with an image list kept elsewhere is exactly the out-of-band knowledge a file must not need.

The shape is a THIRD-PARTY one, so its conventions are its consumer's, and the two arguments are CONVERSION TARGETS applied to data whose own conventions its types fix — the camera's K is canonical by VGC's construction, the poses are millimetres — never labels for it:

to_frame the pixel frame cx, cy are written in; OpenCV's own, PixelFrame{:opencv}, by default. A type, it leads. to_unit the length unit tvec is written in (the poses are carried in millimetres, so to_unit = m divides by a thousand).

Both are also written into the file, under image_origin and unit, and the reader refuses a caller who states different ones.

camera must carry a lens OpenCV's distortion model computes (opencv_coefficients); the file names the coefficients of the shortest OpenCV vector holding it. A K with nonzero skew is refused: the shape has no field for it.
