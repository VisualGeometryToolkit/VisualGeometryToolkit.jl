Batch API

Per-point maps over arrays, the B-spline kernels and the thin-plate spline. See the Batches guide; the lens surfaces (project!, …) are documented with the Lenses API.

Pointwise maps

VisualGeometryToolkitCore.THREADED_MIN_LENGTH — Constant
THREADED_MIN_LENGTH

The batch length from which Auto splits a host batch across threads: below it a task's start-up costs more than the work it saves. Measured (benchmark/lenses/new.toml, 32 threads): at 256 points Serial and Threaded tie for the cheapest lens (one-coefficient division), at 1024 Threaded is 1.2× faster for it and 3.4× for OpenCV's 5-coefficient undistortion.

source
VisualGeometryToolkitCore.Auto — Type
Auto()

Serial below THREADED_MIN_LENGTH points or on one thread, Threaded above it; a device array is always one broadcast kernel.

source
VisualGeometryToolkitCore.ExecutionPolicy — Type
ExecutionPolicy

How pointwise! runs a host batch: Auto (the default), Serial or Threaded. A device array (CUDA, Metal, …) is always one broadcast kernel, whatever the policy.

source
VisualGeometryToolkitCore.Serial — Type

One broadcast loop on the calling task — for callers that already parallelize an outer loop.

source
VisualGeometryToolkitCore.Threaded — Type

The broadcast split into contiguous chunks, one task per available thread.

source
VisualGeometryToolkitCore.pointwise! — Method
pointwise!(f, out, xs...; exec = Auto()) -> out

out[i] = f(xs[1][i], xs[2][i], …) for every index — out .= f.(xs...) — on the backend that owns out: a SIMD loop on host arrays (split across threads per exec), one broadcast kernel on a GPU array. f is any per-point function; for a GPU array it must be isbits and kernel-lawful (no allocation, no throw, no dynamic dispatch), as every lens and camera map is. Every policy gives bitwise identical results.

B-spline Kernels

The B-spline algebra on the CPU is BSplineKit's (knot vectors, evaluation and derivatives, Galerkin matrices, recombined bases). Core keeps only what a GPU kernel needs and BSplineKit cannot give it: the scalar Cox–de Boor basis bspline_basis(knots, Val(p), x) — an SVector of every basis function at x on a static knot vector, isbits and generic in the element type, so it runs in a kernel and under ForwardDiff (hoisted from RadiometricCamera, its arithmetic unchanged; equal to BSplineKit's evaluate_all on the same knots) — its broadcast over a device array, and the tensor-product surface/4D spline kernels built on it; the ChainRulesCore rrules attach via the package extension.

using BSplineKit: BSplineBasis, BSplineOrder, knots
k = SVector{11}(knots(BSplineBasis(BSplineOrder(4), range(-0.5, 0.5; length = 5))))   # 7 cubic control points on [-½, ½]
N = bspline_basis(k, Val(3), 0.12)               # SVector{7}, sum(N) == 1
VisualGeometryToolkitCore.bspline_4d_partial — Method
bspline_4d_partial(u1, u2, u3, u4, degrees, k1, k2, k3, k4, control_points, dim)

∂S/∂udim of the 4D spline at the sample points, via the derivative surface (degree − 1 along dim, differenced CPs, trimmed knots). AD-transparent wrt `controlpoints`.

source
VisualGeometryToolkitCore.bspline_basis — Method
bspline_basis(knots::SVector{K}, Val(p), x) -> SVector{K − p − 1}
bspline_basis(knots::SVector{K}, p::Integer, x)

Every degree-p B-spline basis function on knots at x, N_{1,p}(x), …, N_{K−p−1,p}(x) (Cox–de Boor, Piegl & Tiller 1997): 0/0 is 0, and the last non-empty knot span is closed on the right, so the values sum to one on the whole closed interval [knots[1], knots[K]]. x outside it is clamped onto it (constant extrapolation).

The basis (its knots and degree) leads, the point follows (signatures.md). The degree is a Val so the result's size is static and nothing allocates; the Integer form is the convenience. Scalar, isbits and generic in the element type (promote_type of x's and the knots'): it runs inside a KernelAbstractions kernel, in Float32, and under ForwardDiff. Why it is Core's and not BSplineKit's: a kernel needs an isbits basis on a static knot vector with a static result; on the CPU, BSplineKit's evaluate_all gives the same values (the tests check it). bspline_basis_iterative is its broadcast over an array.

source
VisualGeometryToolkitCore.bspline_basis_iterative — Method
bspline_basis_iterative(u, degree, knots) -> Vector{<:AbstractArray{Float32}}

For each of the n_basis = length(knots) − degree − 1 basis functions, its values at every point of the device array u: bspline_basis broadcast over u (on u's backend) in Float32, split per basis function — the structure-of-arrays form the tensor-product kernels below consume. u outside the knots is clamped onto them, as by bspline_basis.

Kept because the tensor-product kernels below run on the device array's backend; validated against BSplineKit.BSplineBasis on the downstream demo's actual θ knot vector — see test/bspline_tests.jl.

source
VisualGeometryToolkitCore.bspline_surface_partial — Method
bspline_surface_partial(u, v, degree_u, degree_v, knots_u, knots_v, control_points, along)

First partial derivative of a B-spline surface along parameter direction along (1 = u, 2 = v), via the derivative-surface trick: difference the control points, drop one knot at each end, evaluate at degree − 1 along the differentiated direction. Shared by the evaluate_bspline_surface rrule (package extension) and the downstream spline-lens Jacobians.

source
VisualGeometryToolkitCore.contract_basis_4d_weighted — Method
contract_basis_4d_weighted(u1, u2, u3, u4, degrees, k1, k2, k3, k4, w)

Σ_s w_s · (4D basis product at sample s), returned in control-point shape — the single memory-critical primitive behind every 4D control-point gradient (the 4D spline rrule and the downstream boundary/render accumulations). Weights are folded to per-sample scalars FIRST, so only one (n1·n2, N)×(N, n3·n4) GEMM remains and the dense per-sample basis tensor is never materialized.

source
VisualGeometryToolkitCore.evaluate_bspline_4d — Method
evaluate_bspline_4d(u1, u2, u3, u4, degrees, k1, k2, k3, k4, control_points)
    -> AbstractArray{Float32}

4D tensor-product B-spline: S(u) = Σijkl N1i(u1)·N2j(u2)·N3k(u3)·N4_l(u4)·cp[i,j,k,l]. The four inputs must share one shape (callers materialize broadcasts first); the result has that shape. degrees is indexable per dim (NTuple or Vector). Differentiable wrt the inputs and the control points via the ChainRulesCore rrule (package extension).

source
VisualGeometryToolkitCore.evaluate_bspline_surface — Method
evaluate_bspline_surface(u, v, degree_u, degree_v, knots_u, knots_v, control_points)

Tensor-product B-spline surface evaluation on the compute device (kept for the device: BSplineKit evaluates on the CPU; tested equal to its Spline evaluation on the same knots). Inputs u, v are broadcasted device arrays of equal shape; the surface is evaluated point-wise and an array of the same shape is returned. Differentiable wrt u, v, and the control points via the ChainRulesCore rrule (package extension). Periodicity in the second parameter direction is handled by the CALLER tying the wrap control-point columns — no knot wrapping happens here.

The bending energy of a B-spline

bending_gram is ∫∫ f_xx² + 2 f_xy² + f_yy² of a tensor-product B-spline as a quadratic form in its coefficients, from BSplineKit's Galerkin matrices; bending_rows factors it into a regularizer's rows and bending_stencils gives it cell by cell on a large uniform lattice (cubic_lattice_basis, Core's generic-model lattice). The natural boundary condition f'' = 0 of BSplineKit's recombined basis is natural_extrapolation, the rule BoundaryRule applies to a lattice's nodes outside an imaged region.

VisualGeometryToolkitCore.bending_gram — Method
bending_gram(B) -> Matrix{Float64}
bending_gram(Bx, By) -> Matrix{Float64}

The bending energy of a B-spline as a quadratic form in its coefficients: ∫ f''² of a curve on the BSplineKit basis B; ∫∫ f_xx² + 2 f_xy² + f_yy² of the tensor-product surface on Bx ⊗ By, vec(c)ᵀ G vec(c) with c laid [i, j] (the first index fastest). BSplineKit's Galerkin matrices of the basis's derivatives, over the bases' domains. Positive semidefinite, the affine functions its null space. A regularizer reads it as rows (bending_rows) or, on a large uniform lattice, cell by cell (bending_stencils); a lattice of vector-valued controls applies it per component.

source
VisualGeometryToolkitCore.bending_rows — Method
bending_rows(G) -> Matrix{Float64}

A factor L of a bending Gram matrix (bending_gram): ‖L c‖² = cᵀ G c to rounding, so √λ · L (c − c₀) are a regularizer's residual rows (the chart LM's row protocol). L = Λ₊^½ Vᵀ from G = V Λ Vᵀ, one row per positive eigenvalue (the null space's rounding residue dropped); only LᵀL is defined.

source
VisualGeometryToolkitCore.bending_stencils — Method
bending_stencils(nx, ny; spacing = (1, 1)) -> (; windows, L)

The bending energy of an nx × ny uniform cubic lattice (cubic_lattice_basis per axis, cell size spacing) cell by cell, for a lattice too large for a dense form: E = Σₖ ‖L c[windows[k]]‖² over the (nx − 3)(ny − 3) cells, windows[k] the 16 linear indices of cell k's 4 × 4 window (the first index fastest) and L the factor of one cell's 16 × 16 form — bending_gram of a one-cell lattice, shared by every cell of a uniform lattice. A row involves one window only, so a solve that blocks the lattice keeps its rows local.

source
VisualGeometryToolkitCore.cubic_lattice_basis — Method
cubic_lattice_basis(n; spacing = 1) -> BSplineKit.BSplineBasis

The uniform cubic B-spline lattice of n nodes (Core's generic-model lattice) as a BSplineKit basis: knots (−3:n) · spacing, so basis j (node j) is centred at (j − 2) · spacing and the spline's domain is the n − 3 cells [0, (n − 3) · spacing] where the basis sums to one.

source
VisualGeometryToolkitCore.natural_extrapolation — Method
natural_extrapolation() -> (w₁, w₂)

The natural boundary condition f'' = 0 at a border knot of a uniform cubic B-spline as the outermost coefficient's extrapolation from the two inward, c₀ = w₁ c₁ + w₂ c₂: the relation BSplineKit's RecombinedBSplineBasis(B, Natural()) imposes (its recombination matrix's span), (2, −1) — the rule BoundaryRule applies outward from an imaged region.

Thin-plate spline

f(𝐩) = a₁ + a_x 𝐩_x + a_y 𝐩_y + Σᵢ wᵢ U(𝐩, 𝐩ᵢ) with U = ½ r² ln r², through nodal values on scattered nodes (hoisted from RadiometricCamera, its arithmetic unchanged). ThinPlateSplineSystem is the host-side solver; the evaluator tps_evaluate and its gradient tps_gradient take isbits (nodes, w, a), allocate nothing and run in a KernelAbstractions kernel on the CPU backend.

tps = ThinPlateSplineSystem(grid_nodes(5))      # 5 × 5 nodes over [-½, ½]²
w, a = tps_coefficients(tps, values)            # linear in the 25 nodal values
f = tps_evaluate(tps.nodes, w, a, SVector(0.1, -0.2))
∇f = tps_gradient(tps.nodes, w, a, SVector(0.1, -0.2))

Its analogue on the unit sphere, SphericalSplineSystem (Wahba's m = 2 kernel spherical_spline_kernel, a constant in place of the affine part; also hoisted from RadiometricCamera), has the same shape: spherical_spline_coefficients, the isbits evaluator spherical_spline_evaluate, and the shared nodal_weights, bending_energy and bending_factor.

VisualGeometryToolkitCore.SphericalSplineSystem — Type
SphericalSplineSystem(directions) -> SphericalSplineSystem{N}

The solver object of a spherical spline through N unit directions — the ThinPlateSplineSystem's analogue on the sphere, with Wahba's kernel spherical_spline_kernel and a constant in place of the affine part: the directions, the (N + 1) × N matrix coeff that maps nodal values to the weights and the constant, (w; a₁) = coeff · values, and the N × N bending-energy form Q (valuesᵀ Q values = wᵀ K w). coeff is the first N columns of the inverted system matrix [K 1; 1ᵀ 0], formed with inv as RadiometricCamera forms it. The directions are normalized on entry.

source
VisualGeometryToolkitCore.ThinPlateSplineSystem — Type
ThinPlateSplineSystem(nodes) -> ThinPlateSplineSystem{N}

The solver object of a thin-plate spline through N nodes in the plane: the node positions, the (N + 3) × N matrix coeff that maps nodal values to the spline's weights and affine part, (w; a) = coeff · values, and the N × N bending-energy form Q (valuesᵀ Q values = wᵀ K w, K = [U(𝐩ᵢ, 𝐩ⱼ)], see bending_energy).

coeff is the first N columns of the INVERTED system matrix [K P; Pᵀ 0], formed with inv as RadiometricCamera forms it: its golden tests pin these numbers, and a factorization would move them in the last bits. The matrices live on the host; tps_coefficients turns nodal values into the isbits (w, a) that tps_evaluate and tps_gradient take.

source
VisualGeometryToolkitCore.bending_energy — Method
bending_energy(tps::ThinPlateSplineSystem, values) -> scalar
bending_energy(sys::SphericalSplineSystem, values) -> scalar

The bending energy valuesᵀ Q values of the spline through the nodal values values (= wᵀ K w with K = [U(𝐩ᵢ, 𝐩ⱼ)] the radial basis between the nodes; zero for affine values up to rounding); a quadratic regularizer on the values.

source
VisualGeometryToolkitCore.bending_factor — Method
bending_factor(tps::ThinPlateSplineSystem{N}) -> Matrix{Float64}
bending_factor(sys::SphericalSplineSystem{N}) -> Matrix{Float64}

A factor L (N × N) of the bending-energy form: ‖L · values‖² = bending_energy(tps, values) to rounding, so L · values are a regularizer's residual rows. Q is positive semidefinite with the affine values in its null space, so it has no Cholesky factor: L = Λ₊^½ Vᵀ from the eigendecomposition Q = V Λ Vᵀ, Λ₊ the eigenvalues clamped at zero (the null space's rounding residue may come out negative). An eigenbasis is not unique, so only LᵀL is defined — never compare the rows one by one.

source
VisualGeometryToolkitCore.grid_nodes — Method
grid_nodes(n; lo = -0.5, hi = 0.5) -> Vector{SVector{2, Float64}}
grid_nodes(n, r::Rect) -> Vector{SVector{2, Float64}}

The n × n equally spaced nodes over the square [lo, hi]², or over the rectangle r (its corners included: a sensor's Rect(sensor) in pixels), column-major (x fastest).

source
VisualGeometryToolkitCore.nodal_weights — Method
nodal_weights(sys::SphericalSplineSystem{N}, d) -> SVector{N, Float64}

∂f(d)/∂valuesᵢ of the spherical spline at the direction d: node i's weight Σ_r coeff[r, i] φ_r(d), φ = (R(d · d₁) … R(d · d_N), 1).

source
VisualGeometryToolkitCore.nodal_weights — Method
nodal_weights(tps::ThinPlateSplineSystem{N}, 𝐩) -> SVector{N, Float64}

The sensitivity of the spline at 𝐩 to each nodal value, ∂f(𝐩)/∂valuesᵢ. With f(𝐩) = φ(𝐩)ᵀ (coeff · values) and φ = (U(𝐩, 𝐩₁) … U(𝐩, 𝐩_N), 1, 𝐩_x, 𝐩_y), node i's weight is Σ_r coeff[r, i] φ_r(𝐩) — exact, since the spline is linear in its values. Host-side (it reads coeff), in Float64.

source
VisualGeometryToolkitCore.spherical_spline_coefficients — Method
spherical_spline_coefficients(sys::SphericalSplineSystem{N}, values) -> (w::SVector{N}, a₁)

The spline's weights and constant through the nodal values (length N); linear in them and generic in their element type, as tps_coefficients.

source
VisualGeometryToolkitCore.spherical_spline_evaluate — Method
spherical_spline_evaluate(nodes, w, a₁, d) -> scalar
spherical_spline_evaluate(sys::SphericalSplineSystem, w, a₁, d) -> scalar

The spline at the unit direction d: a₁ + Σᵢ wᵢ R(d · dᵢ). The first form takes isbits inputs (nodes::SVector{N, <:StaticVector{3}}) and allocates nothing; generic in the element type (Float32, ForwardDiff Duals).

source
VisualGeometryToolkitCore.spherical_spline_kernel — Method
spherical_spline_kernel(d, e) -> scalar

Wahba's m = 2 spherical-spline kernel between unit directions d and e, R(z) = 1 − π²/6 + Li₂((1 + z)/2) with z = d · e, evaluated from the chord (1 − (1 + z)/2 = ‖d − e‖²/4) so it stays accurate for nearby directions: R(1) = 1 (with zero partials at coincidence, as the planar tps_radial_basis at r = 0), R(−1) = 1 − π²/6. Isbits, generic over Real (dilog's series).

source
VisualGeometryToolkitCore.tps_coefficients — Method
tps_coefficients(tps::ThinPlateSplineSystem{N}, values) -> (w::SVector{N}, a::SVector{3})

The spline's weights w and affine part a = (a₁, a_x, a_y) through the nodal values values (length N). Linear in values, and generic in their element type: a ForwardDiff.Dual or a Float32 is kept (the product with the Float64 matrix is formed first, then converted to the values' element type).

source
VisualGeometryToolkitCore.tps_evaluate — Method
tps_evaluate(nodes, w, a, 𝐩) -> scalar
tps_evaluate(tps::ThinPlateSplineSystem, w, a, 𝐩) -> scalar

The spline at 𝐩: a₁ + a_x 𝐩_x + a_y 𝐩_y + Σᵢ wᵢ U(𝐩, 𝐩ᵢ) with (w, a) from tps_coefficients and U the tps_radial_basis. The first form takes isbits inputs only (nodes::SVector{N, <:StaticVector{2}}, w, a, 𝐩): it allocates nothing and runs in a KernelAbstractions kernel on the CPU backend. It is generic in the element type and PROMOTES the nodes with w and 𝐩: a Float32 evaluation with Float64 nodes returns Float64. This differs from tps_gradient, which converts the nodes, as RadiometricCamera's two functions do; supply the nodes in the evaluation's type (Float32 nodes for Float32) and both work in that type.

source
VisualGeometryToolkitCore.tps_gradient — Method
tps_gradient(nodes, w, a, 𝐩) -> SVector{2}
tps_gradient(tps::ThinPlateSplineSystem, w, a, 𝐩) -> SVector{2}

The analytic gradient ∇f(𝐩) of tps_evaluate: (a_x, a_y) + Σᵢ wᵢ (𝐩 − 𝐩ᵢ)(ln r² + 1), since ∇_𝐩 ½ r² ln r² = (𝐩 − 𝐩ᵢ)(ln r² + 1); a node at r = 0 contributes zero. The sum is RadiometricCamera's board_height_grad term for term (its height field is this spline without the affine part, which is added last). Isbits inputs and allocation-free, and it runs in a KernelAbstractions kernel on the CPU backend, as tps_evaluate. Unlike tps_evaluate, which promotes, it CONVERTS the node coordinates to the promoted element type of w and 𝐩 (RadiometricCamera's board_height_grad rule): Float32 w and 𝐩 with Float64 nodes give a Float32 gradient. Supply the nodes in the evaluation's type and the two agree.

source
VisualGeometryToolkitCore.tps_radial_basis — Method
tps_radial_basis(𝐩, 𝐪) -> scalar

The thin-plate spline's radial basis function U(𝐩, 𝐪) = ½ r² ln r² with r = ‖𝐩 − 𝐪‖ (the same as r² ln r), and U = 0 at r = 0. The zero branch is taken on r² > 0, not by evaluating 0 · log 0, so a ForwardDiff.Dual evaluated on a node gets a zero value with zero partials (the true derivative there) instead of NaN.

Special functions

Device-safe scalar functions — pure arithmetic, generic over Real, so they compile in a KernelAbstractions kernel at any float width and ForwardDiff Duals flow through: log Γ and the digamma/trigamma series of the Student-t adaptation kernels, the normal CDF normcdf_as (Abramowitz & Stegun 7.1.26) and the dilogarithm dilog.

VisualGeometryToolkitCore.digamma_stirling — Method
digamma_stirling(x)

ψ(x) by the Stirling series through the x⁻⁴ term — pure arithmetic, for the Newton step on a Student-t's degrees of freedom inside a device kernel.

source
VisualGeometryToolkitCore.dilog — Method
dilog(x::Real)

The dilogarithm Li₂(x) = −∫₀ˣ ln(1 − t)/t dt on [0, 1]: the Bernoulli series in u = −ln(1 − x) (17 terms, by Horner) for x ≤ ½, the reflection Li₂(x) = π²/6 − ln x·ln(1 − x) − Li₂(1 − x) above; x ≥ 1 reads Li₂(1) = π²/6. Accurate to a few eps in Float64; generic over Real (Float32 kernels, ForwardDiff Duals), the constants in the argument's value type.

source
VisualGeometryToolkitCore.lgamma_lanczos — Method
lgamma_lanczos(x::AbstractFloat)

log Γ(x) by the Lanczos approximation (g = 7, n = 9) — branch-free, only + * / log, so it compiles on every KernelAbstractions backend and every float width. ~1 ulp in Float64 for x ≥ 1; no reflection, so callers keep their argument ≥ 1 (every adaptation call site does).

source
VisualGeometryToolkitCore.normcdf_as — Method
normcdf_as(x::Real)

The standard normal CDF Φ(x) by Abramowitz & Stegun 7.1.26 on erf (|error| < 1.5e-7): branch-free but for the sign, only + * / exp, so it compiles in any KernelAbstractions kernel at any float width. A Dual flows through the polynomial, so its derivative is that of the approximation (φ(x) to ≈ 1e-6) — the exact derivative of the evaluated objective.

source
VisualGeometryToolkitCore.trigamma_stirling — Method
trigamma_stirling(x)

ψ′(x) by the Stirling series through the x⁻³ term; companion of digamma_stirling.

source

Quadrature

The probabilists' Gauss–Hermite rule gauss_hermite_prob (an expectation over N(0, 1), exact to degree 2n − 1) and the Hammersley points hammersley (a kernel's own low-discrepancy sample from its index).

VisualGeometryToolkitCore.gauss_hermite_prob — Method
gauss_hermite_prob(n) -> (nodes::Vector{Float64}, weights::Vector{Float64})

The n-point Gauss–Hermite rule for the standard normal weight (probabilists' form): Σ wᵢ f(xᵢ) ≈ E[f(X)], X ~ N(0, 1), the weights summing to one, exact for polynomials of degree 2n − 1. Closed forms for n ≤ 3; beyond, Golub–Welsch — the eigen-decomposition of the Jacobi matrix of the monic Hermite polynomials He_k (off-diagonal √k), the weights the squared first components of its eigenvectors. Ascending nodes. An ArgumentError for n < 1.

For N(μ, σ²), use the nodes μ + σ·xᵢ with the same weights.

source
VisualGeometryToolkitCore.hammersley — Method
hammersley([T = Float64,] i, N) -> (u₁, u₂)

The i-th point (1 ≤ i ≤ N) of the N-point 2-D Hammersley set in [0, 1)²: u₁ = (i − ½)/N, u₂ the base-2 van der Corput radical inverse of i − 1. Scalar and isbits-only (a kernel computes its own point from its index); the type argument leads, as in rand(T, …).

source
VisualGeometryToolkitCore.square_rule — Method
square_rule(x, w) -> (nodes::Vector{SVector{2, Float64}}, weights::Vector{Float64})

The tensor-product rule over a square of a one-dimensional rule (nodes x, weights w, e.g. QuadGK's gauss(n) or gauss_hermite_prob): node (x[i], x[j]) with weight w[i]·w[j], the first coordinate fastest. The weights sum to the square of the 1-D rule's sum; it integrates exactly the products of the polynomials the 1-D rule integrates exactly.

source
VisualGeometryToolkitCore.unit_disc_rule — Method
unit_disc_rule(n_ρ, n_φ) -> (nodes::Vector{SVector{2, Float64}}, weights::Vector{Float64})

The polar product rule over the unit disc ‖x‖ ≤ 1: Gauss–Legendre in the radius ρ ∈ [0, 1] (n_ρ nodes, QuadGK's gauss mapped from [−1, 1]) times n_φ equally spaced angles φ_j = 2π(j − ½)/n_φ; node (ρ cos φ, ρ sin φ) with weight ρ·w_ρ·2π/n_φ (the polar area element), radius-major (node (k − 1)·n_φ + j). The weights sum to π, the disc's area: Σ wᵢ f(xᵢ) approximates ∫ f over the disc, exactly for ρ^a cos(mφ), ρ^a sin(mφ) with a + 1 ≤ 2n_ρ − 1 and |m| < n_φ.
