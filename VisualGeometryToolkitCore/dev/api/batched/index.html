Batch API

Per-point maps over arrays, the B-spline kernels and the thin-plate spline. See the Batches guide; the lens surfaces (project!, …) are documented with the Lenses API.

Pointwise maps

VisualGeometryToolkitCore.OnBackend — Type
OnBackend(backend; workgroupsize = nothing)
(exec::OnBackend)(kernel[, ndrange]) -> KernelAbstractions.Kernel

The stack's ONE kernel-launch policy. Called on a KernelAbstractions @kernel, it instantiates it on backend itself: the backend value, so its compiler options hold (CUDABackend(; always_inline = true)), with the workgroup workgroupsize names, per backend:

  • nothing: the backend's choice (on the CPU, KernelAbstractions' default: up to 1024 items as one workgroup on the calling task, a larger range in groups of 1024 items over the threads).
  • one work item (1, (1, 1), (1, 1, 1)): one item per workgroup on the CPU, so a kernel whose work item is a long loop (a pool's (pair, model[, grid point]) item) runs its items on every thread where the default's 1024-item groups leave most threads idle; on a device, one warp (32 items) per workgroup: one item would leave 31 of 32 lanes idle, and the backend's own choice puts these small ranges of long items on few multiprocessors (RANSACScoringDoneRight's grids on a B200: the Student-t grid 30.6 ms at one item, 1.55 at the backend's choice, 1.35 at one warp; its mixture marginal 62.1, 90.4 and 17.7 ms).
  • any other size (a kernel's tile, a measured device size): that size, on every backend.

A static ndrange instantiates a statically sized kernel at workgroupsize as given (the CPU's allocation-free one-item launch). Every stack kernel is instantiated here.

As pointwise!'s exec, it is that one kernel's launch; without it the kernel runs on get_backend(out) with the defaults. A functor whose fields are each one of its type parameters or an isbits value reaches the kernel as its fields, rebuilt on the device: one large argument costs local memory there.

VisualGeometryToolkitCore.pointwise! — Method
pointwise!(f, out, xs...; exec = OnBackend(get_backend(out))) -> out

out[i] = f(xs[1][i], xs[2][i], …) for every index, as ONE KernelAbstractions kernel on the backend that owns out (every backend, the CPU's included), or on the backend OnBackend exec names. out and xs share one shape (no broadcasting: a DimensionMismatch otherwise). f is any per-point function; for a GPU array it must be isbits and kernel-lawful (no allocation, no throw, no dynamic dispatch), as every lens and camera map is. On the CPU the launch has finished on return; on a device it is asynchronous, as a device broadcast is: KernelAbstractions.synchronize(backend) before out is read on the host.

B-spline Kernels

The B-spline algebra on the CPU is BSplineKit's (knot vectors, evaluation and derivatives, Galerkin matrices, recombined bases). Core keeps only what a GPU kernel needs and BSplineKit cannot give it: the scalar Cox–de Boor basis bspline_basis(knots, Val(p), x) — an SVector of every basis function at x on a static knot vector, isbits and generic in the element type, so it runs in a kernel and under ForwardDiff (hoisted from RadiometricCamera, its arithmetic unchanged; equal to BSplineKit's evaluate_all on the same knots) — its broadcast over a device array, and the tensor-product surface/4D spline kernels built on it; the ChainRulesCore rrules attach via the package extension.

using BSplineKit: BSplineBasis, BSplineOrder, knots
k = SVector{11}(knots(BSplineBasis(BSplineOrder(4), range(-0.5, 0.5; length = 5))))   # 7 cubic control points on [-½, ½]
N = bspline_basis(k, Val(3), 0.12)               # SVector{7}, sum(N) == 1

VisualGeometryToolkitCore.bspline_basis — Method
bspline_basis(knots::SVector{K}, Val(p), x) -> SVector{K − p − 1}
bspline_basis(knots::SVector{K}, p::Integer, x)

Every degree-p B-spline basis function on knots at x, N_{1,p}(x), …, N_{K−p−1,p}(x) (Cox–de Boor, Piegl & Tiller 1997): 0/0 is 0, and the last non-empty knot span is closed on the right, so the values sum to one on the whole closed interval [knots[1], knots[K]]. x outside it is clamped onto it (constant extrapolation).

The basis (its knots and degree) leads, the point follows (signatures.md). The degree is a Val so the result's size is static and nothing allocates; the Integer form is the convenience. Scalar, isbits and generic in the element type (promote_type of x's and the knots'): it runs inside a KernelAbstractions kernel, in Float32, and under ForwardDiff. Why it is Core's and not BSplineKit's: a kernel needs an isbits basis on a static knot vector with a static result; on the CPU, BSplineKit's evaluate_all gives the same values (the tests check it). bspline_basis_iterative is its broadcast over an array.

The bending energy of a B-spline

bending_gram is ∫∫ f_xx² + 2 f_xy² + f_yy² of a tensor-product B-spline as a quadratic form in its coefficients, from BSplineKit's Galerkin matrices; bending_rows factors it into a regularizer's rows and bending_stencils gives it cell by cell on a large uniform lattice (cubic_lattice_basis, Core's generic-model lattice). The natural boundary condition f'' = 0 of BSplineKit's recombined basis is natural_extrapolation, the rule BoundaryRule applies to a lattice's nodes outside an imaged region by default (order = 2); its order = 3 is the curvature-preserving Δ³c = 0.

VisualGeometryToolkitCore.bending_gram — Method
bending_gram(B) -> Matrix{Float64}
bending_gram(Bx, By) -> Matrix{Float64}

The bending energy of a B-spline as a quadratic form in its coefficients: ∫ f''² of a curve on the BSplineKit basis B; ∫∫ f_xx² + 2 f_xy² + f_yy² of the tensor-product surface on Bx ⊗ By, vec(c)ᵀ G vec(c) with c laid [i, j] (the first index fastest). BSplineKit's Galerkin matrices of the basis's derivatives, over the bases' domains. Positive semidefinite, the affine functions its null space. A regularizer reads it as rows (bending_rows) or, on a large uniform lattice, cell by cell (bending_stencils, and over a mask of held nodes bending_rows(mask)); a lattice of vector-valued controls applies it per component.

VisualGeometryToolkitCore.difference_rows — Method
difference_rows(mask::AbstractMatrix{Bool}, order; axes = (1, 2)) -> SparseMatrixCSC{Float64, Int}
difference_rows(dims::Dims{2}, order; axes = (1, 2))

The forward differences Δᵒʳᵈᵉʳ (difference_stencil, any order ≥ 1: 1 a gradient, 2 the natural rule's, 3 the P-spline's) of a 2-D lattice of coefficients along the lattice axes (a subset of (1, 2), in that order), as a sparse operator on the lattice's column-major vector: one row per window of order + 1 consecutive nodes that lies wholly in mask (true: a node the rows may read), first the windows along the first axis ((i, j) … (i + order, j), j outer), then those along the second. dims is the unmasked lattice (trues(dims)): a full texel page (TW, TH) at order = 1 is its gradient, the horizontal differences first. A lattice of vector-valued controls applies it per component.

DᵀD is the P-spline difference penalty (Eilers & Marx 1996): at order = 3 it annihilates a quadratic along each axis, so only the variation beyond it is penalized. An N × 1 mask is a profile (rows along its one axis only). The isotropic pairing of the order-1 rows is gradient_pairs; a device solve takes the operator as a CSRMatrix.

VisualGeometryToolkitCore.difference_stencil — Method

Penalized least squares

Every penalized solve of the stack is min ‖A x − b‖² + λ‖D (x − c)‖², one owner per piece. The operator D: difference_rows (orders 1–3 on a masked lattice or a texel page, along chosen axes; gradient_pairs its isotropic order-1 pairs) or bending_rows (the bending energy), and row_stencils its rows as a nonlinear solve's residual blocks. The weight's unit: penalty_scale with mean_positive_eigenvalue (m̄). The linear solve on sparse operators, on any KernelAbstractions device: cgls on a PenalizedOperator of CSRMatrixes, or normal_cg on a normal operator AᵀA + DᵀWD that is only applied (its rows never stored): one conjugate-gradient iteration, Jacobi-preconditioned on request, one stopping rule relative to ‖Aᵀb + DᵀWh‖. The weight's choice by generalized cross-validation is VisualGeometryToolkitEstimation's (gcv_curve, gcv_select). No penalty fixes a gauge: a direction neither the data nor the penalty holds is held exactly by its caller.

VisualGeometryToolkitCore.CSRMatrix — Type

A sparse operator in compressed sparse rows on a KernelAbstractions device (default_device() when none is supplied: an accelerator when one is functional, else KA.CPU()): mul!(y, C, x) is one work item per row (each row's sum in its stored order: deterministic on every backend, no atomics). Adapt.adapt(backend, C) moves it. The operator a device solve (cgls) applies; its transpose is a second CSRMatrix of transpose(A) (PenalizedOperator holds both).

VisualGeometryToolkitCore.cgls — Method
cgls(op::PenalizedOperator, b; w = 1, h = nothing, diagonal = nothing, x0 = nothing, rtol = 1e-6, max_iter = 500)
    -> (; x, iterations, converged, relres)

The least-squares solution of min_x ‖A x − b‖² + ‖√w ∘ (D x − h)‖² (op's A and D; w a weight per penalty row, or one for all; h the penalty's target, nothing for 0) by CGLS — conjugate gradients on the normal equations (AᵀA + DᵀWD) x = Aᵀb + DᵀWh applied as the stacked operator [A; √W D], never formed — from x0 (a warm start; nothing: 0), on op's device (the vectors moved there; x returned on it). diagonal, the normal matrix's diagonal diag(AᵀA + DᵀWD) (positive), preconditions the iteration (Jacobi: the unknowns' columns scaled to unit norm), nothing none.

The stopping rule is relative to the normal equations' right-hand side, ‖sₖ‖ ≤ rtol · ‖Aᵀb + DᵀWh‖, sₖ = Aᵀ(b − A xₖ) + DᵀW(h − D xₖ) the normal-equation residual: a reference fixed by the problem, not by the start, so a warm start that is already close needs few or no iterations (a rule relative to ‖s₀‖ asks a warm start for rtol more digits of improvement than a cold one). converged when the rule is met within max_iter iterations; relres is ‖sₖ‖ / ‖Aᵀb + DᵀWh‖.

The rows of A stored; a problem whose normal operator is only applied (its rows never formed) solves with normal_cg, the same iteration.

VisualGeometryToolkitCore.mean_positive_eigenvalue — Method
mean_positive_eigenvalue(D) -> Float64
mean_positive_eigenvalue(Symmetric(DᵀD)) -> Float64

The mean of the positive eigenvalues of a penalty operator's normal matrix DᵀD: the trace over the rank, from the operator D itself (‖D‖²_F / rank D; the rank by a sparse QR for a sparse D, so a lattice of 10⁴ nodes needs no dense eigendecomposition), or from the normal matrix given as Symmetric (tr G / rank G). The two forms agree; a plain matrix is read as the operator, so the normal matrix must come wrapped. The m̄ of the penalty weight's normalization (penalty_scale).

VisualGeometryToolkitCore.normal_cg — Method
normal_cg(N, g; diagonal = nothing, x0 = nothing, rtol = 1e-6, max_iter = 500)
    -> (; x, iterations, converged, relres)

The solution of the normal equations N x = g of a penalized least squares, N = AᵀA + DᵀWD and g = Aᵀb + DᵀWh (cgls's problem), by conjugate gradients on N APPLIED: N a function N(y, x) writing y = N x into y, or an operator with mul!(y, N, x) (a matrix, a CSRMatrix). The problem whose rows are never stored — a panorama's pixels accumulated into a lattice stencil and a Schur block — solves here; one whose rows are stored solves with cgls, which applies the rows and so loses no digits to forming N. Both are one iteration with one stopping rule.

diagonal, N's diagonal (positive), preconditions the iteration (Jacobi), nothing none; x0 is a warm start (nothing: 0). The vectors live on g's KernelAbstractions backend (diagonal and x0 moved there; x returned on it), and N applies there. The stopping rule is cgls's, relative to the right-hand side: ‖g − N xₖ‖ ≤ rtol · ‖g‖, so a warm start at the solution takes 0 iterations. converged when it is met within max_iter iterations; relres is ‖g − N xₖ‖ / ‖g‖.

source
VisualGeometryToolkitCore.penalty_scale — Method
penalty_scale(energy, N, m̄) -> Float64

The unit of a penalty weight: λ = β · energy / N / m̄, β relative to the data's energy per parameter (N parameters) and to the penalty operator's mean positive eigenvalue m̄ (mean_positive_eigenvalue), so β means the same for every operator, lattice and region; β = 1 weighs the penalty like the data. The energy is the caller's: a linear solve's data energy (tr AᵀA, or a radiometric Σϕ²), or a nonlinear refine's Gauss–Newton energy tr JᵀJ over its parameters (the residuals of exact data vanish, so they cannot set a scale).

Vignetting

A camera's relative illumination V on the sensor as a B-spline in V on clamped knots (clamped_knots, bspline_basis), linear in its control points: a tensor-product surface over a sensor box (TensorProductVignetting) or a profile in the radius about a centre (RadialVignetting). A model is callable, v(u), and isbits, so a batch of sensor points goes through pointwise! on a device; coefficient_jacobian is its row of a least squares in the control points, active_coefficients that row's nonzeros, and pole_regular_basis the radial profiles smooth at their centre. The estimators that fit them are their owners': a radiometric calibration's, a panorama's self-calibration. VIGNETTING_TAGS is the fields' tag registry ("tensor_product", "radial", "log"), the type a file or a configuration names them by.

A radial profile reads its normalized radius on a chart of the distance from its centre (RADIAL_CHARTS, radial_chart): linear, ρ = d / radius, constant beyond the radius; or projective (chart = :projective, projective_chart), ρ = d / (radius + d), ½ at the radius and never beyond the knots (projective_knots: uniform in the distance up to the radius, one tail span beyond), so a profile whose centre moves still covers every pixel. with_center moves the centre and center_gradient is ∂V/∂c, for a fit with the centre as a parameter. Ported from RadiometricCamera, bit for bit.

v = RadialVignetting(12, SVector(2128.0, 1424.0), 1700.0)   # control points, centre and radius (camera pixels); V ≡ 1
w = RadialVignetting(13, SVector(2128.0, 1424.0), 2560.0; chart = :projective)   # ρ = ½ at the farthest corner
v = with_control_points(v, pole_regular_basis(v) * y)        # a profile with V′(0) = 0
v(SVector(2500.0, 1300.0))                                   # V at a sensor point

Blur

One blur of an imaging model — a camera's in-focus blur (diffraction, the sensor's anti-aliasing filter, demosaicing), a print's own blur — as a GaussianBlur. A point spread function is a probability density (where a photon from a point source lands), and a Gaussian blur is the density N(0, Σ), so it is held by its covariance, a CovMat{2} (cov; var and std per axis): round, axis-aligned (stored as an SDiagonal) or general, px² on a sensor, m² (quantities) on a print. Several blurs compose into a point spread: two Gaussians in sequence add their covariances (convolve), and a linear map of the plane pushes the covariance forward, Σ ↦ J Σ Jᵀ (propagate).

print  = GaussianBlur(0.02mm, 0.03mm)          # axis-aligned, on the print: m² quantities
total  = convolve(propagate(J, ustrip(mm, print)), camera)   # in mm², through the pixel footprint J (px/mm), then the camera's
std(camera)                                    # (0.6, 0.6) px

Thin-plate spline

f(𝐩) = a₁ + a_x 𝐩_x + a_y 𝐩_y + Σᵢ wᵢ U(𝐩, 𝐩ᵢ) with U = ½ r² ln r², through nodal values on scattered nodes (hoisted from RadiometricCamera, its arithmetic unchanged). ThinPlateSplineSystem is the host-side solver; the evaluator tps_evaluate and its gradient tps_gradient take isbits (nodes, w, a), allocate nothing and run in a KernelAbstractions kernel. tps_coefficients is a loop (no BLAS), and with the pure-bending projection tps_pure_bending it runs in a kernel on an adapted system (Adapt.adapt(backend, tps), a Float32 one by convert_eltype).

∇f = tps_gradient(tps.nodes, w, a, SVector(0.1, -0.2))

VisualGeometryToolkitCore.ThinPlateSplineSystem — Type
ThinPlateSplineSystem(nodes) -> ThinPlateSplineSystem{N}

The solver object of a thin-plate spline through N nodes in the plane: the node positions, the (N + 3) × N matrix coeff that maps nodal values to the spline's weights and affine part, (w; a) = coeff · values, and the N × N bending-energy form Q (valuesᵀ Q values = wᵀ K w, K = [U(𝐩ᵢ, 𝐩ⱼ)], see bending_energy). The target calibration kinds' pure-bending rule (is_pure_bending, tps_pure_bending) reads the 3 × N affine rows coeff[N+1:N+3, :] (a = coeff[N+1:N+3, :] · values); the plane fields [1 𝐩_x 𝐩_y] are formed from the nodes.

Everything it holds is in the CALLER's frame (frame in = frame out): the nodes as given, (w, a) of the spline f(𝐩) in those coordinates, and Q the bending form of those coordinates (valuesᵀ Q values = wᵀ K w, K of the given nodes: the values' unit squared over the nodes' unit squared, a fixed multiple of the bending energy J = ∫ f_xx² + 2f_xy² + f_yy² in the given coordinates).

The system is SOLVED in a conditioned frame, as an estimator's private normalization: the nodes are centred on their centroid and scaled by one isotropic factor σ (HartleyNormalization: mean distance √2 from the centroid), 𝐩′ = σ 𝐩 + 𝐭. An interpolating thin-plate spline is the same surface under a similarity of its domain, so only rounding changes: the weights map back as w = σ² w′, the linear part as (a_x, a_y) = σ (a′_x, a′_y), the constant as a₁ = a′₁ + a′ · 𝐭 + ln σ Σᵢ w′ᵢ |𝐩′ᵢ|² (the kernel's σ² ln σ · r² term, a constant under the side conditions Σ w′ᵢ = 0, Σ w′ᵢ 𝐩′ᵢ = 0), and Q = σ² Q′. (A PER-AXIS scaling is not a similarity: the spline through the same values then bends differently, so it is never used here.) Without it, nodes in pixels (thousands) put r² ln r² near 1e8 beside the unit column of P.

coeff is mapped back from the first N columns of the inverse of the conditioned system matrix [K′ P′; P′ᵀ 0], solved for those N right-hand sides by one LU factorization. The matrices live on the host; tps_coefficients turns nodal values into the isbits (w, a) that tps_evaluate and tps_gradient take.

tps_gradient(tps::ThinPlateSplineSystem, w, a, 𝐩) -> SVector{2}

The analytic gradient ∇f(𝐩) of tps_evaluate: (a_x, a_y) + Σᵢ wᵢ (𝐩 − 𝐩ᵢ)(ln r² + 1), since ∇_𝐩 ½ r² ln r² = (𝐩 − 𝐩ᵢ)(ln r² + 1); a node at r = 0 contributes zero. The sum is RadiometricCamera's board_height_grad term for term (its height field is this spline without the affine part, which is added last). Isbits inputs and allocation-free, and it runs in a KernelAbstractions kernel on the CPU backend, as tps_evaluate. Unlike tps_evaluate, which promotes, it CONVERTS the node coordinates to the promoted element type of w and 𝐩 (RadiometricCamera's board_height_grad rule): Float32 w and 𝐩 with Float64 nodes give a Float32 gradient. Supply the nodes in the evaluation's type and the two agree.

VisualGeometryToolkitCore.tps_pure_bending — Method
tps_pure_bending(tps::ThinPlateSplineSystem{N}, values) -> SVector{N}

The nodal values without the affine term of their interpolant — the pure-bending rule of the thin-plate target calibration kinds (HeightField, ThinPlateSpline): v ↦ v − M a(v), M = [1 u v] the plane fields at the nodes and a(v) the interpolant's affine coefficients (tps_coefficients). The spline through M a is that plane exactly, so the projection keeps the weights w and zeroes a; it is oblique (along the plane fields, not orthogonal to them: orthogonal to the affine rows of coeff) and idempotent. Values whose plane part is within 1e-12 of them (‖M a(v)‖ ≤ 1e-12 ‖v‖, the rule of is_pure_bending) are kept as they are, bit for bit, and a ForwardDiff Dual's partials are projected all the same, so a Dual through it is the derivative of the projection everywhere (the kinds' transform_deriv_params); other values are projected, values and partials. Loops only: allocation-free, generic in the element type and callable in a KernelAbstractions kernel on an adapted system.

tps_radial_basis(𝐩, 𝐪) -> scalar

The thin-plate spline's radial basis function U(𝐩, 𝐪) = ½ r² ln r² with r = ‖𝐩 − 𝐪‖ (the same as r² ln r), and U = 0 at r = 0. Quadrature

The probabilists' Gauss–Hermite rule gauss_hermite_prob (an expectation over N(0, 1), exact to degree 2n − 1) and the Hammersley points hammersley (a kernel's own low-discrepancy sample from its index).

VisualGeometryToolkitCore.gauss_hermite_prob — Method
gauss_hermite_prob(n) -> (nodes::Vector{Float64}, weights::Vector{Float64})

The n-point Gauss–Hermite rule for the standard normal weight (probabilists' form): Σ wᵢ f(xᵢ) ≈ E[f(X)], X ~ N(0, 1), the weights summing to one, exact for polynomials of degree 2n − 1. Closed forms for n ≤ 3; beyond, Golub–Welsch — the eigen-decomposition of the Jacobi matrix of the monic Hermite polynomials He_k (off-diagonal √k), the weights the squared first components of its eigenvectors. Ascending nodes. An ArgumentError for n < 1.

For N(μ, σ²), use the nodes μ + σ·xᵢ with the same weights.

The polar product rule over the unit disc ‖x‖ ≤ 1: Gauss–Legendre in the radius ρ ∈ [0, 1] (n_ρ nodes, QuadGK's gauss mapped from [−1, 1]) times n_φ equally spaced angles φ_j = 2π(j − ½)/n_φ; node (ρ cos φ, ρ sin φ) with weight ρ·w_ρ·2π/n_φ (the polar area element), radius-major (node (k − 1)·n_φ + j). One-dimensional minimization

VisualGeometryToolkitCore.grid_brent_minimum scans an evenly spaced grid and refines its least value by Brent's method: the stack's one 1-D minimizer (public, not exported).

VisualGeometryToolkitCore.grid_brent_minimum — Method
grid_brent_minimum(f, xs::AbstractRange; periodic = false) -> (; x, value, at_end)

The minimum of f over the evenly spaced grid xs (evaluated in its order), the least value refined by Brent's method (golden-section steps with parabolic interpolation; Brent 1973, ch. 5) between its neighbours: (; x, value, at_end) of the smallest value evaluated. Brent stops at its own floor: x within √eps·(|x| + step(xs)) (a smooth minimum is resolved no better than √eps relative), so the result needs no tolerance. On a periodic grid the neighbours wrap (f periodic). On a linear one a least value at an end of the grid is refined on its one neighbouring interval, and at_end says the result lies at that end: Brent's final bracket still has the end as its edge (every evaluation descended towards it). A value of Inf or NaN is never the minimum. The stack's one 1-D minimizer: Core's azimuthal minimum (the view-angle limit, the inscribed radius) and Estimation's GCV weight search (gcv_select).

VisualGeometryToolkitCore.lu_solve! — Method
lu_solve!(A::MMatrix{N, N}, b::MVector{N}) -> Int32

Solve A x = b in place by LU with partial pivoting — A is overwritten with its factors and the solution replaces b. Zero-allocation on static mutable arrays (StaticArrays' generic lu falls back to a heap path at these sizes), and pure register arithmetic, so it runs inside a KernelAbstractions kernel on any backend.

VisualGeometryToolkitCore.tree_sum! — Function
tree_sum!(@context, smem, tid, nt, half = Int32(128))

Workgroup tree reduction: sums smem[1:nt] into smem[1], thread tid of nt folding smem[tid + s] into smem[tid] for s = half, half/2, …, 1 with a barrier per level (left to right within a level, so the sum is the one every 256-thread reduction of the stack forms). half is HALF the workgroup size (the default serves 256-thread groups). A helper, not a kernel — it takes the kernel's @context so it may @synchronize; every thread in the group must call it, after a barrier that follows its write of smem[tid] (the barriers are convergent only then).

On KernelAbstractions' CPU backend a barrier must be written in the kernel body itself (its CPU transform splits the body at a syntactic @synchronize; one inside a called function is an error), so a CPU kernel calls this with a group of one, nt == 1 — the stack's CPU group size for its per-blob kernels — where there is nothing to fold and no barrier is taken: smem[1] is the sum.
