Core API

The package docstring, units and quantities, utilities, synthetic-data generation, the benchmark pool record, and the visualization stubs. The core composition and uncertainty types are on the Core Types API page.

The Package

VisualGeometryToolkitCore.VisualGeometryToolkitCore — Module
VisualGeometryToolkitCore

Geometry, camera models and the robust-estimation core of the visual-geometry stack. VisualGeometryToolkitFeatures, VisualGeometryToolkitIo, VisualGeometryToolkitEstimation and BlobBoards build on it.

Submodules

  • Primitives: conics and feature frames (Ellipse, Circle, Disc, OrientedDisc, EllipticFrame, AffineFrame), hyperplanes (Line2D, Plane3D), 3-D conics (Ellipse3D, Circle3D) and Paraboloid3D.
  • Cameras: sensors (CMOS_SENSORS), intrinsics, lens models (Lens, LiftLens, Pinhole, KannalaBrandt, Division, …), Camera, CameraModel, Rig, projection, calibration fits and P3P.
  • Synthetic: ground-truth generators and metrics for benchmarking estimators.

Key types in the parent module

  • Transform matrices: AbstractHomMat ⊃ AbstractAffineMat ⊃ AbstractSimilarityMat ⊃ AbstractEuclideanMat, plus FundMat, EssentialMat and CameraCalibrationMat.
  • Frame-tagged maps: EuclideanMap and HomographyMap carry Src/Dst tags from the open Frame hierarchy (ViewFrame, PixelFrame, GnomonicFrame, …); composition and inv are frame-checked.
  • Minimal solvers (homography_4pt, p3p, the 5-point essential and the fundamental-matrix solvers) and the manifolds their models are refined on.
  • The robust-loss family (AbstractLossShape, deploy), the block-coordinate-descent/LO interface shared with VisualGeometryToolkitEstimation, and FitResult, the one fit return type.
  • Units: FlexUnits with a pixel dimension (mm, px, dpi, ud"…", Size2).

Plotting loads as a package extension with any Makie backend.

See ARCHITECTURE.md (module graph, include order, extension points) and LOSSES.md (the robust-loss family) at the repository root.

VisualGeometryToolkitCore.default_device — Method
default_device() -> KA.Backend

The device every KernelAbstractions-generic entry point in the package family uses when the caller supplies none: an accelerator when one is loaded AND functional, else KA.CPU().

Memoized: resolution asks the vendor package whether it is functional, which is not free and cannot change within a session. _DEVICE_RESOLVER[] overrides it (including back to KA.CPU()); reset_default_device! clears the memo so the next call resolves again.

Supplying device = explicitly always wins — this only decides what "unspecified" means, and it is deliberately NOT the cheapest device (see the file header).

allowed_keys(::Type{T}, extra...) -> Vector{String}

VisualGeometryToolkitCore.check_keys — Method
check_keys(d::AbstractDict, allowed, section::AbstractString; retired = ())

Refuse unknown keys in table d with an ArgumentError naming the section, the offending keys and the allowed set. A typo'd knob that silently does nothing is the failure a config loader exists to prevent — a config that looks like it set max_trials but spelled it max_trial would otherwise run at the default and report success.

retired is a collection of exact (section, key) pairs: knobs removed because nothing read them, which recorded run sidecars (immutable provenance) legitimately still contain. Those load with a one-time warning; every other unknown key throws. Retirement is section-scoped on purpose — the same key in another table is a typo and must still fail.

VisualGeometryToolkitCore.Synthetic.imc_pose_error — Method
imc_pose_error(F_est, K, R_gt, t_gt) -> Float64

Image Matching Challenge pose error metric (DEGREES).

Decomposes E = KᵀFK into 4 possible (R, t) solutions, computes max(rotation_error, translation_error) for each, and returns the minimum. This is the coherent (single-decomposition) counterpart to optimistic_pose_error, which takes per-axis minima from possibly different decompositions; both report in degrees.

This is the standard metric from the IMC benchmark: it measures how well an estimated fundamental matrix recovers the true relative pose.

Arguments

  • F_est: Estimated 3×3 fundamental matrix
  • K: Shared 3×3 calibration matrix (or K1, K2 for different intrinsics)
  • R_gt: Ground-truth 3×3 rotation matrix
  • t_gt: Ground-truth 3-vector translation

Returns

  • Float64: Pose error in degrees (max of rotation/translation angular errors, minimized over the 4 essential matrix decompositions)

VisualGeometryToolkitCore.Synthetic.maa_score — Method
maa_score(e; T) -> Float64

Per-item contribution to the continuous mean_average_accuracy: max(0, 1 - min(e, T)/T), and 0 for non-finite e. Use this per-sample form for bootstrap resampling; mean(e -> maa_score(e; T), errors) == mean_average_accuracy(errors; T). T is required, as for the aggregate.

source
VisualGeometryToolkitCore.Synthetic.mean_average_accuracy — Method
mean_average_accuracy(errors; T) -> Float64

THE canonical mAA@T (≡ AUC@T): the normalized area under the empirical CDF of errors from 0 to T — (1/T)∫₀ᵀ F(t)dt, equivalently mean_p max(0, 1 - min(e_p, T)/T). Non-finite entries (failed estimates) contribute 0 but stay in the denominator. This is the EXACT AUC; the former discrete threshold-average variant is retired — it is strictly coarser (it cannot resolve errors below T/#thresholds). All consumers use this continuous statistic.

T is required, in the errors' own units: the threshold is a protocol parameter of the caller's benchmark (the IMC pose-error mAA takes T = 10 degrees), never a hidden default.

source
VisualGeometryToolkitCore.Synthetic.optimistic_pose_error — Method
optimistic_pose_error(E::AbstractMatrix, R_gt, t_gt) -> (Δr_deg, Δt_deg)

Lower-bound (per-axis-optimistic) pose error of an essential matrix against a ground-truth pose. Decomposes E into its 4 sign-ambiguous candidates and returns the per-axis minimum errors:

Δr_min = min over decomps k of  rad2deg(rotation_angle(RotMatrix{3}(R_kᵀ R_gt)))
Δt_min = min over decomps k of  rad2deg(translation_angle(t_k, t_gt))

The two minimums may come from different decompositions — the returned tuple does not correspond to any single (R, t) pair, and is therefore unrealizable as a coherent single-decomposition output. It bounds from below what any one decomposition could achieve per axis.

Used by the Shekhovtsov RANSAC-Scoring protocol (per-axis independent min, see RANSAC-Scoring/model_H.py:438-452) and by the pool record Pools.PoolPair, which stores errors_r / errors_t as separate columns.

For a coherent single-decomposition error: select the desired decomposition externally (e.g. via cheirality on real correspondences, or argmin_k max(Δr_k, Δt_k) against the oracle) and call pose_error(R, t, R_gt, t_gt) directly.

See also: pose_error, imc_pose_error.

VisualGeometryToolkitCore.Synthetic.optimistic_pose_error — Method
optimistic_pose_error(H::HomographyMat, R_gt, t_gt) -> (Δr_deg, Δt_deg)

VisualGeometryToolkitCore.Synthetic.projective_distance — Method
projective_distance(A, B) -> Float64

Distance between two models known only up to a nonzero scale and a sign (E, F, H, a radial camera's rows, a homogeneous vector): the Euclidean distance between the unit-normalized entries, with B taken in A's sign,

‖â − sign(â·b̂)·b̂‖ = min(‖â − b̂‖, ‖â + b̂‖),   â = vec(A)/‖A‖.

It lies in [0, √2], is 0 exactly when A ∝ B, and is symmetric. For small values it is the angle between the two representatives: 1 − |â·b̂| = d²/2.

VisualGeometryToolkitCore.Synthetic.perspective_augmentation — Method
perspective_augmentation(rng, H_wi::SMatrix{3, 3}, extent;
                         strengthen_max = 1.0, jitter_max = 0.1) -> SMatrix{3, 3, Float64}

An image→image homography that strengthens H_wi's perspective and adds a random-direction tilt. extent = (cx, cy, hx, hy) is the target's world bounding box (centre + per-axis half-extent). Strengthening scales the projective row's in-plane entries (the vanishing line) by 1 + γ, γ ~ U(0, strengthen_max), leaving the centroid fixed; the jitter is a tilt of magnitude ~ U(0, jitter_max) in a uniformly random direction, in the normalised frame. Returns the identity on any degeneracy (a singular H_wi), i.e. no augmentation.

Benchmark Pools

The pool record and the raw-pair interface (using VisualGeometryToolkitCore.Pools). The pool is the stack's one declared exception to "frame in = frame out": its data is stored in NormalizedImageFrame, and every accessor that crosses the boundary names it.

VisualGeometryToolkitCore.Pools — Module
Pools

The benchmark pool record and the raw-pair interface (using VisualGeometryToolkitCore.Pools):

  • PoolPair: one image pair of a scoring pool — correspondences, minimal-sample models and their pose errors, ground truth — in NormalizedImageFrame, with the per-image maps it was normalized by;
  • its accessors: num_points, num_models, pool_imc, gt_pose, calibration_matrices, pool_normalization, pool_frame_maps, pool_frame_calibrations, pool_pixel_scale, pixel_csponds and rig;
  • StereoRawPair: what a dataset reader's pair provides before a pool is drawn from it (pixel correspondences, calibration, image sizes, GT).

The record holds no residuals: a pool's residual matrices are a separate file, bound to the record by a content key, read by the evaluation package.

source
VisualGeometryToolkitCore.Pools.PoolPair — Type
PoolPair{M}

One image pair of a scoring pool: the light record — everything about the pair except the per-model residual matrix, which is a separate file bound to the record by a content key.

The pool is the one place in the stack that stores data normalized: every point datum and model is in NormalizedImageFrame (image centre, half-diagonal unit), through the per-image maps the record carries. See "Coordinate frame" below.

Type Parameters

  • M: Model type, expressed in NormalizedImageFrame (FundMat{Float64} for the E and F pools, HomographyMat{Float64} for the H pools).

Fields

  • csponds: Correspondences in NormalizedImageFrame — NOT pixels, stored as the columnar csponds(sources, targets) of SVector{2,Float64} sides (any vector of 2-vector pairs is converted to it at construction). Each side is mapped pixel → normalized by its own map (source_map, target_map). pixel_csponds is the exact way back to pixels.
  • K1::SMatrix{3,3,Float64,9}, K2::SMatrix{3,3,Float64,9}: the pixel calibration of the source and target cameras (calibration_matrices).
  • R_gt::SMatrix{3,3,Float64,9}, t_gt::SVector{3,Float64}: the GT relative motion, source → target (X₂ = R_gt·X₁ + t_gt; gt_pose).
  • models::Vector{M}: Precomputed minimal-sample models, expressed in NormalizedImageFrame (e.g. fundamentals conjugated by the per-image maps).
  • sample_indices::Matrix{Int}: (m, num_models) — 1-based sample indices per model.
  • errors_r::Vector{Float64}: (num_models,) — rotation error [deg] per model vs GT.
  • errors_t::Vector{Float64}: (num_models,) — translation error [deg] per model vs GT.
  • gt_inliers::BitVector: (n,) — GT inlier mask (from bundle adjustment), one entry per correspondence (checked at construction).
  • gt_variance::Float64: σ̂²p = RSS/ν of the residuals under the oracle pose (from the GT R, t) on the SfM-track keypoints — NOT a DLT refit. `ν = n·dg` (oracle: no fitted DOF). NaN if too few tracks.
  • source_map::SMatrix{3,3,Float64,9}, target_map::SMatrix{3,3,Float64,9}: the per-image maps T (pixel → NormalizedImageFrame) the data is stored in — the stored truth of the pool's frame, and the two sides of its pool_normalization (source_map(N), target_map(N)); framed, they are pool_frame_maps.
  • snn::Union{Nothing,Vector{Float32}}: (n,) — the per-correspondence second-nearest-neighbour ratio the pool's hypotheses were sampled by, where the generator's is known; nothing otherwise.

Coordinate frame

All point data (csponds, models, and the separate residuals) lives in NormalizedImageFrame: each image is normalized by its own T (source_map/target_map), isotropically — translate to the image centre and scale BOTH axes by 1/s, s = ½√(W²+H²) HALF the image diagonal: (ũ,ṽ) = (u−W/2, v−H/2)/s, which puts the image corners at unit radius (DiagonalNormalization(size) per side: pool_normalization(size1, size2), what the pool generator writes). Every width on pool data — the outlier half-width, the loss width, the IG scale prior — is in this half-diagonal unit. The stored maps are the truth of the frame: every conversion goes through them and none is reconstructed from the image size.

Isotropy is the key property. Feature noise is isotropic in pixels (Σ_px = σ²·I); a single scale maps it to Σ_pool = (σ²/s²)·I, still isotropic, so the scalar σ², the single global outlier half-width, the IG scale prior, and the Sampson distance all stay correctly specified. (A per-axis box normalization would make Σ_pool anisotropic and force a full 2×2 noise covariance through the scoring.) Normalizing by image size — not focal — also keeps the outlier half-width resolution/FOV-uniform: the K⁻¹ calibrated CHART — the z = 1 plane, VisualGeometryToolkitCore's GnomonicFrame — would not (extent ≈ tan(fov/2), so a single outlier half-width drifts ~4× with focal across PhotoTourism), which is why the pool frame is the scoring frame even for the calibrated (essential) problem.

Re-solving / local-optimization applications

Because the pool-frame maps T are stored, the record is self-contained for re-solving and LO: the metric frame is recovered EXACTLY (no reconstruction from image size or principal point). With T and the pixel K, the pool-frame calibration is Kc = T·K (pool_frame_calibrations), and:

  • pool frame → the calibrated z = 1 CHART (GnomonicFrame, not a unit ray): x_chart = inv(Kc) · x_pool, a unit BEARING being x_chart / ‖x_chart‖;
  • a pool-frame fundamental F → metric essential: EssentialMat(F, Kc₁, Kc₂);
  • scoring an essential E in the pool frame: FundMat(E, Kc₁, Kc₂) Sampson.

This is exact, so the global pool-frame outlier half-width needs no per-pair conversion. A pixel tolerance enters the pool frame only through pool_pixel_scale.

Spatial Queries

Allocation-free queries on SpatialIndexing.jl's R-tree (using VisualGeometryToolkitCore.SpatialQueries): the intersection query with early exit and the branch-and-bound nearest neighbour, with a reusable state for batches, and the in-place OMT bulk load. bbox gives a shape's query rectangle.

VisualGeometryToolkitCore.SpatialQueries — Module
SpatialQueries

Allocation-free queries on a SpatialIndexing.jl RTree (using VisualGeometryToolkitCore.SpatialQueries):

  • foreach_intersecting: call a function on every element whose bounding box intersects a query Rect, with early exit;
  • nearest_neighbor: the element nearest a point (branch-and-bound), within an optional squared radius;
  • nearest_neighbor! with a NearestNeighborState: the same query with its state supplied, so a batch of queries allocates nothing;
  • bulk_load!: SpatialIndexing's OMT bulk load, sorting the caller's elements in place.

The trees are SpatialIndexing's own (RTree, SpatialElem, Rect); build them with bulk_load!, or SpatialIndexing's insert! or load!. VisualGeometryToolkitCore's bbox gives a shape's Rect.

Call f(elem) on every element of tree whose bounding box intersects rect (closed boxes: touching counts). f returns true to stop the query early and false to continue. Returns true when f stopped it.
