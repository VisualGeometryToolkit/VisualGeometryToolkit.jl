Generic Camera Models API

Generic camera models: a spline grid of rays over the image, central or noncentral, with its window interface and undistortion. Split from the Cameras API page. See the Cameras guide.

VisualGeometryToolkitCore.Cameras.CentralGenericModel — Type
CentralGenericModel{T} <: AbstractCameraModel

The central generic camera model: a grid of UNIT observation directions (Matrix{Vec3{T}}, indexed [gy, gx]), interpolated by a uniform cubic B-spline over the calibrated image area (calib_min_x, calib_min_y)– (calib_max_x, calib_max_y) (inclusive integer pixel indices, COLMAP frame). backproject is the normalized spline value; project is the reference implementation's pixel-space LM (initialized at the calibrated area's center, or at init). Directions are re-normalized at construction (the reference's Read() behavior).

CentralGenericModel(model::CameraModel, (width, height); grid_size, calib_area)

Initialize FROM a parametric model. init = :interpolate (default) solves the cubic-prefilter tridiagonal system per axis so the spline INTERPOLATES the source's backprojection at the grid nodes — the true approximation floor; init = :sample is quasi-interpolation (control = sample), which smooths curvature by (h²/6)·f″. max_radius_px clamps NODE SAMPLING to the source's lit field (default: just inside the lens's horizon when it has one) — beyond it nodes sample at the radially-clamped pixel, so the global prefilter solve never rings against near-fold curvature or unlit extrapolation. The bridge from the parametric zoo into the generic family.

VisualGeometryToolkitCore.Cameras.NoncentralGenericModel — Type
NoncentralGenericModel{T} <: AbstractCameraModel

The non-central generic camera model: per-grid-point observation LINES — directions (unit, re-normalized at construction) and points (a point on each line), both Matrix{Vec3{T}} indexed [gy, gx] and interpolated by the same uniform cubic B-spline. backproject returns a Ray3; project is the pixel-space LM (_pixel_lm) on the reference's tangent-plane point-to-line residual. With an all-zero points grid the model is exactly central.

NoncentralGenericModel(model::CameraModel, (width, height); grid_size, calib_area)

Initialize from a parametric (central) model: directions by quasi-interpolation, points all zero.

VisualGeometryToolkitCore.Cameras.Ray3 — Type
Ray3(origin, direction)

A 3D ray: origin + t·direction, direction unit by contract. The unprojection currency of NoncentralGenericModel — a non-central pixel observes a LINE in the camera frame, not a direction through a common center.

VisualGeometryToolkitCore.Cameras.default_generic_grid — Method
default_generic_grid(width, height) -> (gw, gh)

The control grid the reference lays over a width × height pixel area: one node every 64 px plus the three border nodes the cubic window needs (ceil(width / 64) + 3, likewise in y; at least 4). Apply it to the CALIBRATED AREA, not the frame, when the two differ — a circular fisheye's lit field is smaller than its sensor.

VisualGeometryToolkitCore.Cameras.direction_tangents — Method
direction_tangents(d) -> (t1, t2)

The reference's orthonormal tangent basis of the unit direction d — the 2-dof chart a grid control moves in (normalize(d + δ₁t1 + δ₂t2)), and the plane a direction residual is measured in.

VisualGeometryToolkitCore.Cameras.spline_support — Method
spline_support(m::CentralGenericModel, pixel) -> (ix, iy) | nothing

The window pixel (COLMAP frame) reads: the 4×4 controls m.grid[iy - 3 + r, ix - 3 + c], r, c ∈ 1:4 (row = y tap, column = x tap) — the index pair spline_weights takes. nothing outside the calibrated area.

source
VisualGeometryToolkitCore.Cameras.spline_weights — Method
spline_weights(m::CentralGenericModel, ix, iy, pixel)
    -> (w::SMatrix{4, 4}, wx::SMatrix{4, 4}, wy::SMatrix{4, 4})

The weights of window (ix, iy)'s 16 controls at pixel — w[r, c] multiplies m.grid[iy - 3 + r, ix - 3 + c] — and their derivatives with respect to the pixel's x and y. The window is the caller's: for a pixel that has drifted off the window's own cell the cubic pieces extrapolate smoothly, which is what a refinement holding the support fixed between rebuilds needs. sum(w .* grid_window) is the unnormalized direction backproject normalizes.

source
VisualGeometryToolkitCore.Cameras.undistort — Method
undistort(m::CentralGenericModel, img, Kr::StaticMatrix{3,3}, rect;
          scale = 1, fillvalue = zero(eltype(img))) -> FramedImage

Render img (taken by the generic camera m) undistorted into the TARGET PINHOLE camera Kr: for each output pixel of the window rect (of the target pinhole's frame), the ray Kr⁻¹·ũ is projected through m and the source sampled bilinearly. A generic model has no K/lens split, so the caller names the pinhole it rectifies into — supply the source parametric camera's K to land in the SAME frame as its own undistort, making the panels directly comparable.

Projection has no closed form (the reference's per-point LM), so the undistortion map – the inverse of a smooth spline diffeomorphism, and therefore exactly as smooth as the model itself – is solved only at a coarse grid (oversample x the model's own grid density, warm-started project calls) and bilinearly interpolated to full output resolution before sampling. Verified against a per-pixel LM sweep (retired after verification; see f6e92fa): max positional error 0.19 px at the default oversample = 4 on a 3 MP hallway calibration, O(h^2) in oversample. Pixels whose ray falls outside the calibrated area fill with fillvalue.

Central only: a NON-central pixel observes a line, so its undistortion is depth-dependent (parallax) — there is no single answer per pixel, and no method is provided on purpose.

VisualGeometryToolkitCore.backproject — Method
backproject(m::CentralGenericModel, pixel) -> SVector{3} | nothing

The unit observation direction of pixel (COLMAP frame): the normalized uniform-cubic B-spline value of the direction grid. nothing outside the calibrated area.

VisualGeometryToolkitCore.backproject — Method
backproject(m::NoncentralGenericModel, pixel) -> Ray3 | nothing

The observation LINE of pixel: both grids evaluated with the same spline window; the direction normalized, the origin as interpolated. nothing outside the calibrated area.

VisualGeometryToolkitCore.project — Method
project(m::CentralGenericModel, rays::AbstractVector{<:StaticVector{3}};
        init, iters = 10, tol = 1.0e-6) -> (; px, ok)

Batched projection: one LM per ray (at most iters iterations) with the ANALYTIC spline Jacobian, on any KernelAbstractions backend — supply device arrays (rays, inits, and a device copy of m.grid uploads automatically) and the solve runs on the GPU; host arrays run the identical kernel threaded on the CPU. The backend is the rays' own: every output is allocated beside them. init is a same-length vector of warm starting pixels (the caller's structure — scanlines, previous frames — is what makes a few iterations enough; see the reference's ProjectWithInitialEstimate). Returns pixel positions and a convergence mask (‖residual‖ < tol).

source
VisualGeometryToolkitCore.project — Method
project(m::CentralGenericModel, X; init = nothing) -> SVector{2} | nothing

Project the camera-frame point X to a pixel (COLMAP frame): the reference's Levenberg–Marquardt in pixel space, minimizing the mismatch between the pixel's unprojected direction and normalize(X), initialized at the calibrated area's center (or init). nothing when the point does not project into the calibrated area (or the optimization fails to reach the reference's 1e-12 cost).

source
VisualGeometryToolkitCore.project — Method
project(m::NoncentralGenericModel, X; init = nothing) -> SVector{2} | nothing

Project the camera-frame point X to a pixel: LM on the reference's tangent-plane point-to-line residual — the two components of origin(p) − X in the tangent basis of the pixel's line direction — so a converged pixel's observation line goes through X. init defaults to the calibrated area's center; for a non-central model a good initial estimate matters (the reference exposes the same knob).

source
VisualGeometryToolkitCore.unproject — Method
unproject(m::CentralGenericModel, pixel, depth) -> SVector{3} | nothing

The 3D point at z-depth depth along the pixel's observation direction (VGC's unproject convention). nothing outside the calibrated area or for a direction with non-positive z.
