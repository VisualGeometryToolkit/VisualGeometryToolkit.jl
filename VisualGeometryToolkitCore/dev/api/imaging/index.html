VisualGeometryToolkitCore.Cameras.FrameTransition — Type
FrameTransition{Src <: RetinalFrame, Dst <: RetinalFrame}

The framed transition map between two retinal frames of the SAME view, {Src → Dst} — a pure radial reparameterization of the viewing sphere, computed once through the sphere as the conjugation

section(Dst) ∘ lift(Src)

so every pair among the five frames (GnomonicFrame, EquidistantFrame, StereographicFrame, EquisolidFrame, OrthographicFrame) is served by ONE implementation, with no per-pair closed forms to keep consistent. Azimuth is preserved; the radial profile map is profile_Dst(profile_Src⁻¹(r)).

Mint with frame_transition; inv is the reverse pair (an honest inverse — on the sphere the frame projections are invertible sections). As a FramedStage it composes junction-checked with the rest of the framed surface, and being isbits it composes into a per-point map that pointwise! runs over a batch.

Domain: the intersection of the two frames' honest domains, enforced — points outside Src's frame radius (equisolid r > 2, orthographic r > 1) and rays outside Dst's domain (gnomonic Z ≤ 0, orthographic Z < 0, the stereographic/equidistant antipode) map to NaN at the edge rather than aliasing.

FramedAffine{Src <: Frame{2}, Dst <: Frame{2}, T}

VisualGeometryToolkitCore.Cameras.FramedAffine — Method
FramedAffine(ImageFrame{id}, NormalizedImageFrame{id}, sz::Size2) -> FramedAffine
FramedAffine(PixelFrame{O}, NormalizedImageFrame{id}, sz::Size2) -> FramedAffine

The normalization map of an image of size sz (pixels, plain or px): x ↦ (x − c) / s, c the image centre and s = hypot(width, height) / 2 the half-diagonal — DiagonalNormalization, framed — so the image corners land at unit radius. The storage frame of the benchmark pools, where one noise level and one threshold must mean the same across resolutions; estimation normalizes by HartleyNormalization. The centre is written in the source's convention: (width/2, height/2) for an ImageFrame (always read :colmap), moved by EuclideanMap(PixelFrame{:colmap}, PixelFrame{O}) for a PixelFrame{O}, so every convention lands on the same normalized point. inv de-normalizes. The view ids must agree (a MethodError otherwise).

VisualGeometryToolkitCore.Cameras.FramedChain — Type
FramedChain{Src <: Frame, Dst <: Frame, T <: Tuple} <: FramedStage{Src, Dst}
FramedChain(stages::FramedStage...)

Composite of framed stages, applied FIRST-TO-LAST (stages[1] innermost): a FramedChain consumes src_frame(stages[1]) coordinates and produces dst_frame(stages[end]) coordinates, and is itself a FramedStage — so chains compose with stages and with each other under the same checked ∘, flattening (no nested chains from composition).

The vararg constructor checks EVERY inner junction under the standing wildcard truth table and throws an ArgumentError naming the first mismatched junction; ∘ between stages performs the same check as a MethodError (the house composition idiom). The callable unrolls at compile time. inv inverts and reverses the stages (frames swap) — and is therefore a MethodError for chains containing a ray projection, whose fiber collapse has no inverse.

VisualGeometryToolkitCore.Cameras.FramedProjection — Type
FramedProjection{Src <: Frame{3}, Dst <: Frame{2}} <: FramedStage{Src, Dst}

The framed ray-frame projection (3D → 2D): the view's unit rays onto the retinal frame Dst, the section of the ray sphere that Dst's family defines (_sphere_section, one definition per family, shared with the lens contract in lens_rays.jl). The stage wears the frames; the math is the lens contract's. One type serves the five geometry-defined families, and the five names below are aliases with the Dst family fixed:

aliasDst familyimage of a ray at polar angle θ, azimuth ψ
FramedPerspectiveGnomonicFrametan θ·(cos ψ, sin ψ) — (X/Z, Y/Z); NaN for Z ≤ 0
FramedEquidistantProjectionEquidistantFrameθ·(cos ψ, sin ψ), θ ∈ [0, π)
FramedStereographicProjectionStereographicFrame2·tan(θ/2)·(cos ψ, sin ψ); NaN at the antipode
FramedEquisolidProjectionEquisolidFrame2·sin(θ/2)·(cos ψ, sin ψ), the whole sphere
FramedOrthographicProjectionOrthographicFramesin θ·(cos ψ, sin ψ); NaN for Z < 0 (the frame folds)

Each alias has the keyword constructor Alias(; id::Symbol = :_), which mints FramedProjection{ViewFrame{id}, Family{id}}() (anonymous view :_ by default — see DistortedFrame); Alias{Src, Dst}() and x isa Alias work as they would on a type of its own. The azimuth is ψ = 0 at the on-axis poles (X = Y = 0). A ray outside a frame's honest domain is answered NaN, never aliased onto an in-frame point.

No inv — deliberate

A projection collapses each ray (a 1-parameter fiber) to a point: a 3D → 2D fiber collapse has no inverse, so inv is absent by design (a MethodError, pinned by test; the explicit throw is needed because CoordinateTransformations defines a generic inv(::Transformation) fallback, an ErrorException, which would misreport the ABSENCE as a missing definition). The right-inverses — the SECTIONS of the projection, each selecting one point per fiber via a depth — are unproject (pixel + depth → 3D point) and backproject (pixel → unit ray, the norm-one section); use those to go back.

Serves the lenses by distortion_frame(lens): the perspective-plane lenses use the gnomonic alias, the omnidirectional ones the others.

VisualGeometryToolkitCore.Cameras.FramedStage — Type
FramedStage{Src <: Frame, Dst <: Frame} <: Transformation

Abstract supertype of the framed imaging-chain stages: a map consuming Src-frame coordinates and producing Dst-frame coordinates (same tag semantics as EuclideanMap/HomographyMap). Concrete stages: FramedPerspective, FramedEquidistantProjection, FramedStereographicProjection, FramedEquisolidProjection, FramedOrthographicProjection (3D → 2D ray projections), FramedLensProjection (the fused model-carrying 3D → 2D projection of a lens with a parametric projection), FramedDistort, FramedUndistort, FramedAffine, FrameTransition (2D → 2D), the sphere self-maps RayMap/InverseRayMap (3D → 3D), and the composite FramedChain.

∘ between framed stages is junction-checked under the standing wildcard truth table (see Base.:∘ at EuclideanMap) and produces a flat FramedChain; a labeled junction mismatch is a MethodError. Composing with a foreign (unframed) Transformation falls through to CoordinateTransformations' lazy composition — gradual, as always.

VisualGeometryToolkitCore.Cameras.RayMap — Type
RayMap{F <: Frame{3}, C <: RetinalFrame, L <: AbstractLensModel}

The lens's SPHERE SELF-MAP D: S² → S² as a framed stage {ViewFrame{id} → ViewFrame{id}}: the lens's forward distortion free of any image frame, computed as the conjugation

D = lift ∘ distort ∘ section

where section is the projection onto the lens's defining frame (distortion_frame) restricted to the unit sphere and lift is its inverse. C records the defining frame the conjugation runs through; D itself needs no 2D frame tag — its input and output are rays of the view's 3D frame.

Acts on RAYS: any 3D representative may be supplied (the input norm is irrelevant — both frame projections are scale-invariant on ray representatives), and the output is always the UNIT bearing vector of the re-oriented ray.

Restricted to the sphere the frame projections are sections — invertible, unlike the fiber-collapsing full projections FramedPerspective / FramedEquidistantProjection — which is why RayMap has an honest inv (the InverseRayMap undistort conjugation) while the projection stages deliberately have none.

Domain: the conjugation is defined exactly where the defining frame is — the forward hemisphere Z > 0 for gnomonic-frame lenses, θ ∈ [0, π) (all but the exact backward ray) for equidistant-frame lenses. Rays outside the frame's domain map to NaN.

Mint with ray_map; direct type-parameter construction is an unchecked expert surface, like relabel.

VisualGeometryToolkitCore.Cameras.distortion_frame — Method
distortion_frame(lens::AbstractLensModel) -> Type{<:RetinalFrame} | nothing

The ray frame a lens model's distortion is DEFINED in — the Src frame kind of its framed distortion stage, and the frame the stage-1 ray projection of imaging_chain must land on. For a Lens it is its projection's frame (projection_frame): GnomonicFrame for the perspective projection, EquidistantFrame for the equidistant one (Kannala–Brandt's θ_d = θ·(1 + k₁θ² + …) is a radial factor there), and so on. A LiftLens is read on the gnomonic frame. nothing for a parametric projection, whose frame its coefficients define — ModelDefined in the FrameDependence vocabulary, which no Symbol tag can carry — so there is no frame + distortion SPLIT; imaging_chain serves such a lens through the fused model-carrying FramedLensProjection onto DistortedFrame{id}.

Relation to the Bool capability traits: has_distortion(lens) == false means the distortion is the identity in this frame, and the chain collapses the ray frame onto DistortedFrame (no distortion stage) — see the collapse rule there. All these frames assume a single center of projection.

VisualGeometryToolkitCore.Cameras.frame_transition — Method
frame_transition(C1::Type{<:RetinalFrame{id}}, C2::Type{<:RetinalFrame{id}}) -> FrameTransition

Mint the framed transition map {C1 → C2} between two retinal frames of view id (the id must MATCH — a transition between frames of different views is a MethodError, the labeled-junction rule):

t = frame_transition(EquidistantFrame{:_}, GnomonicFrame{:_})
t(Vec2(θ, 0.0))            # == Vec2(tan(θ), 0.0)
inv(t)                     # the reverse transition {Gnomonic → Equidistant}

This makes a first-class named object of what production code usually hides in an inline expression: OpenCV's cv::fisheye::undistortPoints ends with the line scale = tan(θ)/θ_d — that line IS frame_transition(EquidistantFrame{id}, GnomonicFrame{id}), the equidistant → gnomonic frame change applied after the polynomial θ-inverse, unnamed and unchecked in the C++. Here the same reparameterization is a framed stage with checked junctions and honest domain edges (see FrameTransition).

VisualGeometryToolkitCore.Cameras.imaging_chain — Method
imaging_chain(intrinsics, lens; id::Symbol = :_) -> FramedChain
imaging_chain(model::CameraModel; id::Symbol = :_)

Mint the fully-typed framed imaging composite {ViewFrame{id} → ImageFrame{id}} — the frame-checked counterpart of imaging_transform's frame-free affine_part(K) ∘ lens. Every inner junction is checked at construction:

ViewFrame{id} ─ ray-frame projection → distortion_frame(lens){id}
              ─ distort_stage(lens)  → DistortedFrame{id}
              ─ calibration_stage(K) → ImageFrame{id}

Stage 1 is FramedPerspective for perspective-plane lenses and FramedEquidistantProjection for equidistant-frame (omnidirectional) lenses — see distortion_frame. When the lens is the identity in its defining frame (Pinhole; a pure Lens(Equidistant())), the distortion stage is omitted and K consumes the ray frame directly (frame collapse — see DistortedFrame). A lens with a parametric projection is served by one fused FramedLensProjection onto DistortedFrame{id}.

The id keyword threads the view identity; the default is the reserved anonymous view :_ (junctions then check by frame KIND — the distort-vs-undistort direction check needs no view identity). Rig-derived chains label from the rig's minted ids:

a, b = ids(rig)
chain₁ = imaging_chain(model(source(rig)); id = a)   # {ViewFrame{a} → ImageFrame{a}}

Numerically the chain matches imaging_transform: bit-identical for perspective-plane lenses (identical operations in identical order); equivalent to floating-point round-off for equidistant-frame lenses, whose framed route works in the model's defining frame instead of hopping through the gnomonic plane (atan/tan cancellation — the legacy callable's route).

VisualGeometryToolkitCore.Cameras.ray_map — Method
ray_map(lens::AbstractLensModel; id::Symbol = :_) -> RayMap

Mint the lens's sphere self-map D: S² → S² as the framed stage {ViewFrame{id} → ViewFrame{id}} — what a central lens actually does, stated with no image frame: it RE-ORIENTS rays. The familiar 2D distortion polynomial is the conjugation section ∘ D ∘ section⁻¹ in the lens's defining frame (distortion_frame); ray_map returns D itself.

Input is any 3D ray representative (norm irrelevant); output is the unit bearing vector of the re-oriented ray. inv yields the undistort conjugation (InverseRayMap) — honest, because on the sphere the frame projections are invertible sections. Rays outside the defining frame's domain (gnomonic: Z ≤ 0; equidistant: the exact backward ray) map to NaN — see RayMap.

For lenses whose distortion is the identity in their defining frame (Pinhole, a pure Lens(Equidistant())), D is the identity map — still framed, still returning the unit representative. For COLMAP's thin-prism fisheye the conjugation runs through its equidistant frame, where its distortion is the additive bundle. A lens with a parametric projection has no frame split and is scoped out (ArgumentError), exactly like distort_stage.

D exists only for CENTRAL lenses (single center of projection, which every VisualGeometryToolkitCore lens model satisfies): a finite or thick pupil has no sphere self-map, because its rays do not share a center — that regime is ray tracing, downstream.

Targets

A calibration target is a MODEL, the analogue of a camera model: AbstractTarget promises points(target) in its own TargetFrame{id}; PointTarget holds explicit (nominal or estimated) points, PlanarTarget a design — its nominal points, or the reference they are resolved from — and a TargetCalibration taking the design to the physical target. A target whose geometry an estimator refines implements the calibratable-target protocol (parameter_vector, with_parameters, minimal_manifold, regularizer, and CoordinateTransformations' transform_deriv_params).

A standard layout is a constructor, an AbstractTargetLayout: Kalibr's AprilGrid is AprilGrid(; tag_rows, tag_cols, tag_size, tag_spacing, apriltag_family, first_id) (lengths, the spacing the gap between two tags), PlanarTarget(grid; calibration, board, canvas, placement) its tag corners in Kalibr's point order and frame, and point_index(grid, tag, corner) the point of a detected corner. Schöps et al.'s tagged star pattern is SchoepsPattern(; squares_x, squares_y, square_length, apriltags, star_segments, apriltag_family), and PlanarTarget(pattern; calibration, board, canvas, placement) its star features in Schöps' feature order (feature id k is point k + 1). The target records its layout, layout(t), so that VisualGeometryToolkitIO writes it as one (its tag in TARGET_LAYOUT_TAGS).

The affine print error is its Iwasawa factors. An affine map of the design p ↦ A p + b factors as A = s·R·D·U (the KAN decomposition): a rotation, a scale, a det-1 diagonal (the aspect) and a unit upper-triangular matrix (the skew). The calibration composes them in that canonical order, EuclideanMap ∘ Scale ∘ Aspect ∘ Skew, and holds only the ones its data observes. With the target's pose estimated jointly, the rotation, the translation and the scale are the pose's — a target and the same target turned, shifted or scaled are the same images — so the print error is Aspect ∘ Skew, two parameters and no gauges; a measured length (a ruler) adds Scale; a known pose (a fixture, motion capture) the rigid member too. The counts agree: an affine map of R^N has N² + N parameters, the pose N(N−1)/2 + N and the scale one, which leaves (N−1) + N(N−1)/2. Aspect, Skew and Scale are N-generic; a planar target takes N = 2.

The thin-plate kinds are pure bending. An in-plane spline's displacements and a height field's heights have no affine term in their interpolant: the spline through each nodal value vector is Σ wᵢ U(·, pᵢ) alone, its affine coefficients a (tps_coefficients) zero — intrinsic to the spline, whatever the node distribution. The constructor and with_parameters project what they are given onto that subspace, v ↦ v − M a(v) with M = [1 u v] at the nodes, keeping the bending (values whose affine term is within 1e-12 of them are kept bit for bit, so RadiometricCamera's board heights, the bending part of its spline at its chart nodes, are kept unchanged). The condition is defined on the nodes the spline is built on: the radial basis U(r) = r² log r is not scale-invariant, and scaling the nodes moves a constant (a piston) between the affine and the bending parts — build the thin-plate kinds on a dimensionless chart of the board. An affine displacement belongs to the affine factors and a plane of heights to the pose; a spline built from either is the identity. So the canonical print error with a jointly estimated pose is

HeightField(nodes, h) ∘ ThinPlateSpline(nodes, fx, fy) ∘ Aspect(a) ∘ Skew(u)

and no kind has a gauge: every direction a composition's parameters may move in is observable, and the joint pose/calibration Jacobian has full column rank. The stored parameters stay the nodal values (2K, K), with 2K − 6 (K − 3) free directions; a covariance over them has that rank.

A PlanarTarget takes one kind, or kinds in the canonical order HeightField ∘ ThinPlateSpline ∘ EuclideanMap ∘ Scale ∘ Aspect ∘ Skew, any of them left out, and refuses any other composition with an ArgumentError; it stores a composition right-associated, whatever association ∘ built. A composition's parameters, names, bounds, Jacobian columns and regularizer rows are in CoordinateTransformations' order, the outer member's first. The 0.4 AffineMap kind (tag "affine") is retired.

The thin-plate kinds are splines over K fixed nodes in the target's plane (the numerics' ThinPlateSplineSystem), their parameters the nodal values; a height is tps_evaluate of its spline, bit for bit. Lengths (a rigid member's translation, nodes, displacements, heights) are in the design's form, plain or physical, and move with ustrip/with_unit; Scale, Aspect and Skew are dimensionless. A calibration may be Uncertain(c, CovMat(Σ)), Σ over its parameters, as a pose may be.

A calibration on the board's own chart. "No affine term" is a property of the nodes a thin-plate kind is built on (r² log r is not scale-invariant: rescaling the nodes moves a piston into the affine part), so a field computed on a dimensionless chart of the board — RadiometricCamera's page [0, 1]² — stays on that chart, and the target places the chart with a placement, Core's SimilarityMap{3} S₃ of scale side, the identity rotation and the translation (origin, 0) (the design point p = origin + side·c): PlanarTarget(…; calibration, placement) applies its calibration as the composition S₃ ∘ lift ∘ C ∘ S₂⁻¹, a height scaled by side. The calibration is plain chart numbers whatever the points' form; the placement is fixed data, plain numbers in the points' unit (metres for a physical target, rescaled by ustrip/with_unit), and adds no parameters. canvas is the printed page the board lies on, a Canvas (its size, its corner in the design chart and optionally the printed image, a CanvasTexture), or nothing: the record of what was printed, which the points, the calibration and surface never read. It is in the points' form like the board, and the board lies on it to within the same rounding margin (an ArgumentError otherwise). canvas(t) reads it; ustrip and with_unit move it with the points.

placement is a SimilarityMap{3}, or nothing: where the calibration's dimensionless chart lies in the target's frame (scale the chart's side, the identity rotation, the translation (origin, 0); see "The placement" in targets.jl). With one, the calibration acts in that chart — a HeightField or ThinPlateSpline built on the chart's nodes (RadiometricCamera's page [0, 1]²), its values in chart units — and is plain numbers whatever the points' form (an ArgumentError for a calibration with units); the placement is plain numbers in the points' unit (metres for a physical target): points(t) = (S₃ ∘ lift ∘ C ∘ S₂⁻¹).(nominal), a height scaled by the placement's side. The calibration's parameters, manifold and regularizer are its own: the placement is fixed data and adds none. A unit move moves the placement and leaves the calibration as it is. placement(t) reads it.

A target built from a parametric design, PlanarTarget(layout; calibration, board, canvas, placement) (an AbstractTargetLayout: AprilGrid, SchoepsPattern), holds the layout's points as its nominal points and records the layout, layout(t); every other construction records none.

VisualGeometryToolkitCore.Cameras.TargetManifold — Type
TargetManifold(target; known = ()) <: Manifold

A calibratable target's manifold anchored at target: minimal_manifold(target; known). No calibration kind has a gauge (the affine factors leave the pose's directions out of the composition, the thin-plate kinds hold no affine or plane part), so the manifold is every direction the calibration's parameters may move in, and with the target's pose estimated jointly every one of them is observable.

That holds for the print error a jointly estimated pose leaves, HeightField ∘ ThinPlateSpline ∘ Aspect ∘ Skew. A rigid member (EuclideanMap) duplicates the pose's rotation and translation, and a Scale the pose's scale (its translation's length): with the pose estimated jointly they are the pose's gauges, and the manifold REFUSES them (ArgumentError) unless the caller states what fixes them — known lists :length (a measured length, a ruler: Scale is observable) or :pose (a known pose, a fixture or motion capture: EuclideanMap and Scale both are). Otherwise drop them from the calibration, or absorb them into the pose, before a joint refinement. (A vgio_migrate of a retired "affine" record keeps all four factors EuclideanMap ∘ Scale ∘ Aspect ∘ Skew, the same map; that record takes known = (:pose,) or that reduction.)

The chart is linear: retract(ch, v) = with_parameters(target, θ₀ + B v), B an n × m matrix with orthonormal columns, so tangent_size(ch) = m and retract_jacobian(ch) = B. For the affine factors B is the identity and the coordinates are the parameters' offsets, named by parameter_names. For a ThinPlateSpline (a HeightField) B spans the 2K − 6 (K − 3) pure-bending directions, the null space of the interpolant's affine-coefficient rows — the complement of an orthonormal basis of those rows' span, from a Householder QR with column pivoting (LAPACK, so one reproducible basis per node set and parameter layout); a composition's the complement of its members' constraints together. action_jacobian(ch, x) = transform_deriv_params(c, x) · B at the design point x; local_coordinates(ch, t) = Bᵀ (θ(t) − θ₀). restrict(ch, names) keeps only the parameters names free, the others held.

NO GAUGE WITH THE POSE, AND AN OBLIQUE COMPLEMENT. The tangent has no direction a change of the jointly estimated pose reproduces: the pose's nodal fields (a piston and two tilts of a height field, an in-plane translation and rotation of a thin-plate spline) are affine, and the thin-plate kinds' free directions are pure bending, their interpolant's affine part zero. That complement of the pose's directions is OBLIQUE, not orthogonal: the basis is orthogonal to the interpolant's affine ROWS (the pose's fields in the metric K⁻¹ of the radial basis), not to the plane fields themselves, so a bending direction correlates with a piston at a set of sampled points while no combination of them is one. The deformation's and the pose's spans intersect trivially — the stacked point Jacobian has full rank (test/mappedsurfacetests.jl pins its condition number and the smallest principal angle between the spans per composition) — which is the gauge-freedom statement; a Euclidean orthogonality in point space is not a property any parametrization can have. The spans can come close: with a 4 × 4 node grid reaching past the detections (nodes at ±0.6, samples to ±0.5 × ±0.4), the nearest bending direction is a nearly constant field of nodal heights — a bowl whose curvature lies outside the data, almost a piston on it — at about 5° (0.095 rad) from the pose's span, which inflates the variance along that one mode about 110×; nodes covered by detections (0.36 rad with the grid inside the samples) and the bending regularizer control it. A Scale and an in-plane EuclideanMap ARE pose directions, hence refused without known.

THE BASIS IS FIXED AT THE ANCHOR, and recenter keeps it: the constrained directions are constants of the nodes, so the slice is the same wherever it is anchored, and the manifold's type does not change.

B is an SMatrix while n ≤ 18 and a Matrix{Float64} above: a static basis compiles in time that grows steeply with its size (the first call of the manifold's verbs, cold: n = 18, 0.6 s static against 0.8 s as a Matrix; n = 32, 2.3 s against 0.7 s; a 5 × 5 in-plane spline, n = 50, 9.9 s against 0.7 s; 7 × 7, n = 98, 100 s against 2.6 s). In the large case retract's step, action_jacobian and local_coordinates are a Vector or a Matrix, and tangent_size is a run-time value. Zero-dimensional for a Rigid target.

The surface a ray meets

surface(pt) gives a posed planar target's geometric primitive, in the pose's destination frame (metres when physical), with the DESIGN chart as its chart — an affine calibration (the factors, Aspect ∘ Skew, …) is the primitive's in-plane affine, so a hit's chart coordinates are the nominal ones it shows — bounded by the target's Board (board = … on PlanarTarget, Rect(board) in the design chart) or else by its nominal points: a Quad for a Rigid or affine calibration, a MappedSurface for any other — a HeightField, an in-plane ThinPlateSpline, either after the affine factors — the surface of the composed chart map pose ∘ S₃ ∘ lift ∘ C ∘ S₂⁻¹, built by MappedSurface(pose, calibration, placement, rect) (a device caller builds it from adapted parts). The choice is by type, so a rigid target's ray caster never compiles the root.

On the device. HeightField, ThinPlateSpline and their ThinPlateSplineSystem take Adapt.adapt (their matrices become device arrays) and convert_eltype (a Float32 form); tps_pure_bending and tps_coefficients give a field's pure-bending values and spline coefficients from nodal values in a kernel (with_parameters on the adapted kind), the same functions the host constructors call. HeightField(nodes, points .=> heights; smoothing) fits a pure-bending field to scattered heights, the plane removed (a one-step algorithm).

No gauge freedom. The thin-plate kinds' pure bending is the OBLIQUE complement of the pose's directions (values orthogonal to the interpolant's affine rows, not to the plane fields), so no deformation direction is a pose change: the stacked Jacobian of the posed points in the deformation and the pose has full rank (test/mappedsurfacetests.jl pins its condition number and the smallest principal angle between the two spans for each composition). The spans can still come close: with nodes reaching past the detections the nearest bending mode is a nearly constant bowl, almost a piston on the data, about 5° from the pose's span (a variance inflation of about 110× along that mode); a node layout covered by detections and the bending regularizer control it. See The Surface a Ray Meets, where surface is documented with the primitives.
