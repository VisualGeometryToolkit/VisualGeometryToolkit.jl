Chart LM API

The chart-rows contract and the stack's one Levenberg–Marquardt (NLLSsolver, through one adapter): its stop settings (LmStops, with the damping strategy and the data's residual resolution), the chart, robust and multi-block solves (lmsolve_chart!, LmProblem), the one success rule, and the device LM (static_lm, StaticLmStops).

VisualGeometryToolkitCore.task_buffers — Method
task_buffers(alloc, key)

The buffer set stored under key in the current task's local storage, built by alloc() on first use. A workspace keyed by its type and sizes is then built once per (task, size) and reused by every later call of that size on that task — task-local, so threaded callers (Threads.@threads bodies are tasks) never share one. The one memo every per-call scratch workspace of the stack draws from.

VisualGeometryToolkitCore.Eliminable — Type
Eliminable{E}(value)

An NLLSsolver variable — a Core Manifold, an SVector, any value with NLLSsolver's nvars/update — that the solver may ELIMINATE (E = true): the Schur-complement linear system eliminates every such variable (a bundle's structure points, a rotation bundle's track directions) before it solves for the rest. nvars and update forward to value (an update re-wraps the updated value); iseliminable is declared only where the installed NLLSsolver has the Schur system (nlls_features().schur), and Eliminable{false} is the same variable left in the full sparse LDL — what a solver without the Schur system takes, and a fallback test forces.

VisualGeometryToolkitCore.LevenbergDamping — Type
MarquardtDamping()
LevenbergDamping()

The damping of the host Levenberg–Marquardt step, a strategy TYPE of LmStops and LmProblem (dispatch, not a flag), each NLLSsolver's own public iterator:

  • MarquardtDamping() (the default): λ·DᵀD, DᵀD the running maximum of diag(JᵀJ) floored at 1e-8 of its largest entry — NLLSsolver's :levenbergmarquardt_dtd; Core 0.10's damping, bit for bit;
  • LevenbergDamping(): λ·I — NLLSsolver's :levenbergmarquardt (RadiometricCamera 0.8.0's).

Measured (Core 0.10.2, 2026-11-14, six iterations of RC's fisheye, Tamron and grid refinements and a non-central origin fit): neither wins everywhere. λ·DᵀD reaches a lower cost on the fisheye case (1711 against 1776), while λ·I converges where DᵀD's weak columns stall (the non-central fit: a cost ratio of 1.7e-18 against DᵀD's 1.2e-8 after 25 iterations, 9.0e-9 after 125), and on the Tamron and grid cases it reaches a slightly lower cost 1.6–1.8× faster (λ·DᵀD rejects more candidate steps). An UNFLOORED running max (Moré's scaling, NLLSsolver's DᵀD without its floor) was measured and rejected: a column whose diag(JᵀJ) is zero leaves H + λDᵀD singular (the grid and non-central factorizations fail), and it is no faster than the floored DᵀD.

VisualGeometryToolkitCore.LmProblem — Type
LmProblem(variables::AbstractVector, blocks::AbstractVector; fixed = nothing, damping = MarquardtDamping())

An NLLSsolver problem as the stack's one LM adapter (lmsolve_chart!) solves it: variables (any NLLSsolver variables — Core Manifolds, SVectors, Eliminables — of one type or several) and the residual blocks (NLLSsolver AbstractResiduals, of one type or several, each with its own varindices and its robustkernel: NLLSsolver.NoRobust(), or a frozen loss through loss_robustifier). The problem is built once, with NLLSsolver's typed OptimizeCache (the linear system's layout — the Schur system where the variables allow it), and kept: a later solve on the same structure (a RANSAC refit's bundle) rebuilds neither.

p.variables is the problem's variable vector: set the start in place before a solve, read the solution after it (NLLSsolver swaps its buffers, so read it through p, never through a saved reference). p.blocks are the blocks; the residual statistics of a solve are nlls_rows_and_jacobian(p.blocks, p.variables).

fixed holds variables: the indices into variables (an Integer or a collection of them) of those the solve keeps as constants the blocks read (NLLSsolver's unfixed mask); the stationarity postcondition reads the free variables' columns only. nothing (the default) holds none, the problem as without the keyword, bit for bit. An index outside variables, or every variable held, is an ArgumentError.

damping (MarquardtDamping, the default, or LevenbergDamping) is the damping the problem's kept NLLSsolver cache is built for: solve it with the same LmStops(; damping) (another damping is correct but rebuilds the cache, as a changed problem does).

VisualGeometryToolkitCore.LmStops — Type
LmStops(; max_iter, ftol, xtol, stationarity_tol, max_time = nothing, damping = MarquardtDamping(), residual_resolution = 0)

THE stop settings of every host Levenberg–Marquardt fit of the stack — the one owner of its knobs, which lmsolve_chart! maps onto NLLSsolver's options in one place. Every keyword defaults to Core's configuration of record (configs/default.toml [lm]); a fit overrides one only from its own configuration table.

knobmeaningNLLSsolver
max_iterthe iteration cap ([lm] 1000)maxiters: outer iterations, one ACCEPTED step each; an iteration's damping loop may reject ~8–10 candidate steps first, so the cap bounds accepted steps, not work
ftolrelative cost tolerance ([lm] 1e-10): stop once a step lowers the cost by less than ftol·F (a relative tolerance: never the exact-fit test, whose threshold is the run's own, _exact_fit_threshold)reldcost
xtolstep tolerance ([lm] 1e-10)dstep: ABSOLUTE, the step's max-norm in chart units (max|pᵢ| < xtol)
stationarity_tolthe stationarity postcondition's column cosine ([lm] 0.05)— (the stack's own test, is_stationary)
max_timewall-clock cap in seconds; nothing (the default) or Inf: nonemaxtime
residual_resolutionthe residual norm the DATA resolve (0, the default: the run's own resolution alone). The success rule's exact-fit test reads it — a cost below its square is zero to what the data resolve, where the rows' rounding points in no direction and the cosine says nothing — and nothing else: the iteration's stops are unchanged. A caller states it DERIVED (the data's noise in the residual's units), never tuned— (the stack's own test; StaticLmStops' residual_resolution)
dampingthe step's damping, a strategy type: MarquardtDamping (the default, λ·DᵀD) or LevenbergDamping (λ·I)iterator: :levenbergmarquardt_dtd / :levenbergmarquardt
—absolute cost decreaseabsdcost = 0: the stack has no such knob
—consecutive failed iterationsmaxfails = 3, NLLSsolver's default

The initial λ is NLLSsolver's (1e-6), not a knob. Single-threaded (numthreads = 1): a fit runs inside the caller's threads. There is no gradient tolerance: success is the stationarity postcondition's (lmsolve_chart!).

VisualGeometryToolkitCore.ManifoldLmWorkspace — Type
ManifoldLmWorkspace{N}
ManifoldLmWorkspace(n, N)

The buffers of the chart LM (lmsolve_chart!) at n residual rows and an N-dimensional chart: the per-row √weights the caller's refit fills, the residual and n × N Jacobian buffers the rows are evaluated into, the stall postcondition's scratch, and the NLLSsolver problem the adapter builds on first use (and keeps, with NLLSsolver's internal data, for every later refit on a linearization state of the same type) — allocated once per problem instead of per LM iteration. N is the model manifold's tangent size (essential 5, fundamental 7, homography 8 in VisualGeometryToolkitEstimation). The residual SEMANTICS come entirely from the caller's linearization state — Sampson distance for E/F, whitened transfer error for H, calibrated reprojection for P3P — which is why the type is named for the manifold, not the distance.

VisualGeometryToolkitCore.StaticLmStops — Type
StaticLmStops(scale::SVector{N, T}; acceptance = Inf, residual_scale = 1, cost_floor = 0, residual_resolution = 0, max_iter, stationarity_tol)

THE stop settings of the device LM static_lm (isbits: a kernel takes it as an argument), owned with the host LM's (LmStops): every keyword has a default of record — max_iter configs/default.toml [lm] device_max_iter, acceptance [lm] device_acceptance, stationarity_tol [lm] stationarity_tol (the ONE success rule's cosine, the host's), and the floors' neutral values.

  • scale: the problem's unit per coordinate, in which the step tolerance (1e-10·(eps(T)/eps(Float64)) ./ scale, RELATIVE to the coordinate) and the DᵀD clamp ([1e-12, 1e16]·scale²) are read.
  • acceptance: the cost a solution must be below, F < acceptance — a root-finding caller's residual bound; by default [lm] device_acceptance, Inf: success by the stationarity rule alone.
  • residual_scale: the residual's scale fs, so the absolute cost and gradient floors are what T resolves of it, (16 eps(T) fs)².
  • cost_floor: the absolute floor under those (0: resolved to rounding; the spline lenses' reference routine stops at eps(Float64)).
  • residual_resolution: the residual norm the DATA resolve, when they carry less precision than T (a Float32 ray or Float32 controls in a Float64 solve: 16 eps(Float32) of a unit residual). The success rule's exact-fit test reads it — a cost below its square is zero to what the data resolve, where the rows' rounding points in no direction and the cosine says nothing — and nothing else: the iteration's stops stay T's.

VisualGeometryToolkitCore.finite_cost — Method
finite_cost(c::Float64) -> Float64

A cost as the stack's NLLSsolver fits read it: c when finite, +Inf otherwise. NLLSsolver (≥ 5.3.1) accepts a trial at a step below xtol whatever its cost and asserts cost == cost_ per iteration, which NaN fails; +Inf compares equal and is rejected like NaN everywhere else. Every NLLSsolver residual block of the stack returns its cost through it.

VisualGeometryToolkitCore.is_stationary — Method
is_stationary(J::AbstractMatrix, f::AbstractVector; tol, ftol) -> Bool

The stall postcondition of lmsolve_chart! for a fit the chart LM does not run (a block-structured NLLSsolver problem, nlls_termination's postcondition): whether the point at which the residual f and its Jacobian J were evaluated is a stationary point of F = ‖f‖² — F < ftol (an exact fit, whose residual points in no particular direction), or every column Jⱼ numerically orthogonal to f, max_j |Jⱼᵀ f| / (‖Jⱼ‖ ‖f‖) ≤ tol (scale-invariant in the residuals and in each unknown; an all-zero column is skipped, a NaN fails). A fit whose solver stopped without this holding stopped where its damping grew, not at a minimizer: its retcode is :stalled.

source
VisualGeometryToolkitCore.is_stationary — Method
is_stationary(blocks, variables, free::AbstractVector{Bool}; tol, ftol) -> Bool

The same stall postcondition for an NLLSsolver problem's residual blocks at its variables, in the chart coordinates of the variables free marks (a held variable's columns are left out, as the solver held them): the cost NLLSsolver minimizes, F = Σₖ ρ(‖rₖ‖²) (ρ each block's robustkernel, the identity for a plain block), is stationary when Σₖ ‖rₖ‖² < ftol (or Σₖ ρ′ₖ‖rₖ‖² < ftol with some ρ′ₖ > 0), or when every free column of the √ρ′-weighted system is numerically orthogonal to its rows, max_j |gⱼ| / (√wⱼ ‖√ρ′ r‖) ≤ tol with gⱼ = Σₖ ρ′ₖ Jₖⱼᵀ rₖ and wⱼ = Σₖ ρ′ₖ ‖Jₖⱼ‖² — the test the matrix method above makes of the stacked rows √ρ′ₖ rₖ and Jacobian √ρ′ₖ Jₖ, and exactly the robust chart LM's (lmsolve_chart!): ρ′ clamped at 0, the unweighted cost below ftol an exact fit, and a plateau (every block past a redescending loss's cutoff, ρ′ = 0 throughout) NOT stationary. The rows and their Jacobian (NLLSsolver.computeresjac of each block with all its variables, as nlls_rows_and_jacobian evaluates them, a held variable's columns skipped) are accumulated block by block into g, w and F: the problem's Jacobian is never held.

VisualGeometryToolkitCore.lmsolve_chart! — Method
lmsolve_chart!(ews::ManifoldLmWorkspace{N}, lm, stops::LmStops = LmStops())
    -> (x::SVector{N}, F, converged, iterations, (code, rule))
lmsolve_chart!(ews::ManifoldLmWorkspace{N}, lm, robustifier, ::Val{C}, stops::LmStops = LmStops())
    -> (x::SVector{N}, F, converged, iterations, (code, rule))
lmsolve_chart!(p::LmProblem, stops::LmStops = LmStops(); callback = nothing)
    -> (; code::ReturnCode.T, rule::StopRule, iterations::Int, cost::Float64)

THE stack's host Levenberg–Marquardt: NLLSsolver (Marquardt's DᵀD damping) under the stop settings stops (LmStops, the one owner of the knobs), on a kept problem and NLLSsolver cache, with ONE success rule.

  1. THE CHART LM minimizes ‖r(x)‖², r the residual_rows! of the linearization state lm (its Jacobian residual_jacobian_rows!, both read through the state's two reductions), from the chart origin x = 0.
  2. THE ROBUSTIFIED CHART LM minimizes Σᵢ ρ(‖rᵢ(x)‖²) from the chart origin, rᵢ datum i's C consecutive rows (C the codimension) and ρ the NLLSsolver robustifier — a stack loss through loss_robustifier(shape, loss_width), applied per datum (NLLSsolver's robustified Hessian), so one solve is the robust M-estimate. F is Σᵢ ρ(‖rᵢ‖²) at x; on return the workspace's r holds the unweighted rows at x.
  3. THE MULTI-BLOCK LM solves an LmProblem — heterogeneous variables and residual blocks, each block with its own robustifier — in place in p.variables; cost is Σₖ ρ(‖rₖ‖²) (‖r‖² without robustifiers), callback an NLLSsolver iteration callback (nothing: none). An indefinite or singular normal system in NLLSsolver's step solve (PosDefException, SingularException, ZeroPivotException, LAPACKException) is a failed solve, (ReturnCode.Failure, NonFinite), the variables as the solver left them.

The chart forms keep the problem and NLLSsolver's OptimizeCache in the workspace (one caching path, plain and robust alike), so a refit rebuilds neither. x is the solution chart vector, F the final cost, converged the stop code (nlls_stop_code's, or -2 for a stop the postcondition fails), iterations NLLSsolver's count (one accepted step each; a start at a stationary point takes one zero step, and only a start whose cost or gradient is not finite stops at 0, :solve_failed), and (code, rule) the termination record, a ReturnCode and a StopRule (nlls_termination's decode).

THE SUCCESS RULE. A stop is a success only at a STATIONARY point: for the cost-decrease stop, the step-size stop and the rejection cap alike, stationarity is TESTED at the returned point, and a stop that fails it is ReturnCode.Stalled (converged = -2) with the rule that fired. A tiny cost decrease or a tiny step proves nothing: a run whose damping grew until no step could lower the cost (a wrong-sign Jacobian; a NaN wall the minimizer lies behind) stops there. Stationary means the cost is zero by the exact-fit test — below the run's own resolution of its starting cost F₀, F < m·ε·F₀ over m residuals, or below the square of the residual norm the data resolve, stops.residual_resolution (0 by default; stops.ftol is the relative cost-decrease stop, never this test). A run that STARTS at an exact fit (a restart from a solve's minimum, F₀ itself rounding) is resolved only by the latter: with the default it is Stalled. Otherwise stationary means every column of the Jacobian is numerically orthogonal to the residual, max_j |Jⱼᵀr| / (‖Jⱼ‖ ‖r‖) ≤ stops.stationarity_tol (√ρ′-weighted per datum or block when robust: is_stationary). The iteration and time caps are MaxIters and MaxTime, a failed solve Failure.

loss_robustifier(shape::AbstractLossShape, loss_width::Real)

NLLSsolver's robustifier (an NLLSsolver.AbstractRobustifier) for the loss shape at loss_width. VisualGeometryToolkitCore.reduce_normal_equations — Method

VisualGeometryToolkitCore.residual_cost! — Function
residual_cost!(r, lm, θ) -> ½‖r(θ)‖²
residual_normal_equations!(r, J, lm, θ::SVector{N}) -> (½‖r‖², Jᵀr::SVector{N}, JᵀJ::SMatrix{N, N})

THE CHART LM'S TWO REDUCTIONS of the rows: what lmsolve_chart! reads.

  • residual_cost! gives the cost at a trial point.
  • residual_normal_equations! gives the cost, the gradient and the Gauss–Newton Hessian at a linearization. It also feeds the stall postcondition, whose cosine |Jⱼᵀr| / (‖Jⱼ‖‖r‖) reads g and diag(H).

The defaults evaluate residual_rows! and residual_jacobian_rows! into the caller's buffers r and J, and reduce on the host.

A state whose rows live on a DEVICE overrides both with one kernel that evaluates every row and its Jacobian and reduces them where they are. The rows never reach the host; r and J go unused. Only the N × N step is the host's.

VisualGeometryToolkitCore.residual_jacobian_rows! — Function
residual_rows!(r, lm, θ) -> r
residual_jacobian_rows!(J, lm, θ) -> J

THE CHART-LM PROTOCOL — one pair for every model: the residual and Jacobian rows the chart LM, NLLSsolver, minimizes in lmsolve_chart!.

lm is the per-call LINEARIZATION STATE a refit builds once: the anchor the chart is centred on, the whitening frozen there, the data views and the √weights. θ is the CHART vector, not a model. The rows are √w-WEIGHTED and live in chart coordinates — a different currency from a RANSAC problem's UNWEIGHTED whitened_residuals!(r, problem, model) in data units. Two names, because one name with two currencies is what the frame-in = frame-out rule exists to prevent.

Ceres analogue: together they are what a CostFunction::Evaluate fills — residual_rows! the residuals buffer, residual_jacobian_rows! the jacobians — with the manifold's retract_jacobian (Ceres' PlusJacobian) already folded into the chart directions. GTSAM's nearest equivalent is a factor's linearize(values), which returns the same rows and Jacobian as a JacobianFactor at the linearization point rather than filling caller buffers.

Both write into caller-owned buffers and return them; neither allocates. Methods live with the models (VisualGeometryToolkitEstimation's problems).

VisualGeometryToolkitCore.static_lm — Method
static_lm(fj, x₀::SVector{N, T}, lb, ub, stops::StaticLmStops{N, T}[, bound]) -> (x, converged, J, e, rule::StopRule)

The stack's ONE device-side Levenberg–Marquardt (the spline lenses' inverse at N = 2, any static N): Marquardt-scaled, bounded to the box [lb, ub] (a step is clipped to it), with an unrolled Cholesky-type solve and explicit fused products, so it allocates nothing, never throws, and runs inside a KernelAbstractions kernel with the same bits in every compiled copy. fj(x) returns (r, J, …) (the residual SVector, its SMatrix Jacobian, anything else returned with them as e); stops its stop settings (StaticLmStops); bound a relative step radius (nothing: none). converged is THE success rule of the stack's LMs — the point is STATIONARY: zero to what the stops resolve (the cost below the exact-fit floor, the gradient below its floor, or the undamped Gauss–Newton step from the point below the step tolerance: the device form of the host's exact-fit test), or max_j |Jⱼᵀr| / (‖Jⱼ‖ ‖r‖) ≤ stops.stationarity_tol, the host LM's cosine; on the box the gradient of a coordinate a bound holds (its descent leaves the box) is dropped, the bounded problem's stationarity — and its cost is below stops.acceptance. rule is the stop that fired: ExactFit (the cost floor), ToleranceMet (the gradient floor), IncrementSize (the step), CostDecrease (the relative cost decrease) or IterationCap; static_lm_termination gives the §14 record. NLLSsolver (lmsolve_chart!) is every host fit's LM.

VisualGeometryToolkitCore.static_lm_termination — Method
static_lm_termination(converged::Bool, rule::StopRule) -> (ReturnCode.T, StopRule)

The §14 termination record of a static_lm solve: ReturnCode.Success when it converged; otherwise ReturnCode.MaxIters at the iteration cap and ReturnCode.Stalled at any other stop (a step, cost or gradient stop short of the tolerance).
