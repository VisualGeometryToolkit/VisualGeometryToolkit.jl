Rigs, Stereo and Captures API

Rigs of cameras and targets, stereo rectification, and the per-frame values of a capture. Split from the Imaging Chain and Targets API page, which holds the imaging chain and the targets. See the Stereo Rigs and Uncertainty guide.

Rigs

A Rig is members with fixed poses in one frame, each a (model, pose) pair: a camera (its model and rig-relative extrinsics) or a PosedTarget. Sensors only, targets only, or both (a camera rig carrying its marker constellation).

VisualGeometryToolkitCore.Cameras.PosedTarget — Type
PosedTarget(target::AbstractTarget, pose)

A target as a Rig member, the target-side counterpart of a PosedCamera and, like it, of its kind's hierarchy: an AbstractTarget whose is_posed is true. It holds the TARGET — its geometry, an unposed AbstractTarget, independent of where it is mounted, so the same target can sit in several rigs — and its POSE, the rigid map taking target-local coordinates (the pattern plane z = 0 for a planar target, the points a HeightField lifts off it as they are) into the rig frame, stored unlabeled (the rig mints TargetFrame{id} → F on access). The pose may be Uncertain (an estimated pose, its 6×6 covariance in the RigidExpManifold6 chart, rotation first); the rig hands it back uncertain, its covariance unchanged by the labels.

Accessors: model(m) is the target (as model(::PosedCamera) is a camera's model, so code over rig members calls model(member) for either kind), pose(m) the pose, extrinsics(m) its inverse (an ArgumentError for an uncertain pose, whose covariance does not invert by relabeling), and points(m) the target's own points. The target must be unposed: posing a PosedTarget is an ArgumentError, as posing a posed camera is.

A physical pose (a translation in metres) holds a physical target (points in metres; for an unresolved planar target, a calibration or board with lengths in metres), a plain pose a plain one: a unitful pose on plain points, or the reverse, is FlexUnits' DimensionError at construction, never a promotion. ustrip(u, m) and with_unit(m, u) move both together.

VisualGeometryToolkitCore.Cameras.Rig — Type
Rig{F, M}

A rigid assembly: members with FIXED poses in a common frame F, each a (model, pose) pair. Three storages, one interface:

  • M <: Tuple{Vararg{AbstractCamera}} — a physical multi-sensor rig. Sensor i's extrinsics is the labeled map F → ViewFrame{idᵢ}, stored inside the camera (a camera IS its model and its pose); the ids, the reference frame and every relative transform are read off those labels — there is no cached inverse, no id tuple, no second copy to drift. The tuple makes the sensor count static: StereoRig IS the 2-tuple case, dispatchable with no runtime length check. Many views over time are NOT a rig — they are frames of one (see the header comment) — which is why a Vector of hundreds of cameras is not accepted.
  • M <: AbstractDict{Symbol, <:PosedTarget} — a rig of targets: each a PosedTarget keyed by identity, its pose stored unlabeled and minted TargetFrame{id} → F on access.
  • M <: NamedTuple{(:sensors, :targets)} — both: a sensor tuple and a target dictionary posed in one frame (a camera rig carrying its motion-capture marker constellation, on BodyFrame{:camera_rig}). Built by Rig{F}(sensors, targets); sensor_rig and target_rig are its two halves as rigs of their own. Ids are distinct across the two.

Type parameters

  • F <: Frame{3}: the frame every member is posed in. THE FRAME IS THE GAUGE: when F is a member's own frame — ViewFrame{id₁} for a stereo rig built by the StereoRig constructors, TargetFrame{uid} for a calibration target gauged on board uid — that member's pose is the identity, checked at construction. A rig posed in an external frame (a body frame, the world, a tracker's room) names that frame instead and has no gauge member.
  • M: the storage, above.

Accessors

ids, pose(rig, id) / extrinsics(rig, id) (label-minting or label-preserving per storage; sensors also by position), rig[id], length, haskey; view_frames / image_frames on sensor rigs, target_frames and points(rig, id) — the target's points in the rig frame, the WORLD POINTS of the assembly — on target rigs; the stereo surface (source, destination, extrinsics(rig), pose(rig)) on the 2-sensor alias.

VisualGeometryToolkitCore.Cameras.with_model — Method
with_model(camera, model) -> PosedCamera/BoundedCamera
with_model(rig::Rig, i => model) -> Rig
with_model(rig::Rig, model) -> Rig            (single-sensor convenience)

Rebuild with sensor i's camera MODEL replaced — after a fit_camera regression or a generic-model init — keeping everything geometric: the labeled rig-relative extrinsics, the ids, any BoundedCamera extent. The rig is reconstructed through its validating constructor (never a raw field update, which would bypass the frame invariants); a lens/K change is metric-neutral to the rigid transforms, so the swap is geometrically exact.

NOTE: swapping the model does NOT re-estimate poses. Poses optimized under the old model keep their values; for an APPROXIMATING model (the fit_camera use case) that is the intent — the approximation error is the fit report's — while for a refinement the new model is the START of another bundle run, not a substitute for one.

VisualGeometryToolkitCore.Cameras.StereoRig — Type
StereoRig{F, U, V} = Rig{F, Tuple{U, V}}

Stereo camera pair — the 2-sensor specialization of Rig: a stereo rig IS a rig whose camera container is a 2-tuple, so the pair's length is in the type and the stereo surface dispatches on it with no runtime check.

The rig has no source, destination or extrinsics fields (none since 0.16): it stores its two cameras rig-relative (reference frame F = ViewFrame{id₁}; camera 1's stored extrinsics is the identity, camera 2's is the labeled relative transform ViewFrame{id₁} → ViewFrame{id₂}), and the three are method-form accessors:

  • source(rig) / destination(rig): the two cameras (rig-relative — the constructors re-express world-posed inputs).
  • extrinsics(rig): the relative rigid transform (monogram X_{V₂V₁}), DERIVED from the stored per-camera maps as extrinsics(rig, 2) ∘ pose(rig, 1) — it consumes source-view (ViewFrame{id₁}) coordinates and produces destination-view (ViewFrame{id₂}) coordinates, i.e. X₂ = R·X₁ + t.
  • pose(rig): inv(extrinsics(rig)) (the typed algebra swaps the frames, X_{V₁V₂}).
  • ids(rig): the identity symbols, read off the stored labels.

The labels ARE the single source of truth — the twin-typing and id-duplication policy violations of 0.6–0.8 remain unrepresentable, and the 0.9-era separately-stored relative transform is gone too (one authority: the per-camera rig-relative maps).

Constructors

StereoRig(left_camera, right_camera)   # Computes relative transform
StereoRig(source, destination, extrinsics)  # Explicit transform, CHECKED against
                                       # the cameras (check = false to skip)
StereoRig(left, right; ids = (:left, :right))  # Mint per-view identities

The ids keyword mints the view identities at construction (label-at- source: the constructor re-expresses the cameras in the rig frame ViewFrame{id₁} and labels the relative transform ViewFrame{id₁} → ViewFrame{id₂}, overriding whatever frames the inputs carried — the rig's ids are authoritative for its own transforms). The labeled per-view tags are exposed by view_frames (3D ViewFrame{id}) and image_frames (2D ImageFrame{id}); essential_form / EpipolarForm(rig) mint the labeled epipolar forms. Purely additive: nothing in the rig forces identities onto callers who ignore them.

The 3-arg constructor validates the given transform against extrinsics(destination) ∘ pose(source) computed from the GIVEN cameras (check = true by default, atol tolerance on the rotation angle and the relative translation deviation). Supply check = false for synthetic rigs whose cameras are placeholders and do not encode the relative geometry. check = false also admits UNPOSED members (a BoundedCamera with no pose): the rig poses them, so only the given relative transform matters. The 2-argument form computes the transform from the cameras and so requires them posed.

VisualGeometryToolkitCore.Cameras.StereoRig — Method
StereoRig(K1, K2, R_rel, t_rel) -> StereoRig

Construct a stereo rig from two intrinsics matrices plus the relative pose (R_rel, t_rel) from camera 1 to camera 2 (extrinsic convention: X_cam2 = R_rel · X_cam1 + t_rel). Camera 1 is placed at the world origin with identity rotation; camera 2 gets the given relative pose.

Convenience constructor for benchmarks where ground-truth is expressed as two calibration matrices plus a per-pair relative pose (e.g. HEB's K_<img> and pose_<pair> keys).

VisualGeometryToolkitCore.Cameras.depth_transfer — Method
depth_transfer(source::PosedCamera, destination::PosedCamera, extrinsics)
depth_transfer(rig::StereoRig)

Depth-ASSUMED point transfer from the source camera to the destination camera: returns a closure mapping a source pixel to a destination pixel by backprojecting to a ray, fixing unit depth in the source camera frame, transforming through extrinsics, and projecting into the destination image.

WARNING: this is a point-to-point transfer under an arbitrary depth assumption — it is NOT the epipolar correlation. Without depth, a pixel backprojects to a ray, not a point; the honest depth-free two-view object is the point-to-LINE map of an EpipolarForm (see epipolar_map, which since 0.8 names only that action). For real transfer with known depth, use transfer with a depth-attributed point; for correspondence search, use triangulation with matched features.

Renamed from epipolar_map in 0.8 — the old name promised a correlation and delivered a transfer.

Arguments

  • source::PosedCamera: Source camera
  • destination::PosedCamera: destination camera
  • extrinsics::EuclideanMap: Relative transform from source to destination

Returns

  • Function mapping pixel coordinates from source to destination camera

VisualGeometryToolkitCore.Cameras.essential_form — Method
essential_form(rig::StereoRig)
    -> EpipolarForm{GnomonicFrame{id₁}, GnomonicFrame{id₂}, EssentialMat}

The rig's CALIBRATED epipolar form: E = [t]×R from the labeled relative transform (x̂₂ᵀ E x̂₁ = 0 for gnomonic coordinates x̂ = π(K⁻¹ũ)), with the slots labeled by the per-view GnomonicFrame tags — NOT ImageFrame, which is documented as the canonical-:colmap PIXEL frame and is never overloaded for gnomonic coordinates. Slot 1 is the source view, matching the pinned x₂ᵀMx₁ convention of EpipolarForm.

Composing its epipolar_map with the calibrated → pixel lifts HomographyMap{GnomonicFrame{idᵢ}, ImageFrame{idᵢ}}(Kᵢ) turns this into the pixel-frame fundamental form — which is exactly what EpipolarForm(rig) does.

VisualGeometryToolkitCore.Cameras.validate_gt_inliers — Method
validate_gt_inliers(rig::StereoRig, csponds, depth_src, depth_tgt;
           rel_tol                  = 0.05,
           metric_tol::Quantity,
           gross_outlier_pixel_frac = 0.01,
           bidirectional_depth      = true) -> BitVector

Validate csponds against GT rig + per-view depth maps, returning a BitVector of inliers. The threshold is a physical metric length at the surface (e.g. 5mm, 50mm); see _gt_inliers_metric for the math.

Pixel-based dispatch was removed in favor of metric-only to keep the GT truth process apples-to-apples across datasets at different resolutions/focal lengths.

VisualGeometryToolkitCore.Cameras.validate_gt_metric — Method
validate_gt_metric(rig, csponds, depth_src, depth_tgt;
                   rel_tol = 0.05, gross_outlier_pixel_frac = 0.01,
                   bidirectional_depth = true)
    -> (residuals::Vector{Vec3{Float64}}, valid::BitVector)

Geometric pre-validation in metric space, without any pixel-residual threshold. A cspond is valid when it satisfies, in order:

  1. a gross-outlier gate: its GT-pose Sampson distance is at most gross_outlier_pixel_frac × the destination image diagonal (pose only, no depth);
  2. depth_src is finite at p_A and depth_tgt is finite at p_B;
  3. the forward warp of p_A lands where depth_tgt is finite, and the predicted and observed destination depths agree within rel_tol (relative);
  4. with bidirectional_depth, warping p_B back at its observed depth agrees with depth_src the same way.

The residual is 3D, in meters: forward, in the destination camera frame,

residuals[i] = unproject(tgt, p̂_B, d̂_B) − unproject(tgt, p_B, d_obs)

and, with bidirectional_depth, the longer of that and the backward residual (in the source camera frame), so ‖residuals[i]‖ is the worse-direction metric disagreement at the surface. Used by calibrate_metric_tol to estimate the noise floor without applying a tolerance gate.

VisualGeometryToolkitCore.Cameras.rectify — Method
rectify(rig::StereoRig; K = nothing) -> (; rig, R, K)
rectify([T = Float64], rig::StereoRig, images::Tuple; K = nothing, out_size = nothing, scale = 1)
    -> (; rig, R, K, images::NTuple{2, FramedImage})

Epipolar rectification of a stereo rig.

Geometry form: computes the rectifying rotations R = (Q₁, Q₂) (RotMatrix3s, original view-i orientation → the common rectified orientation, Q₂ = Q₁·R_relᵀ), the shared pinhole calibration K (SMatrix{3,3}; default: mean focal of the two views, mean principal point, zero skew), and the RECTIFIED rig — a StereoRig of two pinhole cameras with the same ids whose relative transform is the pure baseline translation. Rectified frames are NEW frames; the returned rig's ViewFrame{id}s label those, not the input views.

Image form: additionally resamples the two source images into the shared rectified pixel frame — for each output pixel, K⁻¹ → rotate the ray by Qᵢᵀ → project through view i's OWN lens model → sample: distortion and rectification in ONE fused warp per view, any AbstractLensModel. Returns two FramedImages over the same window Rect(0, 0, W, H) of the rectified pixel frame (out_size = (W, H), default: the elementwise max of the input sizes; scale downsamples like the rect form of undistort). After rectification, corresponding points share a row and disparity = fx·B/z.

KernelAbstractions end to end: the destination is allocated with similar, so it lives on the SOURCE images' backend — supply CuArrays and the fused warp (one bilinear kernel; the isbits chain evaluated per output pixel on the device, no remap grid) runs on the GPU. rectify(Float32, rig, images) keeps the warp math single-precision for GPU throughput (the type leads, as in Base's zeros(Float32, n)).

The construction assumes a predominantly HORIZONTAL baseline (the new x-axis is sign-fixed toward +x); a vertical rig wants the transposed convention. Throws for a near-zero baseline.

VisualGeometryToolkitCore.Cameras.convert_frame — Function
convert_frame(G::Type{<:PixelFrame}, x) -> x in G

The ONE way to change the pixel frame of frame-typed pixel data (TargetPoints2D; a package adds a method for its own frame-typed values): every pixel is moved by EuclideanMap(F, G) and the result is typed G, so a frame is never relabeled without its numbers moving with it.
