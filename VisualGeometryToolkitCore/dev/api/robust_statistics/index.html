Robust Statistics and Solvers API

The robust-statistics toolkit, the generic block-coordinate-descent loop, the chart-rows contract and the chart LM (NLLSsolver, through one adapter): the shared machinery under the contracts of the Robust Estimation API page.

VisualGeometryToolkitCore.IGPrior — Type
IGPrior(alpha0, beta0)

Inverse-Gamma prior on σ²: π(σ²) ∝ (σ²)^{-(α₀+1)} exp(-β₀/σ²). Conjugate to the Gaussian inlier likelihood, so the marginal reduces to a closed-form sweep update.

The Jeffreys prior π(σ²) ∝ 1/σ² is the limiting α₀ = β₀ = 0 case, built by JeffreysPrior() (or IGPrior()); one struct handles both.

Fields

  • alpha0::Float64 — shape hyperparameter (0 ⇒ Jeffreys)
  • beta0::Float64 — scale hyperparameter (0 ⇒ Jeffreys)

VisualGeometryToolkitCore.fit_scale — Method
fit_scale(prior::IGPrior, rss, dof) -> s2

Fit the squared scale ŝ² as the inverse-gamma MAP, (rss + 2β₀)/(dof + 2α₀).

Returns ŝ², the SQUARED scale — never a linear σ̂.

ŝ² is PER COMPONENT: rss sums squared NORMS of dg-vector residuals, so dof counts components — `νdata = (k − modeldof)·dgfor a hard partition, ordg·Σπᵢin the IRLS M-step (updatescale!). The2α₀/2β₀pseudo-counts make a refinement inherit the scoring prior (β₀floors ŝ² at low inlier counts);IGPrior(0, 0)(Jeffreys) givesrss/dof`.

The first argument is THE ESTIMATOR: IGPrior selects the inverse-gamma MAP, its prior being that estimator's parameters. The residuals are TAKEN as inliers, no initial guess is needed, and no inlier decision is made here.

The result is floored at eps(), so a zero rss under Jeffreys returns eps(), not a NaN. A caller that would rather HOLD its previous scale in that case must test the dof itself at the call site.

VisualGeometryToolkitCore.partition_student_t — Method
partition_student_t(prior::IGPrior, rss, k; model_dof, codimension = 1) -> (ν, ŝ²)

The Student-t of a hard partition of k points with residual sum of squares rss. It is the scoring marginal's posterior predictive over it under prior, and THE seed of every Student-t in the stack: counted dof ν_data = (k − model_dof)·codimension, then

ν  = max(ν_data + 2α₀, 2),     ŝ² = fit_scale(prior, rss, ν_data).

The ν ≥ 2 clamp keeps the seed's variance finite (a Student-t has one only for ν > 2) at a thin partition, and fit_scale floors the QUOTIENT at eps. One rule for every caller: both PosteriorWeightState seeds, the partition mixture of posterior_weights!/posterior_inlier_probs!, the consensus scale consensus_s2 and a RANSAC result's σ̂. model_dof is the caller's: the sweep's minimal_sample_size for the scoring marginal, one more for a local-optimization seed that also estimates the scale.

VisualGeometryToolkitCore.GauInlier — Type
GauInlier(s2; nu = Inf, gamma = 1/2, d_g)

Everything the Gaussian-uniform mixture needs EXCEPT the outlier half-width — the half both directions of the boundary share.

  • s2 inlier variance sigma^2
  • nu effective dof: Inf is the Gaussian inlier, a finite value the scale-marginalised (Student-t) one. The Gaussian IS the nu -> Inf limit, and the two closed forms below agree there.
  • gamma the label prior Pr(z_i = 1); a general gamma adds log(gamma/(1-gamma)) to the boundary.
  • d_g the codimension, REQUIRED. It enters the outlier density as the EXPONENT (2·outlier_halfwidth)^-d_g, so no value of it is a safe default.

VisualGeometryToolkitCore.StudentTMixture — Type
StudentTMixture(ν, s_hat_sq, log_two_outlier_halfwidth, d_g[, inlier_prior = 1/2])
StudentTMixture{T}(m::StudentTMixture)

The Student-t inlier + uniform outlier mixture of one E-step, with every per-residual constant precomputed. Its parameters are ν degrees of freedom, squared scale ŝ² = s_hat_sq, outlier support of half-width outlier_halfwidth per axis (log_two_outlier_halfwidth = log(2·outlier_halfwidth), density p_out = (2·outlier_halfwidth)^-d_g), inlier mixing proportion π = inlier_prior. The loggammas are evaluated HERE, once.

An immutable isbits value, so it can be an argument of a KernelAbstractions kernel, and the three scalar functions of it — inlier_posterior, posterior_weight, mixture_nll — are allocation-free plain functions of a squared residual, callable inside a kernel as VGC's ρ is. StudentTMixture{Float32}(m) converts the constants for a Float32 kernel.

These are THE formulas of the mixture: soft_posterior_weights! (the E-step over a buffer) and posterior_weights!/posterior_inlier_probs! (over a partition) build one of these and call the same scalar kernel.

VisualGeometryToolkitCore.next_nu — Method
next_nu(ν, sq_distances, s_hat_sq, w_fixed, n; d_g=1, kwargs...) -> ν_new

M-step: Newton update for ν maximizing the EM Q-function with fixed E-step weights.

Maximizes Q(ν) = Σ wi · log t{dg}(ri; ν, ŝ²) w.r.t. ν, where wi are the fixed posterior inlier probabilities from the E-step (not recomputed), ri² the squared NORM of a d_g-vector residual and ŝ² the per-component scale:

log t_d(r; ν, ŝ²) = logΓ((ν+d)/2) − logΓ(ν/2) − (d/2)·log(νπŝ²) − ((ν+d)/2)·log(1 + z), z = r²/(νŝ²)

∂Q/∂ν = Σ wi · [½ψ((ν+d)/2) − ½ψ(ν/2) − d/(2ν) − ½log(1 + zi) + (ν+d)zi/(2ν(1+zi))]

∂²Q/∂ν² = Σ wi · [¼ψ₁((ν+d)/2) − ¼ψ₁(ν/2) + d/(2ν²) + zi/(2ν(1+zi)) − zi(ν + 2d + d·zi)/(2ν²(1+zi)²)]

with z_i the SCALE-NORMALISED squared residual.

Up to max_newton Newton steps from the current ν, each clamped to [ν_min, ν_max]. Newton is taken only where Q is concave (∂²Q < 0), where its step is uphill; elsewhere the step is geometric, uphill along the gradient — ν ← 2ν if ∂Q/∂ν > 0, ν ← ν/2 otherwise.

VisualGeometryToolkitCore.next_nu_from_sums — Method
next_nu_from_sums(ν, dQ, d2Q_data, sum_w, ψ1_half_νdg, ψ1_half_ν; d_g = 1, ν_min = 2, ν_max = 1e4) -> (ν_new, converged)

One safeguarded Newton update of next_nu from the reduced sums dQ = Σwᵢ·dqᵢ, d2Q_data = Σwᵢ·d2q_dataᵢ (nu_point_terms) and sum_w = Σwᵢ, with ψ1_half_νdg = ψ₁((ν + d_g)/2) and ψ1_half_ν = ψ₁(ν/2) the caller's trigammas. ∂²Q = sum_w·(¼ψ₁((ν+d)/2) − ¼ψ₁(ν/2) + d/(2ν²)) + d2Q_data; Newton is taken only where Q is concave (∂²Q < 0, its step then uphill), elsewhere the step is geometric along the gradient (2ν or ν/2); the result is clamped to [ν_min, ν_max]. converged is true when the weights vanish (sum_w < 1e-10, ν returned unchanged) or |dQ/sum_w| < 1e-8. Generic in the float type, allocation-free: the ν update of a device kernel.

nu_point_terms(z, ν, ψ_half_νdg, ψ_half_ν; d_g = 1) -> (dq, d2q_data)

VisualGeometryToolkitCore.soft_posterior_weights! — Function
soft_posterior_weights!(w, inlier_posterior, sq_distances, ν, s_hat_sq, log_two_outlier_halfwidth, n, d_g=1[, inlier_prior=1/2])

E-step: compute posterior inlier probability and combined IRLS weight.

Stores inlier_posterior[i] = P(inlier | r_i) separately for the ν M-step, and w[i] = inlier_posterior[i] · u_i (combined weight for the θ solve).

d_g is the constraint codimension (1 for scalar residuals, 2 for 2D).

The separation is critical: the ν Newton update must use fixed E-step weights (not recomputed from the changing ν), otherwise ν and inlier_posterior couple in a positive feedback loop that drives ν → ∞.

VisualGeometryToolkitCore.ConsensusDof — Type
ConsensusDof()

The update policy of a Student-t dof HELD at the value its consensus seed gave it: the posterior-predictive dof of the scorer's consensus set, ν = 2α₀ + (k* − model_dof)·d_g (partition_student_t, with its ν ≥ 2 floor), where α₀ is the scale prior's shape (0 under Jeffreys). The seed sets it once; the ν block never moves it afterwards.

Why hold it there: a Gaussian whose scale carries an inverse-gamma posterior marginalizes to a Student-t with exactly that dof — ν measures how well the consensus set DETERMINES σ, not the shape of the inlier tail. Estimating ν instead lets the fit trade one for the other: on a contaminated set a heavy inlier tail (ν → 2) absorbs the outliers — the identifiability collapse this policy prevents.

VisualGeometryToolkitCore.PosteriorWeightState — Type
PosteriorWeightState

Mutable state for computing robust IRLS weights from a Student-t inlier + uniform outlier mixture model. Holds the sufficient statistics (ν, ŝ², logtwooutlierhalfwidth, the inlier prior π) and per-point buffers (w, inlierposterior, r²).

The Posterior in the name is the posterior over the inlier indicator: the weights w/inlier_posterior are P(inlier | r). The noise scale σ² also has a posterior, but it is marginalized away, so it is held here only as the scalar ν/ŝ², never as a posterior.

The per-point buffers are supplied by the caller (typically a workspace's); construction-time allocation is performed only by the n-constructor and median_seeded_posterior.

VisualGeometryToolkitCore.update_scale! — Method
update_scale!(pws, n)

M-step, scale block: overwrite ŝ² from the E-step's weights and the current squared residuals, and nothing else. Call after the residual block fills sq_distances(pws); the ν block is update_nu!, called after this.

ŝ² is the ECM step of the d_g-variate Student-t with scale ŝ²·I:

ŝ²_new = Σ πᵢ uᵢ rᵢ² / (d_g · Σ πᵢ),     uᵢ = (ν + d_g)/(ν + rᵢ²/ŝ²),

with πᵢ the inlier posteriors and rᵢ² squared NORMS. The E-step's weight is precision-scaled, wᵢ = πᵢ·(ν + d_g)/(νŝ² + rᵢ²) = πᵢuᵢ/ŝ², so the numerator is ŝ²·Σwᵢrᵢ² at the ŝ² that E-step used, and the inverse-gamma prior enters as fit_scale(prior, ŝ²·Σwᵢrᵢ², d_g·Σπᵢ). Returns ŝ².

VisualGeometryToolkitCore.block_coordinate_descent! — Method
block_coordinate_descent!(likelihood, method, prob, θ₀; max_iter) -> result

Block coordinate descent on a negative log-likelihood, over three blocks:

  • model — update_model! (the method): weighted least squares, LM, Newton, or nothing at all (a fixed-model method such as a seed EM, which returns θ unchanged);
  • nuisance — update_nuisance! (the likelihood): scale, mixing proportion, ν, Barron α, or nothing;
  • weights — update_weights! (the likelihood): EM responsibilities, loss weights, or GNC surrogate weights.

update_residuals! is bookkeeping between the model and nuisance blocks: it recomputes the residuals block from the new model and descends on nothing. One iteration (step_solver!) is one cycle through every block, in the order model → residuals → nuisance → weights, then post_iteration!. See update_nuisance! for why the nuisance block is not named "scale".

Stopping

The run's criterion is

StopWhenSolveFailed() | stopping_criterion(method) | StopAfterIteration(max_iter)

evaluated in that order by stop_solver! after every iteration: a failed model block ends the run at once (:solve_failed, no other block run); otherwise the method's own criterion is read after post_iteration!, and only then the budget — on the last iteration a method's reason wins over :max_iterations. max_iter ≤ 0 runs no iteration. The result is block_coordinate_result(state, method, prob, θ, reason, iterations, rule) with θ the last model the model block produced (θ₀ if none).

Monotonicity

Instances: EM (under the Neal–Hinton free-energy view EM is coordinate ascent on the free energy, i.e. descent on its negative); IRLS / half-quadratic (VisualGeometryToolkitEstimation's Irls{K} LO strategy is one — the strategy, not this loop); Barron-adaptive; GNC.

"Descent" is on the negative log-likelihood, and monotonicity is each INSTANCE's claim, not the loop's: the best iterate is kept (a method tracks it in post_iteration! with keep_best and returns it from block_coordinate_result), but the loop never rejects a step. An instance proves monotonicity through its post_iteration! trace. GNC is the declared exception — it changes its objective between iterations.

VisualGeometryToolkitCore.residual_jacobian_rows! — Function
residual_rows!(r, lm, θ) -> r
residual_jacobian_rows!(J, lm, θ) -> J

THE CHART-LM PROTOCOL — one pair for every model: the residual and Jacobian rows the chart LM, NLLSsolver, minimizes in lmsolve_chart!.

lm is the per-call LINEARIZATION STATE a refit builds once: the anchor the chart is centred on, the whitening frozen there, the data views and the √weights. θ is the CHART vector, not a model. The rows are √w-WEIGHTED and live in chart coordinates — a different currency from a RANSAC problem's UNWEIGHTED whitened_residuals!(r, problem, model) in data units. Two names, because one name with two currencies is what the frame-in = frame-out rule exists to prevent.

Ceres analogue: together they are what a CostFunction::Evaluate fills — residual_rows! the residuals buffer, residual_jacobian_rows! the jacobians — with the manifold's retract_jacobian (Ceres' PlusJacobian) already folded into the chart directions. GTSAM's nearest equivalent is a factor's linearize(values), which returns the same rows and Jacobian as a JacobianFactor at the linearization point rather than filling caller buffers.

Both write into caller-owned buffers and return them; neither allocates. Methods live with the models (VisualGeometryToolkitEstimation's problems).

VisualGeometryToolkitCore.static_lm — Method
static_lm(fj, x₀::SVector{N, T}, lb, ub, stops::StaticLmStops{N, T}[, bound]) -> (x, converged, J, e, rule::StopRule)

The stack's ONE device-side Levenberg–Marquardt (the spline lenses' inverse at N = 2, any static N): Marquardt-scaled, bounded to the box [lb, ub] (a step is clipped to it), with an unrolled Cholesky-type solve and explicit fused products, so it allocates nothing, never throws, and runs inside a KernelAbstractions kernel with the same bits in every compiled copy. fj(x) returns (r, J, …) (the residual SVector, its SMatrix Jacobian, anything else returned with them as e); stops its stop settings (StaticLmStops); bound a relative step radius (nothing: none). converged is THE success rule of the stack's LMs — the point is STATIONARY: zero to what the stops resolve (the cost below the exact-fit floor, the gradient below its floor, or the undamped Gauss–Newton step from the point below the step tolerance: the device form of the host's exact-fit test), or max_j |Jⱼᵀr| / (‖Jⱼ‖ ‖r‖) ≤ stops.stationarity_tol, the host LM's cosine; on the box the gradient of a coordinate a bound holds (its descent leaves the box) is dropped, the bounded problem's stationarity — and its cost is below stops.acceptance. rule is the stop that fired: ExactFit (the cost floor), ToleranceMet (the gradient floor), IncrementSize (the step), CostDecrease (the relative cost decrease) or IterationCap; static_lm_termination gives the §14 record. NLLSsolver (lmsolve_chart!) is every host fit's LM.
