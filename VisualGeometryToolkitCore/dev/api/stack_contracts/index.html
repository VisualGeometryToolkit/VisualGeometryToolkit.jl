Configuration Tags and Stack Contracts API

TagRegistry is the one TOML tag → type map; CONTRACT_GENERICS and the dependency allow-list are what the quality gates (test_quality_gates) check across the stack; the conformance helpers test an implementation of the contracts of the Robust Estimation API page (their methods load with Test).

VisualGeometryToolkitCore.TagRegistry — Type
TagRegistry(family::Symbol, suffix::AbstractString, pairs::Pair{<:AbstractString}...;
            retired = (), paths = Regex[])

The ONLY structure a configuration loader uses to map a TOML tag to a type (or, rarely, a value). registry[tag] returns the type; a retired tag throws ArgumentError("tag \"keep\" was renamed \"keep_model\""), and an unknown tag throws an ArgumentError that lists the known tags.

  • family names the family (:optimization_strategy, :loss) in messages.
  • suffix is the family's common type-name suffix ("Shape" for TLSShape), stripped before the spelling rule; "" for none.
  • pairs are tag => type. The one value that is not a type is nothing, whose tag is "none".
  • retired are old => new renames: the old tag no longer loads, and the error names its successor.
  • paths are the TOML key paths whose string values are tags of this family, matched whole against the dotted path of a value ("lo.arms[2].type"; an array element is [i], counted from 1). The config gate reads them.

The tag rule: a type's tag is snake_case of its name with suffix stripped from its end when present (the whole name otherwise), and nothing is "none". Construction does not check it — a package's load never fails on a spelling — tag_rule_violations does, and the quality gate runs it over every registry constant. A duplicate tag, or a retired tag that is also current, is a construction error.

keys, values, haskey, get, length and iteration (tag => type pairs, in declaration order) cover the current tags only; tag_of is the reverse lookup.

Base.merge — Method
merge(a::TagRegistry, b::TagRegistry...) -> TagRegistry

The registry of one family that two packages share — the core's tags and a downstream package's (merge(VisualGeometryToolkitEstimation.OPTIMIZATION_STRATEGY_TAGS, LocalOptimizationDoneRight.LODR_STRATEGY_TAGS)): every current and retired tag of each, and their key paths. The family and its suffix must agree, and a tag declared by two of them (or current in one and retired in another) is an ArgumentError, as within one registry. There is no global registry: a caller that loads several packages' tags merges them explicitly.

VisualGeometryToolkitCore.snake_case — Method
snake_case(name::Symbol) -> String
snake_case(name::AbstractString) -> String

The tag spelling of a CamelCase name, by exactly two rules, then lowercase:

  1. an _ goes before an uppercase letter that follows a lowercase letter or a digit;
  2. an _ goes before the last uppercase letter of an uppercase run when a lowercase letter follows it.

A digit stays with its letters.

snake_case(:FixedS2)              # "fixed_s2"
snake_case(:SmoothTLS)            # "smooth_tls"
snake_case(:WelschHQNewton)       # "welsch_hq_newton"
snake_case(:StudentTUniform)      # "student_t_uniform"
snake_case(:TerminalPlacement)    # "terminal_placement"

VisualGeometryToolkitCore.CONTRACT_GENERICS — Constant
CONTRACT_GENERICS

The generic functions of VisualGeometryToolkitCore that another package may add methods to across a package boundary — its extension points. Any stack package may declare its own CONTRACT_GENERICS (a tuple or vector of functions); the quality gate (contract_generic_violations) requires every method a package adds to another stack package's function to land on one of that owner's contracts. Functions owned by Base, Core, the standard library or any package outside the stack are exempt.

VisualGeometryToolkitCore's, by group:

  • the block-coordinate-descent hooks and readers (update_model!, …, current_s2);
  • the chart-LM row protocol (residual_rows!, residual_jacobian_rows!) and its reductions (residual_cost!, residual_normal_equations!);
  • the RANSAC / local-optimization interface, the constraint-problem protocol, the scoring and local-optimization contracts, pool selection and the chart-rows contract;
  • the minimal-solver backends PoseLib.jl implements;
  • the FitResult property forwarding and the TOML config hooks;
  • the geometry and camera accessors other packages implement for their own types (centroid, intrinsics, lens, model, division_coeffs, …);
  • the parameter protocol (parameter_vector, parameter_names, parameter_bounds, with_parameters);
  • the target-calibration protocol (regularizer, is_planar) and the target accessors calibration and design;
  • the surface protocol (intersection, normal, chart, surface_point, bounds) and surface, which builds a posed target's primitive;
  • the camera maps project and backproject, and convert_eltype;
  • the Manifold protocol: tangent_size, retract and recenter (required), local_coordinates, retract_jacobian, action_jacobian, zero_tangent, restrict, tangent_part and transform_covariance (optional), and minimal_manifold and ambient_coordinates, which a downstream model type answers (a model that is not a static array or a tuple of them adds ambient_coordinates rather than overriding retract_jacobian);
  • the plotting stubs the Makie extensions implement.

VisualGeometryToolkitCore.test_constraint_problem — Function
test_constraint_problem(problem, θ)

The constraint-problem protocol on problem at the model θ, as tests: data_size/codimension/minimal_sample_size integers, mahalanobis_distances! type-stable, allocation-free after warm-up, ≥ 0, and equal to mahalanobis_distance at every point to rounding: rtol = 1e-11 of the point's distance or 1e-14 of the largest finite distance (a non-finite one identical); and whitened_residual in the constraint's shape at every point — a number at d_g = 1, d_g components otherwise, so a scalar override at d_g ≥ 2 (a distance under the residual's name, the pre-0.7 hook) is refused — and with its norm equal to the point's distance to the same rounding (a non-finite distance, a gate's, matched by a non-finite residual), so the two hooks describe one point. The rounding is of the measurements, not of the residual: a reprojection residual is a difference of ~1000 px coordinates, so two paths differ by ~1000·eps px whatever the residual (PnP measured 4.8e-14 px on a 1.08 px residual, E 5.7e-14 px; 2026-11). Not bit for bit: the batch loop and a single call may contract StaticArrays' muladds into FMAs differently once the loop vectorizes, so a bitwise rule held for a problem only by forbidding inlining (PnP's @noinline, 15–22% per point) — result accuracy, not bit accuracy. Implemented by VisualGeometryToolkitCoreTestExt.

VisualGeometryToolkitCore.test_manifold_contract — Function
test_manifold_contract(m::Manifold; atol = 1e-12, allocations = true)

The manifold contract on m, as tests — what an optimizer that holds m as its variable relies on: the tangent size a constant of the type (zero_tangent inferred, static); recenter inferred to typeof(m) for a step of m's own float type in any static container (SVector, MVector; a plain Vector returns that type too) and allocation-free (allocations = false records a known allocation as @test_broken); retract_jacobian at the anchor and at a step equal to ForwardDiff through retract within atol; and the chart's own invariants (the essential chart's translation on the unit sphere after a step). VisualGeometryToolkitCore.test_quality_gates — Function
test_quality_gates(M::Module; jet_bound, treat_as_own = [], stale_ignore = (),
                   qualified_ignore = nothing, persistent_tasks = true,
                   tag_rules = :enforce, tag_tables = :enforce, config_tags = :enforce,
                   config_dirs = nothing, registries = (), stack_dependencies = :enforce,
                   stack_name = string(nameof(M)), stack_extra = nothing,
                   public_names = :enforce, third_party_public = :report,
                   contract_generics = :enforce)

The stack's static quality gates over package M, as one test set — RATCHETS: each bound is the value the package meets today and only ever moves down.

  • Aqua: undefined exports, unbound type parameters, stale deps, deps compat, project extras, persistent tasks (persistent_tasks = false skips it), no method ambiguities involving a method of M (pairs touching a test item's Main methods are dropped and logged), and no piracy in M or any of its submodules beyond treat_as_own.

  • ExplicitImports: no implicit imports, explicit imports via their owners, no stale explicit imports beyond stale_ignore; with qualified_ignore (a tuple of names) also every qualified access public, those names excepted.

  • JET: report_package(M) counts at most jet_bound reports, not counting KernelAbstractions LAUNCH reports (a kwcall(::NamedTuple{(:ndrange,)}, ::Kernel, …) no-method report, which JET raises at every launch site because the backend is known only at run time). The filter is checked against a real launch and two decoys every run.

  • Stack contracts, each gate in a mode — :enforce (@test that it finds nothing), :report (every finding logged with @warn and the gate recorded @test_broken; a gate that finds nothing is an ordinary test) or :off:

    • tag_rules: every TagRegistry constant of M and its submodules obeys the tag rule (tag_rule_violations);
    • tag_tables: no tag table outside a TagRegistry in M's src/ (tag_table_violations, a heuristic scan);
    • config_tags: every string at a registry's key path in the TOML files under config_dirs (default: M's configs/, when it exists) is a current tag of M's registries and of the extra registries (config_tag_violations);
    • stack_dependencies: M's Project.toml names only the stack packages in stack_name's row of the allow-list (stack_dependency_violations); a project kept outside the published stack gives its own row as stack_extra (the extra of stack_dependencies);
    • public_names: no _-prefixed name reached from another stack package (private_name_violations over src/ and ext/);
    • third_party_public (default :report): ExplicitImports' check_all_explicit_imports_are_public and check_all_qualified_accesses_are_public (with qualified_ignore) — a non-public name of ANY module, the stack's or a third party's (ForwardDiff's Dual, StaticArraysCore's StaticArray);
    • contract_generics: every method M adds to another stack package's function lands on that owner's CONTRACT_GENERICS (contract_generic_violations).

Implemented by VisualGeometryToolkitCoreQualityExt: using Test, Aqua, ExplicitImports, JET loads it.

VisualGeometryToolkitCore.test_recorded — Function
test_recorded(make; nested = RECORDED_NESTED_STATES) -> Int

That a Recorded run of block_coordinate_descent! IS the bare run, as tests: make() returns a fresh (state, likelihood, method, problem, θ₀, max_iter) each call (fresh workspaces too), whose result has estimate, retcode and iterations. The recorded run returns the bare run's estimate, retcode and iteration count and leaves the same state; it records one iterate per good iteration (a :solve_failed run one fewer), with as many costs and scales; and the bare run truncated after every k has the recorded run's k-th cost — iterate for iterate. A state is compared by what a run moves: its numbers, arrays and best iterates (Attributed(θ, (; cost))), and the fields of the nested state types whose names are in nested; anything else it points into is skipped. Returns the number of recorded iterates. Implemented by VisualGeometryToolkitCoreTestExt (using Test loads it).

VisualGeometryToolkitCore.check_duplication — Function
check_duplication(M::Module; kwargs...) -> Vector{DuplicationViolation}
check_duplication(dir; stack = <ENV["VGTK_STACK_PATHS"]>, similarity = ((0.6, 60), (0.85, 25)),
                  shingle = 8, min_file_tokens = 25) -> Vector{DuplicationViolation}

The stack's no-duplication rule, checked over a package (M, its directory pkgdir(M)) or a directory dir. Six checks:

  1. Name ownership (the Module form only). Every binding M (or a submodule of it) owns — defined there, not imported, a function or type whose parentmodule is that module; method extensions of another package's function do not count — whose name an upstream stack package also owns, private _names included (Julia's per-module eval, include and __init__, and the per-package CONTRACT_GENERICS, are each package's own). Upstream is every package in M's dependency closure (its loaded Project.toml [deps], transitively) that is VisualGeometryToolkitCore or depends on it: Core < IO, Features < Estimation < Eval < the downstream repositories.
  2. Function-body similarity. Every function and macro definition in the Julia files is tokenized with Julia's own tokenizer (JuliaSyntax), its comments and whitespace dropped, each identifier mapped to one symbol and each string piece to another, and cut into shingle-token shingles. Two definitions in different files are a finding when their shingle sets' Jaccard index reaches a threshold of similarity, each a pair (jaccard, min_tokens) that both bodies' token counts must reach: by default J ≥ 0.6 with at least 60 tokens, or J ≥ 0.85 with at least 25. (A shingle shared by more than 40 definitions — a common idiom — is not counted towards any pair.) Compared within the repository and against stack.
  3. Whole files. A Julia file whose token text, comments and whitespace dropped (at least min_file_tokens tokens), equals another file's.
  4. Retired patterns. A line of code (comments and docstrings left out) that spells a pattern whose owner lives elsewhere: NLLSOptions( (Core's nlls_options), acos(clamp((tr(… (Rotations' rotation_angle), the sRGB transfer constants (Features' src/linear_image.jl), and a \newcommand writer (Eval's src/reproduce/number_macros.jl). The failure names the owner.
  5. Backend branches (:backend_branch). A GPU branch's CPU branch is the SAME KernelAbstractions kernel on the CPU backend, so a definition that tests the backend to run different code is a finding: backend isa CPU (KA.CPU, GPU), get_backend(x) isa … (or ==), x isa CuArray (AbstractGPUArray and the other GPU array types), == CPU(); and a pair of methods of one function, one on a CPU type (::CPU) and one on a GPU type (::GPU, ::Backend, ::CuArray). Allowed, so not flagged: the same kernel launched on whatever get_backend returns, and the transfer and allocation helpers, by their names (an upload or download, to_host, to_device, on_device, zeros, ones, fill, an allocation, a synchronization, adapt, a copy, the device queries).
  6. CPU/GPU twins (:twin_name). Two bindings of the package whose names differ only by a CPU/GPU marker: _cpu/_gpu, _host/_device, cpu_/gpu_, or _cuda beside the plain name (the transfer helpers' names excepted).

The repository is the git checkout holding dir. Inside a monorepo the other packages' files are compared too (the package's own files are the ones checked; a pair or a file found twice is reported by each package). stack lists other stack repositories' root directories (by default the paths in the environment variable VGTK_STACK_PATHS, separated by :, or ; on Windows); those absent are skipped with a note, so a CI checkout checks itself only. Files are the ones naming_scope reads (vendored trees out).

Exceptions live in the repository root's DUPLICATION.toml, each with its reason; an entry about this package that matches nothing is itself a finding:

[[name]]                  # a binding M owns that an upstream package also owns
module = "MyPackage"
name = "foo"
reason = "…"

[[similar]]               # two functions, `<path>::<name>` (another repository's `<Repository>:<path>::<name>`)
functions = ["src/a.jl::f", "test/b.jl::g"]
reason = "…"

[[file]]                  # two files (paths as above)
files = ["test/a.jl", "OtherRepo:test/a.jl"]
reason = "…"

[[pattern]]               # a retired pattern in one file
use = "rotation_angle"
file = "src/a.jl"
reason = "…"

[[backend]]               # a backend branch in one function of one file
file = "src/a.jl"
function = "f"
reason = "…"

[[twin]]                  # two names that differ by a CPU/GPU marker
names = ["f_cpu", "f_gpu"]
reason = "…"

Implemented by the VisualGeometryToolkitCoreTestExt extension: using Test loads it.

VisualGeometryToolkitCore.check_raw_decoding — Function
check_raw_decoding(dir; allow = ()) -> Vector{RawDecodingViolation}

The stack's one-RAW-path rule, checked over the code under dir (the files naming_scope reads, less prose: Julia, Python, shell, TOML and YAML files, with comments and docstrings left out). Flags any use, outside VisualGeometryToolkitFeatures' raw module, of rawpy, a LibRaw C call (libraw_…), dcraw, rawpy's postprocess(, a demosaic, a Bayer/CFA interpolation, or PNGFiles.load/Gray.(…) on a decoded RAW output (a line naming linear, decoded, prepared, bin2, green or raw_ images). Line-level matching: a finding is a line to port, read by a person. The raw module's own files (VisualGeometryToolkitFeatures' src/raw_image.jl, its LibRawjll extension and their tests; VisualGeometryToolkitCore's src/raw/ sensor image and its test) are the one allowed place; they are recognized when dir is the owning package's directory, so scan each package of a monorepo from its own directory (from the repository root they are flagged). The Features API asked for its display demosaic, `loadraw(…; mode = :demosaic)orLinearRaw(…; mode = :demosaic)`, is the approved display path in every repository and is not flagged: the mode keyword inside that call's own parentheses, over every line the call spans; a demosaic by any other route, on the same line or not, is.

allow lists a repository's genuine exceptions, each a path relative to dir or a Regex over such paths (one exception may be given bare). They should be rare: a file is allowed only when it cannot go through the Features raw module (say, a third-party script kept verbatim), never as a way to keep a second decoding path.

Implemented by the VisualGeometryToolkitCoreTestExt extension: using Test loads it.

VisualGeometryToolkitCore.sync_manifest — Function
sync_manifest(mode = "update"; io = stdout, repo = nothing) -> NamedTuple{(:created, :moved, :seconds)}

Re-resolve the active project after git moved a Project.toml: mode = "update" runs a full Pkg.update() (an untracked Manifest: a targeted update fails on an illegal Manifest), mode = "instantiate" a Pkg.instantiate() (a tracked Manifest: download only). Prints to io what moved and returns created (no Manifest held a direct dependency before), moved (each direct dependency whose version changed, (name, before, after), before === nothing for a new one) and seconds. With repo (a git working tree whose core.hooksPath install_githooks set to an installed VisualGeometryToolkitCore's hooks), the hooks path is moved to the newly resolved VisualGeometryToolkitCore's, so a Core update never leaves the repository on a copy that Pkg.gc may delete.

The git hooks run it (githooks/sync-manifest) by including this file by path, without loading the package; it is VisualGeometryToolkitCore's for every other caller.
