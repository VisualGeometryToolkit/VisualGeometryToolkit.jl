Core API

The package docstring, units and quantities, utilities, the benchmark pool record, and the visualization stubs. The core composition and uncertainty types are on the Core Types API page, synthetic data and the Monte Carlo calibration on the Synthetic Data API page.

The Package

VisualGeometryToolkitCore.VisualGeometryToolkitCore — Module
VisualGeometryToolkitCore

Geometry, camera models and the robust-estimation core of the visual-geometry stack. VisualGeometryToolkitFeatures, VisualGeometryToolkitIO, VisualGeometryToolkitEstimation and BlobBoards build on it.

Submodules

  • Primitives: conics and feature frames (Ellipse, Circle, Disc, OrientedDisc, EllipticFrame, AffineFrame), hyperplanes (Line2D, Plane3D), 3-D conics (Ellipse3D, Circle3D) and Paraboloid3D.
  • Cameras: sensors (CMOS_SENSORS), intrinsics, lens models (Lens, LiftLens, Pinhole, KannalaBrandt, Division, …), PosedCamera, CameraModel, Rig, projection, calibration fits and P3P.
  • Synthetic: ground-truth generators and metrics for benchmarking estimators.

Key types in the parent module

  • Transform maps carry the class: EuclideanMap ⊂ SimilarityMap ⊂ CoordinateTransformations' affines ⊂ HomographyMap; the algebraic matrices are HomographyMat, FundMat, EssentialMat, CameraCalibrationMat (five parameters) and the symmetric conics.
  • Frame-tagged maps: EuclideanMap, SimilarityMap and HomographyMap carry Src/Dst tags from the open Frame hierarchy (ViewFrame, PixelFrame, GnomonicFrame, …); composition and inv are frame-checked.
  • Minimal solvers (homography_4pt, p3p, the 5-point essential and the fundamental-matrix solvers) and the manifolds their models are refined on.
  • The robust-loss family (AbstractLossShape, deploy), the block-coordinate-descent/LO interface shared with VisualGeometryToolkitEstimation, and FitResult, the one fit return type.
  • Numerics: the B-spline kernels, the thin-plate spline (ThinPlateSplineSystem, tps_coefficients, tps_evaluate, tps_gradient) and the spherical spline (SphericalSplineSystem), public, not exported.
  • Units: FlexUnits as shipped, plus the registered px, pd, dpi and pt (mm, px, dpi, Size2).
  • The sensor image: RawMosaic (a decoded Bayer RAW, an AbstractMatrix of its photosites that knows its colour phase and frame), its channel-first photosite view (a method of ImageCore's channelview), and LinearRaw, its exact linear values on the 2×2 cells, with the exact maps onto the sensor (raw_frame_map, bayer_plane_map). Decoding a file is VisualGeometryToolkitFeatures' (LibRaw).

Plotting loads as a package extension with any Makie backend.

See ARCHITECTURE.md (module graph, include order, extension points) and LOSSES.md (the robust-loss family) at the repository root.

The stack's one check for a package extension a call needs. missing_error is a zero-argument function returning the exception to throw when the extension is not loaded: the caller's own message, naming what to install and load (using X), built only on that path.

VisualGeometryToolkitCore.stable_seed — Method
stable_seed(seed, keys...) -> UInt64

The seed derivation of every random stream in the stack: the first eight bytes (big-endian) of the SHA-256 of seed and keys printed as text, separated by the unit separator \x1f. A fixed algorithm, unlike Base.hash (which changes across Julia versions), and keyed by NAME, unlike seed + i: a scene's draw depends on that scene's name only, so adding, removing or reordering other scenes leaves it unchanged, and no arithmetic coincidence gives two key tuples one stream. Keys are told apart by their printed text (string): 2, "2" and Int32(2) are one key, and a key whose text holds \x1f can collide with two keys; integers and plain names are always distinct. Seed a StableRNGs StableRNG with it (StableRNG(stable_seed(seed, "scene", i))), whose stream is fixed across Julia versions too.

julia> using VisualGeometryToolkitCore: stable_seed

julia> stable_seed(7, "budget", 2, 1)
0xf5154d7e8f0e4d1c

julia> stable_seed(1000, 1, 3) == stable_seed(0, 2, 3)
false

VisualGeometryToolkitCore.default_device — Method
default_device() -> KA.Backend

The device every KernelAbstractions-generic entry point in the package family uses when the caller supplies none: an accelerator when one is loaded AND functional, else KA.CPU().

VisualGeometryToolkitCore.check_keys — Method
check_keys(d::AbstractDict, allowed, section::AbstractString; retired = (), renamed = ())

Refuse unknown keys in table d with an ArgumentError naming the section, the offending keys and the allowed set. A typo'd knob that silently does nothing is the failure a config loader exists to prevent — a config that looks like it set max_trials but spelled it max_trial would otherwise run at the default and report success.

retired is a collection of exact (section, key) pairs: knobs removed because nothing read them, which recorded run sidecars (immutable provenance) legitimately still contain. Those load with a one-time warning; every other unknown key throws. Retirement is section-scoped on purpose — the same key in another table is a typo and must still fail.

renamed is a collection of (section, key) => new_key pairs: keys whose knob lives on under a new name. Each is refused with an ArgumentError naming its new key (there is no alias: the old spelling never loads), before the unknown keys are checked; section-scoped like retired.

A TOML value → the field type (Float64(v), Int(v), Bool(v), Symbol(v)): the one converter behind a typed present_kwargs spec.

Benchmark Pools

The pool record and the raw-pair interface (using VisualGeometryToolkitCore.Pools). The pool is the stack's one declared exception to "frame in = frame out": its data is stored in NormalizedImageFrame, and every accessor that crosses the boundary names it.

VisualGeometryToolkitCore.Pools — Module
Pools

The benchmark pool record and the raw-pair interface (using VisualGeometryToolkitCore.Pools):

  • PoolPair: one image pair of a scoring pool — correspondences, minimal-sample models and their pose errors, ground truth — in NormalizedImageFrame, with the per-image maps it was normalized by;
  • its accessors: num_points, num_models, pool_imc, gt_pose, calibration_matrices, pool_normalization, pool_frame_maps, pool_frame_calibrations, pool_pixel_scale, pixel_csponds, pixel_residuals and rig;
  • StereoRawPair: what a dataset reader's pair provides before a pool is drawn from it (pixel correspondences, calibration, image sizes, GT).

The record holds no residuals: a pool's residual matrices are a separate file, bound to the record by a content key, read by the evaluation package.

source
VisualGeometryToolkitCore.Pools.PoolPair — Type
PoolPair{M}

One image pair of a scoring pool: the light record — everything about the pair except the per-model residual matrix, which is a separate file bound to the record by a content key.

The pool is the one place in the stack that stores data normalized: every point datum and model is in NormalizedImageFrame (image centre, half-diagonal unit), through the per-image maps the record carries. See "Coordinate frame" below.

Type Parameters

  • M: Model type, expressed in NormalizedImageFrame (FundMat{Float64} for the E and F pools, HomographyMat{Float64} for the H pools).

Fields

  • csponds: Correspondences in NormalizedImageFrame — NOT pixels, stored as the columnar csponds(sources, targets) of SVector{2,Float64} sides (any vector of 2-vector pairs is converted to it at construction). Each side is mapped pixel → normalized by its own map (source_map, destination_map). pixel_csponds is the exact way back to pixels.
  • K1::SMatrix{3,3,Float64,9}, K2::SMatrix{3,3,Float64,9}: the pixel calibration of the source and target cameras (calibration_matrices).
  • R_gt::SMatrix{3,3,Float64,9}, t_gt::SVector{3,Float64}: the GT relative motion, source → target (X₂ = R_gt·X₁ + t_gt; gt_pose).
  • models::Vector{M}: Precomputed minimal-sample models, expressed in NormalizedImageFrame (e.g. fundamentals conjugated by the per-image maps).
  • sample_indices::Matrix{Int}: (m, num_models) — 1-based sample indices per model.
  • errors_r::Vector{Float64}: (num_models,) — rotation error [deg] per model vs GT.
  • errors_t::Vector{Float64}: (num_models,) — translation error [deg] per model vs GT.
  • gt_inliers::BitVector: (n,) — GT inlier mask (from bundle adjustment), one entry per correspondence (checked at construction).
  • gt_variance::Float64: σ̂²p = RSS/ν of the residuals under the oracle pose (from the GT R, t) on the SfM-track keypoints — NOT a DLT refit. `ν = n·dg` (oracle: no fitted DOF). NaN if too few tracks.
  • source_map::SMatrix{3,3,Float64,9}, destination_map::SMatrix{3,3,Float64,9}: the per-image maps T (pixel → NormalizedImageFrame) the data is stored in — the stored truth of the pool's frame, and the two sides of its pool_normalization (source_map(N), destination_map(N)); framed, they are pool_frame_maps.
  • snn::Union{Nothing,Vector{Float32}}: (n,) — the per-correspondence second-nearest-neighbour ratio the pool's hypotheses were sampled by, where the generator's is known; nothing otherwise.

Coordinate frame

All point data (csponds, models, and the separate residuals) lives in NormalizedImageFrame: each image is normalized by its own T (source_map/destination_map), isotropically — translate to the image centre and scale BOTH axes by 1/s, s = ½√(W²+H²) HALF the image diagonal: (ũ,ṽ) = (u−W/2, v−H/2)/s, which puts the image corners at unit radius (DiagonalNormalization(size) per side: pool_normalization(size1, size2), what the pool generator writes). Every width on pool data — the outlier half-width, the loss width, the IG scale prior — is in this half-diagonal unit. The stored maps are the truth of the frame: every conversion goes through them and none is reconstructed from the image size.

Isotropy is the key property. Feature noise is isotropic in pixels (Σ_px = σ²·I); a single scale maps it to Σ_pool = (σ²/s²)·I, still isotropic, so the scalar σ², the single global outlier half-width, the IG scale prior, and the Sampson distance all stay correctly specified. (A per-axis box normalization would make Σ_pool anisotropic and force a full 2×2 noise covariance through the scoring.) Normalizing by image size — not focal — also keeps the outlier half-width resolution/FOV-uniform: the K⁻¹ calibrated CHART — the z = 1 plane, VisualGeometryToolkitCore's GnomonicFrame — would not (extent ≈ tan(fov/2), so a single outlier half-width drifts ~4× with focal across PhotoTourism), which is why the pool frame is the scoring frame even for the calibrated (essential) problem.

Re-solving / local-optimization applications

Because the pool-frame maps T are stored, the record is self-contained for re-solving and LO: the metric frame is recovered EXACTLY (no reconstruction from image size or principal point). With T and the pixel K, the pool-frame calibration is Kc = T·K (pool_frame_calibrations), and:

  • pool frame → the calibrated z = 1 CHART (GnomonicFrame, not a unit ray): x_chart = inv(Kc) · x_pool, a unit BEARING being x_chart / ‖x_chart‖;
  • a pool-frame fundamental F → metric essential: EssentialMat(F, Kc₁, Kc₂);
  • scoring an essential E in the pool frame: FundMat(E, Kc₁, Kc₂) Sampson.

This is exact, so the global pool-frame outlier half-width needs no per-pair conversion. A pixel tolerance enters the pool frame only through pool_pixel_scale.

Construction

VisualGeometryToolkitCore.Pools.pixel_residuals — Method
pixel_residuals(pair::PoolPair) -> Matrix{Float32}

The image-plane Sampson residuals of the pair's stored models in the PIXEL frame, num_points × num_models. Pixels are the frame the SIMFIT++ reference works in, so its pixel bounds apply to them without any scalar approximation (the pool frame scales the two images independently, so pool_pixel_scale is a bound on the scale, not a conversion). One n×M scan of the light record: the correspondences come back to pixels through the stored maps (pixel_csponds), each model by composition with the pool normalization's two sides, inv(D) ∘ M ∘ S (a pool F → T₂ᵀ F T₁, a pool H → T₂⁻¹ H T₁). It never reads the pool's stored residual matrix, so it does not depend on that matrix's residual kind. The stored residuals of an essential pool are TANGENT Sampson distances (the pool generator's residual_kind = :tangent_sampson), those of an F or H pool image-plane Sampson (:sampson); this exit is image-plane Sampson for every pool, the quantity SIMFIT++'s pixel bounds are stated in.

VisualGeometryToolkitCore.SpatialQueries — Module
SpatialQueries

Allocation-free queries on a SpatialIndexing.jl RTree (using VisualGeometryToolkitCore.SpatialQueries):

  • foreach_intersecting: call a function on every element whose bounding box intersects a query Rect, with early exit;
