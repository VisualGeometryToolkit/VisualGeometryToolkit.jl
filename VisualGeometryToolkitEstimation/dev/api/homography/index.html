Homography

RANSAC Problem

HomographyProblem is a type alias for MinimalSolveProblem{HomographyMat{T}, 4, T, ...} — a 2D-2D correspondence problem with the 4-point minimal solver and, for LO refinement, Levenberg–Marquardt on the minimal 8-dof sl(3) chart about the current H (Sampson-whitened transfer error).

VisualGeometryToolkitEstimation.HomographyProblem — Type
HomographyProblem(pairs; sampler=nothing, backend=NativeSolver(),
                  src_map=I, dst_map=I, model_frames=nothing)

Construct a HomographyProblem from 2D-2D point correspondences.

  • pairs: any correspondence container satisfying the sources/targets protocol (Csponds, StructArray{<:Pair}, plain Pair vector). The PROSAC prior is its :score attribute column when pairs is a Csponds that has one (VGC withattrs(cs; score = s), the descriptor matcher's output): sampling ordered by descending score; uniform otherwise. Endpoints carry their measurement noise (VisualGeometryToolkitCore conventions/measurement-noise.md): plain = unit isotropic in the point's own frame, Uncertain(p, CovMat(Σ)) = its covariance, exact(p) = none (not both endpoints). The constraint is whitened by G₁Σ₁G₁ᵀ + G₂Σ₂G₂ᵀ in scoring, the refit and the lifts alike; a board or world plane is exact, so its residual is the transfer error in pixels.
  • sampler: override the auto-built sampler (advanced).
  • src_map/dst_map: per-view measurement maps, data frame → model frame. Identity (the default) means the data frame IS the model frame: pixels in, a pixel-frame H out. Non-identity maps declare a calibration instead of baking it into the data — supply PIXELS and K⁻¹ maps, and the returned H is in the model frame the maps point at, verified to 3.7e-13 against a known calibrated H. Scoring, the local optimizations and the consensus gate all treat that H consistently: residuals are measured in the data frame (pixels), the returned model stays in the model frame.
  • model_frames: the (source, destination) frame tags of the model frame, checked against LABELED maps by VGC's junction law at construction. Default nothing means (ImageFrame{:src}, ImageFrame{:dst}).

Which frame is which: declared, then checked against the maps

The model frame of a mapped homography is not a property of HomographyMat — and it is NOT read off the maps: the maps are what gets checked, so the reference they are checked against is declared separately. Raw-matrix maps (and unlabeled HomographyMaps) are the unchecked wildcard and need no declaration. Labeled maps must land in the declared frames, or construction is a MethodError; a calibrated H whose K⁻¹ maps are labeled into the z = 1 chart therefore declares it:

HomographyProblem(pixel_cs; src_map = C₁, dst_map = C₂,
                  model_frames = (GnomonicFrame{:src}, GnomonicFrame{:dst}))

Limit: mapped homographies are PINHOLE by construction

A measurement map is a MATRIX. A general camera's back-projection is not — it is nonlinear, and cannot be expressed as a map at all. So anything routed through src_map/dst_map is restricted to pinhole cameras, and this path is a pinhole island for the same structural reason as the relative-pose bundle's K matrices.

Worth being exact about where the restriction comes from: a calibrated homography is perfectly well defined on bearings — f₂ ∼ H f₁ needs no affine plane — so the limit is imposed by the MAP MECHANISM, not by the geometry. Camera-general calibrated H would take back-projection in place of K⁻¹, which is a separate decision alongside the relative-pose bundle carrying camera models. Nothing is lost for a calibrated pinhole benchmark.

HomographyProblem(pair::PoolPair{<:HomographyMat}; kw...) -> HomographyProblem

The pool-frame homography problem of a pool record: its correspondences (NormalizedImageFrame) verbatim, no measurement maps. Its sample gate reads the scale-free tolerance on its normalized view, so it takes no coincident_tol. kw go to HomographyProblem.

Fitting Pipeline

VisualGeometryToolkitEstimation.find_homography — Function
find_homography(correspondences; threshold=3.0,
    extent=nothing, workspace=nothing,
    max_trials=10000, min_trials=100,
    local_optimization=Irls{TLSShape}(),
    scoring=nothing, config=nothing)

Robust homography estimation via RANSAC with MSAC scoring and least-squares-on-the-inliers local optimization. Every default shown is configs/default.toml's ([ransac], [pipelines.homography]); a keyword overrides.

Returns a RansacEstimate or nothing if fewer than 4 correspondences. iterations(result) is the number of trials (hypotheses drawn); test converged(result) before reading the model (see RansacEstimate).

Arguments

  • correspondences: 2D-2D correspondences — Csponds, StructArray{<:Pair} or a Pair vector (Point2 storage canonicalized internally). A Csponds :score attribute column is the per-match prior (PROSAC, descending score); uniform otherwise. Endpoints carry their MEASUREMENT NOISE (VisualGeometryToolkitCore conventions/measurement-noise.md): a plain point is unit isotropic noise in its own frame, Uncertain(p, CovMat(Σ)) its own covariance, exact(p) none. Image↔image matches stay plain; a board, model or world plane is exact — find_homography(exact.(board) .=> pixels) scores the transfer error in pixels whatever the board's units (a plain metre board would be scored in metres, its threshold silently scaled by the board→image scale).
  • threshold: the MSAC inlier threshold of the default scoring, in PIXELS — the unit of this problem's residuals (every pixel-data find_* pipeline states its threshold by reference to this paragraph). The file default is a convention (OpenCV's), not a tuned value. Builds the default scoring only; supplying it with scoring is an ArgumentError, and so is the retired outlier_halfwidth (a marginal scorer's half-width belongs to that scoring).
  • extent: optional HyperRectangle{2} world-plane region; when given the problem is wrapped in BoundedProblem so the fitted H is validated over the rectangle.
  • workspace: optional pre-allocated RansacWorkspace to reuse — RansacWorkspace(HomographyProblem{Float64}, n_data[, T = Float32]), T the per-point storage precision, holds the DEFAULT (MSAC) scorer's workspace; for another scoring or local optimization build it from them, RansacWorkspace(problem, scoring, local_optimization). Each call checks the workspace against its scoring (VisualGeometryToolkitCore check_workspace).
  • max_trials, min_trials: RANSAC trial bounds ([ransac]).
  • local_optimization: LO-RANSAC strategy (default: the class's [pipelines.<class>] strategy — here Irls{TLSShape}(), least squares on the inliers with its truncation at the scorer's decision point; any other AbstractLocalOptimization changes mechanism — LocalOptimizationDoneRight's half-quadratic lifts among them).
  • scoring: Override scoring function (default: VisualGeometryToolkitCore's MsacScoring(problem; threshold); a paper's scorer, e.g. RansacScoringDoneRight's StudentTUniformScoring, plugs in here).
  • config: Override RansacConfig (ignores max_trials/min_trials).
  • rng: the sampler's random number generator.

These keywords are shared by every find_* pipeline; the others document theirs by reference to this list, stating only their class's defaults.

Examples

# Bare pairs, no prior (uniform sampling)
result = find_homography(pairs)

# Descriptor-similarity prior as a `:score` column (PROSAC sampling) — the
# matcher's `Csponds(...; score, ratio)` output carries it already; from bare
# pairs, build the columnar container (`withattrs` takes a `Csponds`)
result = find_homography(Csponds(sources(pairs), targets(pairs); score = similarities))
