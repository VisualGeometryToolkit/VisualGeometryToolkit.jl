P3P

RANSAC Problem

VisualGeometryToolkitEstimation.AbsolutePoseProblem — Type
AbsolutePoseProblem(model::CameraModel, pairs; backend=NativeSolver())

Construct an absolute-pose (P3P) problem from 3D-2D correspondences and a camera model. Rays are precomputed via backproject(model, u) at construction time; cs_solve pairs the world points with those rays for the P3P solver. Accepts any sources/targets-protocol container of 3D-source / 2D-target correspondences; a Csponds :score column is the PROSAC prior.

The residual currency is the RAW pixel of model for every lens: scoring projects through the intrinsics AND the lens (residuals!), and both local optimizations refine the same reprojection — the Student-t M-step and the Welsch lift run on VGC's full-camera constraint_with_jacobians(model, pose, X, u). A Pinhole model keeps the classic calibrated kernels (bit-identical to before). Nothing is undistorted: supply the detections as measured and the camera as calibrated.

Fitting Pipeline

VisualGeometryToolkitEstimation.find_absolute_pose — Function
find_absolute_pose(camera_model, correspondences; threshold=8.0,
    max_trials=10000, min_trials=100,
    local_optimization=Irls{TLSShape}(),
    scoring=nothing, config=nothing)

Robust absolute pose estimation via P3P + RANSAC with MSAC scoring. Every default shown is configs/default.toml's ([ransac], [pipelines.absolute_pose]); a keyword overrides.

Returns a RansacEstimate or nothing if fewer than 3 correspondences (the P3P minimal sample). iterations(result) is the number of trials (hypotheses drawn); test converged(result) before reading the model (see RansacEstimate).

Arguments

  • correspondences: X => u pairs (world point => raw pixel) — Csponds, StructArray{<:Pair} or a Pair vector; a Csponds :score column is the per-match prior (PROSAC; uniform otherwise).
  • threshold: in PIXELS (the reprojection residual's unit), as find_homography.
  • extent: as find_homography; the pose's _check_extent rejects poses failing cheirality or yielding a non-simple / non-convex image quad.
  • workspace: as find_homography, built with RansacWorkspace(AbsolutePoseProblem, n_data[, T]).
  • local_optimization: default Irls{TLSShape}() on the 6-dof pose chart, as find_homography.
  • the other keywords as find_homography.

Examples

result = find_absolute_pose(camera_model, correspondences)
result = find_absolute_pose(camera_model, correspondences; threshold=10.0)

Result Types

Model type — Extrinsics3, VisualGeometryToolkitCore's world→camera rigid pose (import it from VisualGeometryToolkitCore). It replaces the retired Pose3 alias. Do not confuse it with RVG's Rigid3, the unlabeled alias the hand-eye problem uses — a different type.

VisualGeometryToolkitCore.Extrinsics3 — Type
Extrinsics3

Concrete LABELED CameraExtrinsics alias: CameraExtrinsics{Float64, RotMatrix{3,Float64,9}, Vec{3,Float64}}, i.e. EuclideanMap{3, Float64, …, Src = WorldFrame, Dst = CameraFrame} (monogram X_CW, applies as x_cam = R·X_world + t).

The model currency of the absolute-pose solvers: p3p returns FixedModels{4, Extrinsics3} and P3P <: MinimalSolver{Extrinsics3}. isbitstype(Extrinsics3) == true — stored inline in FixedModels and RansacWorkspace, zero heap allocation on update.

Replaces the deprecated Pose3 alias (removed in 0.7): same layout and element types, but the world-to-camera direction is now a dispatch fact instead of a docstring caveat — an Extrinsics3 IS a CameraExtrinsics, so inv yields a CameraPose and labeled composition is frame-checked. Solver code that composes models against other labeled maps must have the junction frames agree (or unlabel explicitly).

model_type(::AbsolutePoseProblem) = Extrinsics3 and solve returns FixedModels{4, Extrinsics3} | nothing (up to 4 P3P solutions).

Local Optimization

find_absolute_pose deploys Irls{TLSShape}() (least squares on the inliers, at the default MSAC scorer's 8 px threshold; [pipelines.absolute_pose] in configs/default.toml). Any other strategy composes, LocalOptimizationDoneRight's half-quadratic lifts on the 6-dof pose chart among them. The per-iteration M-step for AbsolutePoseProblem is a Levenberg–Marquardt refit on the 6-dof left-perturbation chart about the current pose (VGC's LeftRigidManifold6: R = exp(δω)·R₀, t = exp(δω)·t₀ + δt): it minimizes the weighted calibrated reprojection error from constraint_with_jacobians(::Extrinsics3, X, ray) in VisualGeometryToolkitCore (the raw-pixel error for a distorting lens) with an analytic Jacobian (the chart's closed-form action_jacobian), running VisualGeometryToolkitCore's chart LM (FastLevenbergMarquardt's lmsolve!) on a ManifoldLmWorkspace{6}.
