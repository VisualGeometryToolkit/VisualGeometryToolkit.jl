RANSAC

Main Function

VisualGeometryToolkitEstimation.ransac — Function
ransac(problem, scoring; local_optimization_strategy, config, workspace, rng) -> RansacEstimate

RANSAC on VisualGeometryToolkitCore's scoring and local-optimization contracts: the loop calls only the contract verbs, so any scorer composes with any local optimizer and any problem. The allocating convenience of ransac! (fresh result buffers, and a fresh workspace unless one is supplied).

For each minimal sample, fits θₜ, scores it, and takes the scorer's consensus set. Two independent best-so-far scores are maintained: Sgl gates entry into local optimization; Slo tracks the best locally optimized score. The adaptive trial count uses the hypergeometric distribution (the stopping criterion).

Arguments

  • problem::AbstractRansacProblem: Problem definition (data, solver, residuals)
  • scoring::AbstractScoring: any scorer of the contract — VisualGeometryToolkitCore's MsacScoring/RansacScoring at a threshold, or a scorer from another package (a paper's: RANSACScoringDoneRight's Student-t + uniform marginal)

Keyword Arguments

  • local_optimization_strategy::Union{Nothing, AbstractOptimizationStrategy}=default_local_optimization_strategy(scoring): the LO-RANSAC refinement strategy (default nothing, no local optimization); dispatched in the loop's Phase 2 via locally_optimize!, or — a TerminalLO (lo_placement) — once on the final incumbent of a raw race
  • config::RansacConfig=RansacConfig(): maxtrials, successprob η, min_trials
  • workspace::Union{Nothing,RansacWorkspace}=nothing: Pre-allocated workspace
  • rng::Random.AbstractRNG=Random.default_rng(): source of every random draw the loop makes (sample selection through draw_sample!). Supply a seeded rng (e.g. Xoshiro(seed)) for a bit-reproducible run that is independent of ambient RNG state; the default preserves the historical task-local behavior.
  • on_improvement=nothing: optional anytime-trace hook, called as on_improvement(trial::Int, score, ws::RansacWorkspace) exactly when the tracked best (the acceptance that also re-arms the adaptive trial count) is replaced — read ws.best_model / ws.best_lo_retcode (and ws.best_lo_stop_rule) inside the callback. Improvements are rare (≈ log-many per run), so a cheap callback keeps overhead negligible; nothing (production default) is specialized away at compile time.
  • score_guard::Bool=false: per-candidate ScoreGuarded acceptance — the in-loop analogue of locally_optimize(...; score_guard=true) (the review-requested LO-RANSAC score-monotone variant). When the refined model of a gate-satisfying candidate scores BELOW its own seed under the same scorer, the candidate re-enters the incumbent race as the RAW hypothesis (at its Phase-1 score) instead of the refined model; the race itself stays the standard monotone best-so-far comparison. A raw hypothesis kept this way records its refit's code with the rule SeedKept (lo_retcode, lo_stop_rule) on the result.

Returns

A RansacEstimate; iterations(result) is the number of trials (hypotheses drawn). Why the loop ended is its termination record (retcode(result), stop_rule(result); the table on RansacMetadata): the adaptive count drawn (ReturnCode.Success, AdaptiveCount), every sample of an exhaustive sampler (Success, TrialBudget), or max_trials drawn without reaching the confidence (ReturnCode.MaxIters, TrialBudget: not converged, but a model was found; a confidence count equal to max_trials was reached at the cap: AdaptiveCount). Test VisualGeometryToolkitCore's found_model(result) before reading the model: found_model(result) == false (retcode(result) == ReturnCode.Failure) means NO hypothesis survived — there is no estimate: its estimate is nothing (with quality = -Inf, all-zero weights — an all-false inlier_mask(result) —, rms NaN and a ScaleNone scale).

Examples

result = ransac(problem, MsacScoring(problem; threshold = 2.0); local_optimization_strategy = Irls{TLSShape}())

VisualGeometryToolkitEstimation.locally_optimize — Function
locally_optimize(problem, θ₀; local_optimization_strategy, scoring,
                 workspace=nothing, score_guard=false) -> RansacEstimate

Refine a caller-supplied seed model θ₀ with one local-optimization run — the same score → locally_optimize! → re-score → test_consensus → _finalize machinery a RANSAC trial runs in _try_model!, driven by θ₀ instead of a minimal sample (no draw_sample!, no consensus search). Generic over the problem type. local_optimization_strategy is REQUIRED (no default: the strategy is the experiment's decision; the settled formulations live in the find_* pipelines). If the refined model fails test_consensus the seed is returned. scoring is REQUIRED too (a scorer object: MSAC or RANSAC at its threshold, MsacScoring(problem; threshold); the Student-t + uniform scorer at its outlier half-width, StudentTUniformScoring(problem, outlier_halfwidth; …); …): there is no class here to default it from, and a bare threshold or outlier_halfwidth keyword is refused (ArgumentError, naming scoring). When score_guard=true the refined model is only accepted if it does not lower the seed's score (the seed is kept otherwise).

The local optimizer receives its loss width through its width mode (VGC loss_at): a consensus-anchored strategy (EfficiencyConstant(m)) reads the consensus set's ŝ², an absolute one (LossWidth, see with_width) runs at the caller's width with the scoring untouched — the role-isolated validation controls (solo CV, oracle-scale) deploy the strategy that way — and a strategy with no width follows the scorer's decision_boundary.

source
locally_optimize(problem, models::FixedModels; local_optimization_strategy,
                 scoring, workspace=nothing) -> RansacEstimate

Entry for solvers that return several candidate models (e.g. the two planar-pose ambiguity solutions). Each candidate is scored against the consensus set; the single highest-scoring one that succeeds at test_consensus is kept, and only that one is locally optimized. The candidates are never all optimized — selection is by consensus score, optimization is on the winner alone. Returns a result with no model (found_model false, ReturnCode.Failure) if no candidate clears consensus. The winner's termination record is the selection's (Success, ClosedForm), or — when its refined model is kept — its local optimization's (as in the single-seed method). scoring is required, as in the single-seed method.

Problem Interface

VisualGeometryToolkitEstimation.AbstractRansacProblem — Type
AbstractRansacProblem

Abstract type for RANSAC problem definitions.

A concrete subtype encapsulates the data, sampling strategy, minimal solver, and constraint derivatives for a specific estimation task.

Required Methods

  • minimal_sample_size(p)::Int — minimum data points for a minimal solve
  • data_size(p)::Int — total number of data points
  • codimension(p)::Int — constraint codimension d_g
  • model_type(::Type{<:P})::Type — concrete model type M (for workspace pre-allocation; defined on the TYPE, so RansacWorkspace(P, n) can read it)
  • solve(p, indices) — fit model(s) from sample indices; returns FixedModels{N,M} with count ∈ 0..N (0 means failure)
  • constraint_with_jacobians(p, model, i) — (g, ∂ₓg, ∂_θg) at data point i

Derived Automatically

  • mahalanobis_distances!(r, p, model) — Mahalanobis distance √(gᵀ Σ̃_g⁻¹ g) from constraint_with_jacobians

Optional Methods

  • draw_sample!(rng, indices, p) — custom sampling (default: uniform without replacement)
  • test_sample(p, indices) — degeneracy check (default: true)
  • test_model(p, model, indices) — feasibility check at sample points (default: true)
  • test_consensus(p, model, mask) — consensus set validation (default: true)
  • refine!(ws, p, θ, weights) — the local optimization's one weighted step from the current model θ (default: nothing)
  • solver_covariance(p, model, indices) + provides_solver_covariance(::Type{<:P}) = true — model parameter covariance for predictive scoring; nothing for a degenerate sample (the hypothesis is skipped). A problem without a provider is refused by a predictive scorer.
  • mahalanobis_distances!(r, p, model) — override the default if a faster batch implementation exists

Example

struct MyLineProblem <: AbstractRansacProblem
    points::Vector{SVector{2,Float64}}
end

minimal_sample_size(::MyLineProblem) = 2
data_size(p::MyLineProblem) = length(p.points)
codimension(::MyLineProblem) = 1
model_type(::Type{MyLineProblem}) = SVector{2,Float64}  # (a, b) for y = a + bx

function solve(p::MyLineProblem, idx)
    p1, p2 = p.points[idx[1]], p.points[idx[2]]
    b = (p2[2] - p1[2]) / (p2[1] - p1[1])
    a = p1[2] - b * p1[1]
    model = SVector(a, b)
    FixedModels{1, typeof(model)}(1, (model,))
end

@inline function constraint_with_jacobians(p::MyLineProblem, model, i)
    pt = p.points[i]; a, b = model
    g = pt[2] - a - b * pt[1]           # scalar constraint
    ∂ₓg = SA[one(eltype(pt))]             # ∂g/∂y = 1 (only y has noise)
    ∂_θg = SA[-one(eltype(pt)), -pt[1]]  # ∂g/∂(a,b)
    return (g, ∂ₓg, ∂_θg)
end

fit_hypothesis(problem, θ, sample_indices) -> model | nothing

The hypothesis a minimal sample contributes, given a minimal solution θ of it (solve). For a problem whose minimal sample exactly determines the model this is θ itself (the default). A problem whose minimal sample OVER-determines it (hand-eye: two motions, 12 rows for 6 dof) fits the sample, seeded by θ, so the hypothesis is the sample's least-squares model — the estimator its solver_covariance describes. solve stays the pure minimal solver; nothing skips the hypothesis, as a failed solve does.

source
test_sample(p::AbsolutePoseProblem, idx) -> Bool

Reject degenerate P3P minimal samples. Four checks, distinctness and collinearity in each of the two spaces:

  • world: the 3 control points distinct (_P3P_COINCIDENT_WORLD = 1e-3 in the problem's world unit: 1 mm for physical input, which find_absolute_pose strips in metres, and 1e-3 of the caller's own unit for plain input — 1 μm for plain millimetres; the two forms of one millimetre dataset can therefore reject different samples, but only samples with two control points within 1 mm, which a fixture spread over metres never draws) and non-collinear (thin_ratio > _P3P_DEGENERACY_TOL). Collinear control points ⇒ no unique P3P solution; this one earns its place.
  • image: the 3 image points distinct (_P3P_COINCIDENT_IMAGE, pixels) and their RAYS not coplanar (thinness > _P3P_DEGENERACY_TOL). P3P degenerates when the three rays lie in one plane through the centre. For a Pinhole that is exactly collinear pixels (the pixel plane is an affine image of the z = 1 chart), so the test is thin_ratio on the pixels, as it always was. For a DISTORTING lens it is not: a line of rays images as a curve, so pixel collinearity admitted coplanar rays and rejected well-spread rim rays that the lens had pulled into a line. There the test is _ray_thin_ratio on the context's back-projected rays — thin_ratio in the gnomonic chart tangent at their mean direction.

The image DISTINCTNESS check guards a premise that does not reproduce

It used to be justified here as "two detections at ~the same pixel (distinct world points projecting together) force a grazing, near-degenerate pose". That was constructed, not measured, and measurement does not support it. Sweeping image separation for two genuinely distinct world points (common ray, ≥0.5 world units apart): noise-free, median error stays at 0° and q95 under 6e-5° from 0 px to 40 px; at σ = 0.5 px, the median is 0.181° at EVERY separation from 0 to 150 px, q95 0.655–0.702°, with no failure to return a solution.

Flat at both noise levels including at separation zero, which is geometrically sensible: two world points at different depths along one ray is a well-posed P3P configuration. The second point adds no independent constraint, but the remaining correspondences still determine the pose. Two points projecting together is not by itself a degeneracy.

It is also UNREACHABLE. A near-duplicate pair makes every triangle through it thin, so the image collinearity check rejects first: measured, at any separation small enough for the distinctness check to fire (<1e-3 px) the image thin_ratio is already 3.1e-5, far under its 1e-2 bound; at 0.2 px, where thin_ratio is healthy at 0.0125, distinctness admits. There is no separation at which the image distinctness verdict decides anything.

So it is redundant against a premise that does not reproduce — vestigial, or guarding a configuration nobody has constructed. Note that "a nearly-collinear triple produces a grazing pose" is NOT the missing case: that is exactly what thin_ratio(u…) tests, one line below.

The tolerance was deliberately NOT raised. At 1e-3 px — sixty times below VisualGeometryToolkitFeatures' pinned 0.06 px worst-case refinement bound — its measured duplicate capture is 0%, flat across spreads. That is the same symptom B7 fixed for F, E and H but a different disease: those were frame-COUPLED, their threshold moving with the data's spread, while this one is correctly framed in pixels and simply too small. Raising it would make a dead gate live across six repos on an unreproduced premise. If it is ever revisited, do NOT borrow COINCIDENT_PX: 0.1 px answers "is this the same detection twice?", anchored on a refinement bound, and this check asks a different question — the constant does not transfer even though the units match.

What would settle it is a construction that produces the failure, or a decision that it is vestigial. Not a threshold.

Mirrors test_sample(::HomographyProblem, …), which had the same structure: its coincidence check sat inoperative while _not_collinear caught duplicates incidentally.

VisualGeometryToolkitCore.constraint_with_jacobians — Function
constraint_with_jacobians(p::HandEyeProblem, X::Rigid3, i::Int)
    -> (g::SVector{6}, ∂ₓg::SMatrix{6,6}, ∂_θg::SMatrix{6,6})

Decoupled SE(3) hand-eye constraint and its derivatives.

For motion pair (A_ij, B_ij) = p.motions[i]:

g = [ L · Log(R_A R_X R_B^T R_X^T)
      R_A t_X + t_A − R_X t_B − t_X ]   ∈ ℝ⁶

(L = p.char_length, balancing rotation rad and translation length units.)

The model Jacobian ∂_θg uses the decoupled left-perturbation parameterization (δω, δt) ∈ ℝ⁶ matching AbsolutePoseProblem: RX ← R(δω) · RX, tX ← tX + δt. Under that convention, near the optimum:

∂_θg = [  L · (R_A − I)       0       ]   ← rotation block
       [   [R_X t_B]_×    (R_A − I)   ]   ← translation block

The measurement Jacobian ∂ₓg = I_6 reports the noise model directly on the constraint (the per-pair 6-vector is already in unit-balanced form), so the default mahalanobis_distances! produces ‖g‖.

VisualGeometryToolkitCore.solver_covariance — Function
solver_covariance(p, θ, idx) -> SMatrix or nothing

UNIT-SCALE covariance of the model θ from the constraint rows constraint_with_jacobians(p, θ, i), i ∈ idx: VGC's implicit_covariance, (AᵀW₀A)⁻¹·AᵀW₀·BΣₓBᵀ·W₀A·(AᵀW₀A)⁻¹ with the estimator's own whitening W₀ = blockdiag((BᵢΣ̃ₓBᵢᵀ)⁻¹). On a minimal sample (square) it is the implicit-function covariance of the minimal solve; on an overdetermined set (the local optimization's inlier set, a seed's consensus set) the covariance of the whitened-constraint estimator on it.

Coordinates are those of G_θ — vec(M) for H/F/E (the covariance of the minimal chart minimal_manifold(θ), propagated through its differential; rank ≤ its dof), the chart coordinates for the pose (LeftRigidManifold6), hand-eye (RigidExpManifold6) and line. Unit noise in the data frame the rows are in, so the MULTIPLICATIVE convention holds: physical Σ = s²·Σ̃, s profiled by the scale marginal. nothing for fewer points than a minimal sample or a singular system — a degenerate sample, skipped. Monte Carlo calibration: test/ransacmccalibration_tests.jl.

Residual protocol

The per-point protocol that mahalanobis_distances! runs is VisualGeometryToolkitCore's (mahalanobis_distance(problem, ctx, i), the signed whitened_residual, residual_context); the residual degrees of freedom are this package's.

VisualGeometryToolkitEstimation.residual_dof — Function
residual_dof(problem_or_type, n_in::Int) -> Int

Residual degrees of freedom on a fitted model with n_in inliers:

ν = (n_in − m) · d_g

where m = minimal_sample_size(P) and d_g = codimension(P).

Single source of truth for the per-pair scale-estimate denominator σ̂²_p = RSS / ν and for the score-equation ν. Use this anywhere the residual DOF appears so that the model class drives the formula rather than scattered magic constants (which historically drifted: an earlier Union{E, F} σ̂²p dispatch hard-coded m = 5, biasing F-matrix σ̂²p down by factor (nin − 7)/(nin − 5)).

Returns 0 when n_in ≤ m so callers can ν > 0 || return NaN cleanly.

source
VisualGeometryToolkitEstimation.oracle_residual_dof — Function
oracle_residual_dof(problem_or_type, n::Int) -> Int

Residual DOF when residuals are measured against an oracle model that was NOT fitted to these n points (e.g. the COLMAP ground-truth pose evaluated on a pair's SfM-track keypoints): no parameters are consumed, so

ν = n · d_g          (vs `residual_dof`'s `(n − m)·d_g` for a *fitted* model)

Use this for σ̂²p = RSS/ν under the GT geometry. Subtracting the model DOF (as a fit would) biases σ̂²p up by n/(n−m) — a DLT remnant, not warranted for the oracle.

Solver Backends

The minimal-sample solver used by HomographyProblem, FundMatProblem, and AbsolutePoseProblem is selected by supplying a backend to the constructor:

using VisualGeometryToolkitCore: NativeSolver, PoseLibSolver
HomographyProblem(pairs; backend=NativeSolver())     # default — pure-Julia
HomographyProblem(pairs; backend=PoseLibSolver())    # PoseLib C++ binding

The following names are defined and exported by VisualGeometryToolkitCore (RVG re-exports nothing; import them from there). See the VisualGeometryToolkitCore docs for their full API.

  • AbstractSolverBackend — abstract supertype for backends
  • NativeSolver — pure-Julia implementations of homography_4pt, fundamental_7pt, p3p, etc.
  • PoseLibSolver — bindings to the PoseLib C++ library
  • essential_5pt(x1, x2) — five-point essential matrix solver (native pure-Julia by default; essential_5pt(PoseLibSolver(), x1, x2) with using PoseLib)
  • essential_dlt(x1, x2) — eight-point essential matrix solver (PoseLib only)

Samplers

VisualGeometryToolkitEstimation.AbstractSampler — Type
AbstractSampler

Abstract type for RANSAC sampling strategies.

Subtypes implement draw! and reset! to provide different sampling behaviors (uniform, PROSAC, NAPSAC, etc.). Problems store a sampler as a type-parameterized field for compile-time dispatch.

Required Methods

  • draw!(rng::Random.AbstractRNG, indices::AbstractVector{Int}, sampler) — fill indices with a random sample drawn from rng. Every random decision a sampler makes MUST go through rng — this is what makes a seeded ransac(...; rng = Xoshiro(seed)) run bit-reproducible. There is no two-argument form: the rng is named at every call site, so reaching for ambient task-local state stays visible in the source.
  • reset!(sampler) — reset mutable state for reuse across ransac() calls

Optional

  • reset!(sampler, budget::Int) — reset, and take the run's trial budget (ransac supplies config.max_trials). The default ignores the budget; PROSAC schedules its pool growth over it.
  • trial_budget(sampler, config) / adapts(sampler) — the run's schedule: how many trials ransac allows, and whether the incumbent may shorten it. The defaults are config.max_trials and true (adaptive RANSAC).

Built-in Samplers

  • UniformSampler: Stateless uniform random sampling
  • ProsacSampler: Progressive sampling from high-quality matches
  • GaussianSampler: Weighted sampling without replacement
  • ExhaustiveSampler: Every minimal sample exactly once, no adaptive stop

VisualGeometryToolkitEstimation.ProsacSampler — Type
ProsacSampler

Mutable state for PROSAC progressive sampling.

Maintains a pool of correspondences sorted by quality score. Sampling starts from the top-m highest-scored matches and progressively expands the pool.

Fields

  • N::Int — total data size (constant)
  • T_N::Int — the trial budget the pool grows over; ransac sets it to config.max_trials when it prepares the sampler
  • n::Int — current pool size (grows from m to N)
  • t::Int — current trial count
  • T_n::Float64 — current T_n value (recurrence relation)
  • T_n_prime::Int — discretized cumulative threshold

See also: reset!, _draw_prosac!

VisualGeometryToolkitEstimation.GaussianSampler — Type
GaussianSampler <: AbstractSampler

Weighted sampling where each correspondence's weight is a Gaussian in its SNN score. Stateless (no progressive expansion). Matches Shekhovtsov's sample_subsets (RANSAC-Scoring functional.py:71).

Fields

  • weights::Vector{Float64} — precomputed normalized weights
  • inv_weights::Vector{Float64} — cached 1.0 ./ weights (the Gumbel-Max exponent; caching skips n divisions per draw — bitwise identical keys)
  • keys_buf::Vector{Float64} — scratch for Gumbel-Max keys (draw-local)
  • perm_buf::Vector{Int} — scratch index vector for the top-k partial sort
  • sort_scratch::Vector{Int} — quicksort scratch for the top-k partial sort

The three scratch buffers make draw! allocation-free (the hot RANSAC loop draws once per hypothesis); a GaussianSampler is therefore NOT safe to share across concurrent ransac() calls (one sampler per problem instance, which is how every constructor site builds it).

VisualGeometryToolkitEstimation.RansacEstimate — Type

VisualGeometryToolkitEstimation.RansacMetadata — Type
RansacMetadata{T, S}

RANSAC-specific diagnostics, the metadata of a RansacEstimate: T the per-point storage precision, S the SCORER's type — the producer whose weight_kind gives the weights their meaning (a threshold scorer's BinaryWeights, the Student-t + uniform scorer's PosteriorWeights).

The core fields carry the rest: the termination record (retcode(result), stop_rule(result); below), iterations the number of trials (hypotheses drawn — RANSAC's loop count; VGC's shared FitResult field, no second name), and n and rms the weights' support and weighted root-mean-square residual:

  • n = count(>(0), weights);
  • rms = √(Σᵢ wᵢ rᵢ² / Σᵢ wᵢ).

For a threshold scorer (binary weights) these are the consensus set's size and its rms, so rms is not outlier-dominated. For a posterior scorer they span every point of non-negligible posterior, each counted at its weight.

Fields

  • residuals::Vector{T}: final residuals for all data points (storage precision)
  • weights::Vector{T}: per-point weights in [0, 1] (storage precision), read by weights(result): the consensus membership 1/0 for a threshold scorer, the posterior inlier probability for the Student-t + uniform scorer (a value below eps(T) is stored as an exact 0). inlier_mask(result) cuts them by the scorer's kind (w > 0; the MAP rule w > ½)
  • quality::Float64: total model quality (higher = better) — the marginal score
  • scale::Float64: the scale the scorer ORIGINATES, read by noise_scale(result): √(fit_scale(prior, RSS, ν)) of the consensus partition — the inverse-gamma MAP (VisualGeometryToolkitCore's consensus_s2) under the scoring's scale prior, √((RSS + 2β₀)/(ν + 2α₀)), so √(RSS/ν) under the default Jeffreys prior, floored at √eps (a noise-free partition, RSS = 0, gives ≈ 1.49e-8, not 0). A LINEAR scale, not a variance and not a loss width. NaN when there is no partition to scale (dof == 0, or no model)
  • scale_source::ScaleSource: ScaleEstimated (the scorer's partition), or ScaleNone with a NaN scale, which noise_scale refuses
  • dof::Int: residual degrees of freedom ν = d_g·(n_in − p) of the consensus partition (n_in its size, p the minimal-sample dof); 0 when it is too thin
  • sample_acceptance_rate::Float64: fraction of trials that succeeded at test_sample (effective trials / iterations); low values mean frequent sample degeneracy
  • lo_retcode::ReturnCode.T, lo_stop_rule::StopRule: the termination record of the best model's local optimization, the core of its lo_estimate result (the same record as every result's): (Success, ClosedForm) for no local optimization (nothing), (InitialFailure, NoRule) for a consensus too thin to refine, an iterative optimizer's own; the refit's code with the rule SeedKept when the score guard kept the seed; (ReturnCode.Default, NoRule) — SciMLBase's "not run" — when no local optimization ran for the best model (no model, or the seed kept unscored)
  • nonfinite_scale::Bool: the consensus partition's scale came out non-finite (an overflowing RSS) and was dropped: scale_source ScaleNone, scale NaN, dof the partition's. An estimated scale is finite: ScaleEstimated never carries a non-finite one

quality and scale are Float64 regardless of T: scalars carry no footprint argument, and these are the numbers downstream thresholds compare.

Workspaces

RansacWorkspace{K, M, T, W, L} is the composed workspace of one RANSAC run: the score buffers (VisualGeometryToolkitCore's ScoreBuffers{T, W} — residuals, per-point scores, consensus mask and the scorer's workspace W), the local optimizer's workspace L (lo_workspace(P, T, lo, n)), the incumbent and the minimal sample. Build it from the scorer and the strategy it will run, RansacWorkspace(problem, scoring, local_optimization_strategy); RansacWorkspace(P, n) holds the default MSAC scorer's. The core strategies' workspace is LoBuffers: the refit workspace refine_workspace(P, n) — VisualGeometryToolkitCore's ManifoldLmWorkspace{N} for the chart-LM refits (e.g. N = 8 for HomographyProblem, 7 for FundMatProblem, 6 for AbsolutePoseProblem) — and the posterior-weight buffers. DltWorkspace selects the algebraic DLT step, refine!(ws::DltWorkspace, p, θ, weights) with θ unread, which LO does not call.

  • L: the local optimizer's workspace type (lo_workspace(P, T, lo, n))

VisualGeometryToolkitEstimation.draw_hypotheses — Function
draw_hypotheses(rng, problem; target, max_trials) -> Hypotheses

Draw minimal samples with the problem's own sampler until target samples have each produced at least one model the problem's test_model accepts, or max_trials draws have been made. Every sibling solution of an accepted sample is kept, the last accepted sample's included. No scoring, no consensus, no local optimization.

Each trial is the RANSAC trial, the one code path: draw_sample!, the problem's test_sample, solve, then per solution fit_hypothesis and test_model. The sampler is prepared for the run as ransac prepares it (reset!(sampler, max_trials): a PROSAC schedule spans max_trials). Every draw comes from rng, so a seeded rng makes the result a pure function of the seed and the problem.

Against the retired pool generator (pool format ≤ 3)

Same stopping rule, sibling layout and sample_indices columns; the one difference is the model gate. The old generator applied test_model to H only, while here every family is gated by its problem's own: F's oriented epipolar gate now applies (measured on a PhotoTourism pair under a uniform sampler, it accepts 76 of 510 F solutions), E has no post-solve gate (an E stream is unchanged), H is unchanged. A pool drawn here therefore differs from an F pool drawn there (accepted with pool format 4). A PROSAC sampler's growth horizon is now the run's max_trials (it was the generator's own prosac_T_N).

Configuration

configs/default.toml is the config of record: RansacConfig(), every core local-optimization strategy's keyword defaults, and every find_* pipeline's scoring and local_optimization_strategy read it at precompile time, so there is no second set of Julia literals to drift from it. Single values are overridden by keyword. RansacConfig(path) loads another file's [ransac] table over the shipped one and optimization_strategy_from_toml builds a strategy from its table — absent keys inherit, present keys override, unknown keys or tags are refused.

A strategy is selected in TOML by tag:

[pipelines.homography]
scoring            = { type = "msac", threshold = 3.0 }  # px; a Student-t: { type = "student_t_uniform", outlier_halfwidth = 20.0 }
local_optimization_strategy = { type = "irls", loss = "tls" }     # no width key: follow the scorer
# explicit widths: { type = "irls", loss = "welsch", efficiency_constant = 2.5 }
#              or  { type = "irls", loss = "welsch", loss_width = 2.0 }   (both keys: ArgumentError)

type is a tag of the strategy registry — the core OPTIMIZATION_STRATEGY_TAGS ("none" for nothing, "irls", "triggs", "terminal_lo"), or its explicit merge with a downstream package's — and loss a tag of LOSS_TAGS. The registries are VisualGeometryToolkitCore TagRegistry values; a retired tag is refused with its successor's name. The paper strategies and their cross-validated operating points (efficiency_constant = "cross_validated") are LocalOptimizationDoneRight's:

using VisualGeometryToolkitEstimation: optimization_strategy_from_toml, OPTIMIZATION_STRATEGY_TAGS
import LocalOptimizationDoneRight

lo = optimization_strategy_from_toml(table; class = :homography,
                                  tags = merge(OPTIMIZATION_STRATEGY_TAGS, LocalOptimizationDoneRight.LODR_STRATEGY_TAGS))

The scorer is selected the same way, by one reader through a tag registry (VisualGeometryToolkitCore's SCORING_TAGS, or a downstream merge such as RANSACScoringDoneRight's), every key required:

using VisualGeometryToolkitEstimation: scoring_from_toml
scoring = scoring_from_toml(Dict("type" => "msac", "threshold" => 3.0); problem = HomographyProblem)

Registering strategies

The strategy machinery — the registry, the keyword constructor, the TOML reader and the writer — is one public API that any package registers its strategies with. A package states one row per strategy and its defaults table; @lo_registry defines the row facts and the keyword constructors and returns the package's registry:

import VisualGeometryToolkitCore as VgtkCore   # the machinery is VisualGeometryToolkitCore's

#   type     tag        path   scale  family  label   shape  parametric
const ROWS = ((MyArm, "my_arm", :irls, nothing, nothing, "Mine", nothing, false),)
const MY_STRATEGY_TAGS = VgtkCore.@lo_registry ROWS defaults = MY_DEFAULTS["optimization_strategy"]

The machinery is VisualGeometryToolkitCore's — @lo_registry, lo_construct, lo_tag, lo_defaults, lo_parametric, lo_admits_shape and the loss registry LOSS_TAGS; this package holds the TOML reader and writer below. A strategy's exceptions are methods of the hooks — lo_admits, lo_key, lo_field, lo_field_from_toml, lo_absent, lo_validate, lo_concrete, lo_efficiency_constant_shape and lo_resolve_efficiency_constant — all of them CONTRACT_GENERICS; the reader and writer are the same for every strategy.
