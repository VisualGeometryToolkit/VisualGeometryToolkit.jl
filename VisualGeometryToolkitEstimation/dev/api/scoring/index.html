Scoring API

The RANSAC loop scores through VisualGeometryToolkitCore's scoring contract. The contract, its derived verbs and the baseline scorers are VisualGeometryToolkitCore's and documented in its manual; this page lists them because the loop is built on them. Paper scorers (the Student-t + uniform marginal StudentTUniformScoring) are RANSACScoringDoneRight's and are documented there.

The scoring contract

A scorer implements the required verbs; the optional ones default in VisualGeometryToolkitCore: AbstractScoring, scoring_workspace, score!, consensus_order, is_predictive, scored_model, scale_prior, outlier_halfwidth, inlier_threshold, has_inlier_threshold and check_workspace.

Derived verbs and buffers

Stated once in VisualGeometryToolkitCore for every scorer: the loop's one scoring path (ScoreBuffers, score_model!), the consensus set the local optimization starts from (ConsensusSet, inlier_count, consensus_set), its scale (consensus_s2), and the result's soft weights (inlier_probabilities!).

Baseline scorers

MSAC and RANSAC at a threshold, MsacScoring and RansacScoring, with their residual_quality. MsacScoring(problem; threshold) is the default scorer of every find_* pipeline.

Scale priors

The prior a scorer's consensus scale is computed under (scale_prior, Jeffreys by default): IGPrior and JeffreysPrior.

Weight policies

AbstractWeightPolicy and NormalizedWeightPolicy are VisualGeometryToolkitCore's.

Local Optimization

A strategy implements VisualGeometryToolkitCore's local-optimization contract (lo_workspace, locally_optimize!, returning lo_estimate). The core strategies are NoLocalOptimization, Irls and Triggs — the robustified chart LM: one NLLSsolver solve under a loss with Triggs' second-order correction, its width scale_multiple·ŝ at the hypothesis's Student-t scale, for every chart problem; every other strategy is LocalOptimizationDoneRight's. A width-carrying strategy's loss is resolved by loss_at from its width mode (lo_width, set by with_width): no width follows the scorer's inlier_threshold, ScaleMultiple(m) anchors it at the consensus scale, LossWidth(w) fixes it.

The contract is VisualGeometryToolkitCore's: AbstractLocalOptimization, lo_workspace, lo_width, with_width, loss_at, check_composition, ScaleMultiple and LossWidth. The methods of locally_optimize! for this package's strategies are documented here.

locally_optimize!(L, lo::Irls, problem, model, cs, buf, scoring) -> FitResult

Static M-estimation on the posterior-weight iteration (posterior_irls!): VGC's weight on the loss the width mode deploys (lo_loss), frozen (LossPlainWeights). source
locally_optimize!(L, lo::Triggs, problem::LiftableProblem, model, cs, buf, scoring) -> FitResult

The robustified chart LM: the loss the width mode deploys (lo_loss: scale_multiple·ŝ at θ's Student-t scale), frozen, as VisualGeometryToolkitCore's loss_robustifier, and ONE lmsolve_chart! from model over every datum at unit weight, on the chart-LM refit's own chart and state (_chart, _refit_state: the rows refine! descends) in its workspace (L.refine, the one reuse policy) at its LM settings ([chart_lm]). NLLSsolver's Triggs correction carries the loss; nothing is reweighted here and no inlier set is formed. The model comes back through the chart's recenter and _model_at, as from refine!.

VisualGeometryToolkitEstimation.Irls — Type
Irls{K<:AbstractLossShape} <: AbstractLocalOptimization

STATIC IRLS at a frozen loss width — direct iteratively-reweighted least squares on loss K, no lift, no graduation. Irls{K} is an LO STRATEGY: one instance of VisualGeometryToolkitCore's generic block_coordinate_descent! loop, which is not itself "IRLS" (it also runs EM, the half-quadratic lifts and GNC). Runs the posterior-weight iteration (posterior_irls!) — the PosteriorIrlsMethod / PosteriorIrlsState, same weighted refine! M-step (the problem's chart LM), same best-cost tracking and stop rule — with only the per-iteration weight functor swapped per loss:

  • Irls{WelschShape}: wᵢ = exp(−rᵢ²/loss_width²), loss_width = scale_multiple·ŝ (the paper's Welsch-IRLS arm; 1.5 was the pre-anchoring point)
  • Irls{HuberShape}: wᵢ = min(1, loss_width/|rᵢ|), loss_width = scale_multiple·ŝ (the elbow; 1.345 is the classical value) — the static-tail control (influence constant, never vanishing, past the elbow)
  • Irls{GemanMcclureShape}: wᵢ = (loss_width²/(loss_width²+rᵢ²))², loss_width = decision_width(GM, scale_multiple·ŝ) — the GM static-reweighting arm; its scale_multiple is in the half-weight currency (plain_scale_multiple, the one currency table), so one CV grid transfers across the static and lifted mechanisms (half-weight depth of a Welsch point: scale_multiple·√log2)
  • Irls{GaussianShape}: unit weights, no scale and NO scale multiple — plain least squares over all points, the coverage extreme. It takes no scale_multiple; supplying one is an ArgumentError (a width it would silently ignore)

The loss width is frozen at the start of the call, set by the width mode W (VisualGeometryToolkitCore's loss_at) — no per-iteration scale refit:

  • scale_multiple = m (ScaleMultiple(m)): m·ŝ at the consensus set's Student-t scale ŝ, in the loss's currency above;
  • loss_width = w (LossWidth(w)): the absolute width w;
  • neither (nothing, the default): the scorer's decision point (inlier_threshold) — MSAC with Irls{TLSShape} refits at MSAC's threshold.

Fields

  • max_iter::Int=25: max IRLS iterations per hypothesis
  • width::W: the width mode, nothing | ScaleMultiple{Float64} | LossWidth{NTuple{2,Float64}}
source
VisualGeometryToolkitEstimation.Triggs — Type
Triggs{K<:AbstractLossShape} <: AbstractLocalOptimization

The ROBUSTIFIED LEVENBERG–MARQUARDT local optimization of every chart problem (the MinimalSolveProblem family): from the hypothesis θ, ONE chart LM over all the data minimizing Σᵢ ρ(‖rᵢ‖²) — the problem's own refit rows on its own chart, robustified per datum by loss K through VisualGeometryToolkitCore's loss_robustifier. NLLSsolver applies the loss with Triggs' second-order correction (the ρ″ term of the Gauss–Newton Hessian; Ceres' Corrector), so there is no reweighting loop and no inlier set inside the refit: θ is the initial guess and the loss decides each datum's influence.

The loss width is loss_width = scale_multiple·ŝ (in the loss's currency, plain_scale_multiple, as for Irls), frozen at the start of the call: ŝ is the Student-t marginal scale of θ's residuals — the Sampson errors of all the data — over θ's consensus partition (VisualGeometryToolkitCore's partition_student_t, the scorer's scale_s2), the scale every consensus-anchored strategy reads. scale_multiple is REQUIRED (but for the Gaussian shape): the stack has no established multiple for this strategy, so a configuration states one; an absolute loss_width or no width is an ArgumentError from a keyword or a TOML table. An absolute width reaches it only through with_width, for fixed_width's freeze — with_width(lo, fixed_width(lo, s2)), the loss the consensus-anchored strategy would deploy at ŝ² = s2 (the role-isolated controls).

K is any shape Irls admits — the zero-argument shape tags: Welsch (the pipelines' default), Geman–McClure, Cauchy, smooth TLS, TLS, Huber and Gaussian; Barron, whose shape carries its α, is refused by both. Triggs{GaussianShape} is the plain chart LM over every datum: like Irls{GaussianShape} it has no width and takes no scale_multiple. For TLS and Huber ρ″ is zero (TLS: everywhere but the cutoff), so the Triggs term vanishes there and the step is the Gauss–Newton one with the loss's weights (TLS: the data inside the width at that evaluation); the LM's acceptance test still descends the robust cost, measured to the noise level on a circle.

Fields

  • width: the width mode, set by scale_multiple = m (ScaleMultiple); nothing for Triggs{GaussianShape}

Placement and instrumentation

A strategy runs inside the loop, on every candidate that enters the local-optimization gate, unless it is placed at the end: TerminalLO runs its inner strategy once on the final incumbent of a race decided on raw hypothesis scores. CountedLO counts a strategy's calls in either placement.

VisualGeometryToolkitEstimation.TerminalLO — Type
TerminalLO(inner::AbstractLocalOptimization) <: AbstractLocalOptimization
TerminalLO(; inner)

The TERMINAL placement of a local optimization: ransac decides its incumbent race on raw-hypothesis scores alone, exactly as with NoLocalOptimization (same trials, scores and on_improvement events on the same rng), and after the loop runs inner ONCE on the final incumbent through the seeded path of locally_optimize — the same scorer, inside ransac's wall time. The result is that seeded refine's:

  • estimate: the refined model, or the raw incumbent when the refined model fails test_consensus (as locally_optimize keeps its seed) or the incumbent's consensus set is too thin to refine (lo_retcode :thin_partition). The refined model is kept even if it scores below the raw incumbent (there is no score_guard at the terminal placement);
  • lo_retcode: the inner strategy's (:not_run when the seed was kept);
  • inlier_mask, residuals, weights, quality, sigma, dof, rms: the reported model re-scored under the scorer;
  • iterations and sample_acceptance_rate: the raw race's.

A race that keeps no hypothesis returns its :no_model result unrefined, and an incumbent the scorer cannot score as a seed (a predictive scorer with no covariance on its consensus set) the raw race's result. score_guard = true is an ArgumentError: the guard is a per-candidate acceptance rule and the terminal placement has no candidate to accept. A seeded locally_optimize with a TerminalLO runs inner (a seed has no race).

Every hook the loop, the composition check, the reporting and an external refit read answers as inner's (width, scale interface, loss family, path, marker, workspace, RefitFamily and the external-refit bracket), except the label, "<inner label> (terminal)", so result records tell the placements apart. TOML: { type = "terminal_lo", inner = { … } }, the inner table any registered strategy's. Counting: CountedLO(TerminalLO(inner)) and TerminalLO(CountedLO(inner)) both count the one terminal call per run that keeps a hypothesis (no LO runs inside the race). A wrapper of TerminalLO must forward lo_placement, or ransac runs it in the loop.

source

VisualGeometryToolkitEstimation.CountedLO — Type
CountedLO(inner::AbstractLocalOptimization)

Instrumentation wrapper: counts the locally_optimize! invocations (calls[]) and the iterations they report (iterations[], the sum of iterations(result)), and answers every hook the RANSAC loop, the scorer composition check, the reporting and an external refit read on a strategy exactly as inner does — its RefitFamily, placement and external-refit bracket included — so a run with CountedLO(inner) returns the model a run with inner returns. An external refit (refine_external!) is forwarded uncounted. It is not a registered strategy (no TOML tag): it carries counters, not configuration. A counter is shared by every run that is handed the same wrapper — the counters are Threads.Atomic{Int}, so runs on several threads (a threaded sweep over pairs) add up exactly; build a fresh one per measurement.

Loss resolution

The core strategies resolve the loss they deploy through these helpers. A downstream strategy can use them to follow the same width rules.

VisualGeometryToolkitEstimation.lo_loss — Function
lo_loss(lo, cs::ConsensusSet, scoring, buf) -> DeployedLoss

The loss a loss-parametric strategy (Irls{K}, and downstream families with a strategy_loss) deploys: its shape at the width its mode resolves to (VisualGeometryToolkitCore's loss_at: the consensus scale times its multiple in the shape's currency, an absolute width, or the scorer's decision point). The least-squares arm has no scale and no width: it deploys at s2 = Inf, scale_multiple = 1 (its weights are unit whatever the width).

source
VisualGeometryToolkitEstimation.strategy_loss — Function
strategy_loss(lo_or_type) -> Type{<:AbstractLossShape}

The loss-shape tag of a loss-parametric strategy (Irls{K}; downstream families add methods: LocalOptimizationDoneRight's HQ{K}, Gnc{S}). Read off the TYPE, so a wrapper recurses into its inner strategy.

source
VisualGeometryToolkitEstimation.deployed_shape — Function
deployed_shape(lo) -> AbstractLossShape | nothing

The loss shape a width-carrying strategy deploys, as fixed_width hands it to the currency hook (deployed_scale_multiple): strategy_loss(lo)() for a loss-parametric strategy, nothing (the default) for a strategy whose currency reads no shape. A downstream fixed-loss arm adds its method.

source
VisualGeometryToolkitEstimation.fixed_width — Function
fixed_width(lo, s2) -> LossWidth

The absolute width mode of a strategy deployed at ScaleMultiple(m) with the consensus scale held at s2: LossWidth(m′, s2), m′ the plain multiple of m in the strategy's currency — so with_width(lo, fixed_width(lo, s2)) deploys exactly the loss the consensus-anchored strategy would at ŝ² = s2 (the role-isolated controls: solo CV, oracle scale, the anchoring ablation).

source
VisualGeometryToolkitEstimation.lo_width_value — Function
lo_width_value(w) -> w

A local optimization's width mode, checked: nothing (follow the scorer), ScaleMultiple(m) or LossWidth(w) — never an outlier half-width (a scorer's). Anything else is an ArgumentError.

source
VisualGeometryToolkitEstimation.plain_scale_multiple — Function
plain_scale_multiple(shape, m::Float64) -> Float64

The plain scale multiple a deployment of shape takes for a scale_multiple m stated in the shape's currency: the identity for a width-multiple loss (Welsch, Huber, TLS, smooth TLS), decision_width(shape, m) for a half-weight loss (Geman–McClure, Cauchy). A non-positive multiple of smooth TLS is refused (the retired crossover sentinel: give no width to follow the scorer).

source
VisualGeometryToolkitEstimation.locally_optimize_rescored! — Function
locally_optimize_rescored!(L, lo, problem, θ, buf::ScoreBuffers, scoring) -> FitResult

The loop's Phase-2 step from a score under ANOTHER scoring: re-score θ under scoring on the buffers buf (score_model!), then — when its consensus set is stable (more than m + 1 points; otherwise θ comes back unrefined, :thin_partition) — run lo on its workspace L from that consensus set. The building block of a strategy that refits at a scoring of its own inside a loop (VisualGeometryToolkitEval's RefitHalfwidth).

Lifted local optimization

The chart problems provide VisualGeometryToolkitCore's chart-rows contract, which the half-quadratic lifts of LocalOptimizationDoneRight consume.

VisualGeometryToolkitEstimation.ManifoldLiftProvider — Type
ManifoldLiftProvider{P, D, C, X}

The chart-rows provider (VisualGeometryToolkitCore's rows_provider) of a problem P on a D-dof chart with codimension-C residuals: the problem, its rows (VGC RowsWorkspace{D, C}, one per (task, size)), the point count, and the problem's frozen per-run data aux (nothing unless the problem has some — PnP's pixel block).

source
VisualGeometryToolkitEstimation.LiftableProblem — Type
LiftableProblem

The problems that provide VisualGeometryToolkitCore's chart-rows contract to a lifted local optimizer: the MinimalSolveProblem family, whose every instance has a minimal chart of its model and a codimension-1 or -2 constraint. A lifted strategy's locally_optimize! methods dispatch on it, so the contract still refuses every other problem.
