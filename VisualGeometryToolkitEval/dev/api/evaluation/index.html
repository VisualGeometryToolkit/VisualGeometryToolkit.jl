API: Evaluation

The coarse-to-fine search, the bootstrap tuning harness and the composition evaluator.

Public names

VisualGeometryToolkitEval.Evaluation — Module
Evaluation

The evaluators. The composition evaluator runs a scorer composed with a local optimizer (LO) on stored pool pairs (build_pair_ctx, refit_imc!, apply_lo_refits, evaluate_sample_budget, live_runs, Roster). It is written against VisualGeometryToolkitCore's scoring and local-optimization contracts only, so it runs any scorer with any optimizer. The module also holds the coarse-to-fine search of every cross-validation (coarse_fine_search, coarse_fine_cv) and the bootstrap tuning harness (WindowedGridMethod, compute_method_rows).

VisualGeometryToolkitEval.Evaluation.NativeAxis — Type
NativeAxis

The native width axes, Union{OutlierHalfwidth, LossWidth} (VisualGeometryToolkitCore WidthAxis): what a selector grid, a selection sweep or a refiner's own native lives on. ScaleMultiple() is a width parameterization, never a native.

VisualGeometryToolkitEval.Evaluation.OPERATING_SCALE_MULTIPLE — Constant
OPERATING_SCALE_MULTIPLE

The refit protocol's operating scale multiple, 2.5 by default: the scale multiple at which the outlier-half-width ↔ loss-width crossover is inverted when a loss-width-consuming refiner rides an outlier-half-width selector grid (consumed_native). A definition of the refit protocol, not a tuned value: configs/default.toml [refit] operating_scale_multiple.

VisualGeometryToolkitEval.Evaluation.BootstrapMethod — Type
BootstrapMethod

A tuner the bootstrap harness runs (bootstrap_trials): it implements tune and evaluate. WindowedGridMethod is the one in this package.

VisualGeometryToolkitEval.Evaluation.ComposedSpec — Type
ComposedSpec(base, sel, selection::WidthAxis, kind::WidthAxis, ctor; source = TunedWidth())

One composed score+LO pipeline. sel is the key of its selection sweep (the selections idxs_of[sel] a refit seeds from); selection is that sweep's native axis — VisualGeometryToolkitCore's width_axis of the selection scoring (OutlierHalfwidth() for the Student-t marginal, LossWidth() for a threshold score); kind is the arm's width parameterization; ctor(value) builds the LO strategy at a width value (a scale-multiple arm bakes it in; the other kinds deliver it through their port, see width_delivery); source is where the width value comes from (WidthSource): a SelectionWidth arm requires kind == selection, and the tuning skips it.

VisualGeometryToolkitEval.Evaluation.FlatProtocol — Type
FlatProtocol(val_pair_idx, test_pair_idx)

Fixed deterministic pair-level split, bootstrap pairs only. Trial-level variance reflects pair-sampling variance only (no scene component). Used for ScanNet1500 and other "uniform sample of pairs" datasets.

VisualGeometryToolkitEval.Evaluation.LoRefitSpec — Type
LoRefitSpec(label, lo, axis, grid, idxs; bundle=false)

One post-LO refit of a selection sweep: refine the selected model idxs[p, t] with strategy lo at native parameter consumed_native(lo, axis, grid[t]). axis is the SELECTOR grid's native axis (a NativeAxis: OutlierHalfwidth() | LossWidth()) — cross-axis conversion happens per column inside the refit layer, so callers never pre-convert grids. lo = NoLocalOptimization() records the selection imc (no refit).

Column t refits the model selected at column seedcols[t] of idxs at the EXPLICIT native value natives[t] when those fields are set (no consumed_native conversion — the value is already in the refiner's units). Both default to the standard coupling (seedcols[t] = t, natives === nothing ⇒ derive from grid[t]). This is what the tuning grids (one fixed width parameter per spec) and the fixed-width deployment evaluations (seed at the ζ-scaled column, refit at the exactly-scaled native) are built from.

widths[t] (an absolute loss width): refit at the loss width widths[t] whatever the refiner — the BITWISE-identical call solo_refit_imc! makes, so the tuning and the ladder's test side deliver the width identically. A native refiner sweeps its seed at the column's nat′ (from grid[t] — scoring only, never a width) under the context's solo template and deploys with_width(lo, fixed_width(lo, widths[t]²)); an external refiner refines at widths[t]. Mutually exclusive with natives.

columns restricts which grid columns are EVALUATED (default: all). The others keep the imc matrix's NaN fill. The matrix stays full-width and every column index keeps its meaning, so boundary detection, the evaluation's seed columns and the checkpoint are untouched — this only stops computing cells that a windowed tune never reads, because it argmins inside the standardized window and the grid is far wider than that window. Measured on the PT-E 5% run of 2026-10-02: 45,567 of 386,000 cells per pair were inside the searched windows; the other 88% were computed and discarded. (A cell outside the searched window is never read by a windowed argmin.)

fixed_s2s[t] (a fixed external scale): refit at the column's native exactly as the default path (the refit template), with the strategy deployed at that scale, with_width(lo, fixed_width(lo, fixed_s2s[t])) — the refit_imc!(…; s2) conduit — so its loss width is scale_multiple·√s2 instead of the consensus set's scale_multiple·ŝ. The consensus-anchoring ablation evaluation (miscal_evaluation_refit with plugin_scale) is built from it. Combines with natives; mutually exclusive with widths.

VisualGeometryToolkitEval.Evaluation.MsacSpec — Type
MsacSpec(name, loss_width, lo; refinement_loss_width = nothing)

One MSAC column of evaluate_sample_budget: MSAC selection (VisualGeometryToolkitCore's MsacScoring at threshold loss_width, pool frame), its running best refit by its own refiner lo (a paper's truncated refiner — an ExternalRefit strategy such as PoseLib's TLS-LM) at refinement_loss_width, the arm's tuned refinement loss width; nothing refits at the selection loss width.

VisualGeometryToolkitEval.Evaluation.OracleSelector — Type
OracleSelector(name, outlier_halfwidth)

Oracle selector: the ground-truth-best SINGLE model by model_imc. Recomputes the imc per model (pruned by VisualGeometryToolkitCore's pool_imc, the stored lower bound on that imc) and refines that one model under LO (at a representative outlier half-width, the first method's, unless the config names the arm's refinement native).

VisualGeometryToolkitEval.Evaluation.PairCtx — Type
PairCtx

Everything the refit layer needs about one pair. Built once per pair by build_pair_ctx and reused across every (LO refit spec × grid column), it holds the pair itself (a light PoolPair), its pool-frame problem (ep), the optional RelposeBundleProblem (bp, nothing unless bundle=true), the geometry, the problem class (problem_type) and the refit scoring TEMPLATES: scoring, the scoring every native refit is built from at its own outlier half-width (with_width(scoring, OutlierHalfwidth(nat′))), and solo_scoring, the one an absolute-width (solo) refit sweeps its seed with (by default scoring).

VisualGeometryToolkitEval.Evaluation.PairGeom — Type
PairGeom

Per-pair calibration and ground truth, the context that scores a pool model's pose error. It scores any stored pool-frame fundamental's coherent imc pose error and holds the pool-frame csponds cs (x1 => x2) as a concretely typed Csponds.

VisualGeometryToolkitEval.Evaluation.RefitHalfwidth — Type
RefitHalfwidth(lo, outlier_halfwidth, scoring_of)
RefitHalfwidth(lo, outlier_halfwidth, template::AbstractScoring)

lo refitting under the refit scoring at ITS OWN outlier half-width instead of the selection's: the in-loop form of the refit layer's native port (refit_imc!'s nat′, refit_model). The self-scaled arms (Stu-tU IRLS, BCD) read their half-width from the scoring the loop hands them, so inside a RANSAC loop they would otherwise refit at the SELECTION half-width — not the refit half-width their sequential CV tuned at the fixed a*. scoring_of(problem) builds the refit scoring; the template form is with_width(template, OutlierHalfwidth(outlier_halfwidth)).

In the loop, each call re-scores the model under the refit scoring in the loop's own buffers and runs the loop's own Phase-2 step on that consensus set (VisualGeometryToolkitEstimation's locally_optimize_rescored!): at outlier_halfwidth = the selection's it is the score the loop just ran, so the wrapped arm reproduces the bare arm exactly. The refined model goes back to the loop, which re-scores it under the SELECTION scoring and keeps it only if it beats the incumbent.

VisualGeometryToolkitEval.Evaluation.Roster — Type
Roster(composed, solo, basin)

A paper's arm roster, the argument of every reader that rebuilds arms from a tuned sidecar (deployed_budget_settings, deployed_basin_settings, audit_operating_points). Each field is the paper's builder:

  • composed(problem::Symbol) -> Vector{ComposedSpec} — the composed score+LO roster (scale-multiple / outlier-half-width / natively delivered loss-width arms) of the composed miscal and budget evaluations;
  • solo(problem::Symbol; role::Symbol) -> Vector{SoloSpec} — the solo roster;
  • basin(problem::Symbol) -> Vector{ComposedSpec} — the basin roster (loss-width and outlier-half-width arms only; a scale multiple has no meaning on the basin axis).
VisualGeometryToolkitEval.Evaluation.SampleBudgetConfig — Type
SampleBudgetConfig

Configuration for the sample-budget selection protocol.

Fields (the schedule and the LO are REQUIRED: a sample-budget experiment

states its protocol of record, e.g. a paper's samplebudgetprotocol.toml)

  • sample_cap::Int — total minimal samples drawn per pair
  • batch_size::Int — selection (non-LO) checkpoint stride
  • lo_every::Int — LO checkpoint stride (after the first batch)
  • lo_strategy::AbstractLocalOptimization — LO method
  • budget_unit::Symbol — budget axis: :models counts essential matrices inspected (Shekhovtsov's unit); :samples counts minimal subsets.

  • Selection (running-best, no LO): every batch_size — 100, 200, …, cap.
  • LO (refit the running best): after the first batch, then the lo_every grid — {batch_size} ∪ {lo_every, 2·lo_every, …, cap} = 100, 500, 1000, ….

VisualGeometryToolkitEval.Evaluation.ScoreGuarded — Type
ScoreGuarded(inner::AbstractLocalOptimization)

LO-RANSAC best-so-far monotonicity wrapper for IRLS-family arms. The inner LO runs unchanged, but the refined model is kept only if its SELECTION score (the same marginal that seeded it) does not drop below the seed's (VisualGeometryToolkitEstimation's score_guard). It preserves score monotonicity while the optimizer descends a different objective.

Its RefitFamily and the external-refit bracket (external_workspace, prepare_external!, refine_external!) are inner's, as on VisualGeometryToolkitEstimation's CountedLO and TerminalLO: a guarded external arm is routed, prepared and refined as the bare arm. The guard is score_guard on the native path, so an external refit is forwarded unguarded.

Its running best is refit by the config's LO (lo = nothing) at the config's native (nat_ref, else width), or by its own LO lo at refinement_width (else the config's nat_ref, else width) — the MSAC + truncated-refiner columns.

VisualGeometryToolkitEval.Evaluation.WindowedGridMethod — Type
WindowedGridMethod(label, scene_errors, scene_sigma2, native_grid, window, to_native,
                   criterion)

Tunes on the standardized scale-multiple axis (accv §common-cutoff, eq. 28) instead of the raw native grid, with the reference scale estimated from the validation draw so it tracks the validation cardinality n — the protocol of the windowed_bootstrap tuning scheme.

  • scene_errors[i] — precomputed (pairs × |native_grid|) post-LO error matrix on a fixed grid of native hyperparameter values (native_grid).
  • scene_sigma2[i][j] — pair (i,j)'s noise variance σ̂² (e.g. gt_variance), used to form the cardinality-tied scale σ_med(n).
  • to_native(scale_multiple, scale) -> native — the eq-(28) map for this scoring, a closure over the caller's native_map(axis; d_g) so this package stays decoupled from the scoring-spec types.
  • window — the spec's ScaleMultipleWindow; criterion — its objective (no default: both are parameters of the tuning spec).

Per trial, tune draws n val pairs, forms σ_med(n)=√median σ̂² over them, and takes the FREE ARGMIN of the val objective over every native_grid column inside the standardized window [to_native(lo, σ_med), to_native(hi, σ_med)] (the window's covered range at the drawn supplied scale — corrupting the scale slides the window, which is the miscalibration mechanism). evaluate reads the tuned column on the test pairs.

VisualGeometryToolkitEval.Evaluation.apply_lo_refits — Method
apply_lo_refits(problem_type, specs::Vector{LoRefitSpec}, pairs;
                scoring, solo_scoring = scoring,
                operating_scale_multiple = OPERATING_SCALE_MULTIPLE, on_fail = nothing)
    -> Dict{String, Matrix{Float64}}

Run every refit spec over pairs and return each spec's post-LO error matrix. scoring is the refit scoring TEMPLATE (rebuilt at each refit's own outlier half-width), solo_scoring the absolute-width (widths) columns' template. The run is threaded :greedy over the flat (pair × spec) product so neither a subsampled validation side nor the arms' very uneven per-spec cost leaves threads idle (see the comment in the body), with one PairCtx built per task at exactly that spec's bundle. pairs are light pool records (PoolPair): a refit never reads a residual matrix. on_fail = nothing ⇒ seed-error fallback (LO never worsens the running best); supply NaN for the ladder convention (failed refit ≠ success). Returns label => (P × T) imc matrix.

VisualGeometryToolkitEval.Evaluation.audit_operating_points — Method
audit_operating_points(roster::Roster, path; problem = nothing) -> true

Audit the tuning sidecar at path through its gate-enforced reader. A basin sidecar goes through deployed_basin_settings, a composed one through deployed_budget_settings; it throws on any clipped arm (a boundary argmin never reaches a consumer) and on any other artifact format, and returns true. MANDATORY before a figure or table consumes the sidecar.

VisualGeometryToolkitEval.Evaluation.bootstrap_trials — Method
bootstrap_trials(method, proto::FlatProtocol, budget::BudgetSampling, n;

The per-draw bootstrap: each of the budget.n_draws draws tunes the hyperparameter on n val pairs of proto (tune) and evaluates the tuned column on its test pairs (evaluate): the draw's median test error (a pair without a model counts as Inf) and its mAA@T (the eligibility rule, eligible_maa). VisualGeometryToolkitEval.Evaluation.coarse_search — Method
coarse_search(errorsfn, cells::AbstractDict{K,<:NamedTuple}, scheme; label = string)
    -> Dict{K,NamedTuple}

Stage 1 of the coarse-fine search (module header): per search key k, cells[k] names each axis's coarse SpacedGrid (grid_spec of the spec's axis); the objective over their product, each axis extended on a side while the joint argmin lies within the spec's edge_margin of that face. scheme is a JointCoarseFine or a CoarseFine (one axis, named by the cells). VisualGeometryToolkitEval.Evaluation.compute_method_rows — Method
compute_method_rows(method, budget::BudgetSampling; protocol, sizes = budget.sizes)
    -> (summary::Vector{NamedTuple}, trials::Vector{NamedTuple})

Per-method, per-n evaluation loop over the validation budgets sizes (the schedule's own by default; a miscal evaluation supplies its one fixed budget): budget.n_draws draws per budget (bootstrap_trials), the BCa CIs resampled with resampling_rng(budget, n). VisualGeometryToolkitEval.Evaluation.deployed_budget_settings — Method
deployed_budget_settings(roster::Roster, path; problem = nothing)
    -> Vector{label => (lo, sel, ref, kind)}

Per-arm tuned operating points of a composed tuning sidecar, rebuilt through the roster. The sidecar is read through VisualGeometryToolkitEval load_tuning_artifact, which refuses another format; each arm is rebuilt through roster.composed(problem): the LO instance (the tuned scale multiple baked in for scale-multiple arms), the SELECTION native and the REFINEMENT native (scale-multiple arms refit at the selection native — consensus-anchored; native parameterizations at their tuned value) and the arm's width parameterization kind — the roster's, the one source of an arm's kind (a sidecar's own kinds list is not read). problem defaults to the sidecar's own "problem".

INTERIOR-ARGMIN INVARIANT: a HARD ERROR on any arm whose persisted boundary_hits is non-empty — expand the window on the flagged side and re-run the tuning (a SelectionWidth arm has no width of its own to clip: its list carries the selection's axis alone, and its recorded width must be its selection's, operating_width). A basin sidecar is refused (deployed_basin_settings reads it).

VisualGeometryToolkitEval.Evaluation.deployed_setting — Method
deployed_setting(path; context = path, allow_edge = false) -> NamedTuple

The gated reader of a coarse-fine tuning artifact (save_coarse_fine_artifact): the selected value of every axis, as a NamedTuple. HARD ERROR when the spec is not a coarse-fine one or the search hit its window's edge on any axis (enforce_probe_interior; allow_edge = true downgrades to a warning for FORENSIC reads only). A tuned setting is deployed through this, never from a literal.

Also reads the one-scalar layout written before the joint search (a CV "record" and "x_star_fine"; BlobBoards' half-width run of record): (; <param_name> = x_star_fine).

VisualGeometryToolkitEval.Evaluation.enforce_probe_interior — Method
enforce_probe_interior(rec_or_flag; context, allow_edge = false)

Read-side gate of the coarse-fine search: HARD ERROR when a record (or an explicit boundary_hit::Bool) is flagged — the coarse window clipped the optimum even after the extension budget, so the tuned value is suspect and must never be silently consumed. Re-run the search (it expands itself; if it still hits the budget, the objective has no interior optimum on any reachable window and the method/cell needs attention). allow_edge = true downgrades to a loud warn — FORENSIC reads only, never production. Mirrors the LO engine's _enforce_interior_argmin gate on the product-grid readers.

Only an E context has bearings: on an F or H context ctx.ep holds pool pixels, so this refuses rather than hand 2-vectors to a ray test.

VisualGeometryToolkitEval.Evaluation.evaluate_sample_budget — Method
evaluate_sample_budget(problem_type, methods::Vector{<:SampleBudgetMethodSpec}, pairs, residuals;
                       pair_ids, msac_specs::Vector{<:MsacSpec}, cfg::SampleBudgetConfig,
                       sample_starts = nothing, refit_scoring = methods[1].scoring)
    -> SampleBudgetResults

Run the sample-budget protocol over the pool pairs pairs. The pairs are a flat vector of light pool records (PoolPair) with their residual matrices residuals (residuals[i] is pair i's; VisualGeometryToolkitEval load_pool_residuals, residual_matrix). A :samples budget (cfg.budget_unit) counts minimal samples through sample_starts[i], pair i's minimal-sample starts — VisualGeometryToolkitEval sample_starts(pool), the one reconstruction of sample boundaries; it is required then and ignored for a :models budget. Columns: the scoring methods, then one MSAC column per MsacSpec, then the oracle (last). Every native refit is seeded under refit_scoring (a scoring TEMPLATE, rebuilt at each refit's own outlier half-width) — the methods' own: they must share it. Parallel over pairs; per-method scoring workspaces preallocated per thread.

VisualGeometryToolkitEval.Evaluation.evaluate_sample_budget_pair! — Method
evaluate_sample_budget_pair!(out_err_batch, out_best_idx_batch, out_err_lo,
                             out_lo_ns, out_lo_calls, selectors::Tuple,
                             problem_type, pair, R, cfg; refit_scoring = nothing,
                             sample_starts = nothing)

The per-pair worker of evaluate_sample_budget: walk one pair's pool and fill its slice of the results.

pair is the light pool record, R its residual matrix (numpoints × nummodels, Float32, the pool frame). sample_starts is the pair's minimal-sample starts (VisualGeometryToolkitEval sample_starts), required when the budget counts :samples. The selectors — a Tuple, so every per-model call is statically dispatched — are mutated too (reset per pair, then folded), so the problem type follows them. refit_scoring is the per-pair context's refit template — the one every refit's scoring is built from at its own native — so it must be the selectors' own.

VisualGeometryToolkitEval.Evaluation.guarded_refit — Method

    -> (err::Float64, lo_ns::Int64)

The seed-fallback + timing bracket.

  • opt() -> Union{Nothing, M} — the bracketed optimizer call (data-in → result-out). Throws are caught; nothing signals bail / no consensus.
  • score(m::M) -> Float64 — GT scoring of the refined model, NOT timed. A non-finite score falls back to on_fail (a GT-free decision: the refit produced an unusable model).

VisualGeometryToolkitEval.Evaluation.live_runs — Method
live_runs(scoring, lo, ctxs; problem_of, seed_of, config = RansacConfig(), warmup = true,
          lo_of = nothing, on_improvement_of = nothing, score_guard = false,
          cancelled = () -> false, finalize = nothing)
    -> (; err, trials, wall_s)            # plus `extras` when `finalize !== nothing`

Run one live production ransac per pair context ctxs[j], threaded over pairs. Each run uses the caller's problem of the pair, problem_of(ctxs[j].pair), the selection scoring, the LO strategy lo, adaptive termination under config. Each pair's stream is StableRNG(seed_of(j)), handed to ransac explicitly, so a run is independent of the thread schedule, identical across calls that share seed_of (seed_of should be a stable_seed). Per pair: err[j] the imc pose error [deg] of the final model, Inf when the run yielded no model (converged false) or the pair was cancelled; trials[j] the trials drawn; wall_s[j] the wall clock of the ransac call alone. warmup first runs one short solve on pair 1 (result discarded) so no bracket pays JIT.

The keywords below default so that the result is exactly the plain run's.

  • lo_of(j) returns the LO strategy of pair j, overriding lo. The warmup uses lo_of(1) (an LO holds no recorded state).
  • on_improvement_of(j) returns the ransac improvement callback (on_improvement(trial, score, ws), fired when the incumbent improves). It is called with j = 0 once for the warmup (return a throwaway callback of the same type as for real pairs, writing to scratch storage, so the loop compiles once and the warmup records nothing) and with j = 1:n for the pairs.
  • score_guard is forwarded to ransac: per-candidate ScoreGuarded acceptance.
  • cancelled() is polled before each pair; a cancelled pair is not run and keeps err = Inf, trials = 0, wall_s = NaN. Pairs are threaded, so a pair already started finishes. VisualGeometryToolkitEval.Experiments.cancelled is the kaimon-aware poll.
  • finalize(j, r) runs after pair j's ransac result r, on the pair's thread and outside its wall bracket; its values come back as extras::Vector{Any} (nothing for a pair not run). Without finalize the result has no extras field.

VisualGeometryToolkitEval.Evaluation.refit_imc! — Method
refit_imc!(ctx::PairCtx, lo, seed, nat′::Float64;
           scoring = ctx.scoring, on_fail = nothing, bundle::Bool = false,
           s2 = nothing) -> (imc::Float64, lo_ns::Int64)

Refine the seed model seed with strategy lo at ITS native parameter nat′ (see consumed_native) and return the refined model's imc error [deg] plus the bracketed optimizer wall-clock.

  • scoring (NativeRefit): the scoring TEMPLATE the refit is seeded under, rebuilt at nat′ (with_width(scoring, OutlierHalfwidth(nat′))) — the context's refit template by default; ctx.solo_scoring for an absolute-width (solo) refit.

VisualGeometryToolkitEval.Evaluation.rigid_invariance_errors — Method
rigid_invariance_errors(poses; targets, units = sort!(collect(keys(poses))), min_obs = 3)
    -> (; translation::Matrix{Float64}, rotation::Matrix{Float64}, units, pairs)

The invariance errors of rigidly mounted targets. poses[u][m] is target m's estimated pose in unit u (a value with fields R, the rotation, and t, the translation: target → camera, x_cam = R·X + t, e.g. an Extrinsics3); a target absent from poses[u] was not observed there. targets lists every target that could be observed; pairs are its sorted pairs (m, n), m < n.

For each pair and each unit observing both targets, the relative pose T_m⁻¹ T_n is compared with a LEAVE-ONE-OUT reference over the other units observing that pair: the rotation MEDOID (the observation minimising summed geodesic distance to the others — robust to the two-fold flips a mean would be dragged by) and the componentwise MEDIAN translation. Leave-one-out is not optional: a reference containing the scored observation scores it zero by construction and rewards observing each pair in fewer units.

Returns length(units) × length(pairs) matrices: translation (the translation's distance from the reference, in the poses' units) and rotation (geodesic angle, degrees). An entry is Inf where the pair was not observed in that unit, or was observed in fewer than max(min_obs, 3) units (no reference) — so under eligible_maa (the mAA rule: a non-finite error scores 0 and stays in the denominator) a missed pair counts as a failure, and eligible_maa(e, isfinite.(e)) is the accuracy over what was observed.
