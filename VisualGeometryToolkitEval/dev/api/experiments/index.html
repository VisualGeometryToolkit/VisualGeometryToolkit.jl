API: Experiments

The stage runner, run records, provenance and the data layer of a paper project.

Public names

VisualGeometryToolkitEval.Experiments — Module
Experiments

The paper-generic experiment-codification framework: the Stage table + run_stages entrypoint (--plan/--stage/--force), the run_driver shell-out and its in-process form run_isolated, require_input/fresher declarations, the run records (the configuration-of-record layer), the executable codification contract (contract_violations) and the one data layer of every paper project: the root ladder and artifact view (set_project_root!, data_root, ArtifactView), the input write guard (assert_not_input), the provenance record (write_provenance, read_provenance), the keyed cache (cached_result) and the data policy (data_policy_violations).

This module holds what every paper uses unchanged: the runner mechanics and the contract rules. A paper's own decisions stay in that paper's project: its stage rosters and input paths, its driver wiring (set with set_driver_context!), its artifact destinations, splits and oracle constants.

VisualGeometryToolkitEval.Experiments.RUN_CONFIG_KEYS — Constant
RUN_CONFIG_KEYS :: Vector{Pair{String,Tuple}}

Allowed keys of the run-config sections whose vocabulary THIS package defines, as dotted paths ("render.main" is the nested table). A section absent here belongs to the PROJECT that ships the config and is not key-checked — [source], [extract], [pool], [arm], [ransac] and the rest are read ad hoc by its drivers, and [source.recon_special] is keyed by scene name, so a fixed vocabulary would be wrong. [tuning.<name>] has its own, stricter check (Tuning _read_struct → VisualGeometryToolkitCore.check_keys, driven by the struct fields) and is therefore not restated here.

Nested tables are listed in their own right: a check on [render] alone sees main as one known key and nothing inside it.

VisualGeometryToolkitEval.Experiments.RUN_KEY_EXCLUDED — Constant

Top-level config sections that never touch a run's data and so never key it.

VisualGeometryToolkitEval.Experiments.ArtifactView — Type
ArtifactView(toml; dir, mount = name -> "", default = String[])

A project's published input data as Julia artifacts: toml is the Artifacts.toml binding them (lazy, Zenodo-hosted tarballs), dir the view directory their trees are linked into (default <project>/data/exp_raw, so the view IS the project's DrWatson data directory), mount(name) the subdirectory of dir artifact name mounts at (trees overlap directories, so the view is per-file links), and default the artifacts data_root installs when asked for none in particular.

VisualGeometryToolkitEval.Experiments.DataPolicyAllow — Type
DataPolicyAllow(rule, file, match)

One allowlisted (deferred) violation: rule "D1"…"D4", file relative to the scanned project root, and a substring match of the offending line. Each entry should name what fixes it, in a comment beside it.

VisualGeometryToolkitEval.Experiments.Stage — Type
Stage(name::Symbol, desc::String, done, run)

One idempotent step of a codified experiment: done() is a CHEAP predicate (no GPU, no heavy loads) — a stage whose done() holds is skipped unless --force; run() performs the work (often a run_driver shell-out) and may assume every earlier stage completed. Declared in figure/table order and executed by run_stages.

VisualGeometryToolkitEval.Experiments.TagRename — Type
TagRename(path::Regex, old, new)

One tag rename: a string VALUE old whose dotted key path matches path becomes new. The path of a value is its keys joined by ., an array element adding [i] ("selectors[1]", "geometry.local_optimization.type"), so a rename can be scoped to the family that owns the tag: "fixed" is one tag in nuisance.scale and another in window.type.

VisualGeometryToolkitEval.Experiments.artifact_view! — Method
artifact_view!(view, names) -> String

Install the artifacts names of view (install_artifact) and link each tree into the view directory at its mount (link_tree!), marking the directory .artifact_view. Idempotent; returns the view directory.

VisualGeometryToolkitEval.Experiments.assert_not_input — Method
assert_not_input(path; producer = false)

The runtime guard of every writer here: refuse a write at or under data_root — the read-only input tree — unless the caller declares itself a producer (a pool generator writing a NEW tree under the data root). A results root nested inside the data root (one author binding has data_root()/results/…) is not input. Nothing is guarded when no data root is bound.

VisualGeometryToolkitEval.Experiments.assert_primary_copy — Method
assert_primary_copy(what)

Producers that write INTO the data tree (calibration generators, converters, packagers) call this first: an artifact view is read-only.

VisualGeometryToolkitEval.Experiments.cached_result — Method
cached_result(f, prefix, cfg, dir; key = legacy_hash_key, force = false,
              gitpath = project_root()) -> (data, file)

The keyed result cache: <dir>/<prefix>_<key(cfg)>.jld2 is loaded (DrWatson wload) when present, else f(cfg) (a String-keyed Dict) is computed and saved tagged like DrWatson's tagsave (gitcommit + gitpatch ride along) and written with DrWatson's safesave, so a forced re-run keeps the previous version as _#n. The file name is exactly the one DrWatson's produce_or_load(…; filename = hash, prefix) builds, so its existing caches are found. Justified extension: produce_or_load itself swallows save errors (DrWatson saving_files.jl:107-116 — a failed write returns the data as if cached) and forces safe = false; here a save error propagates.

VisualGeometryToolkitEval.Experiments.cancelled — Method
cancelled() -> Bool

Whether a kaimon cancel_eval was requested for the running evaluation (Main.KaimonGate.is_cancelled()); false outside a kaimon session. Poll it from long loops, e.g. live_runs(...; cancelled = Experiments.cancelled).

VisualGeometryToolkitEval.Experiments.commit_drift — Method
commit_drift(prov; gitpath = project_root()) -> Union{Nothing, Tuple{String,String}}

(recorded, current) when the commit a provenance record names is not the current one of gitpath, nothing when they agree or either is unknown. Compared as COMMITS, through DrWatson's gitdescribe(gitpath; dirty_suffix = ""): a describe string with an annotated tag (v0.7.0-12-g89f65bd), a bare sha and an exact tag all name their commit, and a dirty suffix is not a different commit.

VisualGeometryToolkitEval.Experiments.contract_violations — Method
contract_violations(file) -> Vector{String}

The codification-contract check for one experiment file: returns a human-readable violation per broken rule (empty ⇒ compliant). Support files (registry.jl and *common.jl, e.g. a paper's shared external-arm plumbing) are exempt from R3; *_worker.jl subroutines are exempt from its stage-runner requirement (they are driven by their parent experiment) but still carry a provenance line.

VisualGeometryToolkitEval.Experiments.data_policy_violations — Method
data_policy_violations(root; dirs = ["src", "scripts"],
                       exts = [".jl", ".sh", ".sbatch"], allow = DataPolicyAllow[])
    -> Vector{NamedTuple{(:rule, :file, :line, :text)}}

The data-policy findings (rules D1–D4, see the file header) in the dirs of project root, minus the allowed ones, plus a STALE finding for every allow entry that matched nothing. Empty ⇔ compliant.

VisualGeometryToolkitEval.Experiments.data_root — Method
data_root(; tiers = nothing) -> String

The project's input tree (read-only): ENV["VGTK_DATA_ROOT"] → the project's data/exp_raw (DrWatson datadir("exp_raw"); a link, a directory, or the artifact view) → the project's fallback rung → its ArtifactView, installing tiers (default: the view's default). Configs state input paths RELATIVE to it; nothing under it is written except by a declared producer (assert_not_input).

VisualGeometryToolkitEval.Experiments.experiment_dir — Method
experiment_dir(cfg) -> String

The results directory of the config's [experiment]: <results root>/<dataset>/<matcher>/<problem>. A run's keyed directory lives under it, named by the project.

VisualGeometryToolkitEval.Experiments.fresher — Method
fresher(out, inputs...) -> Bool

The standard Stage done-predicate: out exists, every input exists, and out is at least as new as each input — a stale panel from a missing/renewed input is NOT done.

VisualGeometryToolkitEval.Experiments.install_artifact — Method
install_artifact(name, toml) -> String

Install artifact name of toml (download, verify sha256 and git-tree-sha1, unpack into the depot) unless present, and return its tree. A placeholder URL (an UPPER_CASE token in place of the Zenodo id or the Hugging Face revision: the record is not published or uploaded) and a failed download (an unpublished Zenodo draft, a private dataset) are refused with the way out — bind a data root.

VisualGeometryToolkitEval.Experiments.is_artifact_view — Method

Whether dir is an artifact view (a directory carrying the .artifact_view marker).

VisualGeometryToolkitEval.Experiments.is_primary_copy — Method
is_primary_copy() -> Bool

Whether the data root is a writable primary copy (bound by ENV, the project's data/exp_raw or its fallback) rather than an artifact view, whose trees are content-addressed and read-only. Same resolution as data_root.

VisualGeometryToolkitEval.Experiments.legacy_hash_key — Method
legacy_hash_key(x) -> String

LEGACY, version-UNSTABLE key: string(hash(x)). It names the existing caches of bmvc2026 and other paper projects (<prefix>_<hash(cfg)>.jld2, bmvc2026's detection run_key), which must not move before their next full regeneration — that one re-keys them to run_key (SHA-256 of the sorted TOML). Never use it for a new key.

VisualGeometryToolkitEval.Experiments.link_tree! — Method
link_tree!(tree, dst) -> Int

Link every file of tree into dst (per-file symlinks: artifact trees share directories, so directory links would not compose); an existing path — a link made earlier or an author's own file — is left alone. Returns the number of new links.

VisualGeometryToolkitEval.Experiments.load_run_config — Method
load_run_config(path) -> Dict

Parse a run config: it must carry [experiment] with dataset, matcher, problem and pool_dir, and an unknown key in a section this package owns (RUN_CONFIG_KEYS) is refused.

VisualGeometryToolkitEval.Experiments.oracle_floor_done — Method
oracle_floor_done(path, tag; source) -> Bool

Whether cell tag has its floor in the sidecar path AND the floor was computed on source (oracle_floor_source): every key of source must equal the recorded one. Presence of the key alone is not enough: floors computed on a retired pool tree must not read as done.

VisualGeometryToolkitEval.Experiments.oracle_floor_source — Method
oracle_floor_source(pool_dir, problem, scenes) -> Dict{String,Any}

The record of what an oracle floor was computed on: the pool tree, the problem family and the (sorted) scenes. write_oracle_floor stores it as the floor's source; oracle_floor_done compares it with the current one.

VisualGeometryToolkitEval.Experiments.oracle_floors_note — Method
oracle_floors_note() -> String

The note stored in the oracle-floor sidecar. The mAA threshold in it is the configured one (VisualGeometryToolkitEval.Stats.maa_threshold), not a literal.

VisualGeometryToolkitEval.Experiments.oracle_floors_path — Function

The pseudo-GT oracle-floor sidecar of a results tree (the floors' producer writes it): <root>/oracle_floors.jld2.

VisualGeometryToolkitEval.Experiments.progress — Method
progress(msg) -> nothing

Report msg as the running evaluation's progress (Main.KaimonGate.progress(msg)); a no-op outside a kaimon session.

VisualGeometryToolkitEval.Experiments.project_root — Method

The project the drivers run from: set_project_root!'s root, else DrWatson's projectdir().

VisualGeometryToolkitEval.Experiments.provenance_inputs — Method
provenance_inputs(prov) -> Vector{String}

The declared inputs of a provenance record as absolute paths: relative entries joined to the roots recorded beside them; a retired record's absolute list as is.

VisualGeometryToolkitEval.Experiments.read_provenance — Method
read_provenance(dir) -> Dict{String,Any}

The provenance record of dir as the one flat dict of write_provenance, whatever layout wrote it: the current one; the VisualGeometryToolkitEval ≤ 0.1 one (its _dirty.patch read back as gitpatch); bmvc2026's [provenance] + [config] tables (merged; created read as timestamp). Errors when the record is absent.

VisualGeometryToolkitEval.Experiments.read_rekey_map — Method
read_rekey_map(path) -> Dict{String,String}

The old-key → new-key map of a written re-key file (moved keys only).

VisualGeometryToolkitEval.Experiments.rekey_map — Method
rekey_map(configs; renames, keyed_table, key) -> Vector{NamedTuple}

For each config path in configs: keyed_table(path) is the table the project's key function hashes, computed with the current code, and key(table) that hash. Returns one row per config — config, old_key, new_key, moved and the applied substitutions. A config whose keyed_table throws is recorded with error set and no keys (it is not keyed by this function).

VisualGeometryToolkitEval.Experiments.rename_tags — Method
rename_tags(table, renames) -> (renamed, applied)

A deep copy of table with every matching rename applied, and the list of path => (old, new) substitutions made. A value matched by two renames is an ArgumentError (the renames must be unambiguous).

VisualGeometryToolkitEval.Experiments.require_input — Method
require_input(path; what, provenance)

Declared data input of an experiment: hard error (with the provenance recipe) when absent. Inputs are declared at the top of each experiment file so the dependency graph is readable without running anything.

VisualGeometryToolkitEval.Experiments.results_root — Method
results_root() -> String

The project's results tree: ENV["VGTK_RESULTS_ROOT"] → the project's data/exp_pro (DrWatson datadir("exp_pro")), created when the project binds create_results = true, an error otherwise.

VisualGeometryToolkitEval.Experiments.run_complete — Method
run_complete(outdir; sidecar) -> Bool

Keyed skip-if-complete: a run counts as done only when its result sidecar (a file name under outdir) AND its _provenance.toml exist; when skipping, WARN if the recorded commit differs from the project's current one (warn_commit_drift).

VisualGeometryToolkitEval.Experiments.run_driver — Method
run_driver(script, args...; driver_dir = default_driver_dir(),
           project = default_driver_project(),
           env = Dict(), threads = get(ENV, "SLURM_CPUS_PER_TASK", "auto"))

Shell out to a paper driver in a fresh Julia process (the drivers parse ARGS at include time, so in-process include is not composable). A relative script resolves against driver_dir; the child runs --project=<project>. Errors propagate (run throws on nonzero exit).

VisualGeometryToolkitEval.Experiments.run_isolated — Method
run_isolated(path; args = String[], env = Dict{String,String}(),
             bindings = Dict{Symbol,Any}()) -> Module

Include the script path in a fresh module of its own, in this process: a paper driver defines top-level constants meant for a process of its own, so several drivers included into one session collide, while a throwaway module gives each the clean top level it expects and keeps the loaded packages warm (no new process, no recompilation). While the script's top level runs, ARGS is args and the environment holds env (both restored afterwards, also on error); bindings are constants defined in the module first (a name the script uses unqualified). The module's exit throws instead of ending the session. Returns the module: the functions the script defined live in a newer world, so call them through Base.invokelatest. A separate process (run_driver) is the other way to run a driver.

VisualGeometryToolkitEval.Experiments.run_key — Method
run_key(cfg) -> String

The run identity: the SHA-256 (hex, first 16) of the effective config printed as sorted TOML (Tuning _toml_hash, the one content hash behind tuning_hash too), with the RUN_KEY_EXCLUDED sections removed ([render] holds panel knobs of record, not experiment inputs) and every [tuning.<name>] entry resolved to its COMPLETE table (resolve_tuning!: a default of this package's configs/tuning.toml that the config inherits keys the run like a stated one). Key order does not move it, the Julia version does not move it, and a TOML round trip of the effective config reproduces it, so run_key(TOML.parsefile("_config.toml")) names the directory that holds it.

VisualGeometryToolkitEval.Experiments.run_stages — Method
run_stages(experiment::AbstractString, stages; argv = ARGS)

The uniform experiment entrypoint: --plan prints the stage table and exits (the structural check); otherwise runs every pending stage in declaration order (--stage=NAME restricts to one, or to a comma-separated subset — declaration order is still honored; --force re-runs done stages). The printed table is a snapshot; each stage's done() is RE-EVALUATED immediately before it would be skipped, because an earlier stage of the same run may have invalidated it. A stage failure aborts the run (later stages depend on earlier ones).

VisualGeometryToolkitEval.Experiments.set_driver_context! — Method
set_driver_context!(driver_dir; project = driver_dir)

Register the default script directory (and Julia project) run_driver resolves against — called once by a paper's experiments/common.jl shim.

VisualGeometryToolkitEval.Experiments.set_project_root! — Function
set_project_root!(root = projectdir(); resolve_links = false, data_fallback = nothing,
                  artifacts = nothing, create_results = false)

Bind the project the drivers run from (its git record, its data/exp_raw and data/exp_pro). The keywords are the per-project rungs of the ladder, kept so that every existing path resolves byte-identically:

  • resolve_links: return realpath of the data/exp_raw link rather than the link path itself (bmvc2026: its run keys hash paths under it);
  • data_fallback: a () -> path | nothing rung after the link (bmvc2026's BlobBoards.data_dir() preference);
  • artifacts: the ArtifactView of last resort;
  • create_results: create data/exp_pro when nothing binds a results root (accv2026 errors instead).

set_project_root!("") unbinds (the root then follows DrWatson's projectdir()).

VisualGeometryToolkitEval.Experiments.warn_commit_drift — Method
warn_commit_drift(prov, what; gitpath = project_root()) -> Bool

Skip-if-complete's WARNING (code is not keyed; the record restores it): warn when prov was recorded under another commit (commit_drift) — re-run with force if that change was result-affecting. Returns whether it warned.

VisualGeometryToolkitEval.Experiments.write_oracle_floor — Method
write_oracle_floor(path, tag, floor, maa; source, npairs, driver) -> path

Record the pool-best floor floor (median model error) and ceiling maa (mean pool-best mAA) of cell tag in the sidecar path (oracle_floors_path), which holds "floors" (tag => floor, tag * "_maa" => maa), "sources" (tag => source plus npairs, driver and the time computed) and "note" (oracle_floors_note). The other cells of the file are kept. The read-modify-write is serialized by a pid lock (path * ".lock"), because the oracle stages of concurrent chains write one file.

VisualGeometryToolkitEval.Experiments.write_provenance — Function
write_provenance(dir, fields = Dict(); driver, inputs = nothing,
                 gitpath = project_root(), producer = false) -> String

Write <dir>/_provenance.toml: fields (the caller's record — run key, config source, network hash, frame counts, …) plus driver, timestamp, hostname, julia, and DrWatson's tag! record of gitpath (gitcommit, gitpatch on a dirty tree, with uncommitted_files — the paths that patch touches). inputs (paths) are recorded relative to the results or data root they live under, the roots beside them (inputs = {data = […], data_root = …}). Refuses to write into the data root unless producer (assert_not_input). Returns the record's path.

VisualGeometryToolkitEval.Experiments.write_rekey_map — Method
write_rekey_map(path, rows; project, renames, commits = Dict()) -> path

Write a rekey_map as TOML: the project, the renames, the commits it was computed at, and per config its old and new keys and the substitutions.

VisualGeometryToolkitEval.Experiments.write_run_records — Method
write_run_records(outdir, cfg; driver, config_source, key, inputs = String[], producer = false)

Write the run's _config.toml (the effective config, its tuning specs resolved to their complete tables) and its provenance record (write_provenance: config_source, run_key, the declared inputs relative to their roots, and DrWatson's git record). producer = true is a pool generator's declaration that outdir is a NEW tree under the data root.
