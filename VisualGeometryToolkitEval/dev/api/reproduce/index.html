API: Reproduce

The reproducible-figures contract. See Reproducible figures.

Public names

VisualGeometryToolkitEval.Reproduce — Module
Reproduce

The reproducible-figures contract: paper_asset_graph (what a paper reads), read_reproduce_index (what REPRODUCE.md declares) and reproduce_index_violations (where the two disagree, plus generators that do not write their asset, static assets without provenance, and generated numbers re-typed in prose); and the regeneration's last stages: verify_assets and deploy_assets (a submitted asset is replaced only with sign-off), gather_numbers (the numbers file) and uncited_macros (numbers the paper defines but never cites); and the one writer of a driver's number macros: PaperNumbers, add_number!, add_table_row!, write_numbers, tex_number and number_macro_name, and where its numbers come from: checkout_commit and number_provenance; and a full reproduction as a branch of the paper for review: results_branch, accept_results and remove_results_worktree; and the runner that reproduces a project with one command: a stage graph of record (load_stage_graph, select_stages) on a site (load_site: Slurm or local), the inputs checked first (missing_inputs), a run manifest per launch, finished stages reused by run key, and the results branch at the end (results_branch_of_run); reproduce_main is its command line.

StageSpec

VisualGeometryToolkitEval.Reproduce.accept_results — Method
accept_results(dir, branch; replace_submitted, scratch_root = <results_branch's>) -> NamedTuple

Bring the assets of the results branch (results_branch) of the paper project at dir into its base branch as one merge commit, and tag it accepted/<stamp>. The assets go through deploy_assets: an asset the base holds a different copy of is replaced only with the sign-off replace_submitted (true for every asset, or a collection of the assets' paths relative to dir); without it the acceptance is refused and nothing changes. The merge is made in a worktree of its own under scratch_root (removed at the end, whatever happens); the tag is made on it, then the base moves to it: a checkout of the base fast-forwards (one with local changes to an accepted asset refuses: the tag is deleted again and the base stays; an unrelated local change survives). That fast-forward is a git merge in the user's checkout, so it runs the checkout's own post-merge hook; the commits accept_results makes skip hooks (--no-verify). A base no checkout holds moves by update-ref, so a checkout on another branch is untouched. Only the assets are merged, never the branch's manifest or comparison. A base that moved since the run (the manifest's base_commit) is a warning naming the accepted assets it changed: the branch's comparison is against the older base.

Returns (; commit, tag, deployed): the merge commit, the tag and the assets copied (repository paths).

VisualGeometryToolkitEval.Reproduce.add_macro! — Method
add_macro!(nums, name, body; arity, label = "", provenance = (;)) -> nums

Add the macro \<name> with arity parameters (1 to 9) to nums: its body is TeX in which #1 … #<arity> stand for the arguments (a figure's equal-height panel cell, \parbox[c][\panelht][c]{#1}{\centering #2}). Written by write_numbers as \newcommand{\<name>}[<arity>]{<body>} after its provenance comment, gathered by gather_numbers as it is; it is not a value, so tex_macro_values does not return it. A parameter beyond the arity, an arity outside 1–9, unbalanced braces, an unescaped % and a name nums already holds are each an ArgumentError.

VisualGeometryToolkitEval.Reproduce.add_number! — Method
add_number!(nums, name, value; label = "", provenance = (;), better = nothing, format...) -> nums

Add the number macro \<name> to nums. A value that is a number is typeset by tex_number with the format keywords (digits, sigdigits, percent, group_from, unit); a pair (lo, hi) is a range; a string is its body as typeset (a label, "---" for a missing cell, 10^{-6}) and takes no format. label names what reads the number when it is not the prose: a figure's fig:… (its caption, its axis), a table's tab:…. It goes into the macro's provenance comment. provenance overrides fields of the driver's (PaperNumbers) for this number. better is the direction in which the number improves, :lower (an error, a time), :higher (a rate, a score) or :none (a count, a setting), as a Symbol or a String; it goes into the provenance comment (; better=lower), from which a results comparison (results_branch) calls a change IMPROVED or DEGRADED. Without it a change is reported CHANGED, with no verdict.

name is letters only, never beginning with end (number_macro_name builds one); a name nums already holds, a body of more than one value (an unescaped %, # or &, a row break, unbalanced braces or math shifts, a trailing backslash), a ; in the label or provenance (the comment's separator), a Bool and a NaN are each an ArgumentError.

source
VisualGeometryToolkitEval.Reproduce.add_table_row! — Method
add_table_row!(nums, row, cells; label = "", provenance = (;), better = nothing, format...) -> String

Add a table row's numbers to nums, one macro per cell: cells is an ordered collection (a vector, a tuple, an OrderedDict) of column => value pairs in the table's column order; a Dict or a Set has no column order and is an ArgumentError. The cell's macro is \<row><Column> (row and each column letters only, the column capitalised). Each value is typeset as by add_number!, the format keywords shared by the row; better is one direction for every cell, or a collection of column => direction pairs for the cells that state one (a column the row lacks is an ArgumentError); a cell of another format is given as its tex_number string. Returns the row as the table's tex reads it, "\<row><A> & \<row><B> & …", without the row break.

One macro per cell, not one per row: the prose cites a table's number by the macro the table prints, and the gatherer's checks (compare_fragments, macro_literal_violations, uncited_macros) see each number.

VisualGeometryToolkitEval.Reproduce.deploy_assets — Method
deploy_assets(outdir, paperdir, names; replace_submitted = false) -> Vector{String}

Copy each rendered outdir/<name> into paperdir when the paper has no copy or holds a different one, after verifying them all in one report (verify_assets writes a fresh outdir/verify.tsv first). A submitted copy that differs is replaced only with the author's sign-off on the difference the report states: replace_submitted = true signs off every asset of the call, a collection of names only those (per-asset sign-off, so one call deploys every asset and the report keeps every row). Without it the deploy is refused, as an error naming each differing asset and the report, and copies nothing. A numbers file that differs from the submitted one in its % provenance \<name>: … lines alone (a rerun at a new run key or commit, the same macro values; the report's provenance_only) changed no number: it is deployed without sign-off, its provenance updated. Any other difference, a hand-written comment or whitespace included, still needs sign-off. Returns the assets copied (an identical one is not copied).

VisualGeometryToolkitEval.Reproduce.gather_numbers — Method
gather_numbers(fragments, out; generator, root, root_label = "<results_root()>") -> out

Write the paper's numbers file out from the generators' number-macro fragments (tex files): every argument-free macro of every fragment, one \newcommand{\<name>}{<value>} per line, sorted by name, under a header naming the generator and each fragment as <root_label>/<path relative to root> (no machine path). A macro's provenance comment in its fragment (the % provenance \<name>: … line write_numbers writes) goes before it. Never \providecommand: a macro the manuscript also defines must clash. A macro with parameters that the writer wrote (add_macro!: its provenance comment before it) is gathered as written, its arity kept. A macro that two fragments define, and any other fragment macro with arguments (a number is a value, not a template), are an ArgumentError.

Write out beside the generator's results, not into the paper: a submitted numbers file is replaced under the same sign-off as a figure, by deploy_assets.

VisualGeometryToolkitEval.Reproduce.macro_literal_violations — Method
macro_literal_violations(prose_files, macro_files; root, ignore = String[],
                         min_integer_digits = 3) -> Vector{ReproduceViolation}

Best-effort check that a number a generated macro file defines is not re-typed as a literal in the paper's prose: every argument-free macro of macro_files whose rendered value carries a number is searched for in the comment-stripped prose of prose_files, with number boundaries. A bare integer value is searched only from min_integer_digits digits (the default 3 skips the two-digit counts and percentages that coincide everywhere; 2 is strict and needs literal-ok marks). A TeX length is no literal: a number directly followed by a TeX unit (-0.3cm), or with a space where TeX reads a length (a whole braced argument, \hspace{0.3 cm}; after \kern, \hskip, …); in prose, "1.23 mm" is a number with a unit and is checked. A line holding reproduce: literal-ok (in a comment) is exempt, as is any macro named in ignore.

VisualGeometryToolkitEval.Reproduce.missing_inputs — Method
missing_inputs(g, stages; data_root, env = ENV, site = "", unpublished = nothing) -> Vector{NamedTuple}

Every input of the selected stages that is not there, as data, before anything runs: one row (; path, tier, used_by) per missing path (used_by every stage and config that reads it). A stage's inputs are its configs of record (one per array item) and their [inputs.<id>] tables with a path (relative to data_root) and a tier; a missing config is a row of tier "config of record". With no data root every data input is missing (tier as declared).

Each input's path is relative to ITS TIER's root (tier_data_root): env's <data_env>_<TIER>, else the graph's [sites.<site>.tiers] table, else data_root. A tier root that is named but not there makes each of its inputs a row whose tier says so ("mocap (root /x, from VGTK_DATA_ROOT_MOCAP, is not there)"). Each input is checked by inspect_input (src/codeidentity.jl), the one check a driver's `verifyinputsmakes too: a scratch run's output is refused like another content. An input of the reserved tier [UNPUBLISHEDTIER](@ref) is reported missing as never fetched; withunpublished(a vector), each such input is also pushed there,(; path, present, usedby)`, for the dry run to list.

An input with a sha256 (64 hex digits, of a file) is verified: an input that is there with another content is REFUSED, an ArgumentError naming each such input (its id, config, path, the expected and the actual hash), so nothing runs on data other than the data of record. An input without one is not checked. The hash is streamed and cached by path, size and modification time (file_sha256): a file is read once per process, and a launch that checks the same input from several configs reads it once.

VisualGeometryToolkitEval.Reproduce.number_macro_name — Method
number_macro_name(prefix, parts...) -> String

The name of a number macro (without its backslash) from a driver's prefix and name parts, the stack's naming rule: each part (a string, symbol or number) split into words at _, -, ., /, × and spaces, each word capitalised, each digit spelled out as a word of its own. number_macro_name("chromeTable", "kb_start", "median") is "chromeTableKbStartMedian"; number_macro_name("pose", "fx3_14mm") is "poseFxThreeOneFourMm". The prefix is letters only; a part holding any other character (a Greek letter, %, a comma) is an ArgumentError, as is a name LaTeX refuses (one beginning with end).

paper_asset_graph(tex_files; root = dirname(first(tex_files)), search_dirs = String[]) -> PaperAssetGraph

Every file a paper reads, found by following \input/\include/ \subfile/\includestandalone (recursively), \includegraphics (with the \graphicspath directories and the default extensions tried in LaTeX's order), and pgfplots/tikz data files (\addplot table {file}, \pgfplotstableread{file}, \pgfplotstabletypeset{file}). VisualGeometryToolkitEval.Reproduce.stage_run_state — Function
stage_run_state(record, queue = Dict()) -> (; state, tasks)

What the run of a stage that a run manifest records (record, one of its [stages]) came to, read from the stage's completion markers (stage_markers) and the queue (queue: slurm_queue_states), never from accounting. tasks maps each task to its state: its job's state while the queue holds the task ("PENDING", "RUNNING", …), else its marker's ("completed", "failed"), else "unknown". The queue comes first because Slurm requeues a task under the same job id (preemption with PreemptMode=REQUEUE, scontrol requeue): the attempt it stopped left a "failed" marker, and the task is pending or running again. A task that is finishing (COMPLETING) reads its marker when it has one. state is

  • "failed" when a task's marker says so and the queue no longer holds it;
  • "unknown" when a task has no marker and its job is no longer queued: it died without writing one (a node failure, a kill past the time limit's grace) or its markers are gone. Never taken as finished: a later launch runs the stage again;
  • "in flight" when every task without a marker is still queued;
  • "completed" when every task's marker says so.

A record of the local backend (no job id), which the runner itself writes after every task, is read as it stands: "completed" or "reused" is completed, "failed" failed, anything else (a run stopped mid-way) unknown.

tex_number(x; digits = nothing, sigdigits = nothing, percent = false, group_from = 0,
