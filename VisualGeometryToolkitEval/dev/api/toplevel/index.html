The driver command line, the artifact formats and the path of the defaults of record.

Public names

VisualGeometryToolkitEval.ARTIFACT_FORMATS — Constant
ARTIFACT_FORMATS

The format version this package writes and reads, per artifact kind (:pool, :pool_residuals, :pool_samples, :pnp_pool, :tuning), with the change the version introduced and the remedy for an older file. A kind that reads an earlier version through its version steps names the oldest it reads, read_from, and what that version introduced (read_from_change, quoted when an even older file is refused). The file key is "<kind>_format"; an absent key is version 1.

VisualGeometryToolkitEval.code_tree_changes — Method
code_tree_changes(recorded, current) -> Vector{String}

THE reuse rule of a stored result, for every project: the result stands for the current code only when this is empty. recorded is the code trees stored with the result (nothing when it has none: a result from before code identity was kept, which is computed once more and then records them), current the code's now (code_trees's trees). Each entry names what changed: "VisualGeometryToolkitCore: src 3fa29c01e2 → b71d0e44a9", "src: 18c2… → 9e0a…", "<name>: new" (loaded now, not then), "<name>: no longer loaded".

A result recorded with uncommitted code (a scratch run's: a tree marked +uncommitted, "uncommitted", or in no git checkout) is never reused, even for the same marked trees: the mark names HEAD, not the edits, so two runs under different uncommitted edits carry the same value. Each such tree is a change, "<name>: uncommitted when recorded".

VisualGeometryToolkitEval.code_trees — Method
code_trees(workdir; code = nothing, julia_project = workdir) -> (; trees, dirty, project_paths)

The code identity of a run in the git checkout workdir: trees, by name, the git tree hash of each of the project's code paths (relative to workdir: git rev-parse HEAD:<path>; by default src when there is one) and of every stack package julia_project's environment loads (its [deps] and what they reach in its Manifest, found in it or above it, a workspace's): a package loaded from a path ([sources], Pkg.develop) by the trees of its src, ext and Project.toml in its own repository ("src:<tree> ext:<tree> Project.toml:<blob>"), a released stack package by its Manifest git-tree-sha1. dirty names each of them whose files differ from HEAD (an edit, a staged or deleted file, an untracked one), or that is in no git checkout: a run of record refuses to run with it (refuse_uncommitted_code). Such a tree's value carries +uncommitted (or is "uncommitted"), so a result recorded with it is never reused (the mark names HEAD, not the edits). project_paths lists the project's own paths recorded (none: nothing identifies the project's code).

A workdir that is a REGISTERED install (a package's source in a depot, no git checkout: a registered package's example run with gitpath = pkgdir(Pkg)) is committed code, content-addressed and immutable: it is identified, by its name, by the tree hash the active environment records for it ("<git-tree-sha1> <name> <version> <uuid>", from Pkg.dependencies()), and the environment searched for stack packages is the active project's. Only a git checkout with uncommitted changes, or a path that is neither, is refused.

A tree moves only when a file under it changes: a commit that touches only docs, tests or the paper changes no tree. Compare two records with code_tree_changes.

The answer is kept in this process (git runs several times per path), and given again while nothing git reads has changed: every file under the code paths and under each path-loaded package's src, ext and Project.toml (by path, size, modification and change time and inode: an edit, a new, deleted or replaced file), the project's Project.toml and Manifest, and per repository its HEAD, the ref HEAD names, packed-refs, the index and the ignore files (a commit, a checkout, a staged or unstaged change). A file rewritten within the file system's time resolution with the same size and inode keeps the kept answer, as file_sha256's cache does; so does a change to the index alone made while code_trees runs git (whose own status run rewrites the index).

VisualGeometryToolkitEval.file_sha256 — Method
file_sha256(path) -> String

The SHA-256 (64 hex digits) of the file at path, read in blocks (a file of any size costs its read, never its size in memory) and cached in this process by its real path, size and modification time: a second call on an unchanged file costs a stat. A file rewritten in place within the file system's mtime resolution with the same size keeps its cached hash; a check of record that must exclude that runs in a fresh process. An ArgumentError for a directory or a missing path.

source
VisualGeometryToolkitEval.inspect_input — Method
inspect_input(id, table, root; root_source = "data root", root_name = "", allow_scratch = false)
    -> (; state, path, problem)

THE check of one [inputs.<id>] table under its tier's root (tier_data_root), for the runner's missing_inputs and a driver's verify_inputs alike. state is :present; :root_missing (a tier root other than the data root, named by root_name, that is not there); :missing (no path under root); or :refused (another content than its sha256 — a file's file_sha256, a directory's tree_sha256 with the table's sha256_exclude globs — or a scratch run's output, scratch_record, unless allow_scratch). problem says what, without the input's id. A sha256 that is no 64 hex digits, or a sha256_exclude on a file, is an ArgumentError (a config error).

VisualGeometryToolkitEval.refuse_uncommitted_code — Method
refuse_uncommitted_code(identity; what = "a run of record") -> nothing

The refusal of a run of record whose code is not committed, the same for the runner and a driver's records: identity is code_trees's result. An ArgumentError when any of its trees has uncommitted changes, or is in no git checkout (its results could not name the code they ran), or when it identifies none of the project's own code (no src, no code path).

VisualGeometryToolkitEval.scratch_record — Method
scratch_record(path) -> Bool

Whether path (a run directory, or anything at any depth inside one: run/sub/x.csv) is the output of a scratch run: the nearest _provenance.toml at or above it, the record of the run it belongs to, says scratch = true (Experiments.scratch_run). A scratch output is never an input of record, an upstream run of record, or a promoted run. A path under no record is no scratch output.

VisualGeometryToolkitEval.tier_data_root — Method
tier_data_root(tier, data_root; env = ENV, tiers = nothing, workdir = "", prefix = "VGTK_DATA_ROOT",
               view_mount = nothing, write = false) -> (root, source)

THE root of an input tier: the one resolver of every tier lookup, read and write — the runner's missing_inputs, and Experiments.data_root(; tier), input_path, verify_inputs, keyed_data_dir, promote_run and tier_path. In order:

  1. the environment's tier_variable(tier) (source = "env");
  2. the machine's table tiers (a stage graph's [sites.<site>.tiers]: tier = "<root>", a relative root relative to workdir; source = "site");
  3. when data_root is an artifact view that publishes the tier — view_mount(tier) returns where the view mounts it ("" its top), nothing for a tier it does not publish — <data_root>/<mount> (source = "view"). The mount applies only there: never to a data root set by VGTK_DATA_ROOT, an author's own data/exp_raw or a fallback;
  4. the one data_root (source = "data root").

An [inputs.<id>] path is relative to its tier's root, so a config names no machine path whichever disk a tier lives on. With write = true (a producer's root) a view tier is refused: an artifact view is read-only, and a producer never installs one; it binds the tier's root (the environment or the site table) to produce it.

tier_variable(tier; prefix = "VGTK_DATA_ROOT") -> String

The environment variable that gives the root of the input tier tier: <prefix>_<TIER>, the tier upper-cased with every character other than a letter or a digit made _ (blobcalib_202609 → VGTK_DATA_ROOT_BLOBCALIB_202609).

VisualGeometryToolkitEval.tree_sha256 — Method
tree_sha256(dir; exclude = String[]) -> String

THE content digest of a directory, for an input that is one: the SHA-256 of the lines <relative path> <file sha256>, one per regular file under dir (links followed to their files, not into linked directories), sorted by relative path (/-separated); a path holding a tab or a newline is refused. A relative path matching a glob of exclude (* within a segment, ** across, **/ any directories including none, ?) is left out, so a declared scratch file (a log, an index the reader rebuilds) does not move it. Empty directories do not count. Each file's hash is file_sha256's: streamed, and cached by path, size and mtime, so a second digest of an unchanged tree costs a stat per file.

VisualGeometryToolkitEval._content_key — Method
_content_key(tree) -> String

The content key of the evaluation stack: the SHA-256 (hex, first 16) of tree's canonical JSON (VisualGeometryToolkitCore's canonical_json, the stack's one canonical encoding; tree a lowered tree: nothing, Bool, Int64, Float64, strings, vectors and string-keyed dicts, as a TOML config parses). Key order does not move it, nor a number's spelling: an integral float is the integer (3 and 3.0 key alike, as do 1.0 and 1e0). Fixed across Julia versions (unlike Base.hash). Behind Experiments run_key, Tuning tuning_hash and the runner's stage key.

VisualGeometryToolkitEval.scratch_run — Function
scratch_run(env = ENV) -> Bool

Whether this process runs scratch work rather than runs of record: VGTK_SCRATCH=1 in the environment (env: the runner gives its launch's environment). A run of record (the default) refuses to record a result of uncommitted code (refuse_uncommitted_code, the runner's refusal); a scratch run records it with a warning, its trees marked +uncommitted, so it is never reused (the mark names HEAD, not the edits).

A scratch run is kept apart from the runs of record: its record says scratch = true (write_provenance, cached_result); its keys fold scratch (run_key), so it never shares a keyed directory or a cache file with a run of record; and its output is refused as an input of record (verify_inputs, input_path, missing_inputs), an upstream run of record (run_key's upstream), an input of a run of record (write_provenance's inputs) and a promoted run (promote_run).
