API: Tuning

The cross-validation specification. The schema is described in The [tuning] schema.

Public names

VisualGeometryToolkitEval.Tuning — Module
Tuning

The cross-validation (CV) specification. It holds the grid spacings and the grid constructor grid, the window rules, the persisted grid specs and their extension (extend), the objectives (TuningCriterion), the scene splits and unit samplings of a CrossValidation, the validation-budget draws (BudgetSampling), the schemes that bundle them (TuningScheme), the [tuning] TOML parser and writer (tuning_spec, tuning_table), the tuning-artifact writer and reader (save_tuning_artifact, load_tuning_artifact), the scale-prior strategies (PriorSpec) and the deployment corruption of the miscalibration protocol (corrupt_native).

Every strategy is a type whose fields are its complete parameter set, and its defaults live in configs/tuning.toml.

VisualGeometryToolkitEval.Tuning.CoverageWindow — Type
CoverageWindow(q_lo, q_hi, log_margin, zeta_octaves)

The COVERAGE window of a native axis (outlier half-width, loss width): every native the scale-multiple window can request at any reference scale the validation pool can produce, [native(lo, ŝ_min/ζ)·e^{-m}, native(hi, ŝ_max·ζ)·e^{m}] with [lo, hi] the scale-multiple window, (ŝ_min, ŝ_max) = scale_bounds(s2, (q_lo, q_hi)), ζ = 2^zeta_octaves (the scale corruptions the run reads out at, 0 for none) and m = log_margin (log headroom so a request at the bounds sits strictly inside). TOML tag "coverage".

The name is the GUARANTEE, not the mechanism: the realized grid contains every native the window can request at any scale the pool produces, so a windowed free argmin provably cannot leave its grid. That is what the validation-budget mode needs, where 3500 draws share one sweep and each has its own ŝ(n).

q_lo == q_hi is legal and is the ONE-ANCHOR case: both sides anchor on the same √quantile(σ̂², q), and at q = 0.5 that is reference_scale(s2), so coverage { q_lo = 0.5, q_hi = 0.5, zeta_octaves = 0.0 } is the WINDOW-MATCHED grid — the native image of the scale-multiple window and nothing more. A tune has one reference scale, so this is the tuning case; a spread band is for the modes that have many. (It replaced a separate StandardizedNativeWindow rule, which was this rule with its band collapsed and was a distinct type only because the constructor forbade q_lo == q_hi.)

VisualGeometryToolkitEval.Tuning.Factorial — Type
Factorial(axes, criterion, cross_validation)

Every combination of the named axes (hand-chosen settings of a method's configuration keys), scored by criterion over the validation units of cross_validation. TOML tag "factorial".

NOT a windowed scheme: there is no reference scale and no standardized window, and nothing about it is extended on a boundary. Its consumers live outside this package: a downstream product-grid spec reads its axes through it, and a joint operating-point search is one. Deleting it on the strength of a grep over src/ and test/ alone breaks them.

VisualGeometryToolkitEval.Tuning.MeanAverageAccuracy — Type

The continuous mAA@max_error of the validation errors (VisualGeometryToolkitCore Synthetic.mean_average_accuracy; a non-finite error is a failure that stays in the denominator), MAXIMISED (the objective is its negative). TOML tag "mean_average_accuracy".

VisualGeometryToolkitEval.Tuning.WindowRule — Type
WindowRule

How an axis's window (lo, hi) is found: FixedWindow, StandardizedWindow, CoverageWindow, CenteredWindow. window_bounds(rule; context...) evaluates it; each rule takes only the context it needs and refuses a missing one.

Factored, a window is STATED or PLACED, and the placed ones differ only in their ANCHOR and how their endpoints leave it:

ruleanchorendpoints
FixedWindow—its own two native numbers
StandardizedWindow—the scale-multiple window verbatim
CoverageWindow(ŝ_min/ζ, ŝ_max·ζ), per sidethe window through native, ± margin
CenteredWindowa supplied native point÷/× factor

Note where ζ sits: it scales the ANCHOR, never the endpoints. A window whose anchor spreads is asserting that the scale could be anywhere in that spread — right for a ζ ladder or a budget sweep, wrong for a tune, which has one reference scale. Anchor spread is bought with the grid's resolution.

VisualGeometryToolkitEval.Tuning.bootstrap_argmin — Method
bootstrap_argmin(criterion::TuningCriterion, stats, rng; n_resamples) -> Vector{Int}

The sampling distribution of a cross-validation's selection: stats[c] is candidate c's unit_statistics (one row per sampling unit — a frame, a pair, a scene). Each of n_resamples resamples draws the units WITH replacement (rand(rng, 1:n, n), n the number of units) and returns the candidate whose criterion objective over the resampled rows is smallest (the first such candidate on a tie). The candidates are any flat set — the cells of an N-dimensional search included; the caller maps the indices to their coordinates and reads the interval it wants (per-axis quantiles, say).

This is the bootstrap of the SELECTION over a fixed candidate set. The windowed budget bootstrap (Evaluation bootstrap_trials) differs in what it resamples — budget draws of n validation units for a tuner, each draw evaluated on the test side — and is not a special case of it.

VisualGeometryToolkitEval.Tuning.corrupt_native — Method
corrupt_native(native::Real, ζ::Real) -> Float64

The deployment-corruption map (docs/src/protocol.md §3, miscalibration): a tuned-at-CALIBRATION native width (selection outlier half-width, loss width, or the oracle supplied scale a native is formed from) scaled by the deployment error ζ — the model of a mis-estimated inlier scale at deployment time. Every ζ-scaling of a calibrated native goes through this one function so the corruption sites are greppable.

PARTITION-ANCHORED quantities never go through it: a tuned scale multiple, a seed-partition Student-t ŝ², or any quantity re-derived from the deployed data's own partition is immune to calibration error by construction — that immunity IS the claim the miscal experiment measures.

VisualGeometryToolkitEval.Tuning.fit_prior — Method
fit_prior(::InverseGamma, ::MLE, σ²s) -> IGPrior

MLE of the inverse-gamma shape/scale (α, β). Distributions.jl does not implement fit_mle(InverseGamma, ·) directly, so we use the closed-form transformation

X ~ InverseGamma(α, β)  ⇔  1/X ~ Gamma(shape = α, scale = 1/β)

and call fit_mle(Gamma, 1 ./ x). Returns nothing for n < 2.

VisualGeometryToolkitEval.Tuning.fit_prior — Method
fit_prior(::InverseGamma, fit::RobustFit, σ²s) -> IGPrior

Robust empirical prior: fixed shape α₀ = fit.alpha0, scale β₀ = α₀ · median(σ̂²). The IG prior mean is β₀/(α₀−1); with α₀=1 the mean is undefined but the mode β₀/(α₀+1) = α₀ · median(σ̂²) / 2 anchors near the data median.

Used for HEB-like datasets where per-pair σ̂² estimates are heavy-tailed (low-n_in pairs and non-planar GT-inlier sets contaminate MLE Gamma fits). The median is unaffected by individual outlier σ̂² values, so the prior location stays stable even with single-digit val-pool sizes.

VisualGeometryToolkitEval.Tuning.fitting_tag — Method
fitting_tag(fitting::PriorFitting) -> Symbol

Compact symbol identifying the fitting algorithm. :none for parameterless families, :robust for median-based, :mle for closed-form MLE.

VisualGeometryToolkitEval.Tuning.tuning_spec — Method
tuning_spec(cfg, name; under = Dict(), over = Dict()) -> TuningSpec
tuning_spec(path::AbstractString, name; under, over) -> TuningSpec

The [tuning.<name>] entry of a config (a parsed TOML Dict or a file path), its absent keys inherited from the shipped defaults (configs/tuning.toml of this package). The entry must name its scheme (type); unknown keys and tags are an ArgumentError naming the key path.

under and over layer a campaign's protocol around the entry (layer_tuning): under (a protocol-level table of parameters shared by every entry, such as a cross_validation) is layered beneath the entry, keeping only the keys that are fields of the entry's scheme, so one table serves entries of different schemes; over (a cell's overrides) is layered above it, unfiltered. An over that names another scheme type replaces the entry, as layer_tuning replaces a nested table: the new scheme keeps none of the entry's keys (not even those both schemes have, such as cross_validation or criterion), and under is filtered against the new scheme's fields. With both empty (the default) the entry is read as it is.
