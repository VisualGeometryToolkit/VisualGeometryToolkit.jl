VisualGeometryToolkitEval

VisualGeometryToolkitEval benchmarks robust estimators. It is the evaluation package of the VisualGeometryToolkit stack and holds what the stack's research projects share: statistics of pose errors, a codified cross-validation (CV) of hyperparameters, an experiment framework, figure renderers, scoring-pool input and output, raw dataset readers, and an evaluator that composes a RANSAC scorer with a local optimizer (LO).

What it provides

Each module's names are imported from it, for example using VisualGeometryToolkitEval.Pools: load_pool. The top module exports the modules and the driver command line (cli_option, start_output_flush!).

Evaluationthe coarse-to-fine search of every CV, the bootstrap tuning harness and the composition evaluator

RenderPGFPlots figures and tables in the house style

Datasetsraw readers of PhotoTourism, HEB, RoMa and SuperPoint+LightGlue correspondences, and of the depth-validated stereo datasets ETH3D, ScanNet1500, KITTI and 7-Scenes
DataArtifactsa paper project's published input data as Julia artifacts
Reproducethe reproducible-figures contract of a paper

Its design principles:

  • One protocol. Every experiment of the stack tunes, evaluates and reports the same way, stated once in The experimental protocol.
  • TOML is the authority. Every default that changes a reported number lives in one TOML file and is read through one function; an unknown key or tag is refused (Defaults and file formats).
  • Contracts, not paper code. The evaluator is written against VisualGeometryToolkitCore's scoring and local-optimization contracts, so it runs any scorer with any local optimizer (The composition evaluator).
  • Every result is reproducible. A persisted artifact carries its format stamp and the specification it ran under, and every figure of a paper comes from tracked code (Reproducible figures).

Installation

pkg> add VisualGeometryToolkitEval

The package requires Julia 1.13 or later. It depends on VisualGeometryToolkitCore, VisualGeometryToolkitIO and VisualGeometryToolkitEstimation.

A first example

The example summarizes the pose errors of seven image pairs, then tunes one threshold by the package's coarse-to-fine cross-validation.

using VisualGeometryToolkitEval.Stats: finite_median, eligible_maa, bootstrap_ci
using VisualGeometryToolkitEval.Tuning: tuning_spec, grid_spec
using VisualGeometryToolkitEval.Evaluation: coarse_fine_cv
using Random: Xoshiro
using TOML

# Pose errors in degrees of seven image pairs; NaN marks a pair without a model.
errors = [0.4, 1.2, NaN, 0.8, 3.5, 0.6, 2.1]
finite_median(errors)                               # 1.0
eligible_maa(errors; max_error = 10.0)              # ≈ 0.73: mAA up to 10 degrees; NaN counts as 0
bootstrap_ci(finite_median, Xoshiro(1), errors)     # 95% BCa interval of the median

# A tuning specification, as a paper's TOML config states it. The keys left out
# take their defaults from the package's configs/tuning.toml.
config = TOML.parse("""
    [tuning.threshold]
    type = "coarse_fine"
    coarse = { type = "spaced", window = { type = "fixed", lo = 0.1, hi = 10.0 }, spacing = { type = "log_per_decade", per_decade = 4 } }
    cross_validation = { scene_split = { type = "registered", name = "phototourism" } }
    """)
spec = tuning_spec(config, "threshold")

# A stand-in for the validation errors at threshold x; they are smallest at x = 2.
validation_errors(x) = [abs(log(x / 2)) + 0.1 * k for k in 1:5]
result = coarse_fine_cv(validation_errors, grid_spec(spec.scheme.coarse), spec.scheme;
                        method_name = :threshold)
result[:x_star_fine]                                # ≈ 2.0, the tuned threshold
result[:boundary_hit]                               # false: the optimum is inside the window

VisualGeometryToolkitEval — Module
VisualGeometryToolkitEval

The evaluation base of the visual-geometry stack: statistics (Stats), the codified cross-validation (Tuning, Evaluation), the stage/run-record framework (Experiments), rendering (Render), pool IO (Pools), the raw dataset readers (Datasets), the published-data catalog (DataArtifacts), the reproducible-figures contract (Reproduce) and the paper-project conventions (PaperProjects), with the artifact formats, the defaults of record and the driver CLI. Depends on VisualGeometryToolkitCore, VisualGeometryToolkitIO and the core estimator VisualGeometryToolkitEstimation (its loop and problems, for the composition evaluator) — never on a paper's scorer or optimizer package.

Each submodule's API is reached through it (using VisualGeometryToolkitEval.Pools); this module exports the submodules and the CLI.

source

Role in the VisualGeometryToolkit stack

VisualGeometryToolkitEval builds on VisualGeometryToolkitCore (the scoring and local-optimization contracts, the pool record), VisualGeometryToolkitIO and VisualGeometryToolkitEstimation (the RANSAC loop). The research projects that evaluate particular scorers or local optimizers depend on it, never the other way round. The portal links every package of the toolkit.
