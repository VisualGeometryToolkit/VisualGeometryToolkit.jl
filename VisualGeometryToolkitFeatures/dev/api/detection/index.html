VisualGeometryToolkitFeatures.VisualGeometryToolkitFeatures — Module
VisualGeometryToolkitFeatures

Feature detection and descriptor matching.

  • Detection: ASIFT (IMAS-25) on KernelAbstractions. asift_detect runs on the CPU or any KernelAbstractions GPU backend and returns Detections (a frame plus metadata). VisualGeometryToolkitIO writes and reads them as JSON (json_value, from_json).
  • Matching: nearest-neighbour descriptor matching, one KernelAbstractions implementation on the CPU or any GPU backend (nn_match, match), and a stacked matcher over many galleries (nn_match_stacked).
  • LoMa: the learned DeDoDe descriptors and LoMa matchers, from the authors' ONNX exports (LoMaDescriptor, LoMaMatcher).
  • Extensions: JLD2 backs FileCache; Makie draws detections and correspondences.

VisualGeometryToolkitFeatures.Detection — Type
Detection{F<:FeatureFrame, M}

Type alias for Attributed{F, M} — a detection result composing a geometric frame with detector-specific metadata.

The frame type F determines the geometry:

  • Detection{Disc{T}, M} - isotropic detection (3 DOF)
  • Detection{OrientedDisc{T}, M} - oriented isotropic detection (4 DOF)
  • Detection{EllipticFrame{T}, M} - anisotropic detection (5 DOF)
  • Detection{AffineFrame{T}, M} - full affine detection (6 DOF)
  • Detection{<:Uncertain{F}, M} - a frame F with its covariance (VisualGeometryToolkitCore's Uncertain(frame, Σ)), from asift_detect(…; uncertainty = FeatureCovariance()): cov(d) is the covariance, feature_frame(d) the bare frame, geom(d) the detection without it, and the properties below read as on the bare detection

Type Parameters

  • F<:FeatureFrame: The geometric frame type
  • M: Metadata, a NamedTuple. ASIFT emits (response, edge_score, laplacian_scale_score, warp_idx); laplacian_scale_score is the polarity field is_dark/is_light read (> 0 dark, < 0 light).

Fields (from Attributed)

  • value::F: The geometric frame (center + shape)
  • attributes::M: Detector-specific scores and information

Coordinates

The frame's center is (x, y) in COLMAP pixel-centre coordinates, the convention of every detector in this package: x along the image columns, y along the rows, the top-left pixel's centre at (0.5, 0.5). The pixel img[r, c] has its centre at (c − 0.5, r − 0.5). asift_detect documents its measured sub-pixel accuracy.

Property Access

Properties are forwarded from frame and metadata:

  • d.frame, d.value → the geometric frame
  • d.metadata, d.attributes → the metadata
  • d.center → frame.center
  • d.σ → scale from frame (exact for Disc, characteristic_scale for anisotropic)
  • d.Σ → moment matrix (blob shape, not measurement covariance)
  • d.response, d.edge_score, etc. → forwarded from metadata

Example

julia> using VisualGeometryToolkitFeatures, VisualGeometryToolkitCore

julia> det = Detection(Disc(Point2(100.0, 200.0), 5.0), (response = 0.05, laplacian_scale_score = -0.1));

julia> Tuple(det.center), det.σ, det.response   # from the frame and the metadata
((100.0, 200.0), 5.0, 0.05)

julia> is_light(det)
true

See also: Disc, EllipticFrame, VisualGeometryToolkitCore's Attributed

VisualGeometryToolkitFeatures.MserRegion — Type
MserRegion

One maximally stable extremal region, as detect_mser returns it.

Fields

  • seed::CartesianIndex{2}: the region's reference pixel, a pixel at the region's level (the tree node MaxTree chose; VLFeat may pick another pixel of the same plateau). A VLFeat seed s (0-based linear index into the column-major H × W image given with dims = (H, W)) is the pixel CartesianIndices(img)[s + 1], and ours is VLFeat's index LinearIndices(img)[seed] - 1.
  • level::UInt8: the region's level in the input image: a :dark region is the 8-connected component of img .<= level holding seed, a :light one that of img .>= level. img[seed] == level.
  • area::Int: its number of pixels.
  • variation::Float32: VLFeat's (in)stability (|R₊Δ| − |R|) / |R|.
  • polarity::Symbol: :dark or :light.

The seed and level determine the region, so its pixels and boundary are not stored (nested regions would hold every pixel many times over): they are formed on demand from the image the region was detected in — region_mask(region, img) the pixels as a mask (VLFeat's vl_erfill), boundary_contours(region, img) their boundary as closed polygons. is_dark and is_light read the polarity.

VisualGeometryToolkitFeatures.boundary_contours — Method
boundary_contours(pixels) -> Vector{Vector{Point2{Float64}}}
boundary_contours(region::MserRegion, img) -> Vector{Vector{Point2{Float64}}}

The boundary of a set of pixels (CartesianIndex{2} (row, column), a Bool mask, or an MSER of img — its region_mask), traced along the pixel edges: one closed polygon per boundary curve (the last vertex joins the first), vertices only where the boundary turns, with x along the columns and y along the rows in the COLMAP pixel origin (conventions/pixel-origins.md), so the pixel (r, c) is the square [c − 1, c] × [r − 1, r] and every vertex is a pixel corner with integer coordinates. The polygons are sorted by signed shoelace area, descending: the outer boundaries first (positive, clockwise on screen), the largest first, then the holes (negative), the smallest first and the largest last. Diagonal neighbours are connected (8-connectivity, the connectivity of an MSER), so where two pixels of the set meet at a corner one curve runs through it; holes are 4-connected.

VisualGeometryToolkitFeatures.detect_mser — Method
detect_mser(img; delta = 5, min_area = 3 / length(img), max_area = 0.75,
            max_variation = 0.25, min_diversity = 0.2,
            bright_on_dark = true, dark_on_bright = true) -> Vector{MserRegion}

The maximally stable extremal regions (MSER; Matas, Chum, Urban and Pajdla, "Robust wide baseline stereo from maximally stable extremal regions", BMVC

  1. of the 8-bit gray image img, selected as VLFeat's vl_mser selects

them (Andrea Vedaldi and Brian Fulkerson, BSD license; src/mser.jl carries the notice). VLFeat's stability criterion is its own, simpler than the paper's.

The extremal regions are the 8-connected components of the level sets img .<= l, arranged in a tree by ImageMorphology's MaxTree. The variation of a region R at level l is (|R₊Δ| − |R|) / |R|, where R₊Δ is the largest region containing R at a level at most l + delta. Of a region and its parent region exactly one level up, the one of larger variation (on a tie, the child) is not maximally stable; the root never is. The survivors are then filtered, largest first:

  • max_variation: a region of variation >= max_variation is dropped;
  • max_area, min_area: FRACTIONS of length(img); a region larger than max_area * length(img) or smaller than min_area * length(img) pixels is dropped (the default min_area is three pixels);
  • min_diversity: a region whose area differs from that of its nearest surviving enclosing region by less than min_diversity times the latter's area is a duplicate and is dropped (min_diversity = 1 turns this off).

An image of fewer than three pixels has no region (VLFeat returns none): MserRegion[], the area fractions not checked.

dark_on_bright returns the dark regions (polarity = :dark) and bright_on_dark the light ones (:light), the components of img .>= l: VLFeat runs the same on 255 .- img, whose <= level sets these are. Dark regions come first; each polarity is ordered as VLFeat orders it, by level (darkest first, resp. brightest first), then by seed.

Input

A matrix of UInt8, N0f8 or Gray{N0f8}: VLFeat's vl_mser_pix is a byte, and these hold its 256 levels exactly. Any other element type is an ArgumentError: quantize explicitly (e.g. gray_u8), so the levels the regions are cut at are the caller's choice.

julia> using VisualGeometryToolkitFeatures

julia> using VisualGeometryToolkitFeatures: boundary_contours

julia> img = fill(0xc8, 40, 60); img[11:20, 21:35] .= 0x28;   # a dark rectangle

julia> r = only(detect_mser(img; bright_on_dark = false));

julia> r.polarity, r.area, Tuple.(only(boundary_contours(r, img)))
(:dark, 150, [(20.0, 10.0), (35.0, 10.0), (35.0, 20.0), (20.0, 20.0)])

VisualGeometryToolkitFeatures.detect_foerstner — Method
detect_foerstner([T = Float32], img; device = default_device(),
                 method = :foerstner, noise_sigma = 2.0,
                 derivative = :gaussian2d, integration = :box,
                 derivative_sigma = 1.0, integration_sigma = 1.41 * derivative_sigma,
                 precision_threshold = 0.5, roundness_threshold = 0.3,
                 significance_level = 0.999) -> StructArray{<:Detection}

The Förstner interest operator (Förstner and Gülch, 1987): the junction (corner) points and circular points of a grey image at sub-pixel precision, each with its covariance, after the reference implementation ip_fop.m (Luxen, 2005), with Köthe's doubled resolution and window criterion (Köthe, 2003).

Returns one row per optimal window, a StructArray of Detection(Uncertain(PointFrame(x), Σ), (; label, window, F)) (VisualGeometryToolkitCore's PointFrame: a position, no scale):

  • label: :corner (a junction point), :circular (Förstner & Gülch's circular point: the centre of a rotationally symmetric pattern, with no size estimate) or :unknown (the significance test assigned neither);
  • the frame: the corner or circular point's position and its 2×2 covariance (px², (x, y) order); for an :unknown row the window centre with a NaN covariance (the reference returns no estimate for it);
  • window: the window centre, a Point2;
  • F: the classification statistic Ω_corner / Ω_circular.

filter(d -> d.label === :corner, points) are the corners; Ellipse(d; sigma = 1) is a point's 1σ error ellipse (ip_errell.m's default).

img is any grey image the package's detectors take, read through gray_f32 as grey values in [0, 1] (an 8-bit image as value/255, as MATLAB's im2double); it is not stretched to its own range. The image-wide steps run on device, any KernelAbstractions backend, in precision T (the reference computes in Float64; supply Float64 for that).

Keywords (defaults: the values the reference's CODE runs with)

  • method: :foerstner — windows where the roundness 4 det/tr² > roundness_threshold and the precision det/tr > (σₙ / precision_threshold)², ranked by det/tr; :koethe — windows whose precision test succeeds, ranked by the smaller eigenvalue.
  • noise_sigma: the standard deviation of the (constant) image noise, in GREY LEVELS OF AN 8-BIT IMAGE (0–255), as the reference's for a uint8 image; σₙ = noise_sigma / 255 on the [0, 1] image.
  • derivative: :gaussian2d (a Gaussian derivative smoothed across by a Gaussian of the same σ) or :gaussian1d (the derivative alone).
  • integration: :box (a box whose standard deviation is integration_sigma) or :gaussian.
  • derivative_sigma, integration_sigma: in input pixels.
  • precision_threshold: the largest accepted point standard deviation, input px.
  • roundness_threshold: the smallest accepted roundness (:foerstner only).
  • significance_level: of the F-test that labels a point corner or circular.

Algorithm (ip_fop.m, step by step)

  1. The image is doubled bilinearly (the package's one 2× upsampling, ASIFT's) and every scale and threshold doubled with it (lines 170–180).
  2. The gradient by correlation with the derivative taps (radius ⌈3.3σ⌉, zero padding, as imfilter), its squares and product (the squared gradient), and their integration by the box (width 2⌈√(12σ² + 1)/2⌉ + 1) or the Gaussian (radius ⌈3.3σ⌉), zero padded (lines 184–207, 617–678).
  3. The window measure (det/tr or the smaller eigenvalue) masked by the tests above; its regional maxima (8-connected plateaus higher than every neighbour, imregionalmax), thinned by a second non-maximum suppression over a square of radius 2⌈√(12σᵢ² + 1)⌉ doubled pixels, away from the border (lines 210–281).
  4. In the (2ρ + 1)² window around each centre, ρ = ⌈√(12σᵢ² + 1)/2⌉ + 1 (σᵢ doubled), the pixels weighed equally (the reference's choice, also for a Gaussian integration): the corner is the least-squares intersection of the lines through every pixel ACROSS its gradient (normal matrix Σ ∇g∇gᵀ), the circular point that of the lines ALONG it (Σ ∇g⊥∇g⊥ᵀ). Each has a weighted residual sum Ω, redundancy (2ρ + 1)² − 2 and covariance Ω/redundancy · N⁻¹ (lines 314–423, 440, 449).
  5. F = Ω_corner / Ω_circular against the F distribution of (redundancy, redundancy) degrees of freedom, as the reference's (T < F(α)) − (T > F(1 − α)) (line 429): a corner below the 1 − significance_level quantile, a circular point above the significance_level quantile, unknown in between.

Coordinates

COLMAP pixel centres of the input image, (x, y) = (column, row), converted once, at the output. The doubled image's pixel (r′, c′) (1-based) samples the input at 1-based (r′/2, c′/2), so a doubled-grid position is at COLMAP ((c′ − 1)/2, (r′ − 1)/2) in the input, and its covariance is the doubled one /4, reordered to (x, y).

Differences from ip_fop.m

  1. Undoing the doubling — fixed. The reference doubles with MATLAB's imresize(g, 2, 'bilinear') (line 172; doubled pixel j samples input j/2 + 1/4) but maps positions back with transf_H, transf_v (lines 340–350, applied at 436, 446, 457), the inverse of an align-corners grid: its points are off by ((n + 1)/2 − x)/(2n − 1) (1-based, n the image size), 0 at the centre, up to 0.25 px toward the centre at the borders. Here the doubling is the package's upsampling (input j/2, a quarter pixel from imresize's grid) undone by its own exact inverse.
  2. The circular point's residual sum — kept as the reference has it. Its line 423 takes two of the three terms from the corner model's residuals; the circular model's own residual sum would take all three from its own. Monte Carlo coverage favours the reference's form, so it is kept.
  3. Defaults — the code's, not the header's. The header states SIGMA_N = 2.5 and SIGMA_DIFF = 0.7 (lines 37, 50); the code runs 2.0 and 1.0 (lines 521, 524). A documentation conflict, not a fix.

The docs page gives the evidence for each. The reference warns that with a Gaussian integration the window estimation still weighs the pixels equally; so does this.

Example

julia> using VisualGeometryToolkitFeatures, VisualGeometryToolkitCore

julia> img = [Float32((c - 20.5)^2 + (r - 24.5)^2 < 6.25) for r in 1:48, c in 1:40];   # a dot at pixel (24.5, 20.5)

julia> points = detect_foerstner(img);

julia> only(points).label
:circular

julia> round.(Tuple(only(points).center); digits = 1)   # COLMAP: (column − ½, row − ½)
(20.0, 24.0)

VisualGeometryToolkitFeatures.gaussian_blur — Function
gaussian_blur(img::AbstractArray{<:Real, 3}, σ[, mask]) -> Array{Float64, 3}

The H × W × C image convolved per channel with the separable Gaussian of standard deviation σ pixels, truncated at ⌈3σ⌉ pixels and normalized to unit sum; at the image border the kernel is renormalized over the pixels inside it (no padding value enters). The taps are the package's one Gaussian taps builder's, at truncation 3 — not ASIFT's pyramid's 4σ with a mirrored border: the vignetting chain this smooths for was reproduced with this truncation and border rule, so they stay as they are.

With a mask (an H × W array of weights, 0 outside the support — a fisheye's image circle) it is the NORMALIZED convolution blur(img·mask) / blur(mask): pixels outside the mask do not bleed in, and a pixel where the mask is zero is 0. σ = 0 returns a Float64 copy (masked to zero outside the mask). Edge-safe smoothing of a linear image before it is sampled (the rooftop vignetting chain's cell samples).

VisualGeometryToolkitFeatures.batched_rows — Method
batched_rows(run_chunk, N::Int, max_batch::Int; retry_single = false) -> Matrix{Float32}

Run run_chunk(offset, n) over 1:N in chunks of at most max_batch rows (max_batch <= 0 means one chunk) and assemble the N × D result: the row width D is read off the FIRST chunk's output (any shape with n * D elements), the matrix is allocated lazily then, and each chunk is assigned into its contiguous row slice. VisualGeometryToolkitFeatures.asift_detect — Method
asift_detect(img; device=default_device(), nms=:mxm, window_half=3,
             cutoff=3.0, intensity_thr=0.04, edge_thr=10.0,
             polarity=:none, band_octaves=0.0, band_reach=1, boundary_K=3.0,
             tilts=nothing, upsample=true, seed_sigma=1.6, raw=false,
             uncertainty=nothing)

Run the IMAS-25 ASIFT detector on img (H×W; Gray, UInt8, or real-valued in [0,1]) and return Vector{Detection{EllipticFrame}} in COLMAP coords.

Coordinates. A detection's center is (x, y), with x along the image columns and y along the rows, in COLMAP pixel-centre coordinates: the top-left pixel's centre is (0.5, 0.5), so a blob centred on the pixel img[r, c] is returned at (c − 0.5, r − 0.5). Measured on isotropic Gaussian blobs on the CPU (pinned by the test suite):

  • a blob centred on a pixel centre comes back exact (within 0.005 px);
  • between pixel centres, the quadratic sub-pixel refinement pulls the centre toward the nearest pixel centre, by at most 0.03 px at σ = 4 (−0.007, −0.015, −0.021, −0.027 px at fractions 0.1–0.4, mirrored above 0.5) and 0.06 px for σ from 2 to 8;
  • an exact half-pixel centre, where the DoG ties between the two pixels, is refined like any other: the extremum test breaks the tie toward the first pixel, so it carries that side's bias (−0.031 px at σ = 4). A test strict against all 26 neighbours would reject both pixels and leave an unrefined detection from a coarser octave, 0.5 px low;
  • a feature found only on a pyramid boundary scale slice is not refined and sits on that octave's pixel grid.

With raw = true the features are in 0-indexed OpenCV coordinates (top-left pixel centre (0, 0)), 0.5 less on both axes.

nms selects the cross-warp non-max suppression: :mxm (centroid window, default), :ellipse (Mahalanobis footprint), or :none (full per-warp feature pool). polarity gates by DoG sign (:dark → response > 0, :light → response < 0, :none → both) BEFORE the cross-warp NMS, so a blob of the other sign never suppresses a kept one. band_octaves > 0 makes the NMS scale-banded: a feature can only be suppressed by features whose geometric-mean scale band ⌊log2(√det S) / band_octaves⌋ is within band_reach of its own, so board-sized extrema and tilted-warp streaks stop erasing the small blobs inside them (see asift_detect!). raw=true returns the ImasFeatureKA vector instead of Detections. device, tilts, upsample and seed_sigma pick the plan; the others but raw go to asift_detect!, which refuses a keyword it does not take.

Keypoint uncertainty. uncertainty = FeatureCovariance() returns each detection's frame as Uncertain(frame, Σ̃), Σ̃ = cov(d) a 3×3 CovMat over (x, y, log σ) for unit iid pixel noise in the detector's intensity units — see FeatureCovariance for the model, the parameterization and the units. With raw = true the result is then (; features, cov). The default nothing runs the detector without it, the kernels compiled exactly as before.

The plan for (size, device, tilts, upsample, seed_sigma) is cached (see set_max_cached_plans!) and every call holds a process-wide lock, so concurrent calls are safe but do not run in parallel. On a KA.CPU() device every kernel launch is statically scheduled over the threads, or dynamically when the call runs inside a threaded region (e.g. a Threads.@threads loop over frames); the features are the same either way.

VisualGeometryToolkitFeatures.asift_detections — Method
asift_detections(feats::Vector{ImasFeatureKA}) -> Vector{Detection}
asift_detections(feats, cov) -> Vector{Detection}

Convert raw ASIFT features (0-indexed opencv pixel coords, input frame) into Detection{EllipticFrame}s in COLMAP convention (+0.5 on both axes, so the top-left pixel's centre is (0.5, 0.5); see asift_detect). The metadata is (response, edge_score, laplacian_scale_score, warp_idx): laplacian_scale_score = sign(response) (+1 dark, −1 light — the DoG sign convention polarity gates on), which is what is_dark and is_light read; edge_score is a placeholder (always 0). Given the features' covariances (asift_detect!(…; uncertainty = FeatureCovariance())), each frame is Uncertain(frame, Σ̃) (see FeatureCovariance); the +0.5 shift leaves a covariance unchanged.

VisualGeometryToolkitFeatures.clear_asift_plans! — Method
clear_asift_plans!()

Drop all cached AsiftPlans, releasing their device buffers immediately rather than leaving them to a finalizer.

The cache is keyed by (W, H, device, tilts, upsample, seed_sigma) and holds at most set_max_cached_plans! plans (default 1), evicting the least recently used. Call this to release the resident plans outright — e.g. between sequences in a mixed-resolution corpus, or before handing the device to another workload.

VisualGeometryToolkitFeatures.AsiftPlan — Type
AsiftPlan(W, H; device = default_device(), tilts = <IMAS-25>, seed_sigma = 1.6,
          input_blur = 0.5, nb_scales = 3, capacity = 2^20, chunk = 0,
          upsample = true)

The preallocated buffers of the ASIFT detector for W×H images on device (any KernelAbstractions backend): the tilted warps, the scale-space pyramids, the feature pool and the compiled kernels. asift_detect! runs the detector in them without allocating on the device.

asift_detect builds and caches plans itself (see set_max_cached_plans! and clear_asift_plans!), so most callers never construct one. Build one to own its lifetime, or to detect in a loop over same-size frames without the cache's lock.

  • tilts: the tilt schedule, a vector of (t, φ) pairs (tilt and longitude in radians). The default is the 25 tilts of IMAS-25; [(1.0, 0.0)] alone is plain DoG-SIFT.
  • seed_sigma, input_blur, nb_scales, upsample: the SIFT pyramid's seed blur, the input's assumed blur, the scales per octave and whether the first octave is the 2× upsampled image.
  • capacity: the initial size of the feature pool; it grows when a frame produces more extrema.
  • chunk: how many warps stay resident at once; 0 sizes the chunk from the device's free memory.

A plan holds device memory (several GiB for a large image under the full schedule). It is mutable only because its feature pool grows.

julia> using VisualGeometryToolkitFeatures

julia> plan = AsiftPlan(64, 48; tilts = [(1.0, 0.0)]);

julia> img = zeros(Float32, 64, 48);   # (W, H): x along the first axis

julia> asift_detect!(plan, img)
ImasFeatureKA[]

VisualGeometryToolkitFeatures.asift_detect! — Method
asift_detect!(plan, img_xy; nms=:none, window_half=3, cutoff=3.0,
              polarity=:none, band_octaves=0.0, band_reach=1,
              intensity_thr=0.04, edge_thr=10.0,
              boundary_K=3.0, uncertainty=nothing) -> Vector{ImasFeatureKA}

Full batched IMAS-25 detection in the plan's preallocated buffers. With nms = :mxm or :ellipse the cross-warp NMS runs on-device and only the survivors are returned; :none returns the full boundary-filtered pool. polarity (:dark → response > 0, :light → response < 0) gates the pool BEFORE the NMS splat, so a blob of the other sign can never suppress a kept one. band_octaves > 0 restricts suppression to features of comparable scale: a feature in scale band b = ⌊log2(√det S) / band_octaves⌋ can only be suppressed by features in bands b ± band_reach (see _band_pool!); 0 is the whole-pool rule. The seed blur σ₀ — the pyramid's, and the one the reported σ is scaled by — is the plan's (AsiftPlan(W, H; seed_sigma)).

uncertainty = FeatureCovariance() also returns each feature's covariance: the result is then (; features, cov), cov[i] the FeatureCovariance covariance of features[i], a CovMat{3} over (x, y, log σ).

VisualGeometryToolkitFeatures.ImasFeatureKA — Type
ImasFeatureKA

One raw feature of the ASIFT detector, as asift_detect! and asift_detect(img; raw = true) return it, before conversion to a Detection by asift_detections. All fields are in the input image's frame:

  • x, y: the refined centre in 0-indexed OpenCV pixel coordinates (top-left pixel centre at (0, 0), 0.5 less than the COLMAP coordinates of a Detection);
  • σ: the characteristic scale, in input pixels;
  • intensity: the DoG response at the extremum, positive for a dark blob and negative for a light one;
  • s_xx, s_xy, s_yy: the symmetric 2×2 shape matrix of the elliptic frame, back-projected from the tilted warp it was found in;
  • warp_idx: the index of that warp in the plan's tilt schedule (1 is the identity).

julia> f = ImasFeatureKA(10.0, 20.0, 2.0, -0.1, 2.0, 0.0, 2.0, 1);

julia> d = only(asift_detections([f]));

julia> d.center, is_light(d)
([10.5, 20.5], true)

VisualGeometryToolkitFeatures.FeatureCovariance — Type
FeatureCovariance()

Ask asift_detect for each keypoint's 3×3 covariance over (x, y, log σ), by the implicit function theorem, for iid unit pixel noise.

asift_detect(img; uncertainty = FeatureCovariance()) returns detections whose frame is VisualGeometryToolkitCore's Uncertain(frame, Σ̃); the default uncertainty = nothing runs the detector unchanged. cov(d) is Σ̃, feature_frame(d) the frame, and d.center, d.σ and the metadata read as on any detection.

Model. A refined DoG keypoint is a stationary point of the detector's local quadratic model of the DoG in (slice, x, y). With Ĥ its finite-difference Hessian and C the covariance, under unit iid pixel noise, of that model's gradient at the keypoint, Σ̃ = J·Ĥ⁻¹·C·Ĥ⁻¹·Jᵀ: C is tabulated exactly for the discrete pyramid (warp, upsample, blurs, octave downsamples) once per plan, and J maps to the reported coordinates, then through the ASIFT back-projection.

Parameterization. Σ̃ is a CovMat{3} over (x, y, log σ) in the detection's image frame (COLMAP pixel centres, as d.center), σ = d.σ (the frame's characteristic scale √det S), log natural. Position-only consumers take the top-left 2×2 block (the marginal). A tilted ASIFT warp's frame has the shape S = σ_w·M_w with M_w fixed by the warp (d.warp_idx into the tilt schedule), so (x, y, log σ) are its only free parameters and Σ̃ is full rank.

Units. Unit noise variance in the detector's intensity units: those of a float input image, and the [0, 1] scale for 8-bit input (UInt8, N0f8, …; σn = σgray / 255). The physical covariance is σ_n²·Σ̃.

Unrefined detections — on a boundary scale slice, or whose sub-pixel refinement failed — sit on the octave's pixel grid and have no such covariance: their Σ̃ is all NaN.

Extension point (not implemented): an intensity-dependent noise model, e.g. FeatureCovariance(noise = ShotNoise(a, b)), makes the middle term K·diag(σ²(I))·Kᵀ, gathered from the pyramid per keypoint instead of tabulated.

VisualGeometryToolkitFeatures._ift_cov_reference — Method
_ift_cov_reference(H, off, M, sf, S) -> SMatrix{3, 3} over (x, y, log σ)

Host reference of the covariance _bextract! emits, through VisualGeometryToolkitCore's implicit_covariance: the square system g(v, f) = ĝ + Ĥ·(v − v₀) = 0 with A = ∂g/∂v = Ĥ and B = ∂g/∂f = P(off) over the nine functionals f, whose covariance is M; then propagate by J = diag(sf, sf, ln2/S), which also reorders (s, x, y) to (x, y, log σ).

VisualGeometryToolkitFeatures.cross_warp_nms — Method
cross_warp_nms(feats, W, H; device, mode=:mxm, window_half=3, cutoff=3.0,
               band_octaves=0.0, band_reach=1) -> Vector{ImasFeatureKA}

Cross-warp NMS over an aggregated feature pool (input-frame). mode is :mxm (centroid window window_half) or :ellipse (Mahalanobis footprint, cutoff cutoff). band_octaves > 0 restricts suppression to features of comparable scale — band ⌊log2(√det S) / band_octaves⌋ ± band_reach. It runs the kernels asift_detect! runs on its device pool, so on the pool asift_detect(img; nms = :none, raw = true) returns it keeps the features asift_detect(img; nms = mode, raw = true) keeps, given the same detection keywords — up to exact ties in the quantized response, which break toward the later pool index (and pool order varies between calls on a multithreaded or GPU backend). Returns the survivors.
