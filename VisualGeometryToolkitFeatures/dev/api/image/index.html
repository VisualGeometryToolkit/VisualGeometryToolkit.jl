Image Input

The image-input helpers, the linear-radiance PNG reader (load_linear_image) and the camera RAW reader (load_raw).

Camera RAW

load_raw(path; mode, gain, decoder) reads a Bayer RAW file as exact linear values, (raw − black[c]) / (white − black[c]) × gain, in the sensor's orientation. The decode is an extension, chosen by a token:

decoderloadbackend
LibRawDecoder (default)using LibRaw_jllLibRaw 0.22 through ccall, no Python
RawpyDecoderusing PythonCallrawpy and exifread (CondaPkg)

Everything after the decode — the :bin2 quads or the :green photosites, the per-quad saturation flags and each plane's true sample position — is the same Julia code for both. On 21 Sony ARW frames the two decoders return identical photosites, colour indices, black and white levels and visible area; their EXIF differs in precision only: LibRaw stores exposure, f-number and focal length as Float32 (0.01666666753590107 s for exifread's 1/60) and keeps no sub-second time (subsec = "").

The EXIF fields become VisualGeometryToolkitCore's typed values through exposure_settings, lens_settings, body_identity, lens_identity and capture_time, from a mosaic or from load_raw_metadata (the headers only); extract_capture_settings gathers a capture's frames into a CaptureSettings. A lens's EXIF name is a claim: on an adapter (the FX3 with Sigma EF lenses) it names another lens, so a pipeline that knows its lens states it.

VisualGeometryToolkitFeatures.LibRawDecoder — Type
LibRawDecoder()

Decode with LibRaw through LibRawjll (`using LibRawjll): accalllayer over LibRaw's C API, no Python. The extension checks LibRaw's version at load and the layout of every structure it reads against LibRaw's own accessors, and refuses (ErrorException`) a library it was not written for.

VisualGeometryToolkitFeatures.LinearRaw — Type
LinearRaw

A RAW mosaic as linear values: (raw − black[c]) / (white − black[c]) × gain, camera raw colour, white balance 1, 1.0 = the white level (before the gain). Not clipped: a value above 1 (a gain above 1) or below 0 (noise under the black level) is kept.

  • image::Array{Float64, 3} — image[row, column, plane].
  • sampled::BitMatrix — the pixels that carry a sample (every pixel in :bin2; the green photosites in :green).
  • saturated::BitMatrix — the pixels whose value includes a photosite at the white level (raw ≥ white): in :bin2 a quad is saturated when ANY of its four photosites is, so a quad whose two greens straddle the white level is flagged rather than averaged into a plausible value.
  • plane_offsets::Vector{SVector{2, Float64}} — per plane, where its sample sits relative to the pixel centre, (Δx, Δy) in this image's pixels: the sample of pixel (row, column), plane k, is at the COLMAP point (column − ½, row − ½) + plane_offsets[k].
  • mode, gain, and the mosaic's metadata.

VisualGeometryToolkitFeatures.LinearRaw — Method
LinearRaw(mosaic::RawMosaic; mode::Symbol, gain::Real = 1) -> LinearRaw

The mosaic's linear values, (raw − black[c]) / (white − black[c]) × gain, arranged by mode (required: there is no neutral choice between them):

  • :bin2 — 2×2 Bayer quads, H ÷ 2 × W ÷ 2 × 3 (an odd last row or column is dropped): R, the mean of the two greens, B. A COLMAP coordinate of the raw scales by exactly ½. The green sample sits at the quad centre (offset (0, 0): the two greens are diagonal); R and B sit at their photosites, (±¼, ±¼) binned pixels from it (plane_offsets).
  • :green — the green photosites alone, H × W × 1 on the raw's own grid, 0 at the red and blue photosites (sampled says which), offset (0, 0).

The values are those convert_raw.py writes, in the same Float64 arithmetic and order, before its clip to [0, 1] and 16-bit rounding.

Saturation is raw ≥ white with no margin: on the Sony ARW sets this was written for, codes pile up exactly at the white level (16383) while the histogram runs smoothly through the camera's declared linear limit (15360, metadata.linear_max), so any margin would be a tuned constant. A caller who wants that stricter limit thresholds mosaic.raw itself.

VisualGeometryToolkitFeatures.RawMosaic — Type
RawMosaic

A RAW file decoded and nothing more: the visible area of the sensor, as LibRaw reports it.

  • raw::Matrix{UInt16} — the visible photosites, raw[row, column], in the sensor's orientation (no EXIF flip): pixel (row, column) is the raw's COLMAP pixel centred at (column − ½, row − ½).
  • pattern::Matrix{UInt8} — the smallest repeating colour pattern, square, at most 4 × 4, from the full raw frame's origin (rawpy's raw_pattern), in LibRaw's colour indices: 0 R, 1 G, 2 B, 3 the second G of an RGBG pattern. Each photosite's index is photosite_colors(mosaic), the pattern tiled from that origin.
  • black::NTuple{4, Float64} — the black level per colour index (the common and per-channel parts summed, LibRaw's adjust_bl).
  • white::Float64 — the white level (LibRaw's maximum): the code at which a photosite is saturated.
  • visible_origin::NTuple{2, Int} — (top_margin, left_margin), the visible area's offset into the full raw frame, which is raw_size ((height, width)).
  • metadata::NamedTuple — the EXIF fields (datetime_original, subsec, exposure_s, fnumber, focal_mm, iso, model, make, body_serial, lens_make, lens_model, lens_serial, focus_distance_m; nothing where absent, a non-finite or non-positive focus distance too; typed by exposure_settings, lens_settings, body_identity, lens_identity and capture_time), daylight_wb (LibRaw's daylight white balance, R G B), linear_max (the camera's declared linear-response limit per channel, nothing when the file has none), decoder and libraw_version.
source
VisualGeometryToolkitFeatures.RawpyDecoder — Type
RawpyDecoder()

Decode with rawpy and exifread through PythonCall (using PythonCall; the Python packages are declared in the package's CondaPkg.toml). Python opens the file once and returns the arrays once; no per-pixel Python call.

rawpy reports only LibRaw's per-channel black levels (black_level_per_channel), not the spatial black pattern behind them, so where LibRawDecoder refuses a file whose spatial pattern has no per-channel form, this decoder cannot see it and returns the per-channel levels (the pattern dropped). Use LibRawDecoder() where that matters (DNGs with a black-level pattern).

VisualGeometryToolkitFeatures.extract_capture_settings — Method
extract_capture_settings(frames; lens = nothing) -> CaptureSettings

The camera settings of a capture from its RAW files' EXIF: frames maps a frame index to a RawMosaic or its metadata (load_raw_metadata); each frame's settings are exposure_settings and lens_settings. The body is the frames' body_identity, which must be one (identities agree when no field both state differs, case aside; ArgumentError otherwise). The lens is lens where the caller states it — a config knows an adapted lens EXIF misnames — and the frames' one EXIF claim otherwise (lens_identity, which must then agree across the frames); a stated lens that disagrees with EXIF is used, with a warning naming both. EXIF's claim stays readable from the metadata.

VisualGeometryToolkitFeatures.lens_identity — Method
lens_identity(x) -> DeviceIdentity

The lens a RAW file CLAIMS took it (lens_make, lens_model, lens_serial). Kept, not trusted: a lens on an adapter is named by what the adapter reports (the FX3 with Sigma EF lenses claims "DT 8mm F4 SAM"), so a pipeline that knows its lens states it (extract_capture_settings's lens).

VisualGeometryToolkitFeatures.lens_settings — Method
lens_settings(x) -> LensSettings

The lens settings a RAW frame was taken with, as Core's LensSettings: the focal length the lens reports (focal_mm, the NOMINAL value, not a calibration) and the focus distance where the file states a finite, positive one (nothing otherwise — the FX3's adapted lenses report infinity). A file without a focal length is an ArgumentError.

VisualGeometryToolkitFeatures.load_raw — Method
load_raw(path; mode::Symbol, gain::Real = 1, decoder::RawDecoder = LibRawDecoder()) -> LinearRaw

A camera RAW file as exact linear values: load_raw_mosaic, then LinearRaw(mosaic; mode, gain). mode is :bin2 (2×2 Bayer quads) or :green (the green photosites on the raw grid). The pixels stay in the sensor's orientation (no EXIF flip), in the raw's COLMAP frame (scaled by ½ in :bin2).

Rounded to 16 bits (round(UInt16, clamp(x, 0, 1) * 65535)), :bin2 equals the linear PNG of RadiometricCamera's convert_raw.py (--mode bin2), value for value; unlike that PNG, saturated flags the quads that contain a photosite at the white level.

source
VisualGeometryToolkitFeatures.load_raw_metadata — Method
load_raw_metadata(path; decoder::RawDecoder = LibRawDecoder()) -> NamedTuple

The EXIF fields of a camera RAW file, as RawMosaic's metadata holds them, without keeping the photosites: LibRawDecoder reads the headers only (no unpack), RawpyDecoder decodes the file. The typed accessors (exposure_settings, …) take it as they take a mosaic.

VisualGeometryToolkitFeatures.load_raw_mosaic — Method
load_raw_mosaic(path; decoder::RawDecoder = LibRawDecoder()) -> RawMosaic

Decode a camera RAW file (any format LibRaw reads: ARW, CR2, NEF, DNG, …) to its RawMosaic. Only flat Bayer sensors (one colour per photosite) are supported. The decoder's package must be loaded: using LibRaw_jll for LibRawDecoder, using PythonCall for RawpyDecoder.

VisualGeometryToolkitFeatures.photosite_colors — Method
photosite_colors(mosaic::RawMosaic) -> Matrix{UInt8}

Each visible photosite's colour index (LibRaw's: 0 R, 1 G, 2 B, 3 the second G), the size of mosaic.raw: the pattern tiled from the full raw frame's origin, so visible photosite (row, column) reads pattern[mod(top + row − 1, n) + 1, mod(left + column − 1, n) + 1] with (top, left) = visible_origin — rawpy's raw_colors_visible.

VisualGeometryToolkitFeatures.gray_f32 — Method
gray_f32(img) -> AbstractMatrix

img as float gray: a float Gray matrix or a bare Float32 matrix (a device array already in the kernels' form) is returned UNTOUCHED — no copy, no wrap, so a CuArray{Float32} stays on the device; anything else (fixed-point gray, any colorant) converts to Gray{Float32}.

VisualGeometryToolkitFeatures.gray_u8 — Method
gray_u8(img) -> Matrix{UInt8}

img as H×W gray bytes, in a Matrix{UInt8} the caller owns. A Matrix{UInt8} is returned as is; a Gray{N0f8} matrix is copied byte for byte (its pixels already are bytes); everything else is quantised through Gray{N0f8} (float colorants LOSE precision here by design — use gray_f32 where sub-pixel photometry matters).

VisualGeometryToolkitFeatures.box_downsample — Method
box_downsample(img::AbstractMatrix, f::Integer) -> Matrix
box_downsample(img::AbstractArray{T, 3}, f::Integer) -> Array{float(T), 3}

The H × W image (or H × W × C, per channel) averaged over f × f blocks: output pixel (i, j) is the mean of input rows (i − 1)f + 1 : if and columns (j − 1)f + 1 : jf. The output is H ÷ f × W ÷ f (× C); rows and columns past the last whole block are dropped. The element type is a real number or a colour (Gray{Float32}, RGB{N0f8}, …); the sums accumulate, and the output is stored, in its floating-point type float(T) — Float64 for a Float64 or integer image, Float32 for a Float32 or 8-bit one (the patches BlobBoards' descriptor reads, byte for byte) — each block summed column by column and scaled once by 1/f² in that type. f = 1 returns a float(T) copy.

VisualGeometryToolkitFeatures.gaussian_blur — Function
gaussian_blur(img::AbstractArray{<:Real, 3}, σ[, mask]) -> Array{Float64, 3}

The H × W × C image convolved per channel with the separable Gaussian of standard deviation σ pixels, truncated at ⌈3σ⌉ pixels and normalized to unit sum; at the image border the kernel is renormalized over the pixels inside it (no padding value enters). The taps are the package's one Gaussian taps builder's, at truncation 3 — not ASIFT's pyramid's 4σ with a mirrored border: the vignetting chain this smooths for was reproduced with this truncation and border rule, so they stay as they are.

With a mask (an H × W array of weights, 0 outside the support — a fisheye's image circle) it is the NORMALIZED convolution blur(img·mask) / blur(mask): pixels outside the mask do not bleed in, and a pixel where the mask is zero is 0. σ = 0 returns a Float64 copy (masked to zero outside the mask). Edge-safe smoothing of a linear image before it is sampled (the rooftop vignetting chain samples it at fixed points).

VisualGeometryToolkitFeatures.load_linear_image — Method
load_linear_image(path; srgb = false, downsample = 1) -> Array{Float64, 3}

A PNG file as an H × W × 3 Float64 array of linear RGB values in [0, 1]: the samples AS STORED (read with gamma = 1, so a gAMA/sRGB chunk never re-encodes them; gray files are replicated to three channels, an alpha channel is dropped, 8- and 16-bit depths both normalized to [0, 1]).

  • srgb = true: the file is display-encoded (a phone or camera photograph); srgb_to_linear decodes every sample.
  • downsample = f: the decoded image averaged over f × f blocks (box_downsample), in linear space.

The array is indexed [row, column, channel]; pixel (row, column) is the image's PixelFrame{:julia} pixel (column, row).

source
VisualGeometryToolkitFeatures.srgb_to_linear — Method
srgb_to_linear(x) -> linear value

The sRGB (IEC 61966-2-1) electro-optical transfer function: an encoded value x ∈ [0, 1] to linear, x / 12.92 for x ≤ 0.04045, otherwise ((x + 0.055) / 1.055)^2.4.
