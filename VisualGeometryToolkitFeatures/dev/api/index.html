VisualGeometryToolkitFeatures.VisualGeometryToolkitFeatures — Module
VisualGeometryToolkitFeatures

Feature detection and descriptor matching.

  • Detection: ASIFT (IMAS-25) on KernelAbstractions. asift_detect runs on the CPU or any KernelAbstractions GPU backend and returns Detections (a frame plus metadata), which round-trip through JSON.
  • Matching: nearest-neighbour descriptor matching, one KernelAbstractions implementation on the CPU or any GPU backend (nn_match, match), and a stacked matcher over many galleries (nn_match_stacked).
  • Extensions: JLD2 backs FileCache; Makie draws detections and correspondences.

Stereo datasets, ground truth and RoMa match IO moved to VisualGeometryToolkitEval in 0.8.

VisualGeometryToolkitFeatures.Detection — Type
Detection{F<:FeatureFrame, M}

Type alias for Attributed{F, M} — a detection result composing a geometric frame with detector-specific metadata.

The frame type F determines the geometry:

  • Detection{Disc{T}, M} - isotropic detection (3 DOF)
  • Detection{OrientedDisc{T}, M} - oriented isotropic detection (4 DOF)
  • Detection{EllipticFrame{T}, M} - anisotropic detection (5 DOF)
  • Detection{AffineFrame{T}, M} - full affine detection (6 DOF)
  • Detection{<:Uncertain{F}, M} - a frame F with its covariance (VGC's Uncertain(frame, Σ)), from asift_detect(…; uncertainty = FeatureCovariance()): cov(d) is the covariance, feature_frame(d) the bare frame, geom(d) the detection without it, and the properties below read as on the bare detection

Type Parameters

  • F<:FeatureFrame: The geometric frame type
  • M: Metadata, a NamedTuple. ASIFT emits (response, edge_score, laplacian_scale_score, warp_idx); laplacian_scale_score is the polarity field is_dark/is_light read (> 0 dark, < 0 light).

Fields (from Attributed)

  • value::F: The geometric frame (center + shape)
  • attributes::M: Detector-specific scores and information

Coordinates

The frame's center is (x, y) in COLMAP pixel-centre coordinates, the convention of every VGF detector: x along the image columns, y along the rows, the top-left pixel's centre at (0.5, 0.5). The pixel img[r, c] has its centre at (c − 0.5, r − 0.5). asift_detect documents its measured sub-pixel accuracy.

Property Access

Properties are forwarded from frame and metadata:

  • d.frame, d.value → the geometric frame
  • d.metadata, d.attributes → the metadata
  • d.center → frame.center
  • d.σ → scale from frame (exact for Disc, characteristic_scale for anisotropic)
  • d.Σ → moment matrix (blob shape, not measurement covariance)
  • d.response, d.edge_score, etc. → forwarded from metadata

Example

disc = Disc(Point2(100.0, 200.0), 5.0)
det = Detection(disc, (response=0.05, edge_score=3.2, laplacian_scale_score=-0.1))
det.center       # from frame
det.σ            # scale
det.response     # from metadata

See also: Disc, EllipticFrame, Attributed

VisualGeometryToolkitFeatures.FeatureCovariance — Type
FeatureCovariance()

Ask asift_detect for each keypoint's 3×3 covariance over (x, y, log σ), by the implicit function theorem, for iid unit pixel noise.

asift_detect(img; uncertainty = FeatureCovariance()) returns detections whose frame is VisualGeometryToolkitCore's Uncertain(frame, Σ̃); the default uncertainty = nothing runs the detector unchanged. cov(d) is Σ̃, feature_frame(d) the frame, and d.center, d.σ and the metadata read as on any detection.

Model. A refined DoG keypoint is a stationary point of the detector's local quadratic model of the DoG in (slice, x, y). With Ĥ its finite-difference Hessian and C the covariance, under unit iid pixel noise, of that model's gradient at the keypoint, Σ̃ = J·Ĥ⁻¹·C·Ĥ⁻¹·Jᵀ: C is tabulated exactly for the discrete pyramid (warp, upsample, blurs, octave downsamples) once per plan, and J maps to the reported coordinates, then through the ASIFT back-projection.

Parameterization. Σ̃ is a CovMat{3} over (x, y, log σ) in the detection's image frame (COLMAP pixel centres, as d.center), σ = d.σ (the frame's characteristic scale √det S), log natural. Position-only consumers take the top-left 2×2 block (the marginal). A tilted ASIFT warp's frame has the shape S = σ_w·M_w with M_w fixed by the warp (d.warp_idx into the tilt schedule), so (x, y, log σ) are its only free parameters and Σ̃ is full rank.

Units. Unit noise variance in the detector's intensity units: those of a float input image, and the [0, 1] scale for 8-bit input (UInt8, N0f8, …; σn = σgray / 255). The physical covariance is σ_n²·Σ̃.

Unrefined detections — on a boundary scale slice, or whose sub-pixel refinement failed — sit on the octave's pixel grid and have no such covariance: their Σ̃ is all NaN.

Extension point (not implemented): an intensity-dependent noise model, e.g. FeatureCovariance(noise = ShotNoise(a, b)), makes the middle term K·diag(σ²(I))·Kᵀ, gathered from the pyramid per keypoint instead of tabulated.

VisualGeometryToolkitFeatures.KnnMatch — Type
KnnMatch(k) <: NNStrategy

k-nearest-neighbor matching: for each desc1 row, keep its k nearest desc2 columns instead of only the single best. Permissive by design — surfaces true matches that sit at rank 2..k or just under a strict cutoff (common with repetitive patterns, where a confuser can out-rank the true neighbor). Downstream geometry (e.g. RANSAC) disambiguates the extra candidates. Pair with min_similarity to bound the kept scores.

VisualGeometryToolkitFeatures._ift_cov_reference — Method
_ift_cov_reference(H, off, M, sf, S) -> SMatrix{3, 3} over (x, y, log σ)

Host reference of the covariance _bextract! emits, through VisualGeometryToolkitCore's implicit_covariance: the square system g(v, f) = ĝ + Ĥ·(v − v₀) = 0 with A = ∂g/∂v = Ĥ and B = ∂g/∂f = P(off) over the nine functionals f, whose covariance is M; then propagate by J = diag(sf, sf, ln2/S), which also reorders (s, x, y) to (x, y, log σ).

VisualGeometryToolkitFeatures._nn_select — Method
_nn_select(strategy, metric, dev, offsets, sizes; gal, feat, S, chunk_bytes)
    -> (top_idx, top_sc, rev_idx)

The selection behind every match, on backend dev. The gallery is the rows, cut into blocks (offsets, 0-based, and sizes); the scores are either computed from descriptors already on dev (gal, rows × D, and feat, features × D, in the score type) a row range at a time, or read from a precomputed matrix S (rows × features). Returns host arrays: per row the top k feature indices and their signed scores (rows × k), and for MutualNN each feature's best row within each block (features × blocks, block-local), else nothing.

The score block is the pipeline's largest single allocation (M × N: 3.09 GiB for a 60k gallery against 13.7k detections, 9.79 GiB against 43.5k). Materialising it whole is what OOMs on cluttered frames, so it is built _row_chunks at a time and each block released eagerly via KA.unsafe_free! rather than waiting for a finalizer. The result does not depend on the chunking.

VisualGeometryToolkitFeatures._row_chunks — Method
_row_chunks(backend, M, N, T, chunk_bytes) -> Vector{Tuple{Int, Int}}

Consecutive ROW ranges of an M-row gallery whose score block (rows × N of T) fits the budget. chunk_bytes > 0 is honoured verbatim; otherwise the budget is _SCORE_BUDGET of device_free_bytes, which returns typemax on backends exposing no query — yielding a single chunk, the historical behaviour.

Rows, not whole galleries: one calibration target with thousands of blobs is ONE gallery whose block alone can exceed the card (9.3 GiB against a 40k-feature frame, 2026-09-15), so a gallery may span several chunks. That is still exact — the forward sweep is per row, and the reverse sweep merges a gallery's per-column best across its chunks (_ka_top1_cols_blocked!).

VisualGeometryToolkitFeatures.asift_detect! — Method
asift_detect!(plan, img_xy; nms=:none, window_half=3, cutoff=3.0,
              polarity=:none, band_octaves=0.0, band_reach=1,
              intensity_thr=0.04, edge_thr=10.0,
              boundary_K=3.0, uncertainty=nothing) -> Vector{ImasFeatureKA}

Full batched IMAS-25 detection in the plan's preallocated buffers. With nms = :mxm or :ellipse the cross-warp NMS runs on-device and only the survivors are returned; :none returns the full boundary-filtered pool. polarity (:dark → response > 0, :light → response < 0) gates the pool BEFORE the NMS splat, so a blob of the other sign can never suppress a kept one. band_octaves > 0 restricts suppression to features of comparable scale: a feature in scale band b = ⌊log2(√det S) / band_octaves⌋ can only be suppressed by features in bands b ± band_reach (see _band_pool!); 0 is the whole-pool rule. The seed blur σ₀ — the pyramid's, and the one the reported σ is scaled by — is the plan's (AsiftPlan(W, H; seed_sigma)).

uncertainty = FeatureCovariance() also returns each feature's covariance: the result is then (; features, cov), cov[i] the FeatureCovariance covariance of features[i], a CovMat{3} over (x, y, log σ).

VisualGeometryToolkitFeatures.asift_detect — Method
asift_detect(img; device=default_device(), nms=:mxm, window_half=3,
             cutoff=3.0, intensity_thr=0.04, edge_thr=10.0,
             polarity=:none, band_octaves=0.0, band_reach=1, boundary_K=3.0,
             tilts=nothing, upsample=true, seed_sigma=1.6, raw=false,
             uncertainty=nothing)

Run the IMAS-25 ASIFT detector on img (H×W; Gray, UInt8, or real-valued in [0,1]) and return Vector{Detection{EllipticFrame}} in COLMAP coords.

Coordinates. A detection's center is (x, y), with x along the image columns and y along the rows, in COLMAP pixel-centre coordinates: the top-left pixel's centre is (0.5, 0.5), so a blob centred on the pixel img[r, c] is returned at (c − 0.5, r − 0.5). Measured on isotropic Gaussian blobs on the CPU (pinned by the test suite):

  • a blob centred on a pixel centre comes back exact (within 0.005 px);
  • between pixel centres, the quadratic sub-pixel refinement pulls the centre toward the nearest pixel centre, by at most 0.03 px at σ = 4 (−0.007, −0.015, −0.021, −0.027 px at fractions 0.1–0.4, mirrored above 0.5) and 0.06 px for σ from 2 to 8;
  • an exact half-pixel centre, where the DoG ties between the two pixels, is refined like any other: the extremum test breaks the tie toward the first pixel, so it carries that side's bias (−0.031 px at σ = 4). A test strict against all 26 neighbours would reject both pixels and leave an unrefined detection from a coarser octave, 0.5 px low;
  • a feature found only on a pyramid boundary scale slice is not refined and sits on that octave's pixel grid.

With raw = true the features are in 0-indexed OpenCV coordinates (top-left pixel centre (0, 0)), 0.5 less on both axes.

nms selects the cross-warp non-max suppression: :mxm (centroid window, default), :ellipse (Mahalanobis footprint), or :none (full per-warp feature pool). polarity gates by DoG sign (:dark → response > 0, :light → response < 0, :none → both) BEFORE the cross-warp NMS, so a blob of the other sign never suppresses a kept one. band_octaves > 0 makes the NMS scale-banded: a feature can only be suppressed by features whose geometric-mean scale band ⌊log2(√det S) / band_octaves⌋ is within band_reach of its own, so board-sized extrema and tilted-warp streaks stop erasing the small blobs inside them (see asift_detect!). raw=true returns the ImasFeatureKA vector instead of Detections. device, tilts, upsample and seed_sigma pick the plan; the others but raw go to asift_detect!, which refuses a keyword it does not take.

Keypoint uncertainty. uncertainty = FeatureCovariance() returns each detection's frame as Uncertain(frame, Σ̃), Σ̃ = cov(d) a 3×3 CovMat over (x, y, log σ) for unit iid pixel noise in the detector's intensity units — see FeatureCovariance for the model, the parameterization and the units. With raw = true the result is then (; features, cov). The default nothing runs the detector without it, the kernels compiled exactly as before.

The plan for (size, device, tilts, upsample, seed_sigma) is cached (see set_max_cached_plans!) and every call holds a process-wide lock, so concurrent calls are safe but do not run in parallel. On a KA.CPU() device every kernel launch is statically scheduled over the threads, or dynamically when the call runs inside a threaded region (e.g. a Threads.@threads loop over frames); the features are the same either way.

VisualGeometryToolkitFeatures.asift_detections — Method
asift_detections(feats::Vector{ImasFeatureKA}) -> Vector{Detection}
asift_detections(feats, cov) -> Vector{Detection}

Convert raw ASIFT features (0-indexed opencv pixel coords, input frame) into VGF Detection{EllipticFrame} in COLMAP convention (+0.5 on both axes, so the top-left pixel's centre is (0.5, 0.5); see asift_detect). The metadata is (response, edge_score, laplacian_scale_score, warp_idx): laplacian_scale_score = sign(response) (+1 dark, −1 light — the DoG sign convention polarity gates on), which is what is_dark and is_light read; edge_score is a placeholder (always 0). Given the features' covariances (asift_detect!(…; uncertainty = FeatureCovariance())), each frame is Uncertain(frame, Σ̃) (see FeatureCovariance); the +0.5 shift leaves a covariance unchanged.

VisualGeometryToolkitFeatures.batched_rows — Method
batched_rows(run_chunk, N::Int, max_batch::Int; retry_single = false) -> Matrix{Float32}

Run run_chunk(offset, n) over 1:N in chunks of at most max_batch rows (max_batch <= 0 means one chunk) and assemble the N × D result: the row width D is read off the FIRST chunk's output (any shape with n * D elements), the matrix is allocated lazily then, and each chunk is assigned into its contiguous row slice. With retry_single, a chunk that throws is retried one row at a time (the batch size drops to 1 for the rest of the run) — the recovery an inference session wants when a batch overflows its arena. N == 0 returns an empty 0 × 0 matrix.

Hoisted from BlobBoards, where the ONNX host, ORT device-tensor and two Lux describe backends had each drifted their own copy (2026-09).

VisualGeometryToolkitFeatures.match — Function
match(desc1, desc2, [strategy]; metric, dm, ratio_threshold,
      min_similarity, max_distance) -> Vector{NNMatch}

Match descriptors using nearest-neighbor search, on the CPU. It runs the same KernelAbstractions matcher as nn_match on a GPU, so a device returns what this returns. Descriptors are compared in their own float type.

Public but not exported, because it would shadow Base.match: import it (using VisualGeometryToolkitFeatures: match) or call VisualGeometryToolkitFeatures.match.

Arguments

  • desc1::AbstractMatrix{<:Real}: N1×D descriptor matrix (rows = descriptors)
  • desc2::AbstractMatrix{<:Real}: N2×D descriptor matrix
  • strategy::NNStrategy: MutualNN() (default), NN() or KnnMatch(k)

Keyword Arguments

  • metric::DescriptorMetric: CosineSimilarity() (default) or L2()
  • dm: Precomputed N1×N2 pairwise matrix (skip pairwise_matrix computation)
  • ratio_threshold: Lowe's SNN ratio threshold; nothing = disabled
  • min_similarity: Minimum score for DescriptorSimilarity metrics
  • max_distance: Maximum score for DescriptorDistance metrics

Returns

Vector{NNMatch} sorted by score (best first).

Usage

using VisualGeometryToolkitFeatures: match, pairwise_matrix, MutualNN, NN, CosineSimilarity, L2

# Cosine similarity (default) — good for L2-normalized descriptors
match(d1, d2, MutualNN())
match(d1, d2, MutualNN(); min_similarity=0.7)

# L2 distance
match(d1, d2, MutualNN(); metric=L2(), max_distance=0.8)

# Precomputed distance matrix
dm = pairwise_matrix(CosineSimilarity(), d1, d2)
match(d1, d2, MutualNN(); dm)

# With Lowe's ratio test
match(d1, d2, NN(); ratio_threshold=0.8)

VisualGeometryToolkitFeatures.nn_match_stacked — Method
nn_match_stacked(strategy, galleries::AbstractDict, features;
                 backend, index = nothing, min_similarity = 0.6, chunk_bytes = 0)
    -> Dict{K, Vector{NNMatch}}

Match features against every gallery in galleries with one stacked GEMM. Per gallery the result is identical to matching that gallery alone with strategy (MutualNN reverse checks are block-local; KnnMatch(k) takes any k): it is the matcher match runs, with the galleries as blocks of its rows. Matches use LOCAL indices: m.first indexes into gallery k's rows, m.second into features. Supply a prebuilt StackedDescriptorIndex as index to skip the per-call stack/upload.

When index is given it — not galleries — defines what gets matched: the returned dictionary has one entry per index.keys, and galleries supplies only the key type K. The two key sets therefore need NOT agree, and callers rely on that: a caller narrowing its gallery set across calls can keep ONE index built over the full set rather than restaging descriptors every call, and simply ignore the extra entries. Build the index from the widest set you will ever match against.

The score matrix is built a row range at a time. chunk_bytes > 0 caps each range's score block (rows × features) at that many bytes; the default 0 sizes the ranges from free device memory. The result does not depend on the chunking. Scores are cosine similarities in the wider of the index's and the features' float type.

VisualGeometryToolkitFeatures.resolve_one_to_one! — Method
resolve_one_to_one!(used_a::AbstractVector{Bool}, used_b::AbstractVector{Bool},
                    candidates; a = c -> c.first, b = c -> c.second) -> Vector{Int}

Greedy one-to-one reduction over an ALREADY-ORDERED candidate list: visit candidates in the given order, keep a candidate when neither of its endpoints is used yet, and mark both endpoints used. Returns the kept indices into candidates (in visit order); used_a/used_b are mutated in place, so pre-seeded entries (e.g. matches certified by an earlier stage) are respected and callers can chain several candidate lists through one pair of masks.

a/b extract the two endpoint indices from a candidate — the defaults serve NNMatch (m.first/m.second); supply accessors for tuple lists.

The caller owns the ORDER: sort best-first (descending similarity, ascending distance) for best-first assignment (the reduction MutualNN sets already satisfy, and the one KnnMatch(k) sets need), by overlap for geometric association, etc.

VisualGeometryToolkitFeatures.resolve_one_to_one — Method
resolve_one_to_one(matches::AbstractVector{NNMatch}, n_a, n_b;
                   metric = CosineSimilarity()) -> Vector{NNMatch}

Best-first one-to-one reduction of an NNMatch list: visit the best match first and keep each first/second index at most once. metric must be the metric the matches were scored with, because it decides what "best" means: the highest score for a DescriptorSimilarity (the default, CosineSimilarity()), the lowest for a DescriptorDistance such as L2(). n_a/n_b bound the two index spaces. MutualNN output is returned unchanged (already one-to-one); KnnMatch(k) output collapses to its best consistent assignment.
