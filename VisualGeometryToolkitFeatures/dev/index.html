VisualGeometryToolkitFeatures.jl

Feature detection, description and matching for the VisualGeometry stack.

  • Detection. ASIFT (IMAS-25) on KernelAbstractions. asift_detect runs on the CPU or any KernelAbstractions GPU backend and returns Detections (a feature frame plus detector metadata), optionally with each keypoint's covariance. VisualGeometryToolkitIO writes and reads detections as JSON.
  • Matching. Nearest-neighbour descriptor matching, with one KernelAbstractions implementation for the CPU and every GPU backend (nn_match, match), and a stacked matcher over many galleries (nn_match_stacked).
  • LoMa. The learned DeDoDe descriptors and LoMa matchers of LoMa (Nordström et al., ECCV 2026), run from the authors' ONNX exports through ONNX Runtime on the CPU or CUDA (LoMaDescriptor, LoMaMatcher). See Citing.
  • Extensions. JLD2 backs FileCache, and Makie draws detections and correspondences.

The geometric types (feature frames, correspondences, covariances) are VisualGeometryToolkitCore's. This package adds the detector, the descriptors and the matchers that work on them.

Installation

using Pkg
Pkg.add("VisualGeometryToolkitFeatures")

The package requires Julia 1.12 and is part of the VisualGeometryToolkit stack.

Quick start

The example detects the blobs of a synthetic image and matches two sets of descriptors. It needs no files and no network.

using VisualGeometryToolkitFeatures
using Random   # a standard library, shipped with Julia

# A 120×160 gray image with three Gaussian blobs, given as
# (row, column, σ, amplitude): two light blobs and one dark one.
blobs = [(40, 50, 4.0, 0.35), (70, 100, 3.0, -0.3), (30, 130, 6.0, 0.3)]
img = [0.5 + sum(a * exp(-((r - y)^2 + (c - x)^2) / (2s^2)) for (y, x, s, a) in blobs)
       for r in 1:120, c in 1:160]

# Detect with the default IMAS-25 tilt schedule.
dets = asift_detect(img)
length(dets) == 3                      # true
count(is_dark, dets) == 1              # true

# A centre is (x, y) in COLMAP pixel coordinates, where the top-left pixel's
# centre is (0.5, 0.5): the blob at row 70, column 100 is found at (99.5, 69.5).
dark = only(filter(is_dark, dets))
round.(dark.center; digits = 1) == [99.5, 69.5]   # true

# Match descriptors, one per row. Here they are random unit vectors, and the
# second set is the first shuffled and perturbed.
rng = Xoshiro(1)
unit_rows(D) = D ./ sqrt.(sum(abs2, D; dims = 2))
D1 = unit_rows(randn(rng, Float32, 100, 32))
perm = randperm(rng, 100)
D2 = unit_rows(D1[perm, :] .+ 0.05f0 .* randn(rng, Float32, 100, 32))
matches = nn_match(D1, D2)             # mutual nearest neighbours, cosine similarity
all(perm[m.second] == m.first for m in matches)   # true

Detections are written to and read from JSON by VisualGeometryToolkitIO (json_value(d, contract; kind), from_json(Detection, obj, contract; kind)), which owns the stack's quantity JSON format.

LoMa

LoMaDescriptor and LoMaMatcher run the networks of LoMa by David Nordström, Johan Edstedt, Georg Bökman, Jonathan Astermark, Anders Heyden, Viktor Larsson, Mårten Wadenbäck, Michael Felsberg and Fredrik Kahl. The architectures, the trained weights and the ONNX exports are theirs, downloaded from the authors' release; this package only feeds them keypoints and reads their matches back. The descriptors are DeDoDe's (Edstedt et al.). If you use them in published work, cite both:

@inproceedings{nordstrom2026loma,
  title     = {{LoMa: Local Feature Matching Revisited}},
  author    = {David Nordström and Johan Edstedt and Georg Bökman and Jonathan Astermark and Anders Heyden and Viktor Larsson and Mårten Wadenbäck and Michael Felsberg and Fredrik Kahl},
  booktitle = {Proceedings of the European Conference on Computer Vision (ECCV)},
  year      = {2026}
}

@inproceedings{edstedt2024dedode,
  title     = {{DeDoDe: Detect, Don't Describe --- Describe, Don't Detect for Local Feature Matching}},
  author    = {Johan Edstedt and Georg Bökman and Mårten Wadenbäck and Michael Felsberg},
  booktitle = {2024 International Conference on 3D Vision (3DV)},
  year      = {2024},
  organization = {IEEE}
}

LoMa's code is MIT-licensed except its matcher, which inherits LightGlue's Apache-2.0; DeDoDe is MIT except the DINOv2 backbone of DeDoDe-G (Apache-2.0).
