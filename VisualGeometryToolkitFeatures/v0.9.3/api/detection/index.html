VisualGeometryToolkitFeatures.VisualGeometryToolkitFeatures — Module
VisualGeometryToolkitFeatures

Feature detection and descriptor matching.

  • Detection: ASIFT (IMAS-25) on KernelAbstractions. asift_detect runs on the CPU or any KernelAbstractions GPU backend and returns Detections (a frame plus metadata). VisualGeometryToolkitIO writes and reads them as JSON (json_value, from_json). The image circle of a lens, measured from photographs (detect_image_circle: the rim's log-brightness drops on log-polar profiles here, the RANSAC fit through the VisualGeometryToolkitEstimation extension).
  • Matching: nearest-neighbour descriptor matching, one KernelAbstractions implementation on the CPU or any GPU backend (nn_match, match), and a stacked matcher over many galleries (nn_match_stacked).
  • LoMa: the learned DeDoDe descriptors and LoMa matchers, from the authors' ONNX exports (LoMaDescriptor, LoMaMatcher).
  • Camera RAW: the stack's one RAW path. load_raw decodes a Bayer RAW file (LibRaw) into VisualGeometryToolkitCore's RawMosaic and its exact linear values on the 2×2 Bayer cells (Core's LinearRaw: the green-cell image for geometry and radiometry, or R G B), with saturation flags, true sample positions and the exact frame map onto the raw (Core's raw_frame_map); a display-only demosaic for figures, of a file or a mosaic.
  • Extensions: JLD2 backs FileCache; Makie draws detections and correspondences; LibRaw_jll is the RAW decoder.

VisualGeometryToolkitFeatures.Detection — Type
Detection{F<:FeatureFrame, M}

Type alias for Attributed{F, M} — a detection result composing a geometric frame with detector-specific metadata.

The frame type F determines the geometry:

  • Detection{Disc{T}, M} - isotropic detection (3 DOF)
  • Detection{OrientedDisc{T}, M} - oriented isotropic detection (4 DOF)
  • Detection{EllipticFrame{T}, M} - anisotropic detection (5 DOF)
  • Detection{AffineFrame{T}, M} - full affine detection (6 DOF)
  • Detection{<:Uncertain{F}, M} - a frame F with its covariance (VisualGeometryToolkitCore's Uncertain(frame, Σ)), from asift_detect(…; uncertainty = FeatureCovariance()): cov(d) is the covariance, feature_frame(d) the bare frame, geom(d) the detection without it, and the properties below read as on the bare detection

Type Parameters

  • F<:FeatureFrame: The geometric frame type
  • M: Metadata, a NamedTuple. ASIFT emits (response, edge_score, laplacian_scale_score, warp_idx); laplacian_scale_score is the polarity field is_dark/is_light read (> 0 dark, < 0 light).

Fields (from Attributed)

  • value::F: The geometric frame (center + shape)
  • attributes::M: Detector-specific scores and information

Coordinates

The frame's center is (x, y) in COLMAP pixel-centre coordinates, the convention of every detector in this package: x along the image columns, y along the rows, the top-left pixel's centre at (0.5, 0.5). The pixel img[r, c] has its centre at (c − 0.5, r − 0.5). asift_detect documents its measured sub-pixel accuracy.

Property Access

Properties are forwarded from frame and metadata:

  • d.frame, d.value → the geometric frame
  • d.metadata, d.attributes → the metadata
  • d.center → frame.center
  • d.σ → scale from frame (exact for Disc, characteristic_scale for anisotropic)
  • d.Σ → shape matrix (blob shape, not the position covariance)
  • d.response, d.edge_score, etc. → forwarded from metadata

Example

julia> using VisualGeometryToolkitFeatures, VisualGeometryToolkitCore

julia> det = Detection(Disc(Point2(100.0, 200.0), 5.0), (response = 0.05, laplacian_scale_score = -0.1));

julia> Tuple(det.center), det.σ, det.response   # from the frame and the metadata
((100.0, 200.0), 5.0, 0.05)

julia> is_light(det)
true

See also: Disc, EllipticFrame, VisualGeometryToolkitCore's Attributed

VisualGeometryToolkitFeatures.MserRegion — Type
MserRegion

One maximally stable extremal region, as detect_mser returns it.

Fields

  • seed::CartesianIndex{2}: the region's reference pixel, a pixel at the region's level (the tree node MaxTree chose; VLFeat may pick another pixel of the same plateau). A VLFeat seed s (0-based linear index into the column-major H × W image given with dims = (H, W)) is the pixel CartesianIndices(img)[s + 1], and ours is VLFeat's index LinearIndices(img)[seed] - 1.
  • level::UInt8: the region's level in the input image: a :dark region is the 8-connected component of img .<= level holding seed, a :light one that of img .>= level. img[seed] == level.
  • area::Int: its number of pixels.
  • variation::Float32: VLFeat's (in)stability (|R₊Δ| − |R|) / |R|.
  • polarity::Symbol: :dark or :light.

The seed and level determine the region, so its pixels and boundary are not stored (nested regions would hold every pixel many times over): they are formed on demand from the image the region was detected in — region_mask(region, img) the pixels as a mask (VLFeat's vl_erfill), boundary_contours(region, img) their boundary as closed polygons. is_dark and is_light read the polarity.

VisualGeometryToolkitFeatures.boundary_contours — Method
boundary_contours(pixels) -> Vector{Vector{Point2{Float64}}}
boundary_contours(region::MserRegion, img) -> Vector{Vector{Point2{Float64}}}

The boundary of a set of pixels (CartesianIndex{2} (row, column), a Bool mask, or an MSER of img — its region_mask), traced along the pixel edges: one closed polygon per boundary curve (the last vertex joins the first), vertices only where the boundary turns, with x along the columns and y along the rows in the COLMAP pixel origin (conventions/pixel-origins.md), so the pixel (r, c) is the square [c − 1, c] × [r − 1, r] and every vertex is a pixel corner with integer coordinates. The polygons are sorted by signed shoelace area, descending: the outer boundaries first (positive, clockwise on screen), the largest first, then the holes (negative), the smallest first and the largest last. Diagonal neighbours are connected (8-connectivity, the connectivity of an MSER), so where two pixels of the set meet at a corner one curve runs through it; holes are 4-connected.

VisualGeometryToolkitFeatures.detect_mser — Method
detect_mser(img; delta = 5, min_area = 3 / length(img), max_area = 0.75,
            max_variation = 0.25, min_diversity = 0.2,
            bright_on_dark = true, dark_on_bright = true) -> Vector{MserRegion}

The maximally stable extremal regions (MSER; Matas, Chum, Urban and Pajdla, "Robust wide baseline stereo from maximally stable extremal regions", BMVC

  1. of the 8-bit gray image img, selected as VLFeat's vl_mser selects

them (Andrea Vedaldi and Brian Fulkerson, BSD license; src/mser.jl carries the notice). VLFeat's stability criterion is its own, simpler than the paper's.

The extremal regions are the 8-connected components of the level sets img .<= l, arranged in a tree by ImageMorphology's MaxTree. The variation of a region R at level l is (|R₊Δ| − |R|) / |R|, where R₊Δ is the largest region containing R at a level at most l + delta. Of a region and its parent region exactly one level up, the one of larger variation (on a tie, the child) is not maximally stable; the root never is. The survivors are then filtered, largest first:

  • max_variation: a region of variation >= max_variation is dropped;
  • max_area, min_area: FRACTIONS of length(img); a region larger than max_area * length(img) or smaller than min_area * length(img) pixels is dropped (the default min_area is three pixels);
  • min_diversity: a region whose area differs from that of its nearest surviving enclosing region by less than min_diversity times the latter's area is a duplicate and is dropped (min_diversity = 1 turns this off).

An image of fewer than three pixels has no region (VLFeat returns none): MserRegion[], the area fractions not checked.

dark_on_bright returns the dark regions (polarity = :dark) and bright_on_dark the light ones (:light), the components of img .>= l: VLFeat runs the same on 255 .- img, whose <= level sets these are. Dark regions come first; each polarity is ordered as VLFeat orders it, by level (darkest first, resp. brightest first), then by seed.

Input

A matrix of UInt8, N0f8 or Gray{N0f8}: VLFeat's vl_mser_pix is a byte, and these hold its 256 levels exactly. Any other element type is an ArgumentError: quantize explicitly (e.g. gray_u8), so the levels the regions are cut at are the caller's choice.

julia> using VisualGeometryToolkitFeatures

julia> using VisualGeometryToolkitFeatures: boundary_contours

julia> img = fill(0xc8, 40, 60); img[11:20, 21:35] .= 0x28;   # a dark rectangle

julia> r = only(detect_mser(img; bright_on_dark = false));

julia> r.polarity, r.area, Tuple.(only(boundary_contours(r, img)))
(:dark, 150, [(20.0, 10.0), (35.0, 10.0), (35.0, 20.0), (20.0, 20.0)])

VisualGeometryToolkitFeatures.detect_foerstner — Method
detect_foerstner([T = Float32], img, seeds::AbstractVector{<:Detection}; device = default_device(),
                 noise = nothing, derivative = :gaussian2d, derivative_sigma = 1.0,
                 significance_level = 0.999) -> StructArray{<:Detection}

The Förstner operator's window estimation (steps 4–6 of the method above, its doubled resolution, its kernels) at GIVEN windows: one window per seed, centred on the doubled-grid pixel nearest the seed's centre, its integration scale the seed's characteristic scale σ (input pixels; a detect_sfop row's selected σ). The box window has the standard deviation σ, the estimation window the half-width ⌈√(12(2σ)² + 1)/2⌉ + 1 doubled pixels, as integration_sigma = σ would give: SFOP's N(σ) = 12σ² + 1 is the pixel count of the box of the same energy as its Gaussian G_σ. The image-wide window search (step 3) is not run.

Returns the rows of detect_foerstner(img) (label, frame and covariance, window, F; the F-test of each window at its own redundancy), one per seed whose window lies inside the doubled image, in the order of seeds.

VisualGeometryToolkitFeatures.detect_foerstner — Method
detect_foerstner([T = Float32], img; device = default_device(),
                 method = :foerstner, noise = nothing, noise_sigma = something(noise, 2.0),
                 derivative = :gaussian2d, integration = :box,
                 derivative_sigma = 1.0, integration_sigma = 1.41 * derivative_sigma,
                 precision_threshold = 0.5, roundness_threshold = 0.3,
                 significance_level = 0.999) -> StructArray{<:Detection}
detect_foerstner([T = Float32], L::LinearRaw; sensor_model::SensorModel = SensorModel(), kwargs...)

The Förstner interest operator (Förstner and Gülch, 1987): the junction (corner) points and circular points of a grey image at sub-pixel precision, each with its covariance, after the reference implementation ip_fop.m (Luxen, 2005), with Köthe's doubled resolution and window criterion (Köthe, 2003).

Returns one row per optimal window, a StructArray of Detection(Uncertain(PointFrame(x), Σ), (; label, window, F, covariance_status)) (VisualGeometryToolkitCore's PointFrame: a position, no scale):

  • label: :corner (a junction point), :circular (Förstner & Gülch's circular point: the centre of a rotationally symmetric pattern, with no size estimate) or :unknown (the significance test assigned neither);
  • the frame: the corner or circular point's position and its 2×2 covariance (px², (x, y) order); for an :unknown row the window centre with a NaN covariance (the reference returns no estimate for it);
  • window: the window centre, a Point2;
  • F: the classification statistic Ω_corner / Ω_circular;
  • covariance_status: how the frame's covariance was obtained, or why there is none: the image noise propagated through the detector (below) — :propagated for a given σₙ, :propagated_measured / :propagated_estimated / :propagated_specified for a RAW under its frame's SensorModel, by the source of its Poisson–Gaussian noise — :a_posteriori (the reference's Ω/redundancy · N⁻¹, when no noise is known), or :unclassified on an :unknown row (no estimate, a NaN covariance).

filter(d -> d.label === :corner, points) are the corners; Ellipse(d.value; sigma = 1) is a point's 1σ error ellipse (ip_errell.m's default).

img is any grey image the package's detectors take, read through gray_f32 as grey values in [0, 1] (an 8-bit image as value/255, as MATLAB's im2double); it is not stretched to its own range. The image-wide steps run on device, any KernelAbstractions backend, in precision T (the reference computes in Float64; supply Float64 for that).

Keywords (defaults: the values the reference's CODE runs with)

  • method: :foerstner — windows where the roundness 4 det/tr² > roundness_threshold and the precision det/tr > (σₙ / precision_threshold)², ranked by det/tr; :koethe — windows whose precision test succeeds, ranked by the smaller eigenvalue.
  • noise: the image noise the covariance is propagated from: the standard deviation σₙ of iid pixel noise, in grey levels of an 8-bit image (0–255, as noise_sigma). The covariance is then σₙ² J Jᵀ (σₙ on the [0, 1] image), J the exact first-order derivative of the estimate with respect to every input pixel, through the detector's own doubling, derivative taps, squared gradient and window estimate (step 6). nothing: no noise is known, and the covariance is the reference's a-posteriori Ω/redundancy · N⁻¹ (step 4), marked covariance_status = :a_posteriori; that one is not calibrated (it carries the model misfit, which does not scale with the noise).
  • sensor_model (a RAW's green cells, L::LinearRaw, read through VisualGeometryToolkitCore's green_plane, positions on the cell grid): the frame's resolved SensorModel (sensor_model), the one L was linearised with. Under a Poisson–Gaussian noise (a gain) L carries each value's variance (Core's one law), and each pixel's variance weighs its column, Σ = J diag(var) Jᵀ; read noise alone, a relative noise or none leaves the a-posteriori covariance (the owner's ruling: only a gain-carrying model is fed).
  • noise_sigma: the noise level of the PRECISION TEST (step 3), in grey levels of an 8-bit image (0–255), as the reference's for a uint8 image; σₙ = noise_sigma / 255 on the [0, 1] image. It defaults to noise when that is given, else to the reference's 2. It does not enter the covariance.
  • derivative: :gaussian2d (a Gaussian derivative smoothed across by a Gaussian of the same σ) or :gaussian1d (the derivative alone).
  • integration: :box (a box whose standard deviation is integration_sigma) or :gaussian.
  • derivative_sigma, integration_sigma: in input pixels.
  • precision_threshold: the largest accepted point standard deviation, input px.
  • roundness_threshold: the smallest accepted roundness (:foerstner only).
  • significance_level: of the F-test that labels a point corner or circular.

Algorithm (ip_fop.m, step by step)

  1. The image is doubled bilinearly (the package's one 2× upsampling, ASIFT's) and every scale and threshold doubled with it (lines 170–180).
  2. The gradient by correlation with the derivative taps (radius ⌈3.3σ⌉, zero padding, as imfilter: gaussian_gradient), its squares and product (the squared gradient), and their integration by the box (width 2⌈√(12σ² + 1)/2⌉ + 1) or the Gaussian (radius ⌈3.3σ⌉), zero padded (lines 184–207, 617–678).
  3. The window measure (det/tr or the smaller eigenvalue) masked by the tests above; its regional maxima (8-connected plateaus higher than every neighbour, imregionalmax), thinned by a second non-maximum suppression over a square of radius 2⌈√(12σᵢ² + 1)⌉ doubled pixels, away from the border (lines 210–281).
  4. In the (2ρ + 1)² window around each centre, ρ = ⌈√(12σᵢ² + 1)/2⌉ + 1 (σᵢ doubled), the pixels weighed equally (the reference's choice, also for a Gaussian integration): the corner is the least-squares intersection of the lines through every pixel ACROSS its gradient (normal matrix Σ ∇g∇gᵀ), the circular point that of the lines ALONG it (Σ ∇g⊥∇g⊥ᵀ). Each has a weighted residual sum Ω, redundancy (2ρ + 1)² − 2 and a-posteriori covariance Ω/redundancy · N⁻¹ (lines 314–423, 440, 449).
  5. F = Ω_corner / Ω_circular against the F distribution of (redundancy, redundancy) degrees of freedom, as the reference's (T < F(α)) − (T > F(1 − α)) (line 429): a corner below the 1 − significance_level quantile, a circular point above the significance_level quantile, unknown in between.
  6. With noise given, the covariance is propagated instead (not in the reference): the estimate x̂ = N⁻¹ b moves, by the implicit-function theorem, by δx̂ = N⁻¹ Σₚ A(p) δ∇g(p) with A(p) w = (vᵀe) R w + v eᵀ R w, v = R∇g, e = p − x̂ (R the identity for a corner, the 90° rotation for a circular point), the window centre fixed; the gradient is linear in the input, so each input pixel q gives the column J[:, q], exact at the image borders, and Σ = Σ_q σₙ² J[:, q] J[:, q]ᵀ. Monte Carlo against each dot's noise-free estimate gives the χ²₂ NEES ≈ 2 and 95 % coverage (Förstner study, Part 2).

Coordinates

COLMAP pixel centres of the input image, (x, y) = (column, row), converted once, at the output. The doubled image's pixel (r′, c′) (1-based) samples the input at 1-based (r′/2, c′/2), so a doubled-grid position is at COLMAP ((c′ − 1)/2, (r′ − 1)/2) in the input, and its covariance is the doubled one /4, reordered to (x, y).

Differences from ip_fop.m

  1. Undoing the doubling — fixed. The reference doubles with MATLAB's imresize(g, 2, 'bilinear') (line 172; doubled pixel j samples input j/2 + 1/4) but maps positions back with transf_H, transf_v (lines 340–350, applied at 436, 446, 457), the inverse of an align-corners grid: its points are off by ((n + 1)/2 − x)/(2n − 1) (1-based, n the image size), 0 at the centre, up to 0.25 px toward the centre at the borders. Here the doubling is the package's upsampling (input j/2, a quarter pixel from imresize's grid) undone by its own exact inverse.
  2. The circular point's residual sum — kept as the reference has it. Its line 423 takes two of the three terms from the corner model's residuals; the circular model's own residual sum would take all three from its own. Monte Carlo coverage favours the reference's form, so it is kept.
  3. Defaults — the code's, not the header's. The header states SIGMA_N = 2.5 and SIGMA_DIFF = 0.7 (lines 37, 50); the code runs 2.0 and 1.0 (lines 521, 524). A documentation conflict, not a fix.

The docs page gives the evidence for each. The reference warns that with a Gaussian integration the window estimation still weighs the pixels equally; so does this.

Example

julia> using VisualGeometryToolkitFeatures, VisualGeometryToolkitCore

julia> img = [Float32((c - 20.5)^2 + (r - 24.5)^2 < 6.25) for r in 1:48, c in 1:40];   # a dot at pixel (24.5, 20.5)

julia> points = detect_foerstner(img);

julia> only(points).label
:circular

julia> round.(Tuple(only(points).center); digits = 1)   # COLMAP: (column − ½, row − ½)
(20.0, 24.0)

VisualGeometryToolkitFeatures.gaussian_gradient — Function
gaussian_gradient(img::AbstractMatrix{<:Real}, σ[, mask]; derivative = :gaussian2d) -> (gx, gy)

The gradient of img at scale σ (pixels): gx the derivative along the columns (COLMAP x, ∂/∂column), gy along the rows (y, ∂/∂row), each the image's size, in its element type (an integer image's float), on its device (the image's KernelAbstractions backend: a host array on the CPU, a GPU array on its GPU — one kernel for both). Per pixel, so a step of height 1 gives a peak of ≈ 1/(√(2π)σ) per pixel for :gaussian2d.

The derivative of a Gaussian, correlated along one axis: the taps x·exp(−x²/2σ²)/(√(2π)σ³) on radius ⌈3.3σ⌉; along the other axis derivative = :gaussian2d smooths with the unit-sum Gaussian of the same σ and radius, :gaussian1d not at all. Zero padding at the image border (MATLAB's imfilter): the Förstner operator's gradient (detect_foerstner calls this one), bit for bit.

With a mask (an H × W array of weights, 0 outside the support — a fisheye's image circle) it honours gaussian_blur's semantics: the gradient of the NORMALIZED convolution blur(img·mask) / blur(mask) (the blur the across-axis Gaussian), (∂N·D − N·∂D) / D² with N and ∂N of img·mask, D and ∂D of mask; pixels outside the mask do not bleed in, and the gradient is 0 where the mask is zero.

VisualGeometryToolkitFeatures.batched_rows — Method
batched_rows(run_chunk, N::Int, max_batch::Int; retry_single = false) -> Matrix{Float32}

Run run_chunk(offset, n) over 1:N in chunks of at most max_batch rows (max_batch <= 0 means one chunk) and assemble the N × D result: the row width D is read off the FIRST chunk's output (any shape with n * D elements), the matrix is allocated lazily then, and each chunk is assigned into its contiguous row slice. With retry_single, a chunk that throws is retried one row at a time (the batch size drops to 1 for the rest of the run) — the recovery an inference session wants when a batch overflows its arena. N == 0 returns an empty 0 × 0 matrix.

Hoisted from BlobBoards, where the ONNX host, ORT device-tensor and two Lux describe backends had each drifted their own copy (2026-09).

VisualGeometryToolkitFeatures.asift_detect — Method
asift_detect(img; device=default_device(), nms=:mxm, window_half=3,
             cutoff=3.0, intensity_thr=0.04, edge_thr=10.0,
             polarity=:none, band_octaves=0.0, band_reach=1, boundary_K=3.0,
             tilts=:imas25, exclusion_mask=nothing, upsample=true, seed_sigma=1.6,
             raw=false, uncertainty=nothing, refinement=nothing)

Run the IMAS-25 ASIFT detector on img (H×W; Gray, UInt8, or real-valued in [0,1]) and return Vector{Detection{EllipticFrame}} in COLMAP coords.

Coordinates. A detection's center is (x, y), with x along the image columns and y along the rows, in COLMAP pixel-centre coordinates: the top-left pixel's centre is (0.5, 0.5), so a blob centred on the pixel img[r, c] is returned at (c − 0.5, r − 0.5). Measured on isotropic Gaussian blobs on the CPU (pinned by the test suite):

  • a blob centred on a pixel centre comes back exact (within 0.005 px);
  • between pixel centres, the quadratic sub-pixel refinement pulls the centre toward the nearest pixel centre, by at most 0.03 px at σ = 4 (−0.007, −0.015, −0.021, −0.027 px at fractions 0.1–0.4, mirrored above 0.5) and 0.06 px for σ from 2 to 8;
  • an exact half-pixel centre, where the DoG ties between the two pixels, is refined like any other: the extremum test breaks the tie toward the first pixel, so it carries that side's bias (−0.031 px at σ = 4). A test strict against all 26 neighbours would reject both pixels;
  • every detection is refined: extrema are searched on the interior scale slices only (each with a slice above and below), and an extremum whose refinement fails is dropped (plan.refine_dropped counts them), never returned on the octave's pixel grid; with uncertainty = FeatureCovariance(), so is a detection whose covariance is singular or NaN (counted there too).

With raw = true the features are in 0-indexed OpenCV coordinates (top-left pixel centre (0, 0)), 0.5 less on both axes.

nms selects the cross-warp non-max suppression: :mxm (centroid window, default), :ellipse (Mahalanobis footprint), or :none (full per-warp feature pool). polarity gates by DoG sign (:dark → response > 0, :light → response < 0, :none → both) BEFORE the cross-warp NMS, so a blob of the other sign never suppresses a kept one. band_octaves > 0 makes the NMS scale-banded: a feature can only be suppressed by features whose geometric-mean scale band ⌊log2(√det S) / band_octaves⌋ is within band_reach of its own, so board-sized extrema and tilted-warp streaks stop erasing the small blobs inside them (see asift_detect!). raw=true returns the ImasFeatureKA vector instead of Detections. device, tilts, upsample and seed_sigma pick the plan; the others but raw and exclusion_mask go to asift_detect!, which refuses a keyword it does not take.

Tilts. tilts is a tilt_schedule name or a vector of (t, φ) pairs: :imas25 (the default) the 25 tilts of IMAS-25, :untilted the identity warp alone (plain DoG-SIFT), whose detections localize best (about 0.3 px rms on real panorama frames, against about 0.95 px for a tilted warp's): the schedule for views that differ by a rotation, such as a panorama's. Under :untilted every detection has warp_idx == 1, and they are exactly the identity warp's detections under :imas25.

Exclusion mask. exclusion_mask, an H×W AbstractMatrix{Bool} (true where detection is not allowed: clipped or saturated pixels, a vignetted rim, an overlay), drops every detection whose centre lies within three of its scales (characteristic_scale, the DoG's support) of a masked pixel, so no detection is read off masked pixels. It applies after the cross-warp NMS, to raw features and covariances alike. The detector on a StabilizedImage masks its saturated pixels by this rule.

Determinism. The result is a function of the image and the keywords: the same detections, in the same order, run to run, on one thread or many, launched statically or from inside a threaded region. The extrema pool fills in the order the threads reach it, so before the cross-warp NMS (which breaks ties in its quantized response by pool order) it is sorted into a canonical order: by position, scale and response, then every other field (the covariance's too). The detections come back in that order.

Detection uncertainty. uncertainty = FeatureCovariance() returns each detection's frame as Uncertain(frame, Σ̃), Σ̃ = cov(d) a 3×3 CovMat over (x, y, log σ) for unit iid pixel noise in the detector's intensity units — see FeatureCovariance for the model, the parameterization and the units. With raw = true the result is then (; features, cov). The default nothing runs the detector without it, the kernels compiled exactly as before.

Continuous refinement (opt-in). refinement = ContinuousRefinement() replaces each detection's one-step quadratic refinement, after it, by an iterative one on a continuous model of the DoG response (Core's device LM, in a kernel, on the CPU and any GPU): the same candidates, the half-sample jump of the one-step refinement gone, and with uncertainty = FeatureCovariance() each refined detection's covariance recomputed at its own point from that model's derivatives. A detection whose continuous refinement fails keeps today's. See ContinuousRefinement for the response models; the default refinement = nothing is the detector unchanged.

The plan for (size, device, tilts, upsample, seed_sigma) is cached (see set_max_cached_plans!) and every call holds a process-wide lock, so concurrent calls are safe but do not run in parallel. On a KA.CPU() device every kernel launch is statically scheduled over the threads, or dynamically when the call runs inside a threaded region (e.g. a Threads.@threads loop over frames); the features are the same either way.

VisualGeometryToolkitFeatures.FeatureCovariance — Type
FeatureCovariance()

Ask asift_detect for each detection's 3×3 covariance over (x, y, log σ), by the implicit function theorem, for iid unit pixel noise.

asift_detect(img; uncertainty = FeatureCovariance()) returns detections whose frame is VisualGeometryToolkitCore's Uncertain(frame, Σ̃); the default uncertainty = nothing runs the detector unchanged. cov(d) is Σ̃, feature_frame(d) the frame, and d.center, d.σ and the metadata read as on any detection.

Model. A refined DoG detection is a stationary point of the detector's local quadratic model of the DoG in (slice, x, y). With Ĥ its finite-difference Hessian and C the covariance, under unit iid pixel noise, of that model's gradient at the detection, Σ̃ = J·Ĥ⁻¹·C·Ĥ⁻¹·Jᵀ: C is tabulated exactly for the discrete pyramid (warp, upsample, blurs, octave downsamples) once per plan, and J maps to the reported coordinates, then through the ASIFT back-projection.

Parameterization. Σ̃ is a CovMat{3} over (x, y, log σ) in the detection's image frame (COLMAP pixel centres, as d.center), σ = d.σ (the frame's characteristic scale √det S), log natural. Position-only consumers take the top-left 2×2 block (the marginal). A tilted ASIFT warp's frame has the shape S = σ_w·M_w with M_w fixed by the warp (d.warp_idx into the tilt schedule), so (x, y, log σ) are its only free parameters and Σ̃ is full rank.

Units. Unit noise variance in the detector's intensity units: those of a float input image, and the [0, 1] scale for 8-bit input (UInt8, N0f8, …; σn = σgray / 255). The physical covariance is σ_n²·Σ̃.

Every detection is refined, and has a covariance: the detector searches the interior scale slices only and drops an extremum whose sub-pixel refinement fails, and with FeatureCovariance it drops, exactly so, a detection whose covariance is singular or NaN (the implicit-function system singular: not finite and positive definite), before the cross-warp NMS; plan.refine_dropped counts both. Every returned detection's Σ̃ is finite and positive definite.

Extension point (not implemented): an intensity-dependent noise model, e.g. FeatureCovariance(noise = ShotNoise(a, b)), makes the middle term K·diag(σ²(I))·Kᵀ, gathered from the pyramid per detection instead of tabulated.

VisualGeometryToolkitFeatures.detect_sfop — Method
detect_sfop(img; device = default_device(), noise_sigma = 2.0, significance_level = 0.999,
            precision_threshold = 0.5, nb_octaves = 3, nb_scales = 3, input_blur = 0.5,
            upsample = true, seed_sigma = (upsample ? 2 : 1) * input_blur) -> StructArray{<:Detection}

SFOP scale selection (Förstner et al., 2009) for CIRCULAR points (the spiral model at α = 90°): each point where the precision w of a circular point's estimate peaks in position and scale, with the integration scale σ it peaks at. Rows Detection(Disc(x, σ), (; precision)), COLMAP pixel centres of the input and σ in input pixels; precision is w (px⁻²). Seed detect_foerstner(img, seeds) with them to localise each point at full resolution in its own window.

  • The scale space: gaussian_scale_space(img; nb_octaves, nb_scales, seed_sigma, input_blur, upsample), ASIFT's pyramid. Its first level is the input itself (seed_sigma the input's own blur in the first octave's pixels: no seed blur), so the finest scale searched is the finest the image holds: with the defaults the integration scales run from 3·2^(2/3)·0.5 ≈ 2.4 input pixels (the second level of the 2× upsampled octave) up. Level l of octave o (blur σₗ, octave pixels) gives the differentiation scale τ = σₗ₊₁, the next level's blur: gaussian_gradient on the level at the pyramid's own blur increment √(σₗ₊₁² − σₗ²), so every octave's levels sit on one ladder of scales and an octave's last levels are the next one's first; the integration scale is σ = 3τ.
  • The precision: w = (N(σ) − 2)·λ₂(M̄)/Ω̄, N(σ) = 12σ² + 1 (σ in the octave's pixels, so w is in px⁻² of the input at every octave), M̄ the structure tensor (the squared gradient's average under the unit-sum Gaussian G_σ), Ω̄ = Σ G_σ(d)·(dᵀ ∇g⊥)² the circular model's weighted squared distances about the window centre (eq. 5 of the paper at α = 90°).
  • Maxima: of w over the 26 neighbours in (x, y, level), levels 2 … S + 2 of every octave (adjacent octaves share a level), refined by the quadratic interpolation of ASIFT's extraction on −1/w (sub-pixel, sub-level; the reference point's misfit is quadratic in its offset), or kept on its pixel and level where that interpolation fails (where clutter enters the window w steps); precision is w at the sample.
  • Significance: λ₂ > T, T = ½E[tr M̄]·χ²_ν(significance_level)/ν for white noise of noise_sigma grey levels of an 8-bit image: E[tr M̄] and the degrees of freedom ν = 2E²/Var (Satterthwaite) of the Gaussian-weighted sum of the correlated squared gradients, both from the gradient field's exact covariance under the level's blur. No empirical factor: the paper's 1.5 was the correlation the independent-pixel count 2N(σ) ignored. λ₂ ≤ tr/2, so the test is conservative.
  • Precision: a maximum is kept when its point standard deviation 1/√w is at most precision_threshold (input pixels, detect_foerstner's keyword and default): the paper's T_w.
  • Accuracy: seeded detect_foerstner at the selected σ equals the best fixed window within Monte Carlo error at dot radii 0.9–5 px, except near 1.8 px, where it is 0.0008 px RMS worse (0.0092 vs 0.0084 px): a measured, accepted limit of the window estimator's pixel locking (no window rule tested removed it).
  • Suppression: ASIFT's elliptical NMS (cross_warp_nms), the paper's eq. (8) with its defaults (fp = 1, fs = ½, T_r = 1) as footprint overlap: a footprint of radius σ/√2 and half-octave scale bands, ± 1 band.

VisualGeometryToolkitFeatures.spread_strongest — Method
spread_strongest(detections, image_size, n; tolerance = 0.1, device = default_device()) -> detections

About n of the strongest detections spread over the image: Suppression via Square Covering (SSC; Bailo et al., Pattern Recognition Letters 106, 2018, ported from the authors' code, https://github.com/BAILOOL/ANMS-Codes, MIT). In descending |response| (ties: the earlier detection first), a detection is kept unless a kept one lies in the square of side w about it (on a grid of cells of side w / 2); the side w is an integer number of pixels, found by the authors' binary search until the kept count is within round(n ∓ n·tolerance). The kept detections are returned in detector order.

Where the global top n by |response| would sit (on a frame with a bright window and a dim interior) nearly all in the window, this keeps the strongest of each neighbourhood, at whatever contrast the neighbourhood has.

image_size is (H, W) or a channelview's (C, H, W); the detections' centroids are in its COLMAP pixel frame ([0, W] × [0, H]). With n or fewer detections, detections itself is returned; n = 1 is the single strongest. Where no integer width lands in the band (the reference then returns its last covering, outside the band), the width is refined between the two bracketing integers by bisection, and if the count still jumps over the band, the covering above it loses its weakest detections down to the band's top; whenever the reference's search lands in the band, the result is the reference's. The count is below the band only when every covering is (fewer detections than the band can hold).

One KernelAbstractions implementation on the CPU or any GPU backend (device): the covering is computed in parallel (a per-cell maximum, then synchronous rounds of the greedy independent set of the cells in score order), and its result is the reference's sequential sweep's exactly, ties included; every backend returns the same set, run to run.

VisualGeometryToolkitFeatures.detect_image_circle — Method
detect_image_circle([rng,] [T = Ellipse,] frames; outlier_halfwidth, initial = nothing, rim_band = (0.8, 0.0),
                    rim_angles = :auto, significance = 0.01,
                    device = default_device())
    -> (; circle::T, fit, contour, cut, rim_gap, covariance, center_scale, axes_scale, rim::RimProfile) | nothing

The image circle of a lens MEASURED from photographs frames — an iterable of images of one size (a vector, or a generator that streams them: one camera, one lens, one focus, so the circle is the same in all of them) — in the frames' COLMAP pixel frame: the lens COVERAGE, where its light ends. No lens model predicts it (a model's fold says where the MODEL is valid, not where the field stop or the lens's own image circle cuts the light). The lit region is not necessarily round: it is fitted as the model type T, Core's Ellipse (the default) or Circle.

The fit is VisualGeometryToolkitEstimation's find_ellipse / find_circle, through this package's extension on it: using VisualGeometryToolkitEstimation first (without it the call is an ArgumentError naming the package).

The frames are gray images (anything Colors.gray reads: Gray, a real) or camera RAW images, never both:

  • a LinearRaw of mode :green_cells or a RawMosaic (read as LinearRaw(mosaic; mode = :green_cells)) is measured on its GREEN CELLS, the geometry image, its saturated cells excluded, and the result is taken to the raw's pixels by the cells' raw_frame_map (Core's similarity action on an Ellipse or a Circle). The keywords in pixels are in GREEN-CELL pixels, the resolution measured on (half the raw's). Every frame must have the same map (one sensor, one window), and a cell image on a device is read to the host. Cells read under a sensor model with a variance law (an Uncertain image) carry each value's variance, and the rim's noise is then the MODEL's (SensorModelNoise); otherwise it is the data's (EmpiricalNoise). The type decides;
  • any other image is measured as it is (its white, 1, is its saturation), and its result is in its own pixels.

Each frame lights a different part of the rim, and a scene's own edges move between frames; their union of light does the measuring:

  1. the per-pixel MAXIMUM over the frames (a region dark in one frame is filled by another; a scene edge is washed out), saturated where any frame is;
  2. resampled by VisualGeometryToolkitCore's log-polar warp (logpolar_map, image_warp!) about the initial model's centre — initial, by default the image centre with the half diagonal for radius — over the radii (1 − rim_band[1])·min(axes) … (1 + rim_band[2])·max(axes) (the default: 0.2…1 of the half diagonal, every rim inside the frame down to a fifth of it), at most 1 px apart in radius (Δ(ln r) ≤ 1/r_max) and in arc (Δθ ≤ 1/r_max) at the outer end, so every pixel of the band contributes. The sample rows are grouped into angle bins and every (angle bin, radius) reduced to its MEDIAN (one KernelAbstractions kernel), both on device. A bin is skipped when a sample's bilinear taps leave the frame or more than half its samples are saturated. The angle bins (rim_angles = :auto) are chosen from the image: of the binnings doubling from 45 (8°) to 3 sample rows per bin, the one whose coverage is the most precise (the smallest standard error of its mean radius, the inliers' rms over √(wedges with an inlier), the rms no finer than the edges' own median uncertainty nor the radial grid's spacing over √12, with at least 20 such wedges). Finer bins give more wedges but noisier medians and, in a textured scene, the scene's edges among the candidates;
  3. per angle, the CANDIDATES: every EDGE of the profile's OUTER ENVELOPE — the brightest it gets at or beyond each radius: where the light ends it does not come back, while a scene edge or a dark object inside the disc is followed by light again and leaves the envelope alone. Every radius is in pixels through the log-polar map, its differential and its inverse (Core's transform_deriv, inv): the drop at a radius r is across exactly 2 px about it (the bilinear taps' support; its ends r ± 1 px through the inverse map, the profile interpolated between columns), so it is continuous in r. An edge is a maximal run of significant drops; its candidate is the steepest drop in LOG brightness per pixel from the run's start to the next edge's (the log floored at the angle's darkest level or its noise), at its sub-sample peak in the grid coordinate taken to pixels by the map. A log drop is a ratio, independent of the exposure: a blurred sharp stop's steepest log drop is at the stop, a soft ramp's at its foot, where it meets the floor; a rim that falls in two steps (lit, a dim band, the floor) gives both (owner ruling 2026-11-14). A drop is significant when it exceeds its noise √(σ(r − 1)² + σ(r + 1)²) (σ each bin's noise at its pixels, rows × arc from the map's differential: the sensor model's, or the data's) by z = Φ⁻¹(1 − α/m), α = significance the family-wise level over the angle's m drops: the floor's noise alone makes an edge in an angle with probability at most α;
  4. the model: find_ellipse(candidates; scoring, rng) for Ellipse, find_circle(…) for Circle — RANSAC with the robustified-LM local optimization, scored by the Student-t + uniform marginal (the inlier scale marginalized; the outliers uniform over ±outlier_halfwidth; its priors the stack's default, VisualGeometryToolkitEstimation's scoring_from_toml of student_t_uniform), on ONE candidate per angle, so the support counts angles and an angle with many edges does not dominate: first each angle's OUTERMOST edge (where its light ends); then each angle's edge NEAREST that model, any of its edges (stray light, or a step off the model, gives way), fitted again: the coverage. Per angle that edge, an inlier, is the rim's edge there (rim.edge); an angle whose rim is hidden (an object against the lens) is an outlier.

Returns nothing when no model is found (fewer than 5 candidates, or no consensus: a lens that lights the whole frame has no rim) or the model contains the whole frame (its light covers the sensor). Otherwise:

  • circle: the lens coverage, an Ellipse{Float64} or a Circle{Float64} (T), COLMAP pixels (a RAW frame's: raw pixels);
  • fit: the second RANSAC's RansacEstimate, on one candidate per angle that has any (each angle's edge nearest the first model, in angle order); inlier_mask(fit) indexes those points. For RAW frames the RANSAC ran on the green cells: its estimate is mapped to raw pixels (Core's map_estimate, estimate(fit) == circle), but its rms and every residual or scale in its metadata stay in GREEN-CELL pixels (raw pixels ÷ 2);
  • contour: the rim's points, Vector{Point2{Float64}}, in circle's pixels: per angle bin with one, the inlier candidate nearest the coverage (rim.edge);
  • cut: whether the coverage reaches past the frame (an APS-C lens on the full frame: the rim is seen in arcs);
  • rim_gap: the largest angle, radians, between consecutive inliers around the coverage's centre. Below π the rim is seen on all sides of the centre and the centre and radius are measured; above π the observed rim is one arc, and the boundary away from it is the model's extrapolation;
  • covariance: the coverage's covariance in Core's ambient_coordinates of the MEASURED plane (an ellipse's centre and form (Q₁₁, Q₁₂, Q₂₂); a circle's centre and radius): s²·solver_covariance on the inliers, s² their squared distances to the model along their rays over n − dof (nothing when singular, and for a Circle: its problem provides no solver covariance); center_scale, axes_scale the standard deviations of the centre and of the semi-axes (a, b) in circle's pixels (NaN without a covariance);
  • rim: the measurement (RimProfile): the profiles, every angle's candidates and edge, the noise statistics.

Keywords

  • outlier_halfwidth (required, pixels > 0): the Student-t + uniform scorer's outlier half-width; a literal of the caller's, no computed default. 1000 full-resolution px held one basin on every set measured, for 750–2000.
  • initial: the initial model (the result's pixels): its centre is the log-polar origin, its axes scale the band. By default the image centre with the half diagonal (no prior: a camera's principal point is a better centre when known).
  • rim_band = (inner, outer), fractions of the initial model's axes: the radii resampled, from (1 − inner)·min(axes) to (1 + outer)·max(axes). The default (0.8, 0.0), with the default initial (the half diagonal), resamples from a fifth of the half diagonal out to the corners. The outer end is derived: the corners are the farthest any light reaches on the sensor. The inner end is a stated ASSUMPTION, not a fit: the coverage reaches at least a fifth of the half diagonal (a lens whose light ends nearer the centre leaves 96 % of the sensor dark, no use as a camera). It cannot be 0 because the log grid needs a positive inner radius, and the band's cost grows only as ln(1/0.2)·r_max radial samples. Narrow it when the coverage is known roughly, e.g. from a previous run.
  • rim_angles: the angle bins, :auto (chosen as in step 2) or a count ≥ 5.
  • significance: the edge test's family-wise level per angle: the probability that the floor's noise alone makes an edge anywhere in an angle. 0.01 is the conventional 1 % level, stated, not tuned. A false edge is one more candidate, and it is not consistent with the coverage, so the RANSAC rejects it as an outlier; the level only trades such outliers against missing a faint rim's edge.
  • device: the KernelAbstractions backend of the warp and the bin medians (default_device(): the GPU when one is functional).
  • min_hole_area, smoothing_weight, border_margin: the hull fit's keywords before 0.9.2, accepted and ignored with a deprecation warning (the hull is gone).

VisualGeometryToolkitFeatures.RimProfile — Type
RimProfile

The measurement behind detect_image_circle's coverage (its rim field): the log-polar profiles of the frames' per-pixel maximum around the initial model, every angle's candidates and its chosen edge.

Fields (radii and centre in the MEASURED plane's pixels: a RAW frame's green cells):

  • center::Point2{Float64}, initial — the log-polar origin and the initial model it is the centre of (the measured plane's pixels);
  • angles::Vector{Float64} — each angle bin's centre, radians, atan(y − cy, x − cx) (COLMAP pixels, y down);
  • radii::Vector{Float64} — the samples' radii from center, ascending, Δ(ln r) ≤ 1 / r_max (≤ 1 px at r_max);
  • bin_samples::Vector{Int} — each angle bin's sample rows (≤ 1 px of arc apart at r_max);
  • profile::Matrix{Float64} — profile[a, j], the median of angle bin a at radius j, NaN where the bin is skipped;
  • bin_reason::Matrix{Symbol} — :ok, :off_frame (a sample's bilinear taps leave the frame) or :saturated (more than half the bin's samples saturated);
  • statistics — SensorModelNoise() or EmpiricalNoise(), chosen by the frames' type (the provenance); profile_scale::Matrix{Float64} each bin's noise under the sensor model (NaN without one): the median over the bin's meff distinct pixels of the maximum of the N frames' noise, standard error `√v̄ / (2·N·φ(q)·Φ(q)^(N−1)·√meff),q = Φ⁻¹(2^(−1/N)), v̄ the model's variance there (one frame:√(π/2·v̄/meff)`); meff the bin's rows × its cells' arc, from the log-polar map's differential (Core's transform_deriv): its pixels (a column is at most a pixel thick, sharing its pixels with its neighbours);
  • noise::Vector{Float64} — each angle's noise PER PIXEL σ₁ (a bin of meff pixels has σ₁/√meff): the model's (the median over the angle of its bin noise × √meff) or the data's; `modelscatter::Vector{Float64}— with a sensor model, the empirical noise over the model's per angle (≈ 1 when the model holds;NaN` without one);
  • candidates::Vector{Vector{Float64}} — per angle the radii of its candidates;
  • edge, edge_scale::Vector{Float64} — per angle the chosen candidate (NaN where none is an inlier of the coverage) and its standard uncertainty, the drop's noise through the profile's slope;
  • reason::Vector{Symbol} — per angle :ok, :no_candidate (no significant drop) or :no_inlier.

VisualGeometryToolkitFeatures.ContinuousRefinement — Type
ContinuousRefinement(; prefilter_halfwidth, spatial_bound, scale_bound, min_curvature)

The continuous DoG-extremum refinement, opt-in: asift_detect(img; refinement = ContinuousRefinement()) (the detector's default, refinement = nothing, is today's one-step refinement). One recipe: the spatial gradient is Farid and Simoncelli's matched first-derivative filters on the prefiltered slices (IEEE TIP 2004), interpolated by the cardinal cubic spline; the scale row is the cardinal spline of the UNFILTERED slices, Lagrange in scale — so the prefilter sharpens the position and leaves the scale unbiased; the LM's Jacobian is the exact derivative of that gradient. The keywords are the bounds of _refine_dog_extremum; every default is configs/continuousrefinement.toml's (its comments give each derivation). The LM's stop settings are VisualGeometryToolkitCore's, the stack's one owner (StaticLmStops, its [lm] table); `maxiter,convergedtol2andcostfloor` are retired here. An isbits value, so a kernel takes it.
