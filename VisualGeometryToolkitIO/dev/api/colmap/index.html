COLMAP

The COLMAP adapter: the wire records, the unit contract, the model directory reader and writer, the database handle, and the conversion to and from VGC types.

VisualGeometryToolkitIO.MM_PX — Constant

The stack-canonical contract: world in millimeters (image values are pixels).

VisualGeometryToolkitIO.UnitContract — Type
UnitContract(world, density = dpi; lengths = (;))
UnitContract(; world = mm, density = dpi, lengths = (;))
UnitContract(density, lengths::NamedTuple)

world, density and every role's unit are FlexUnits dynamic units (mm, pt, dpi, or parse_unit of a name).

Declares the units a file's magnitudes are expressed in: lengths, a table of LENGTH ROLES, each a named length unit; and density, a unit of pixels per length (dimension 1/length, since a pixel is dimensionless), for print and sensor densities. The role world is REQUIRED and is the default role: the unit of translations, 3D points and every other length. Further roles (pattern = pt) serve a record whose lengths are declared in more than one unit — a board's canvas in mm and its pattern in pt, each written decimal-exactly in its own unit. A field read or written in a role names it (read_quantity(x, :length, c; role = :pattern)). Pixel counts need no declaration: pixels are the only image unit.

In memory the contract is that table, world first: UnitContract(mm, dpi; lengths = (pattern = pt,)).lengths == (world = mm, pattern = pt). The first two forms are conveniences that merge world into the table (the keyword form also reads a world already in lengths; naming it twice is an error); the third is the canonical one and refuses a table without world.

The FILE layout is separate and unchanged: the serialiser alone knows it. Inline fields in vgio JSON records hold "units": {"world": "mm", "density": "dpi", "lengths": {"pattern": "pt"}} — world top level, the other roles under lengths — written by json_value(contract) and read by from_json(UnitContract, d); a vgio_units.json sidecar for COLMAP model directories holds world and density only. Files stay self-describing. The roles are a CLOSED set, the ones the contract declares: an ArgumentError for a missing world, a role that is not a length, a role named density, a role name that is not snake_case, a density that is not pixels per length, and (on use) a role the contract does not declare.

VisualGeometryToolkitIO.UnknownScale — Type
UnknownScale()

The contract of a model whose world has NO unit: a structure-from-motion reconstruction without metric control (PhotoTourism, any plain COLMAP run) is fixed only up to a similarity, so its translations and 3D points are numbers in the reconstruction's own arbitrary scale. Declaring mm or m for them would be false, and nothing declares this either unless someone says so: the caller states it (load(ColmapModel, dir; contract = UnknownScale())), or the model's vgio_units.json sidecar does ("world": "unknown", written by save for such a model). It is never a default.

Under it the wire values stay what they are, plain numbers (ColmapImage.tvec, ColmapPoint3D.xyz), and anything that needs a length unit refuses: rigid_transform(image, contract) (a metric EuclideanMap) and colmap_image(pose, …; contract) (a metric pose written into the model) throw an ArgumentError. What does not depend on scale is read from the wire as usual: the rotation qvec, and translation directions.

VisualGeometryToolkitIO.load_units_sidecar — Method
load_units_sidecar(dir) -> Union{UnitContract, UnknownScale, Nothing}

Read the vgio_units.json sidecar of a COLMAP model directory; nothing if absent (a model produced by other tools — the caller must then declare units explicitly). "world": "unknown" is an UnknownScale model. A v1 sidecar is refused by name: nothing reads a retired version. A sidecar without a density has dpi.

VisualGeometryToolkitIO.role_unit — Function
role_unit(contract::UnitContract, role::Symbol = :world) -> Units

The unit contract declares for the lengths of role: contract.lengths[role]; an ArgumentError listing the declared roles for a role it does not declare. Every read of a contract's length unit goes through it (the unit of :world, the default, included).

VisualGeometryToolkitIO.ColmapCamera — Type
ColmapCamera

One row of COLMAP's cameras table: intrinsics in COLMAP's pixel convention (pixel centers at 0.5), params ordered per the model zoo. Unit-free wire type — magnitudes are px by COLMAP's definition, the only image unit (the contract declares the world unit alone).

source
VisualGeometryToolkitIO.ColmapImage — Type
ColmapImage

One row of COLMAP's images table: the world→camera pose as a wxyz quaternion qvec + translation tvec (world units per contract; plain numbers in the reconstruction's own scale under UnknownScale), plus observed 2D points (x, y, point3D_id) with point3D_id == -1 when untracked.

VisualGeometryToolkitIO.ColmapModel — Type
ColmapModel

A COLMAP model directory's contents plus the unit contract its magnitudes are expressed in: a UnitContract, or UnknownScale for a structure-from-motion model whose world has no unit.

VisualGeometryToolkitIO.load — Method
load(ColmapModel, dir; contract = nothing) -> ColmapModel

Read a COLMAP model directory (binary preferred, text fallback). The unit contract comes from the vgio_units.json sidecar when present; for models produced by other tools supply contract explicitly — refusing to guess units is the point of the sidecar. A structure-from-motion model with no metric scale (PhotoTourism) is contract = UnknownScale(): its translations stay unitless, and metric assembly refuses (see UnknownScale). A caller contract that contradicts the sidecar is refused.

save(dir, model::ColmapModel; format = :binary)

VisualGeometryToolkitIO.keypoints — Method
keypoints(cdb, image_id) -> Matrix{Float32}   (n × cols)

Row i is keypoint i-1 in COLMAP's 0-based match indexing. Columns are x, y[, scale, orientation | affine params] in pixels (COLMAP convention: the origin is the upper-left corner of the upper-left pixel, so the CENTER of the first pixel is (0.5, 0.5)).

VisualGeometryToolkitIO.colmap_image — Method
colmap_image(pose::EuclideanMap{3}, image_id, camera_id, name; contract = MM_PX) -> ColmapImage

COLMAP images hold world→camera poses; a detected object→camera pose is the same direction, with "world" = the object frame. The pose is metric — its translation lengths, written in the contract's world unit (write_length); a plain translation is refused — so an UnknownScale contract, which has no length unit to write it in, is refused.

source
VisualGeometryToolkitIO.colmap_model — Method
colmap_model(lens) -> Union{Symbol, Nothing}

The COLMAP camera model whose function the lens computes — the one colmap_camera writes — or nothing when no COLMAP model computes it (a double sphere, a lift with a numerator, a thin prism on a perspective view). Always a two-focal model; reading a single-focal one (SIMPLE_RADIAL) and writing it back gives the two-focal model of the same function (OPENCV).

source
VisualGeometryToolkitIO.colmap_params — Method
colmap_params(lens, fx, fy, cx, cy) -> Vector{Float64}

The parameter vector of colmap_model(lens), in COLMAP's documented order for that model.

VisualGeometryToolkitIO.rigid_transform — Method
rigid_transform(im::ColmapImage, contract) -> EuclideanMap{3}

Assemble the world→camera pose of a COLMAP image row under the model's unit contract: its translation lengths in metres, read in the contract's world unit (read_length). An EuclideanMap is metric, so under UnknownScale this refuses; the row's qvec and unitless tvec are the pose up to scale.
