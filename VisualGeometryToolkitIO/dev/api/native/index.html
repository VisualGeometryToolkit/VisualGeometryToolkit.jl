VisualGeometryToolkitIO.VisualGeometryToolkitIO — Module
VisualGeometryToolkitIO

File formats for the VisualGeometryToolkit stack. Each vgio/<kind> JSON file is the serialization of one VisualGeometryToolkitCore type: load(T, path) returns a value of type T, and save(path, value) writes one. Both verbs are public but not exported, so call them qualified (import VisualGeometryToolkitIO as VgtkIO; VgtkIO.load(...)).

The package also reads and writes COLMAP models, reads COLMAP databases and OpenCV/MATLAB calibration exports, and exports to TUM, EuRoC, BOP and TRC.

VisualGeometryToolkitIO.read_length — Method
read_length(x::Real, u::Units) -> Quantity

The file number x, written in the length unit u, as a base-form quantity in metres. For a power-of-ten unit (mm, cm, μm, m, km) the conversion shifts the decimal exponent of x, so read_length(62.8, mm) is the metre value nearest the decimal 0.0628 and write_length returns 62.8 exactly; other units (inch, ft, pt) multiply by the unit's scale. Any Float64 crosses — negative, ±0 with its sign, NaN, ±Inf; an integer is read as its Float64. An ArgumentError for a unit that is not a length.

This is the stack's one hand-rolled unit conversion: FlexUnits' own x * u of a float x multiplies by the Float64 of the unit's exact rational scale, one ulp off the decimal for about one number in seven. It is removed — read_length(x, u) becoming base_quantity(x * u) — when FlexUnits applies a rational scale to a float as x * num / den, rounded once (Deduction42/FlexUnits.jl#131).

VisualGeometryToolkitIO.write_length — Method
write_length(q::Quantity, u::Units) -> Float64

The number a file holds for the length q in the unit u, the inverse of read_length: write_length(read_length(x, u), u) prints as x for every x of at most 15 significant digits, and read_length of the result is q itself whenever any file number reads back to it. When none does (a full-precision metre value computed in code, about one in eight in millimetres), the number written reads back as q's PERSISTED value, its metre value at 15 significant digits (the value content_id hashes): either way the length, the file written from it and the length loaded back have one identity, and a rewrite is byte for byte (IO 0.10.1; 0.10.0 wrote the nearest number, an ulp off, whose identity could differ). A power-of-ten unit shifts the decimal exponent of the metre value; any other unit takes the fewest significant digits (1 to 17) that read_length maps back to the identical q. NaN and ±Inf are written as they are. An ArgumentError for a unit that is not a length, or a quantity that is not one.

The search is not a conversion and stays: FlexUnits' ustrip(u, q), even correctly rounded, gives back the file's own number for only about three quarters of decimal file numbers, since the stored metre value is on a different grid; write_length returns the number that reads back to q.

StructUtils.lower — Function
JSON.lower(s::VgioStyle, f::FeatureFrame[, tags])
JSON.lower(s::VgioStyle, u::Uncertain{<:FeatureFrame})
JSON.lift(s::VgioStyle, F::Type{<:FeatureFrame}, x[, tags])
JSON.lift(s::VgioStyle, Uncertain{F}, x)

THE frame codec, one over VisualGeometryToolkitCore's FeatureFrame interface: a frame is {"center": [x, y]} and its shape — a PointFrame nothing, a Disc "sigma", an OrientedDisc "sigma" and "angle" (radians), an EllipticFrame "shape_matrix" and an AffineFrame "affine_matrix", each in rows. Its numbers are plain (pixel coordinates in the file's pixel frame) or quantities under the field's tags ((; quantity = :length[, role])). The lift builds F's element type (PointFrame{Float32} reads Float32; a type without one plain Float64).

An uncertain frame adds its "covariance": the frame's frame_dof × frame_dof covariance over its parameters, the centre (x, y) first, in the storage it holds (rows, {"diagonal": […]}, {"isotropic": λ}); a PointFrame's is the uncertain point's 2×2. Its entries are the frame's own numbers' (px², never converted): an uncertain frame holds plain numbers. A covariance of another size, a non-finite one (a detection states why it has none: vgio/detection's covariance_status) and a labeled one are an ArgumentError. A precision form is written as its covariance and reads back as one.

julia> import JSON

julia> s = VgtkIO.VgioStyle();

julia> JSON.json(OrientedDisc(1.0, 2.0, 3.0, 0.5); style = s)
"{\"center\":[1.0,2.0],\"sigma\":3.0,\"angle\":0.5}"

julia> u = Uncertain(PointFrame(10.5, 20.25), CovMat{2, Float64}(0.5, 0.0, 0.0, 0.25));

julia> JSON.json(u; style = s)
"{\"center\":[10.5,20.25],\"covariance\":[[0.5,0.0],[0.0,0.25]]}"

julia> JSON.lift(s, Uncertain{PointFrame{Float64}}, JSON.parse(JSON.json(u; style = s))) == u
true

StructUtils.lower — Method
JSON.lower(s::VgioStyle, r::Union{RegionIntersection, WholePlane})
JSON.lower(s::VgioStyle, r, (; region = true))
JSON.lift(s::VgioStyle, T, x)

THE region body: a 2-D region of VisualGeometryToolkitCore's — a Rect2, an Ellipse, a Circle, their RegionIntersection (nested to any depth) or the WholePlane — as one tagged object,

{"rect": [x, y, w, h]} | {"ellipse": [cx, cy, a, b, θ]} | {"circle": [cx, cy, r]}
  | {"intersection": [<region>, <region>]} | {"whole_plane": {}}

its leaves the positional records a Rect2, Ellipse and Circle are written as everywhere (extents positive, an ellipse's major semi-axis first, θ in radians), an intersection Core's binary one with its two parts in order (nest one for more). The numbers are PIXELS in the file's units.pixel frame: the writer moves the region from Core's canonical frame into the style's pixel frame and the reader back, by Core's action of the pixel-frame map on every region. A camera's lens_coverage is this body restricted to its leaves.

An intersection or the whole plane is lowered by the two-argument form; a leaf lowers to its positional record there, so a field that holds any region asks for the region body by the tag (; region = true) (which an intersection and the whole plane take too). The lift reads the body from an object (a leaf's positional record is an array) into T, a region type or a Union of them (Union{Rect2, RegionIntersection}, …); a region of another type is an ArgumentError. A parsed record is checked first (an unknown tag, an intersection of other than two regions, a degenerate leaf: an ArgumentError naming its place), and an intersection is read as stored, through RegionIntersection's constructor (never ∩, which folds two rectangles into one), so the value reads back with its type.

s = VgtkIO.VgioStyle()
r = RegionIntersection(Rect2(0.0, 0.0, 1920.0, 1200.0), Ellipse(Point2(960.0, 600.0), 700.0, 650.0, 0.0))
JSON.json((initial_region = r,); style = s)
# {"initial_region":{"intersection":[{"rect":[0.0,0.0,1920.0,1200.0]},{"ellipse":[960.0,600.0,700.0,650.0,0.0]}]}}
JSON.lift(s, typeof(r), JSON.parse(JSON.json(r; style = s))) == r     # true

VisualGeometryToolkitIO.VgioStyle — Type
VgioStyle(; length_unit = mm, pixel_frame = PixelFrame{:colmap}, density = dpi, length_roles = (;)) <: JSON.JSONStyle
VgioStyle(contract::UnitContract; pixel_frame = PixelFrame{:colmap})
VgioStyle(record) -> VgioStyle

VisualGeometryToolkitIO's serialization style: every VGC value a vgio/<kind> record embeds is written by a JSON.lower(::VgioStyle, x) method and read by a JSON.lift(::VgioStyle, T, record) method (StructUtils' lower and lift, the JSON.JSONStyle hooks), on this style only. It carries the file's units declaration: a UnitContract (its length unit, every lengths in decimal-exact through write_length and read_length, its further length roles and its density) and the pixel_frame its pixel coordinates are written in. The writer takes it as JSON.json(x; style = VgioStyle(…)); every file's units object is the style's (length the contract's world unit, length_roles its further roles, density, and pixel the pixel frame), which write_record writes into the envelope.

VgioStyle(record) is the style a parsed record's units object declares (the reader's: a record a package of its own reads with read_record), the record read by property access (a JSON.Object or a NamedTuple).

A package serializing a kind of its own embeds VGC values the same way (a pose, a CameraModel, a target with its calibration, a layout, an Ellipse); a lift reads a parsed JSON.Object or a NamedTuple:

julia> import JSON

julia> s = VgtkIO.VgioStyle(; length_unit = mm);

julia> e = Ellipse(Point2(1.0, 2.0), 3.0, 1.0, 0.5);

julia> JSON.json((domain = e,); style = s)
"{\"domain\":[1.0,2.0,3.0,1.0,0.5]}"

julia> JSON.lift(s, Ellipse, JSON.parse(JSON.json(e; style = s))) == e
true

VisualGeometryToolkitIO.lattice_from_json — Method
lattice_from_json(record, ::Val{K}; name, length_unit = nothing) -> (; spline::ChartSpline{K}, present)

The lattice a lattice record states (the inverse of lattice_json): spline the ChartSpline of its K-vector controls name over its area, NaN in the nodes the record does not hold (no evaluation reads one), and present its presence mask ([gy, gx]), or nothing when the record holds every node. With length_unit the controls are lengths in that unit, read as plain metres, decimal-exactly. record is a Record or a parsed AbstractDict; it is validated first — exactly its keys, a finite area of positive widths, at least 4 × 4 nodes, the runs inside the lattice and apart, one K-vector control per held node — each problem an ArgumentError naming it (what, the record's name in the message).

VisualGeometryToolkitIO.lattice_json — Method
lattice_json(spline::ChartSpline; name, present = nothing, length_unit = nothing) -> NamedTuple

A uniform cubic B-spline lattice — VisualGeometryToolkitCore's ChartSpline, its K-vector controls over a rectangle of a chart — as THE lattice record, the one every spline is stored in (a SplineLens's backward and forward splines, a non-central model's, RadiometricCamera's aperture spline):

{"area": [x, y, w, h], "grid_size": {"width": gw, "height": gh},
 "present": [[row, [[col_lo, col_hi], …]], …],     (optional) the held nodes; absent = every node
 "controls": {"<name>": [[c₁, …, c_K], …]}}        the held nodes' controls, row by row

area is the spline's rectangle, grid_size its lattice (columns, rows). present (a Bool matrix of the lattice's size, [gy, gx], Core's presence mask; nothing: every node) is written as runs per lattice row, 1-based (the file's index_base) and inclusive, and only the held nodes' controls are written, under name (:direction, :point, :radius, …). The controls are written as they are (JSON's shortest round-trip floats, so a Float64 spline reads back bit for bit), or, with length_unit, as lengths: plain metres in memory, the file's numbers in that unit through write_length's decimal shift. lattice_from_json reads it back.

julia> rec = (area = [0.0, 0.0, 1.0, 1.0], grid_size = (width = 4, height = 4), controls = (radius = fill([2.0], 16),));   # radii, in mm

julia> L = VgtkIO.lattice_from_json(rec, Val(1); name = :radius, length_unit = mm); L.spline.controls[1, 1][1]   # metres
0.002

julia> VgtkIO.lattice_json(L.spline; name = :radius, length_unit = mm) == rec
true

VisualGeometryToolkitIO.read_record — Method
read_record(path; allownan = false) -> JSON.Object
read_record(io::IO; allownan = false) -> JSON.Object

The record a JSON file (or the JSON text io holds) is, as its kind's CURRENT record: parsed (a JSON.Object, read by property access — the form JSON.lift(::VgioStyle, T, record) takes) and, when its schema is an earlier version that a schema owner's version steps read (migrate_schema), run through them by migrate_record in memory; the file is not rewritten. VisualGeometryToolkitIO.validate — Method
validate(path) -> String

Check a vgio file — or a COLMAP model directory's vgio_units.json, when path is the directory — against its kind's table (the envelope's schema, generator, units and conventions, then the body), the check every reader runs before using a field and every writer runs before writing, and return the kind ("cameras", "rig", …). VisualGeometryToolkitIO.write_record — Method
write_record(path, record; style = VgioStyle(), allownan = false)

Write record — a NamedTuple or AbstractDict, the record of a kind a package owns, its VisualGeometryToolkitCore values left for style to lower — as a JSON file in the shape every vgio file has (pretty-printed, a four-space indent, no trailing newline), with the envelope every vgio file has: its schema first ("<owner>/<kind>/v<major>.<minor>", the record's own), then the generator (VisualGeometryToolkitIO and the calling package, with_caller), the units object style declares (its length unit and roles, density and pixel frame) and the fixed conventions, then the record's other keys in their order. A kind's owner writes its records with this and reads them with read_record (VgioStyle(record) is the style its units declare); this function checks no kind's fields.

VisualGeometryToolkitIO.colmap_cameras — Method
colmap_cameras(cameras::AbstractDict{Symbol}) -> (cameras::Vector{ColmapCamera}, ids::Dict{Symbol, Int})

Project a camera store onto COLMAP camera rows, for feeding a ColmapModel. Ids are assigned 1..n in name order.

TWO LOSSES, both deliberate and both surfaced rather than papered over:

  1. Names do not survive. COLMAP has no camera name field, so the identity a config refers to is gone on the far side. The returned ids map is the remainder — persist it beside the model if anything downstream needs to get back to a name.
  2. Inexpressible cameras throw. A lens no COLMAP model computes has no colmap_model, and that ArgumentError is the correct outcome — a silently dropped or approximated lens model is worse than a failed export. Filter first if a partial export is what you want: filter(p -> colmap_model(lens(last(p))) !== nothing, cameras).

VisualGeometryToolkitIO.load — Method
load(BoundedCamera, path; name = nothing, file_unit = nothing, intrinsics = nothing) -> BoundedCamera
load(CameraModel,  path; name = nothing) -> CameraModel

Read ONE camera from a vgio/cameras/v6.0 store — the bounded camera, or just its model (its calibration_record, if any, is the store's to read). VisualGeometryToolkitIO.content_id — Method
content_id(targets) -> String

The identity an observations file (vgio/observations, target_homographies) names a target definition by — targets a Rig, a single unposed AbstractTarget (Attributed ones by their target), or a vgio/rig or vgio/target path (any version that reads): the SHA-256 (lowercase hex) of the RFC 8785 (JCS) serialization (VisualGeometryToolkitCore's canonical_json) of its IDENTITY TREE.

VisualGeometryToolkitIO.target_calibration_json — Method
target_calibration_json(s::VgioStyle, c) -> NamedTuple

A planar target's calibration c — VisualGeometryToolkitCore's TargetCalibration (Rigid, a planar EuclideanMap, Scale, Aspect, Skew, ThinPlateSpline, HeightField or a composition of them in Core's canonical order), or an Uncertain one — as the calibration record every target body embeds (its calibration), on IO's style s: the PARAMETRIC RECORD {"type", ["nodes"], ["parameters"]}, its kind's tag in Core's TARGET_CALIBRATION_TAGS, its parameter_vector with every length (by length_mask) in the style's length_unit through write_length's decimal shift, a thin-plate kind's nodes beside them (lengths too); a composition {"type": "composition", "compose": [outer, …, inner]}; an Uncertain one its covariance beside, covariance, each entry in the unit raised to its length dimension. target_calibration_from_json reads it back ==.

VisualGeometryToolkitIO.save_panorama — Function
save_panorama(path, camera::BoundedCamera, rotations::Trajectory, vignetting, gains, fit = nothing;
              length_unit = mm, provenance = (;))

Write a panorama's results — the camera of a sweep that only rotated, its frames' rotations, its vignetting and its frames' exposure gains (PanoramaStitching's) — as a vgio/panorama/v2.0 file, each through the body another kind writes: the camera store's bounded camera body (K, lens, a sensor's pitch in length_unit, its lens coverage), the trajectory body (rotations: per frame index its pose from → to, its image and time where the trajectory has them) and the vgio/vignetting body, positions in the canonical (colmap) pixel frame. The rotations map the camera to the world (Trajectory{CameraFrame, WorldFrame}) and every pose's translation is a zero length: other frames, a translation that is not zero (the camera only rotates) and a plain one (attach its unit, EuclideanMap(R, zeros(3) .* m)) are an ArgumentError, nothing written.

vignetting is an AbstractVignetting, or nothing: a panorama with no Core vignetting (a candidate with no correction, or one of its own — a sampled map, a flat field's binned radial profile, vgio/radial_profile), which writes none and reads back nothing.

fit is the bundle's FitResult (any estimate and metadata: only its termination record is written — retcode, stop_rule, iterations, rms, n, the stack's one record, _FIT_RECORD) or nothing (none recorded).

gains is nothing (every frame at one exposure) or a K × C matrix, gains[k, c] the exposure gain of frame index k in colour plane c (PanoramaStitching's fit_vignetting metadata.gains), every one positive; the rotations' frame indices are then 1:K. Numbers of a narrower type (Float32) are written exactly. load_panorama reads the file back.

VisualGeometryToolkitIO.read_tiff — Method
read_tiff(T, path) -> Matrix{T}

The grey image of the TIFF at path (its first image), as (rows, columns), the first row on top, read through libtiff: T is UInt8 for an 8-bit unsigned image and Float32 for a 32-bit IEEE floating-point one (every value bit for bit, NaN included). The file holds one sample per pixel, min-is-black or — an 8-bit image only, as pdftocairo -gray may write it — min-is-white, which is returned inverted (0xff - v), so a value is always the grey level with black

  1. Any compression and predictor libtiff decodes is read. A file of another

sample type, more than one sample per pixel, or a min-is-white Float32 image is an ArgumentError naming it; a libtiff failure an error. The reader of write_tiff's files and of load_raster's payload.

VisualGeometryToolkitIO.write_tiff — Method
write_tiff(path, image::AbstractMatrix{T}; compression = :none, predictor = :none, rows_per_strip = 64,
           density = nothing, software = nothing, icc = nothing) -> path

Write a grey image — T is UInt8 (8 bits, unsigned) or Float32 (32 bits, IEEE floating point, every value bit for bit, NaN included) — as a little-endian TIFF of one image, one sample per pixel (min-is-black), in strips of rows_per_strip rows, through libtiff. image is (rows, columns), the first row on top. compression is :none, :lzw or :deflate (zlib), all lossless; predictor :none or :horizontal (row differences, which make a smooth image compress; a compression's, so not with :none). Optional tags: density, a pixel density (300dpi), in the resolution tags (pixels per inch); software, a string; icc, an ICC profile's bytes, embedded. Nothing else is written.

The stack's one TIFF writer: BlobBoards' board TIFFs (8-bit, LZW with the horizontal predictor, its density and profile) and the payload of a vgio/raster/v1 file (save_raster: Float32, uncompressed or Deflate, no tag that means anything) are written by it. A libtiff failure — a path it cannot open, a full disk — is an error naming the file; read_tiff reads the image back.

VisualGeometryToolkitIO.load_raster — Method
load_raster(path) -> (; values::Matrix{Float32 | UInt8}, frame, nan::Symbol)

Read a vgio/raster/v2.0 file (save_raster's; a v1 file through its step): the header is validated, the TIFF it names (beside it) must hash to the header's SHA-256 — a corrupted or replaced payload is an ArgumentError naming it, before it is decoded — and must be of the raster profile for its element type and of the header's size. values is (rows, columns), every value as stored, NaN bit for bit; frame the header's, (chart, area) with area a Rect2{Float64} in plain metres, or the PixelFrame type the file declares; nan :unobserved or :none (a NaN in a :none raster is refused).

VisualGeometryToolkitIO.save_raster — Method
save_raster(path, values::AbstractMatrix{Float32 | UInt8}; frame, nan, length_unit = mm, compression = :deflate,
            provenance = (;)) -> path

Write a raster as a vgio/raster/v2.0 file: the JSON header at path and the values beside it, <name>.tiff (path's name with its extension replaced), a TIFF of the raster profile (one image, one sample per pixel — a 32-bit IEEE float or an unsigned byte —, little-endian, in strips, compression :deflate or :none, both lossless, and no predictor), so every value — NaN included — reads back bit for bit. The header states the raster's size ({width, height}: its columns and rows), its element type, its frame, what a NaN means and the SHA-256 of the TIFF's bytes; nothing the values mean is in the TIFF's tags. values is (rows, columns), row 1 on top.

  • frame, required: a chart rectangle, (chart = :page, area = Rect2(x, y, w, h)) (or chart = :texture; the design chart, x right and y up, area its lower-left corner and widths in plain metres, written in length_unit) — row 1 its top edge — or a pixel frame, PixelFrame{:colmap} — values[r, c] the image's pixel at row r, column c (the file's units.pixel).
  • nan, required: :unobserved (a NaN is a value nothing observed) or :none (the raster holds no NaN: one is refused; a UInt8 raster's).

Both files are written through a staging directory beside them and renamed into place once the TIFF has been checked against the profile and the header validated (write_staged); load_raster reads them back.
