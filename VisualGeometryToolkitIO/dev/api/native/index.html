VisualGeometryToolkitIO.VisualGeometryToolkitIO — Module
VisualGeometryToolkitIO

File formats for the VisualGeometryToolkit stack. Each vgio/<kind> JSON file is the serialization of one VisualGeometryToolkitCore type: load(T, path) returns a value of type T, and save(path, value) writes one. Both verbs are public but not exported, so call them qualified (import VisualGeometryToolkitIO as VgtkIO; VgtkIO.load(...)).

The package also reads and writes COLMAP models, reads COLMAP databases and OpenCV/MATLAB calibration exports, and exports to TUM, EuRoC, BOP and TRC.

VisualGeometryToolkitIO.read_length — Method
read_length(x::Real, u::Units) -> Quantity

The file number x, written in the length unit u, as a base-form quantity in metres. For a power-of-ten unit (mm, cm, μm, m, km) the conversion shifts the decimal exponent of x, so read_length(62.8, mm) is the metre value nearest the decimal 0.0628 and write_length returns 62.8 exactly; other units (inch, ft, pt) multiply by the unit's scale. Any Float64 crosses — negative, ±0 with its sign, NaN, ±Inf; an integer is read as its Float64. An ArgumentError for a unit that is not a length.

This is the stack's one hand-rolled unit conversion: FlexUnits' own x * u of a float x multiplies by the Float64 of the unit's exact rational scale, one ulp off the decimal for about one number in seven. It is removed — read_length(x, u) becoming base_quantity(x * u) — when FlexUnits applies a rational scale to a float as x * num / den, rounded once (Deduction42/FlexUnits.jl#131).

source
VisualGeometryToolkitIO.write_length — Method
write_length(q::Quantity, u::Units) -> Float64

The number a file holds for the length q in the unit u, the inverse of read_length: write_length(read_length(x, u), u) prints as x for every x of at most 15 significant digits, and read_length of the result is q itself whenever any file number reads back to it (a full-precision metre value may have none in millimetres; the nearest is written, within an ulp). A power-of-ten unit shifts the decimal exponent of the metre value; any other unit takes the fewest significant digits (1 to 17) that read_length maps back to the identical q. NaN and ±Inf are written as they are. An ArgumentError for a unit that is not a length, or a quantity that is not one.

The search is not a conversion and stays: FlexUnits' ustrip(u, q), even correctly rounded, gives back the file's own number for only about three quarters of decimal file numbers, since the stored metre value is on a different grid; write_length returns the number that reads back to q.

VisualGeometryToolkitIO.from_json — Method
from_json(T, d, contract::UnitContract; kind, role = :world)
from_json(UnitContract, d)

The value of type T a JSON record holds as d (a parsed JSON.Object, any dictionary with string keys, or a NamedTuple), the inverse of json_value: T is Size2, PointFrame, Disc, OrientedDisc, EllipticFrame, AffineFrame or a detection type (VisualGeometryToolkitCore's AbstractDetection, or VisualGeometryToolkitFeatures' Detection). kind, required and never defaulted, declares what the numbers of a Size2 or a Disc are — :plain (plain numbers), :length, :pixel — and is read through read_quantity (a length in the unit of the contract's length role); the other frames hold plain numbers (kind = :plain). Every quantity is a number: a {"value": v, "unit": u} object is refused. A detection's frame type is read off its keys (A, S, θ, a PointFrame for a center alone, else a Disc); its documented metadata fields (response, edge_score, laplacian_scale_score) come first, as Float64, and the others follow sorted by name, each as it was parsed (a Symbol was written as a string and reads back a string, a Point2 as a two-number array); a cov makes the frame Uncertain again, and so does a point frame's covariance (a null one the NaN 2×2). The frames read back in Float64: a Float32 frame is written exactly and reads back as the same numbers in Float64.

from_json(UnitContract, d) reads a record's "units" declaration; a declaration without a density has dpi, one without lengths no further length roles.

julia> import JSON

julia> VgtkIO.from_json(Size2, JSON.parse("{\"width\": 640, \"height\": 480}"), MM_PX; kind = :pixel) ==
           Size2(width = 640px, height = 480px)
true

julia> VgtkIO.from_json(UnitContract, JSON.parse("{\"world\": \"m\"}")) == UnitContract(world = m)
true

VisualGeometryToolkitIO.json_value — Method
json_value(x, contract::UnitContract; kind, role = :world)
json_value(contract::UnitContract)

The plain value (a NamedTuple of numbers, arrays and strings, which JSON.jl's JSON.json writes) a JSON record holds for x under contract, its quantities as numbers in the declared units (write_quantity); read it back with from_json. Defined for VisualGeometryToolkitCore's Size2 ({"width": w, "height": h}), PointFrame ({"center": [x, y]}, plain pixels), Disc ({"center": [x, y], "σ": s}), OrientedDisc (… "θ": angle), EllipticFrame ({"center": …, "S": [S11, S21, S12, S22]}, column order), AffineFrame (… "A": …) and a detection — an Attributed feature frame, VisualGeometryToolkitCore's AbstractDetection — written as its frame under frame, an Uncertain frame's covariance entries (column order) under cov (null when not finite, with the matrix's size N under cov_size: the size is the value's, an ASIFT EllipticFrame's covariance is 3×3), and each metadata field under its own name. An uncertain PointFrame (VisualGeometryToolkitFeatures' Förstner detections) writes its 2×2 covariance as an uncertain point does (vgio/target_points2d's covariance: rows, {"diagonal": […]} or {"isotropic": λ}, the storage it holds; null when not finite), the one encoding of a point and its covariance.

kind, required, declares what the numbers of the value are — :plain (plain numbers), :length or :pixel — the same kind its reader gives from_json. A value holding a number of another kind, and a quantity in a detection's metadata (it has no declared kind), are an ArgumentError. The OrientedDisc, EllipticFrame and AffineFrame hold plain numbers only (kind = :plain). The lengths of a Size2 or a Disc are written in the unit of the contract's length role (:world by default).

json_value(contract) is the record's declaration of its units, (world = "mm", density = "dpi") for MM_PX, with lengths = (pattern = "pt", …) when the contract declares further length roles (registered unit names; an ArgumentError for a unit without one).

julia> import JSON

julia> JSON.json(VgtkIO.json_value(Size2(width = 640px, height = 480px), MM_PX; kind = :pixel))
"{\"width\":640,\"height\":480}"

julia> JSON.json(VgtkIO.json_value(Disc(Point2(1.0mm, 2.0mm), 3.0mm), UnitContract(world = m); kind = :length))
"{\"center\":[0.001,0.002],\"σ\":0.003}"

julia> VgtkIO.json_value(MM_PX)
(world = "mm", density = "dpi")

julia> VgtkIO.json_value(UnitContract(world = mm, lengths = (pattern = pt,)))
(world = "mm", density = "dpi", lengths = (pattern = "pt",))

read_quantity(x, kind::Symbol, contract::UnitContract; role = :world) -> Quantity

VisualGeometryToolkitIO.write_quantity — Method
write_quantity(q::Quantity, contract::UnitContract; role = :world) -> Real

The number a JSON record holds for the quantity q under contract: a length in the unit of the contract's length role (:world is the default role, a named role's otherwise; through write_length, decimal-exact), a pixel count (a dimensionless quantity: px is dimensionless) as its number of pixels, a density in contract.density. VisualGeometryToolkitIO.VgioStyle — Type
VgioStyle(; length_unit = mm, pixel_frame = PixelFrame{:colmap}) <: JSON.JSONStyle

VisualGeometryToolkitIO's serialization style: every VGC value a vgio/<kind> record embeds is written by a JSON.lower(::VgioStyle, x) method and read by a JSON.lift(::VgioStyle, T, record) method (StructUtils' lower and lift, the JSON.JSONStyle hooks), on this style only. It carries what the enclosing file declares for the value — the length_unit its lengths are written in (decimal-exact, through write_length and read_length) and the pixel_frame its principal points are written in — and the writer takes it as JSON.json(x; style = VgioStyle(…)).

A package serializing a kind of its own embeds VGC values the same way (a pose, a CameraModel, a target with its calibration, a layout, an Ellipse); a lift reads a parsed JSON.Object or a NamedTuple:

julia> import JSON

julia> s = VgtkIO.VgioStyle(; length_unit = mm);

julia> e = Ellipse(Point2(1.0, 2.0), 3.0, 1.0, 0.5);

julia> JSON.json((domain = e,); style = s)
"{\"domain\":[1.0,2.0,3.0,1.0,0.5]}"

julia> JSON.lift(s, Ellipse, JSON.parse(JSON.json(e; style = s))) == e
true

VisualGeometryToolkitIO.read_record — Method
read_record(path; allownan = false) -> JSON.Object
read_record(io::IO; allownan = false) -> JSON.Object

The record a JSON file (or the JSON text io holds) is, as its kind's CURRENT record: parsed (a JSON.Object, read by property access — the form JSON.lift(::VgioStyle, T, record) takes) and, when its schema is an earlier version that a schema owner's version steps read (migrate_schema), run through them by migrate_record in memory; the file is not rewritten. A step's refusal (an ArgumentError, or a key its version always held missing) is an ArgumentError naming the file and its schema. VisualGeometryToolkitIO.validate — Method
validate(path) -> String

Check a vgio v2 file — or a COLMAP model directory's vgio_units.json, when path is the directory — against its kind's table, the check every v2 reader runs before using a field and every writer runs before writing, and return the kind ("cameras", "rig", …). An ArgumentError names the file, the offending key and the problem. A file of an earlier version is checked as the current record its version steps give (as load reads it); a version no step reads is refused by name, a retired kind with its successor. Semantic checks that need more than the one file — that measurements resolve in their targets — are the exporters'.

with_provenance(body::NamedTuple, provenance::NamedTuple) -> NamedTuple

A record's body with the writer's free-form provenance (the provenance keyword of every save), as the writers store it: body itself when provenance is empty, else body with the field provenance appended (the last key). VisualGeometryToolkitIO.write_record — Method
write_record(path, record; style = VgioStyle(), allownan = false)

Write record — a NamedTuple or AbstractDict, the record of a kind a package owns, its VisualGeometryToolkitCore values left for style to lower — as a JSON file in the shape every vgio file has (pretty-printed, a four-space indent, no trailing newline). Every VGC value in it is written by its JSON.lower(::VgioStyle, x) method on style, which carries the declarations the file makes (its length_unit and pixel_frame). The text is parsed back before it is written, and a NaN or ±Infinity is refused naming its field, as a vgio file's is; allownan = true writes one as JSON.jl's NaN / Infinity instead (a run report's statistic over nothing), for read_record(path; allownan = true).

A kind's owner writes its records with this and reads them with read_record. The record states its own schema ("<owner>/<kind>/v<n>"); this function writes what it is given and checks no kind's fields.

VisualGeometryToolkitIO.pose_from_json — Method
pose_from_json(p, unit::AbstractString) -> EuclideanMap{3} | Uncertain

pose_json's inverse: an embedded {rotation, translation[, covariance]} read in the file's length unit (a unit name), returned UNLABELED, its translation lengths in metres (read_length) — Uncertain iff a covariance is stated, its translation block in m² and its cross block in m·rad. VisualGeometryToolkitIO.pose_json — Function
pose_json(X, unit = mm) -> NamedTuple

A physical pose — a VGC EuclideanMap{3} whose translation is lengths, or an Uncertain one, any labels — as the embedded {rotation, translation[, covariance]} of every pose-carrying kind: the rotation a w-x-y-z quaternion with w ≥ 0 (a QuatRotation's own, exactly; any other rotation converted, reading back as a QuatRotation), the translation in the length unit (write_length), the 6×6 covariance (over [δω; δt], rad and unit) iff Uncertain. Its frames are not written: they are given by where it sits. A plain translation is an ArgumentError (attach its unit, EuclideanMap(rotation(X), t .* m)). The inverse is pose_from_json.

VisualGeometryToolkitIO.colmap_cameras — Method
colmap_cameras(cameras::AbstractDict{Symbol}) -> (cameras::Vector{ColmapCamera}, ids::Dict{Symbol, Int})

Project a camera store onto COLMAP camera rows, for feeding a ColmapModel. Ids are assigned 1..n in name order.

TWO LOSSES, both deliberate and both surfaced rather than papered over:

  1. Names do not survive. COLMAP has no camera name field, so the identity a config refers to is gone on the far side. The returned ids map is the remainder — persist it beside the model if anything downstream needs to get back to a name.
  2. Inexpressible cameras throw. A lens no COLMAP model computes has no colmap_model, and that ArgumentError is the correct outcome — a silently dropped or approximated lens model is worse than a failed export. Filter first if a partial export is what you want: filter(p -> colmap_model(lens(last(p))) !== nothing, cameras).

VisualGeometryToolkitIO.load — Method
load(Dict{Symbol, BoundedCamera}, path; intrinsics = nothing) -> Dict{Symbol, Union{BoundedCamera, Attributed{<:BoundedCamera}}}

Read a vgio/cameras/v5 store: name → BoundedCamera of a CameraModel (its K moved from the file's declared pixel frame into the canonical one), an Attributed one where the file states the camera's calibration block. A v1–v4 store is read through its version steps (migrate_record), and a central vgio/generic_camera/v2 or v3 file as the store of its one camera, named after the file's basename (fisheye_14mm.json → :fisheye_14mm; a CameraModel with a SplineLens: noncentralsplineschema.jl).

VisualGeometryToolkitIO.load — Method
load(BoundedCamera, path; name = nothing, file_unit = nothing, intrinsics = nothing) -> BoundedCamera
load(CameraModel,  path; name = nothing) -> CameraModel

Read ONE camera from a vgio/cameras/v5 store — the bounded camera, or just its model (its calibration block, if any, is the store's to read). Without name the store must hold exactly one camera: a multi-camera store is REFUSED with the available names rather than defaulting to the first — which camera a run uses is an identity, and silently guessing it is how a config ends up calibrated for the wrong lens while reporting success.

The grid cameras of Schöps et al. read through the same call, by the file's content: a central vgio/generic_camera/v2 or v3 file as its camera with a SplineLens (its nominal pinhole the K, else the lattice's gauge; its domain the lens coverage), a vgio/noncentral_spline record (or an old non-central vgio/generic_camera/v2/v3 file, through its steps) as a BoundedCamera{<:NoncentralSplineModel}, and the reference implementation's intrinsics0.yaml as either (schoeps.jl; a non-central YAML's point_grid unit is the caller's file_unit). Old grid files are read, never rewritten.

load(CameraModel, path) refuses a camera whose lens coverage is not its whole sensor (an image circle, an old grid file's domain) rather than drop it: load the BoundedCamera.

VisualGeometryToolkitIO.save — Method
save(path, cameras::AbstractDict{Symbol}; length_unit = mm, provenance = (;))

Write a camera store — name → BoundedCamera of a CameraModel, or an Attributed one carrying its calibration block — as a vgio/cameras/v5 file, cameras sorted by name. A camera bounded by its physical Sensor carries the sensor's pitch in length_unit, which the file then declares. provenance is the file's one free-form object, which VGIo never reads back.

content_id(targets) -> String

The identity a measurement file (target_points2d, target_points3d, target_homographies) names a target definition by — targets a Rig, a single unposed AbstractTarget (Attributed ones by their target), or a vgio/rig or vgio/target path (any version that reads): the SHA-256 of the canonical JSON (canonical_json) of the rig's IDENTITY TREE. The tree is built from the in-memory value by the record writer's own walk, under the fixed names below — names of the identity's own, which a later record format must keep mapping to — every length in metres (base units), the targets sorted by id, and no schema version, declaration or provenance. The identity therefore does not change when the file format does: a rig, every file written from it in any decimal length_unit, the rig loaded back from such a file, and a migration of the file to the next rig version have one identity. A relabeled provenance does not change it; a target's calibration kind, its parameters, its covariance its board and its canvas (with its texture reference) do. A planar target built from a layout (layout(t), written as a layout record) enters by its nominal points, as a target given by its points does: the layout is not hashed, so a layout file and a nominal file of the same design name one target, and a target of no layout has the identity it had before layouts existed.

The identity is of the persisted representation; a value and the file written from it hash equal by construction. Every length enters as the number a file in millimetres holds for it and reads back as (read(write(x)), idempotent), so a quantity built in code as v * mm, which sits an ulp from the nearest decimal of v, hashes as the file written from it. A pose's rotation enters as the quaternion the writer stores (one conversion, shared by the writer and the tree: w-x-y-z, w ≥ 0; a QuatRotation as held, any other rotation converted once), so a rig held with RotMatrix poses, the file written from it and the rig loaded back have one identity. A rotation converted matrix → quaternion → matrix is not bit-exact, so two in-memory rigs built from the same matrix by different routes can differ in the last ulp, and so can their identities: mint an identity from what you save. Lengths likewise: a decimal unit (mm, cm, m, μm) holds every metre value exactly, so its files share the value's identity; a non-decimal unit (inch) is exact only for numbers born in it, so an inch file of mm-born numbers reads back within an ulp and its identity differs from the value's.

A single target's identity is the SHA-256 of its target record below alone (the same record a rig's identity holds under each "target"), so a target's id is that of the file save wrote and load reads back, and differs from every rig's (a rig's tree has frame). A PosedTarget is an ArgumentError.

The identity tree, fixed (a test pins it for a rig of every target kind):

rig        {"frame": <frame name>,
            "sensors": [{"id", "camera", "extrinsics": <pose>}, …]  (iff sensors, in rig order),
            "targets": [{"id", "target", "pose": <pose>}, …]        (iff targets, sorted by id)}
pose       {"rotation": [w, x, y, z] (Hamilton, w ≥ 0), "translation": [m, m, m],
            "covariance": 6×6 rows over [δω; δt], rad and m       (iff Uncertain)}
camera     {"intrinsics": [fx, fy, cx, cy, skew] (px, the canonical pixel frame),
            "extent": [width, height] (px),
            "lens": VGC's lens_record of the lens, its stages in sequence under "chain" in application
                    order (the inner stage first); a SplineLens's spline record
                    {"spline": {"area", "grid_size", "present"?, "controls", "forward"?}}
            | "noncentral_spline": a non-central grid camera's spline record {"area", "grid_size", "present"?,
                    "directions", "points": [[m, m, m], …]},
            "pitch": [m, m]                                                   (iff bounded by its sensor),
            "lens_coverage": {"circle" | "ellipse" | "rect": […]} (px)       (iff not the whole sensor)}
target     {"kind": "points", "points": [[m, …], …], "point_covariances": per point d×d rows, m² (iff Uncertain)}
         | {"kind": "planar", "reference": <id> | "nominal": [[m, m], …], "calibration": <calibration>,
            "board": {"size": [width, height] (m), "origin": [m, m]}  (iff the target has a board),
            "canvas": {"size": [width, height] (m), "origin": [m, m],
                       "texture": {"path", "sha256", "size": [width, height] (m), "origin": [m, m]} (iff it has one)}
                                                                      (iff the target has a canvas),
            "placement": {"origin": [m, m], "side": m}                (iff the target has a chart placement;
                                                                       its calibration's numbers are then the chart's, as held)}
calibration {"kind": <the kind's tag> | "calibration_chain" (a composition), "parameters": parameter_vector (lengths in m),
             "nodes": [[m, m], …] (thin-plate kinds), "members": [<calibration>, <calibration>] (a composition, in application order: the inner map first,
             whatever order the record lists them in),
             "covariance": rows over the parameters, m^(lᵢ+lⱼ) (iff Uncertain)}

VisualGeometryToolkitIO.save — Method
save(path, th::TargetHomographies{F}; provenance = (;))

Write a VGC TargetHomographies as a vgio/target_homographies/v1 file whose declared pixel frame is F, the value's own type — no pixel is converted and none can be written under another frame's label — and whose targets are the value's th.targets: the content_ids of the definitions its target ids resolve in, each the identity of a rig of boards (vgio/rig/v9) or of a single unposed target (vgio/target/v5). Per frame index (sorted) it writes the image and sensor (both required), the time, and every target's homography (ids sorted) as the homography record:

{"target": "a1f2", "type": "homography_map", "parameters": [h11, h12, h13, h21, h22, h23, h31, h32, h33]}

— VGC's parameter protocol of the HomographyMap: its nine entries row-major, canonical (unit Frobenius norm, h33 ≥ 0, VGC sign_normalize), so one placement always writes the same bytes and a stored H seeds HomographyManifold8(H) directly; an H already canonical is written as it is. An Uncertain homography adds its 8×8 covariance in that chart.

H maps the target's plane — its design frame, millimetres — to a pixel of F, BEFORE the lens of the camera the frame's sensor names, about that camera's centre: exactly RadialHomography's H. An H is paired with that camera by VGC's radial_homography(camera, H): for a projective camera the camera itself is the model; for a metric one (fx == fy, no skew) it converts the division coefficients kₚ of K's normalized chart to λₚ = kₚ / f^(2p) about the principal point — equivalently, a plane point X lands on the pixel project(camera, K⁻¹·H·[X; 1]).

A degenerate H (negligible norm, or non-finite), a value naming no targets, and a frame with no image or sensor are an ArgumentError, and no file is written.
