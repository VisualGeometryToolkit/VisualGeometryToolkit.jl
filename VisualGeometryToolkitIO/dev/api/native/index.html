Native Kinds

load, save and validate for the vgio/<kind> files, the frame grammar, content identities, and the building blocks other packages reuse for kinds of their own.

VisualGeometryToolkitIO.VisualGeometryToolkitIO — Module
VisualGeometryToolkitIO

File formats for the VisualGeometryToolkit stack. Each vgio/<kind> JSON file is the serialization of one VisualGeometryToolkitCore type: load(T, path) returns a value of type T, and save(path, value) writes one. Both verbs are public but not exported, so call them qualified (import VisualGeometryToolkitIO as VgtkIO; VgtkIO.load(...)).

The package also reads and writes COLMAP models, reads COLMAP databases and OpenCV/MATLAB calibration exports, and exports to TUM, EuRoC, BOP and TRC.

VisualGeometryToolkitIO.validate — Method
validate(path) -> String

Check a vgio v2 file — or a COLMAP model directory's vgio_units.json, when path is the directory — against its kind's table, the check every v2 reader runs before using a field and every writer runs before writing, and return the kind ("cameras", "rig", …). An ArgumentError names the file, the offending key and the problem; a retired version is refused by name, a retired kind with its successor. Semantic checks that need more than the one file — that measurements resolve in their targets — are the exporters'.

VisualGeometryToolkitIO.pose_from_json — Method
pose_from_json(p, unit::AbstractString) -> EuclideanMap{3} | Uncertain

pose_json's inverse: an embedded {rotation, translation[, covariance]} read in the file's length unit (a unit name), returned UNLABELED in millimetres — Uncertain iff a covariance is stated, its translation block moved to mm². The rotation is the stored quaternion itself, a QuatRotation (not renormalized, not converted to a matrix), so the value writes back to the same numbers. The quaternion must be unit-norm to 1e-6 (refused otherwise, never normalized silently).

VisualGeometryToolkitIO.pose_json — Method
pose_json(X) -> NamedTuple

A pose — a VGC EuclideanMap{3} or an Uncertain one, any labels — as the embedded {rotation, translation[, covariance]} of every pose-carrying kind: the rotation a w-x-y-z quaternion with w ≥ 0 (a QuatRotation's own, exactly; any other rotation converted, reading back as a QuatRotation), the translation in millimetres, the 6×6 covariance (over [δω; δt], rad and mm) iff Uncertain. Its frames are not written: they are given by where it sits. The inverse is pose_from_json.

VisualGeometryToolkitIO.save — Method
save(path, poses::AbstractVector; provenance = (;))

Write labeled rigid poses — EuclideanMap{…, S, D} or Uncertain ones — as a vgio/transforms/v3 file: each record's from/to are its labels' frame names (frame_name), its translation in millimetres, a covariance iff Uncertain. An unlabeled or half-labeled pose is refused (relabel it with the frames it maps between). provenance is the file's free-form object.

VisualGeometryToolkitIO.colmap_cameras — Method
colmap_cameras(cameras::AbstractDict{Symbol}) -> (cameras::Vector{ColmapCamera}, ids::Dict{Symbol, Int})

Project a camera store onto COLMAP camera rows, for feeding a ColmapModel. Ids are assigned 1..n in name order.

TWO LOSSES, both deliberate and both surfaced rather than papered over:

  1. Names do not survive. COLMAP has no camera name field, so the identity a config refers to is gone on the far side. The returned ids map is the remainder — persist it beside the model if anything downstream needs to get back to a name.
  2. Inexpressible cameras throw. A lens no COLMAP model computes has no colmap_model, and that ArgumentError is the correct outcome — a silently dropped or approximated lens model is worse than a failed export. Filter first if a partial export is what you want: filter(p -> colmap_model(lens(last(p))) !== nothing, cameras).

VisualGeometryToolkitIO.load — Method
load(BoundedCamera, path; name = nothing) -> BoundedCamera
load(CameraModel,  path; name = nothing) -> CameraModel

Read ONE camera from a vgio/cameras/v3 store — the bounded camera, or just its model (its calibration block, if any, is the store's to read). Without name the store must hold exactly one camera: a multi-camera store is REFUSED with the available names rather than defaulting to the first — which camera a run uses is an identity, and silently guessing it is how a config ends up calibrated for the wrong lens while reporting success.

VisualGeometryToolkitIO.pixel_frame_name — Method
pixel_frame_name(::Type{<:PixelFrame}) -> String
pixel_frame_from_name(name) -> Type{<:PixelFrame}
pixel_origin(::Type{<:PixelFrame}) -> Symbol

The serialized spelling of a pixel frame, its inverse, and the origin symbol VGC's image_origin keyword takes. Parallel to frame_name/frame_from_name for 3D frames, deliberately separate because the grammars differ: a 3D frame serializes prefixed ("view:cam1"), a pixel frame bare ("colmap").

pixel_frame_from_name validates by constructing the conversion to the canonical pixel frame (colmap). VGC decides whether a pixel frame exists, and its error names the registered set. This only restates that refusal as the ArgumentError every corrupt record in this package raises.

VisualGeometryToolkitIO.save — Method
save(path, cameras::AbstractDict{Symbol}; provenance = (;))

Write a camera store — name → BoundedCamera of a CameraModel, or an Attributed one carrying its calibration block — as a vgio/cameras/v3 file, cameras sorted by name. provenance is the file's one free-form object, which VGIo never reads back.

JSON only, deliberately: cameras are configuration-adjacent (referenced by name from a TOML, hand-inspected, diffed on recalibration), the payload is kilobytes at rig scale, and Julia prints Float64 in its shortest round-trippable form so nothing is lost.

VisualGeometryToolkitIO.load — Method
load(Rig, path; resolve = nothing) -> Rig

Read a vgio/rig/v4 file back into a fully labeled VGC Rig of the storage it holds: sensors (each a BoundedCamera labeled frame → ViewFrame{id}), targets (each Mounted, minted TargetFrame{id} → frame on access), or both. resolve(design) supplies a referenced planar design's nominal points (see target_from_json). VisualGeometryToolkitIO.canonical_json — Method
canonical_json(io::IO, tree)
canonical_json(tree) -> String

The canonical encoding of a lowered JSON tree (see the file header): sorted keys, no whitespace, Int64 bare, integral Float64 printed as an integer, other floats shortest-round-trip. Throws on a non-finite number and on any value outside the lowered vocabulary — a config that cannot be encoded must fail loudly, never hash to something.

VisualGeometryToolkitIO.append_jsonl — Method
append_jsonl(path, row)

Append row (anything JSON.json serializes — a NamedTuple, Dict, …) to path as one JSON line. Thread-safe within the process (per-path lock) and process-append-safe (the line is written with a single write call on an append-mode handle, so concurrent writers interleave at line boundaries). Read the file back with JSON.parse per line.
