VisualGeometryToolkitIO.VisualGeometryToolkitIO — Module
VisualGeometryToolkitIO

File formats for the VisualGeometryToolkit stack. Each vgio/<kind> JSON file is the serialization of one VisualGeometryToolkitCore type: load(T, path) returns a value of type T, and save(path, value) writes one. Both verbs are public but not exported, so call them qualified (import VisualGeometryToolkitIO as VgtkIO; VgtkIO.load(...)).

The package also reads and writes COLMAP models, reads COLMAP databases and OpenCV/MATLAB calibration exports, and exports to TUM, EuRoC, BOP and TRC.

VisualGeometryToolkitIO.read_length — Method
read_length(x::Real, u::Units) -> Quantity

The file number x, written in the length unit u, as a base-form quantity in metres. For a power-of-ten unit (mm, cm, μm, m, km) the conversion shifts the decimal exponent of x, so read_length(62.8, mm) is the metre value nearest the decimal 0.0628 and write_length returns 62.8 exactly; other units (inch, ft, pt) multiply by the unit's scale. Any Float64 crosses — negative, ±0 with its sign, NaN, ±Inf; an integer is read as its Float64. An ArgumentError for a unit that is not a length.

This is the stack's one hand-rolled unit conversion: FlexUnits' own x * u of a float x multiplies by the Float64 of the unit's exact rational scale, one ulp off the decimal for about one number in seven. It is removed — read_length(x, u) becoming base_quantity(x * u) — when FlexUnits applies a rational scale to a float as x * num / den, rounded once (Deduction42/FlexUnits.jl#131).

VisualGeometryToolkitIO.write_length — Method
write_length(q::Quantity, u::Units) -> Float64

The number a file holds for the length q in the unit u, the inverse of read_length: write_length(read_length(x, u), u) prints as x for every x of at most 15 significant digits, and read_length of the result is q itself whenever any file number reads back to it (a full-precision metre value may have none in millimetres; the nearest is written, within an ulp). A power-of-ten unit shifts the decimal exponent of the metre value; any other unit takes the fewest significant digits (1 to 17) that read_length maps back to the identical q. NaN and ±Inf are written as they are. An ArgumentError for a unit that is not a length, or a quantity that is not one.

The search is not a conversion and stays: FlexUnits' ustrip(u, q), even correctly rounded, gives back the file's own number for only about three quarters of decimal file numbers, since the stored metre value is on a different grid; write_length returns the number that reads back to q.

VisualGeometryToolkitIO.from_json — Method
from_json(T, d, contract::UnitContract; kind, role = :world)
from_json(UnitContract, d)

The value of type T a JSON record holds as d (a parsed JSON.Object, any dictionary with string keys, or a NamedTuple), the inverse of json_value: T is Size2, Disc, OrientedDisc, EllipticFrame, AffineFrame or a detection type (VisualGeometryToolkitCore's AbstractDetection, or VisualGeometryToolkitFeatures' Detection). kind, required and never defaulted, declares what the numbers of a Size2 or a Disc are — :plain (plain numbers), :length, :pixel — and is read through read_quantity (a length in the unit of the contract's length role); the other frames hold plain numbers (kind = :plain). Every quantity is a number: a {"value": v, "unit": u} object is refused. A detection's frame type is read off its keys (A, S, θ, else a Disc); its documented metadata fields (response, edge_score, laplacian_scale_score) come first, as Float64, and the others follow sorted by name, each as it was parsed; a cov makes the frame Uncertain again.

from_json(UnitContract, d) reads a record's "units" declaration; a declaration without a density has dpi, one without lengths no further length roles.

julia> import JSON

julia> VgtkIO.from_json(Size2, JSON.parse("{\"width\": 640, \"height\": 480}"), MM_PX; kind = :pixel) ==
           Size2(width = 640px, height = 480px)
true

julia> VgtkIO.from_json(UnitContract, JSON.parse("{\"world\": \"m\"}")) == UnitContract(world = m)
true

VisualGeometryToolkitIO.json_value — Method
json_value(x, contract::UnitContract; kind, role = :world)
json_value(contract::UnitContract)

The plain value (a NamedTuple of numbers, arrays and strings, which JSON.jl's JSON.json writes) a JSON record holds for x under contract, its quantities as numbers in the declared units (write_quantity); read it back with from_json. Defined for VisualGeometryToolkitCore's Size2 ({"width": w, "height": h}), Disc ({"center": [x, y], "σ": s}), OrientedDisc (… "θ": angle), EllipticFrame ({"center": …, "S": [S11, S21, S12, S22]}, column order), AffineFrame (… "A": …) and a detection — an Attributed feature frame, VisualGeometryToolkitCore's AbstractDetection — written as its frame under frame, an Uncertain frame's covariance entries (column order) under cov (null when not finite, with the matrix's size N under cov_size: the size is the value's, an ASIFT EllipticFrame's covariance is 3×3), and each metadata field under its own name.

kind, required, declares what the numbers of the value are — :plain (plain numbers), :length or :pixel — the same kind its reader gives from_json. A value holding a number of another kind, and a quantity in a detection's metadata (it has no declared kind), are an ArgumentError. The OrientedDisc, EllipticFrame and AffineFrame hold plain numbers only (kind = :plain). The lengths of a Size2 or a Disc are written in the unit of the contract's length role (:world by default).

json_value(contract) is the record's declaration of its units, (world = "mm", density = "dpi") for MM_PX, with lengths = (pattern = "pt", …) when the contract declares further length roles (registered unit names; an ArgumentError for a unit without one).

julia> import JSON

julia> JSON.json(VgtkIO.json_value(Size2(width = 640px, height = 480px), MM_PX; kind = :pixel))
"{\"width\":640,\"height\":480}"

julia> JSON.json(VgtkIO.json_value(Disc(Point2(1.0mm, 2.0mm), 3.0mm), UnitContract(world = m); kind = :length))
"{\"center\":[0.001,0.002],\"σ\":0.003}"

julia> VgtkIO.json_value(MM_PX)
(world = "mm", density = "dpi")

julia> VgtkIO.json_value(UnitContract(world = mm, lengths = (pattern = pt,)))
(world = "mm", density = "dpi", lengths = (pattern = "pt",))

read_quantity(x, kind::Symbol, contract::UnitContract; role = :world) -> Quantity

VisualGeometryToolkitIO.write_quantity — Method
write_quantity(q::Quantity, contract::UnitContract; role = :world) -> Real

The number a JSON record holds for the quantity q under contract: a length in the unit of the contract's length role (:world is the default role, a named role's otherwise; through write_length, decimal-exact), a pixel count (a dimensionless quantity: px is dimensionless) as its number of pixels, a density in contract.density. VisualGeometryToolkitIO.colmap_cameras — Method
colmap_cameras(cameras::AbstractDict{Symbol}) -> (cameras::Vector{ColmapCamera}, ids::Dict{Symbol, Int})

Project a camera store onto COLMAP camera rows, for feeding a ColmapModel. Ids are assigned 1..n in name order.

TWO LOSSES, both deliberate and both surfaced rather than papered over:

  1. Names do not survive. COLMAP has no camera name field, so the identity a config refers to is gone on the far side. The returned ids map is the remainder — persist it beside the model if anything downstream needs to get back to a name.
  2. Inexpressible cameras throw. A lens no COLMAP model computes has no colmap_model, and that ArgumentError is the correct outcome — a silently dropped or approximated lens model is worse than a failed export. Filter first if a partial export is what you want: filter(p -> colmap_model(lens(last(p))) !== nothing, cameras).

VisualGeometryToolkitIO.content_id — Method
content_id(targets) -> String

The identity a measurement file (target_points2d, target_points3d) names a target definition by — targets a Rig or a vgio/rig/v5 path: the SHA-256 of the canonical JSON (canonical_json) of the rig's IDENTITY TREE. The tree is built from the in-memory value by the record writer's own walk, under the fixed names below — names of the identity's own, which a later record format must keep mapping to — every length in metres (base units), the targets sorted by id, and no schema version, declaration or provenance. The identity therefore does not change when the file format does: a rig, every file written from it in any decimal length_unit, the rig loaded back from such a file, and a migration of the file to the next rig version have one identity. A relabeled provenance does not change it; a target's calibration kind, its parameters, its covariance its board and its canvas (with its texture reference) do.

The identity is of the persisted representation; a value and the file written from it hash equal by construction. Every length enters as the number a file in millimetres holds for it and reads back as (read(write(x)), idempotent), so a quantity built in code as v * mm, which sits an ulp from the nearest decimal of v, hashes as the file written from it. A pose's rotation enters as the quaternion the writer stores (one conversion, shared by the writer and the tree: w-x-y-z, w ≥ 0; a QuatRotation as held, any other rotation converted once), so a rig held with RotMatrix poses, the file written from it and the rig loaded back have one identity. A rotation converted matrix → quaternion → matrix is not bit-exact, so two in-memory rigs built from the same matrix by different routes can differ in the last ulp, and so can their identities: mint an identity from what you save. Lengths likewise: a decimal unit (mm, cm, m, μm) holds every metre value exactly, so its files share the value's identity; a non-decimal unit (inch) is exact only for numbers born in it, so an inch file of mm-born numbers reads back within an ulp and its identity differs from the value's.

The identity tree, fixed (a test pins it for a rig of every target kind):

rig        {"frame": <frame name>,
            "sensors": [{"id", "camera", "extrinsics": <pose>}, …]  (iff sensors, in rig order),
            "targets": [{"id", "target", "pose": <pose>}, …]        (iff targets, sorted by id)}
pose       {"rotation": [w, x, y, z] (Hamilton, w ≥ 0), "translation": [m, m, m],
            "covariance": 6×6 rows over [δω; δt], rad and m       (iff Uncertain)}
camera     {"intrinsics": [fx, fy, cx, cy, skew] (px, the canonical pixel frame),
            "extent": [width, height] (px), "lens": VGC's lens_record of the lens}
         | {"grid_model": "central" | "noncentral", "extent": [width, height],
            "calibrated_area": [min_x, min_y, max_x, max_y], "grid": [width, height],
            "directions": row-major [[x, y, z], …], "points": row-major [[m, m, m], …] (non-central),
            "nominal_intrinsics": [fx, fy, cx, cy, skew] (px)               (iff the model has one),
            "domain": {"ellipse": [cx, cy, a, b, θ]} (px, a ≥ b, rad)       (iff not the whole plane)}
target     {"kind": "points", "points": [[m, …], …], "point_covariances": per point d×d rows, m² (iff Uncertain)}
         | {"kind": "planar", "reference": <id> | "nominal": [[m, m], …], "calibration": <calibration>,
            "board": {"size": [width, height] (m), "origin": [m, m]}  (iff the target has a board),
            "canvas": {"size": [width, height] (m), "origin": [m, m],
                       "texture": {"path", "sha256", "size": [width, height] (m), "origin": [m, m]} (iff it has one)}
                                                                      (iff the target has a canvas)}
calibration {"kind": <the kind's tag>, "parameters": parameter_vector (lengths in m),
             "nodes": [[m, m], …] (thin-plate kinds), "members": [<calibration>, …] (a chain),
             "covariance": rows over the parameters, m^(lᵢ+lⱼ) (iff Uncertain)}

Write a VGC TargetPoints2D as a vgio/target_points2d/v1 file whose declared pixel frame is F, the value's own type — no pixel is converted and none can be written under another frame's label. Every frame must name its image and sensor, and the value must name the target definitions its indices resolve in (obs.targets, their content_ids).

VisualGeometryToolkitIO.save — Method
save(path, obs::TargetPoints3D{F}; length_unit = mm, provenance = (;))

Write a physical VGC TargetPoints3D as a vgio/target_points3d/v1 file in frame F, in length_unit: per frame its sensor (required), image and time where stated; an Uncertain point writes its 3×3 covariance (length_unit²). Plain points are an ArgumentError (attach the unit, p .* m).

save(path, tp::TargetPoses{F}; length_unit = mm, provenance = (;))

Write a physical VGC TargetPoses as a vgio/target_poses/v1 file declaring to = frame_name(F): per frame index (sorted), its image and sensor (both required) and time, and every target's pose (ids sorted; a covariance iff Uncertain), in length_unit. Plain poses are an ArgumentError.

VisualGeometryToolkitIO.canonical_json — Method
canonical_json(io::IO, tree)
canonical_json(tree) -> String

The canonical encoding of a lowered JSON tree (see the file header): sorted keys, no whitespace, Int64 bare, integral Float64 printed as an integer, other floats shortest-round-trip. Throws on a non-finite number and on any value outside the lowered vocabulary — a config that cannot be encoded must fail loudly, never hash to something.

VisualGeometryToolkitIO.append_jsonl — Method
append_jsonl(path, row)

Append row (anything JSON.json serializes — a NamedTuple, Dict, …) to path as one JSON line. Thread-safe within the process (per-path lock) and process-append-safe (the line is written with a single write call on an append-mode handle, so concurrent writers interleave at line boundaries). Read the file back with JSON.parse per line.
