Related Formats and Exporters

How the kinds compare with community formats

The geometry kinds were designed against the formats the community already uses. They keep the spirit of those formats but follow this package's rules: one JSON schema per kind, declared conventions, typed frames, and Uncertain values stored with a covariance. The exact foreign syntax is produced only by the exporters. The references below were read from shallow clones taken on 2026-10-09.

Exporters

The exporters are write-only. The tests verify each by reading its text back (test/rig_schema_tests.jl).

  • save_tum_trajectory(path, tr; stamp = :time) writes TUM: metres, x,y,z,w, the pose of from in to, with a # comment header that evo skips.
  • save_euroc_trajectory(path, tr; stamp = :time) writes EuRoC ground truth: nanosecond timestamps, metres, w first. evo reads 8 or more columns.
  • save_bop_scene(to_frame, dir, tp, cameras; obj_ids, undistorted) writes scene_gt.json and scene_camera.json laid out as bop_toolkit's save_json writes them, with K moved into to_frame. It returns the obj_id and image maps.
  • save_trc(path, obs; data_rate, stamp) writes OpenSim TRC: tab-separated, in millimetres, with missing markers as empty fields.

There is no C3D writer. A maintained Python writer exists (ezc3d, on conda-forge), but a Python dependency for one binary format is out of proportion for this package, and TRC carries the same marker trajectories.
